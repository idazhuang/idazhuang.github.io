## 上午段 · 写 Method 章的 Overview + 核心组件 1

**① 先垫概念（Method 章是什么 + 为什么先写 Overview）**：
- **Method 章**（通常是论文第 3 章）是论文的「技术核心」——它要把你的方法**讲清楚到「别人能复现」的程度**。它回答的问题是：你的方法长什么样？由哪些部分组成？每部分为什么这么设计？怎么训练？
- **Method 章的标准结构**（第一篇你已经写过一遍，这套骨架直接复用）：① **Overview**（方法总览——一段话 + 一张架构图，让读者先看到全貌）；② **核心组件逐个展开**（你方法的每个创新模块，一个一个讲：是什么、怎么算、为什么这么设计）；③ **训练策略 / 损失函数**（怎么训、用什么 loss）；④（可选）**Algorithm 伪代码**（把整个前向流程写成伪代码，明天写）。
- **为什么先写 Overview（自顶向下 vs 自底向上）**：写 Method 最容易犯的错是「一上来扎进某个组件的公式细节」，结果读者看了半天不知道这个组件在整个方法里的位置。**正确顺序是先写 Overview——先给读者一张「地图」**（方法整体是什么、输入输出是什么、有哪几个关键模块、它们怎么串起来），读者有了全局观，再看每个组件的细节才不会迷路。这和你给别人讲一个系统是一个道理：先讲架构，再讲模块。
- **★ 第二篇的复利在哪（写作质变的来源）**：第一篇写 Method 时，你是「第一次摸索怎么描述一个方法」——光是「Overview 该写多少、组件该怎么组织、公式该怎么排版」就花了大量时间反复改。**第二篇你已经有了第一篇这套成熟的 Method 写法**：Overview 写几句、每个组件分几段（动机 → 公式 → 直觉解释）、符号怎么定义、图怎么配——这些「写作模式」全都现成。所以你今天写 Overview，本质是「往第一篇的 Overline 模板里换内容」，会快很多。**这就是为什么第二篇该比第一篇快一倍：不是方法简单，是你不用再摸索「论文该怎么写」了。**
- **Overview 怎么写（一段话讲清四件事）**：① 你的方法叫什么、解决什么任务（如「针对 SAR 图像旋转舰船检测中的 speckle 噪声敏感问题，我们提出 XXX」）；② 整体由哪几个关键模块组成（点名两个核心组件）；③ 这些模块怎么协同（数据从输入怎么流到输出）；④ 一句话点出和现有方法的关键不同（你的核心创新）。**配一张架构图（中午画）**，文字和图相互印证。
- **核心组件 1 怎么写（每个组件三段式：动机 → 方法 → 直觉）**：写你的第一个核心组件——**复用第一篇写组件的「三段式」**：① **动机段**（为什么需要这个组件——现有方法在这里有什么问题，如「SAR 的 speckle 是乘性噪声，普通卷积会被噪声主导」）；② **方法段**（这个组件具体怎么算——给公式 + 符号定义 + 数据维度）；③ **直觉解释段**（为什么这么设计能解决动机里的问题——用通俗的话讲清 insight，不只是堆公式）。**第三段（直觉）最容易被新手省略，但它恰恰是审稿人最看重的**——它证明你「懂自己方法为什么work」，不是瞎凑的。

> **和通用 CV 论文写作对比**：通用 CV（如普通图像分类/检测）的 Method 写法你可能更熟——其实**遥感/SAR 论文的 Method 结构和通用 CV 完全一样**（Overview + 组件 + 训练），差别只在「内容」：你的动机段要讲清遥感/SAR 特有的难点（speckle、方位角、跨域），你的方法段要体现你针对这些难点的设计。**所以会写通用 CV 的 Method，就会写遥感的 Method——把领域特有的难点和你的针对性设计填进去即可。** 这也是你做这个方向的优势：通用 CV 的写作范式你已掌握，迁过来只换内容。

**② 手把手带做**：
1. 打开第二篇论文的写作文档（建议复用第一篇的 LaTeX/Word 模板——章节框架、宏包、图表样式全现成）。
2. 写 Method 的 **3.1 Overview**：一段话讲清「方法叫什么 + 解决什么任务 + 由哪两个核心组件组成 + 怎么协同 + 核心创新」。预留架构图位置（`Figure 2: Overview of ...`）。
3. 写 **3.2 核心组件 1**（如「Speckle-aware 特征模块」）：按三段式——动机段（现有方法的问题）→ 方法段（公式 + 符号定义 + 维度）→ 直觉段（为什么这么设计 work）。
4. 给所有数学符号在首次出现时定义（如「令 \( F \in \mathbb{R}^{C \times H \times W} \) 为输入特征图……」）。

**③ 合格样例**：写好了 3.1 Overview（一段话 + 架构图占位）和 3.2 核心组件 1（动机/方法/直觉三段齐、公式有、符号都定义了）。判断标准：一个**没看过你代码**的同行，读完这两节能大致明白「你的方法整体长什么样、第一个组件是干嘛的、为什么这么设计」。

**④ 常踩的坑**：
- **一上来扎进组件细节、没写 Overview** → 读者没有全局观会迷路，必须先写 Overview 给地图。
- **只给公式、没有直觉解释段** → 审稿人会觉得「不知道为什么 work」，第三段（直觉）必须写。
- **符号用了不定义**（如直接写 \(F\) 不说它是什么）→ 所有符号首次出现必须定义，否则读者读不懂。
- **直接抄第一篇的句子改几个词** → 这是自我抄袭，结构可复用、句子要重写。

**⑤ 卡住自救（决策树）**：
- 不知道 Overview 写多少？→ 看第一篇的 Overview 长度（通常半页一段 + 一张图），照那个体量。
- 组件的「直觉段」不知道写什么？→ 问自己「如果用一句大白话向师弟解释这个模块为什么有用，我会怎么说」，把那句话展开。
- 公式怎么排版？→ 复用第一篇的公式格式（编号、对齐），别重新折腾。
- 不确定先写哪个组件？→ 先写最核心/最能体现创新的那个（通常是针对你这篇主打难点的模块）。

**⑥ 今天（这一步）你同时学会了什么**：你学会**用「Overview + 组件三段式」的标准结构写 Method 章**。**做了**（写 3.1 Overview + 3.2 组件 1）、**学了**（Method 标准结构、自顶向下先写 Overview、组件三段式中「直觉段」最关键、符号必须定义、第二篇复利来自复用第一篇写作模式）、**会了**（把一个做好的方法准确清楚地描述成 Method 章）。

> **技能卡｜第二篇的写作复利（为什么该快一倍）**：第一篇写到 v1 用 4 周（W21–W24），第二篇目标 1 周写到 v0.5——快的不是方法简单，是你不用再摸索「论文怎么写」。可复用资产：① 章节框架（Method/Exp 的小节顺序）；② 句式骨架（组件三段式、Intro 四段式）；③ 图表规范（架构图风格、表格样式、公式排版）；④ 论文语言（学术英语句式）。**复用结构和句式，重写全部内容**（自我抄袭同样违规）。一周写完 v0.5 = 你的写作能力已质变。

## 中午段 · 画架构图（复用第一篇绘图工具和风格，保持系列感）

**① 先垫概念（架构图的作用 + 为什么要「保持系列感」）**：
- **架构图**（通常是论文 Figure 2）是 Method 章的「门面」——审稿人和读者**第一眼看的就是它**。一张好的架构图能让人 30 秒看懂你方法的整体流程；一张乱的架构图会让人还没读文字就先困惑。
- **架构图要画清楚的三件事**：① **数据流**（输入图 → 各模块 → 输出），用箭头串起来；② **你的核心组件**（用醒目的颜色/框标出，让人一眼看到「创新在哪」）；③ **关键的维度/操作**（如特征图尺寸、关键算子），标在图上辅助理解。
- **★ 为什么要「复用第一篇的绘图工具和风格，保持系列感」**：这是一个容易被忽略但很有价值的细节。① **效率**：第一篇你已经摸索好了用什么工具画（如 draw.io / PowerPoint / TikZ）、用什么配色、模块框怎么画——第二篇直接复用这套，几小时就能画好，不用从零折腾工具；② **系列感（个人品牌）**：如果你两篇论文的架构图**风格统一**（同样的配色逻辑、同样的模块表示法、同样的排版气质），它们看起来就像「同一个研究者的系列工作」，专业、成体系。**当空天院老师或同行看到你两篇风格一致的论文时，会形成「这个人有自己成熟的研究和表达体系」的印象**——这种一致性本身就是一种隐性的专业信号。反之，如果两篇图风格迥异（一篇很精致一篇很潦草），会显得不够成熟。
- **从这件事看「表达的一致性」对长期的价值**：你未来会有第三篇、第四篇，会有 GitHub 仓库、会有作品集 PDF、会有给老师汇报的 PPT——**如果它们的视觉风格是统一的（同一套配色、同一种图表气质、同一种排版逻辑），你整个「作品集」就有了辨识度和专业度**。这就像一个设计师的作品集有统一的视觉语言。对你这个要「用强作品说话、给空天院留下专业印象」的人，从第二篇开始有意识地维护「视觉系列感」，是在低成本地积累个人品牌资产。今天复用第一篇的绘图风格，就是这件事的起点。

**② 手把手带做**：
1. 打开第一篇论文的架构图源文件（draw.io/PPT/TikZ 工程），**另存为第二篇的图**——保留配色、模块框样式、字体、箭头风格。
2. 改内容：把第一篇的模块换成第二篇的（输入改成 SAR 图、组件框改成你的两个核心组件、输出改成对应任务结果）。
3. 标出**你的核心组件**（用和第一篇一致的「高亮色」），让创新点一眼可见。
4. 标关键维度/算子（特征图尺寸、关键操作名），辅助读者理解数据流。
5. 导出高分辨率矢量图（PDF/SVG，确保论文里放大不糊）。

**③ 合格样例**：一张和第一篇风格统一的架构图——数据流清晰（输入→模块→输出有箭头）、核心组件用一致的高亮色标出、关键维度有标注、矢量导出不糊。判断标准：让一个没读文字的人只看图，能说出「输入是 SAR 图、经过这两个模块、输出是检测结果，创新在被高亮的那两块」。

**④ 常踩的坑**：
- **从零重画、不复用第一篇工程** → 浪费时间且风格不统一，应另存第一篇的图改内容。
- **核心组件没高亮，混在普通模块里** → 创新点看不出来，必须用醒目色标出。
- **导出位图（PNG 低分辨率）放进论文** → 放大糊，必须矢量（PDF/SVG）。
- **图和正文 Overview 描述不一致**（图里有的文字没提、文字提的图里没有）→ 图文必须对应。

**⑤ 卡住自救（决策树）**：
- 没有第一篇的图源文件了？→ 用同样的工具按同样的配色重建（至少保持风格一致）。
- 图太复杂塞不下？→ 抓主干（核心数据流 + 两个核心组件），次要细节省略或放附录。
- 不会画矢量图？→ draw.io 免费、能导 PDF/SVG，复用第一篇模板最省事。
- 配色不知道选什么？→ 直接用第一篇的配色（这正是「保持系列感」的意义）。

**⑥ 今天（这一步）你同时学会了什么**：你学会**画一张和已有论文风格统一的架构图**。**做了**（复用第一篇图源、改内容、高亮核心组件、矢量导出）、**学了**（架构图要画清数据流/核心组件/关键维度、复用风格=效率+系列感、视觉一致性是个人品牌资产）、**会了**（高效产出专业、成体系的论文架构图）。

> **技能卡｜论文架构图（门面 + 系列感）**：架构图是 Method 的门面（审稿人第一眼看）。画清三件事：数据流（箭头串输入→模块→输出）/核心组件（高亮色标出，创新一眼可见）/关键维度。★复用第一篇的绘图工具和配色——既省时间，又让两篇论文有「系列感」（同一研究者的成熟体系，隐性专业信号）。必须矢量导出（PDF/SVG，放大不糊），图文对应。

## 晚上段 · 写核心组件 2 + 训练策略

**① 先垫概念（组件 2 + 训练策略怎么写）**：
- **核心组件 2**：写你方法的第二个核心模块——**还是用三段式**（动机 → 方法 → 直觉），和上午写组件 1 一模一样的结构。如果两个组件有协同关系（如组件 2 用了组件 1 的输出），在方法段里说清它们怎么衔接。
- **训练策略 / 损失函数（Method 的 3.4 节）**：讲你怎么训练这个方法——① **损失函数**（用了什么 loss，如分类 loss + 回归 loss + 你可能加的针对性 loss，给公式）；② **训练细节里属于「方法」的部分**（如有特殊的训练流程、两阶段训练、特殊的数据处理策略——注意：纯粹的超参如 lr/batch size 不放这里，放 Experiment 的「实现细节」）。
- **★ 「方法细节」vs「实现细节」的分界（新手常混）**：这是写论文要分清的一条线——**Method 章写「方法本质」（损失设计、模块结构、训练策略这类「换个人复现也得这么做」的东西）；Experiment 章的「实现细节」写「具体配置」（lr=0.01、batch=8、训练 12 epoch、用 RTX 4090 这类「可调的工程参数」）**。判断标准：如果这个细节是「你方法成立的一部分」，放 Method；如果是「跑实验时的具体设置」，放 Experiment。比如「我们用 Focal Loss 处理类别不平衡」是方法（放 Method），「Focal Loss 的 \(\gamma=2\)」是实现细节（放 Experiment）。

**① 先垫概念（Introduction 的作用 + 「四段结构」模板）**：
- **Introduction**（第 1 章）是论文的「门面 + 说服」——审稿人读完标题和摘要后，**Intro 决定他对这篇论文的第一印象和基本判断**（这个问题重要吗？这个 Gap 真实吗？这个方法有道理吗？）。Intro 写好了，审稿人会带着好感读下去。
- **★ Intro 的「四段结构」模板（第一篇你用过，直接复用）**：这是一个非常通用、好用的 Intro 写法——① **第一段：背景 + 重要性**（你的任务是什么、为什么重要，如「SAR 图像舰船检测在海洋监测中至关重要……」）；② **第二段：现有方法 + 它们的不足（Gap）**（别人怎么做的、还有什么问题没解决，如「现有方法多直接套用光学图像的检测器，忽略了 SAR 的 speckle 噪声和方位角特性，导致……」）；③ **第三段：你的方法（怎么填这个 Gap）**（你提出了什么、核心 idea 是什么，如「为此我们提出 XXX，通过……」）；④ **第四段：贡献列表（Contributions）**（用 bullet 列 2–4 条你的贡献，如「• 我们提出了 speckle-aware 模块……• 在 N 个数据集上 SOTA……• 仅用单张 4090……」）。
- **★ 第二篇 Intro 的复利（这正是「四段结构」威力的体现）**：第一篇写 Intro 时，你可能反复纠结「背景写多少、Gap 怎么引出、贡献怎么列」——光是摸索出这个「四段结构」就花了不少时间。**第二篇你直接套这个结构**：第一段背景（换成 SAR 检测的背景）、第二段 Gap（换成第二课题针对的问题——很可能就是第一篇 Limitation 提到的那个）、第三段你的方法、第四段贡献。**结构现成，只换内容，一上午能写完。这就是写作质变最直观的体现——同样一篇 Intro，第一篇要磨好几天，第二篇半天搞定。**
- **Gap 段（第二段）是 Intro 的灵魂**：审稿人最看重「你解决的问题是不是真问题」。所以第二段要把 Gap 讲**清楚且真实**——不是泛泛说「现有方法不够好」，而是具体指出「现有方法在 X 方面有什么具体缺陷，导致 Y 后果」。**你的 Gap 来自第一篇的 Limitation 或真实调研**（不是编的），这让它经得起推敲。

> **和通用 CV 论文的 Intro 对比**：通用 CV 论文的 Intro 也是这个四段结构（背景→Gap→方法→贡献），**完全一样**。差别只在「背景和 Gap 要讲遥感/SAR 特有的」：你的背景要讲 SAR/遥感任务的重要性，你的 Gap 要讲「现有方法（很多是通用 CV 直接套用的）忽略了 SAR 的物理特性」——**而「现有方法直接套用通用 CV、忽略遥感特性」恰恰常常就是你的 Gap 和卖点所在**。这再次说明你做这个方向的优势：你既懂通用 CV（知道别人套用了什么），又在补遥感特性这块（你的创新），写 Gap 时这个对比天然成立。

**② 手把手带做**：
1. 复制第一篇 Intro 的四段结构作为骨架。
2. 写**第一段**（背景+重要性）：SAR/第二课题任务的重要性。
3. 写**第二段**（Gap）：现有方法的具体不足（来自第一篇 Limitation/调研，讲清「什么缺陷→什么后果」）。
4. 写**第三段**（你的方法）：你提出什么、核心 idea。
5. 写**第四段**（贡献列表）：bullet 列 2–4 条贡献（含「单张 4090 高效」这条卖点）。

**③ 合格样例**：Introduction 完成——四段齐全（背景/Gap/方法/贡献），Gap 段具体真实（来自第一篇 Limitation 或调研），贡献列表清晰（含效率卖点）。判断标准：审稿人读完 Intro，认同「这是个真问题 + 这个方法有道理 + 贡献清楚」。

**④ 常踩的坑**：
- **Gap 写得泛**（只说「不够好」不说具体缺陷）→ 要具体指出「什么缺陷→什么后果」。
- **贡献列表写成「我做了什么」而非「我的贡献是什么」**（如「我跑了实验」不是贡献）→ 贡献要是「提出了什么新东西/达到了什么效果」。
- **直接抄第一篇 Intro 改几个词** → 结构复用、内容（尤其背景和 Gap）必须重写成第二课题的。
- **Intro 太长**（背景铺垫一大堆）→ 四段精炼，重点在 Gap 和方法，背景别啰嗦。

**⑤ 卡住自救（决策树）**：
- Gap 不知道怎么讲？→ 回到第一篇的 Limitation（第二篇很可能就是解决它的），那就是现成的、真实的 Gap。
- 贡献列几条？→ 2–4 条（核心方法创新 + 实验效果 + 效率/其他亮点）。
- 第一段背景写多少？→ 看第一篇第一段体量，别长篇大论。
- 第三段和 Method 重复？→ Intro 第三段是「高层 idea 一句话」，Method 是「详细怎么做」，详略不同。

**⑥ 今天（这一步）你同时学会了什么**：你学会**用「四段结构」模板写 Introduction**。**做了**（写背景/Gap/方法/贡献四段）、**学了**（Intro 决定第一印象、四段结构模板、Gap 段是灵魂要具体真实、第二篇 Intro 复利来自复用结构、贡献是「新东西/效果」不是「做了什么」）、**会了**（高效写出有说服力的 Introduction）。

> **技能卡｜Intro 四段结构模板（复用第一篇）**：①背景+重要性（任务为什么重要）；②Gap（现有方法的具体缺陷→什么后果，灵魂段，来自第一篇 Limitation/调研，要真实）；③你的方法（核心 idea 一句话）；④贡献列表（bullet 2–4 条：方法创新/实验效果/效率卖点）。★第二篇直接套结构换内容，一上午写完=写作质变最直观体现。Gap 段务必具体（不泛说「不够好」），贡献写「新东西/效果」不是「做了什么」。

## 中午段 · 写 Related Work（在第一篇 RW 基础上增量更新）

**① 先垫概念（Related Work 的作用 + 「增量更新」）**：
- **Related Work**（相关工作，第 2 章）：系统梳理与你工作相关的已有研究，**说清「别人做到哪了、你和他们什么关系」**。它的作用是：① 显示你了解领域（学术素养）；② 把你的工作定位在已有研究的版图上（你补了什么空白）。
- **RW 的典型组织**：按主题分几小段（如「2.1 旋转目标检测」「2.2 SAR 图像检测」「2.3 你方法相关的技术，如去噪/跨域」），每段梳理该主题的代表工作 + 简评，**最后点出你和它们的不同/你补的空白**。
- **★ 第二篇 RW 的最大复利：增量更新（不用从零写）**：这是第二篇省时间的大头——**第一篇你已经写过一个 RW，里面梳理的相关工作（旋转检测、遥感检测等）很多在第二篇还能用**。第二篇的 RW 写法是「**在第一篇 RW 基础上增量更新**」：① 第一篇已有的、第二篇还相关的部分——**直接复用并适度精简/改写**（注意改写避免自我抄袭）；② 第二课题**特有的新方向**（如 SAR speckle 处理、跨域检测的相关工作）——**新增这部分的梳理**；③ 加入这一年的**最新工作**（第一篇之后发表的新论文）。**所以第二篇 RW = 复用第一篇大部分 + 新增第二课题特有方向 + 补最新——比第一篇从零写快得多。**
- **从这件事理解「文献积累是复利资产」**：你读过的每一篇论文、写过的每一段 RW，都不是「一次性消耗」——它们沉淀成你的**文献库**，会在第二篇、第三篇反复复用。第一篇你认真梳理了旋转检测的相关工作，第二篇这部分几乎白送；第二篇你新增梳理 SAR 处理，第三篇可能又能复用。**这就是为什么坚持读论文、认真做文献笔记是高复利的**——你的「领域知识库」越积越厚，每篇新论文的 RW 成本越来越低，而且你对领域的全局把握越来越强（这对最终和空天院老师对话、找准研究定位也极有价值）。今天的「RW 增量更新」就是你前期文献积累在兑现复利。

**② 手把手带做**：
1. 把第一篇 RW 复制过来作为基础。
2. **复用 + 精简改写**第一篇里第二篇仍相关的部分（如旋转检测、遥感检测——改写避免自我抄袭）。
3. **新增**第二课题特有方向的梳理（如 SAR speckle 处理 / 跨域泛化的相关工作）。
4. **补最新工作**（第一篇之后发表的、与第二课题相关的新论文，体现你在追踪前沿）。
5. 每个主题段末尾点出「你和这些工作的不同/你补的空白」。

**③ 合格样例**：Related Work 完成——复用了第一篇相关部分（已改写）+ 新增第二课题特有方向 + 补了最新工作 + 每段点出你的定位。判断标准：审稿人觉得「这个作者了解领域全貌，且清楚自己工作在版图上的位置」。

**④ 常踩的坑**：
- **直接整段复制第一篇 RW 不改写** → 自我抄袭，复用的部分必须改写。
- **没新增第二课题特有方向** → 第二课题有特有的相关工作（如 SAR 处理）必须新增梳理。
- **没补最新工作** → 要加入第一篇之后的新论文，否则显得文献不更新。
- **只罗列工作、不点定位**（光说别人做了啥，不说你和他们关系）→ 每段末要点出你的不同/空白。

**⑤ 卡住自救（决策树）**：
- 哪些第一篇的 RW 能复用？→ 与第二课题任务相关的（如都是旋转检测/遥感检测的）能复用，无关的删。
- 第二课题特有方向不知道梳理哪些？→ 你 M8 立项、M9 做实验时调研过的相关工作（baseline 们、相关方法）。
- 最新工作哪找？→ 你这几个月读的新论文 + Google Scholar Alert 推送的（D258 还会读 2 篇）。
- RW 多长合适？→ 看第一篇 RW 体量，第二篇通常相近或略增（多了新方向）。

**⑥ 今天（这一步）你同时学会了什么**：你学会**用「增量更新」高效写 Related Work**。**做了**（复用第一篇相关部分+新增第二课题方向+补最新+点定位）、**学了**（RW 显素养+定位工作、增量更新=复用大部分+新增特有+补最新、文献积累是复利资产、每段要点出你的空白）、**会了**（基于已有积累快速写出体现领域把握的 RW）。

> **技能卡｜Related Work 增量更新（文献复利）**：RW=按主题梳理相关工作+点出你的定位（补了什么空白）。★第二篇最大复利：在第一篇 RW 基础上增量更新——①复用第一篇仍相关的部分（改写避免自我抄袭）；②新增第二课题特有方向（如 SAR 处理/跨域）；③补第一篇之后的最新工作。比从零写快得多。文献积累是复利资产：读过的论文/写过的 RW 反复复用，领域知识库越积越厚、每篇 RW 成本越来越低。

## 晚上段 · 写 Conclusion + Abstract

**① 先垫概念（Conclusion + Abstract 怎么写 + 为什么 Abstract 最后写）**：
- **Conclusion**（结论，论文最后一章）：**总结全文**——简要回顾你做了什么（问题 → 方法 → 主要结果），可呼应 Limitation 点一句未来工作。它和 Intro 首尾呼应（Intro 提出问题，Conclusion 总结解决）。**比 Intro 短**，是浓缩的收尾。
- **Abstract**（摘要，放在最前面但**最后写**）：全文的「极致浓缩」——**一段话（通常 150–250 词）讲清四件事**：① 问题/背景（一句）；② 你的方法（一两句，核心 idea）；③ 主要结果（一两句，关键数字，如「在 N 个数据集上达到 X mAP，提升 +Y」）；④（可选）亮点（如单张 4090 高效）。
- **★ 为什么 Abstract 最后写**：Abstract 是全文的浓缩——**只有全文都写完了，你才知道「最值得浓缩进摘要的是什么」**（最重要的方法点、最亮眼的结果数字）。如果一开始写 Abstract，往往写不准（还没定稿）。所以顺序是：先写完所有章节 → 最后浓缩出 Abstract。**Abstract 虽然最后写，却是除标题外审稿人最先读、读得最仔细的部分**（很多审稿人靠摘要决定要不要细读、给什么基调），所以要反复打磨到精准、有吸引力。
- **★ Abstract 是论文「传播」的关键（被检索、被引用的第一接口）**：你的论文将来在 arXiv、在 Google Scholar、在数据库里，**别人最先看到的就是标题和摘要**——他们靠摘要决定「要不要点开读、要不要引用」。一个清楚、有亮点的摘要，能让更多人读你的论文、引用你的工作，**也能让空天院的老师在检索时被吸引**。所以摘要不只是「应付格式」，它是你论文触达更多人的第一接口。把四件事（问题/方法/结果/亮点）在一小段里讲得清楚有力，是一项要专门练的能力。对你这个要「用论文成果说话、扩大影响力」的人，写好摘要 = 让你的硬成果被更多人看见。

**② 手把手带做**：
1. 写 **Conclusion**：回顾问题→方法→主要结果（呼应 Intro）+ 一句未来工作（呼应 Limitation）。比 Intro 短。
2. 写 **Abstract**（最后写）：一段话讲清四件事——① 问题（一句）② 方法核心（一两句）③ 主要结果+关键数字（一两句）④ 亮点（单张 4090 等）。
3. 反复打磨 Abstract 到精准有力（控制在 150–250 词，每句都有信息量，无废话）。
4. 检查 Abstract 里的数字和正文一致、亮点和贡献列表呼应。

**③ 合格样例**：Conclusion（总结全文+呼应 Intro/Limitation）+ Abstract（一段话讲清问题/方法/结果/亮点，数字准、有吸引力）。判断标准：只读 Abstract，读者就能准确知道「你解决了什么、怎么解决的、效果如何、亮点在哪」，并产生「想读全文」的兴趣。

**④ 常踩的坑**：
- **Abstract 一开始就写、没等全文定稿** → 最后写才能浓缩准确。
- **Abstract 没有具体结果数字**（只说「效果很好」）→ 要给关键数字（X mAP、+Y 提升）。
- **Abstract 太长/有废话** → 控制 150–250 词，每句有信息量。
- **Conclusion 和 Abstract 内容雷同** → Conclusion 是「全文回顾」（可展开些），Abstract 是「极致浓缩」（更短更密），且 Conclusion 在文末、Abstract 在文首。
- **Abstract 数字和正文不一致** → 必须一致（这是全文数字一致检查的一部分）。

**⑤ 卡住自救（决策树）**：
- Abstract 写不下四件事？→ 砍废话（背景别铺垫太多），优先保证方法核心 + 结果数字。
- 不知道摘要放哪个数字？→ 放最亮眼的主结果（最高 mAP / 最大提升 / 效率优势）。
- Conclusion 写什么？→ 三句话版：我们解决了 X 问题，提出了 Y 方法，达到了 Z 结果（+一句未来）。
- Abstract 不够吸引人？→ 突出「新意+效果+亮点」（你的方法新在哪、赢多少、单张 4090 高效）。

**⑥ 今天（这一步）你同时学会了什么**：你学会**写 Conclusion 和 Abstract（论文的浓缩与门面）**。**做了**（写 Conclusion 总结+呼应、最后写 Abstract 浓缩四件事+打磨）、**学了**（Conclusion 首尾呼应 Intro、Abstract 最后写才浓缩准、Abstract 讲清问题/方法/结果/亮点、Abstract 是论文传播被引的第一接口）、**会了**（写出精准有吸引力的摘要和收尾全文的结论）。

> **技能卡｜Abstract（最后写的「第一接口」）**：Abstract 放最前但最后写（全文定稿才知道浓缩什么）。一段话（150–250词）讲清四件事：①问题（一句）②方法核心（一两句）③主要结果+关键数字（一两句）④亮点（单张 4090）。★它是除标题外审稿人最先、最仔细读的，也是论文被检索/被引用/被空天院老师看见的第一接口——要打磨到精准有力（每句有信息量、数字与正文一致）。Conclusion 则首尾呼应 Intro（问题→方法→结果+未来），比 Intro 短。

> **今日交付**：✅ Introduction（四段结构）✅ Related Work（增量更新）✅ Conclusion ✅ Abstract。

## 上午段 · 英文润色

**① 先垫概念（英文润色的目标 + 方法）**：
- **英文润色**：把论文的英文表达提升到「地道、清楚、无语法错误」——**目标不是「华丽」，是「准确清楚、读起来顺、符合学术规范」**。学术英语贵在精确和简洁，不需要文学性。
- **润色的重点**：① **语法/拼写**（无低级错误）；② **句子清楚**（一句话表达一个意思，别太长太绕）；③ **学术句式地道**（用学术论文常用的表达，如「We propose...」「Experiments demonstrate that...」「In contrast to...」）；④ **时态一致**（一般现在时描述方法/事实，过去时描述你做的实验，复用第一篇的时态惯例）；⑤ **用词准确**（术语用对、避免口语化）。
- **★ 第二篇英文润色的复利 + 工具的正确用法**：① **复利**——第一篇你积累了大量学术英语句式（怎么说「我们提出」「实验表明」「相比之下」「值得注意的是」），第二篇直接复用这些句式模板，润色快很多；② **工具辅助、你把关**——可以用语法检查工具（如 Grammarly）辅助查语法，可以参考你读过的好论文的表达，但**最终要你自己把关**：工具能查语法，但**不懂你的技术内容**（可能把对的术语改错、把你的意思改偏）。**所以：工具帮你查语法/提建议，你判断每个建议对不对、保留技术准确性。** 不能盲目全盘接受工具的修改。
- **从这件事理解「英文是工具，内容才是核心」**：作为非英语母语者，英文表达可能是你的相对短板，但**别让它成为心理负担**——审稿人评判论文，核心看「工作的质量」（idea、方法、实验），英文只要「清楚、无碍理解」即可，不需要母语级文采。**很多优秀的论文出自非英语母语者，英文朴实但内容扎实**。你要做的是：把英文打磨到「清楚、规范、无语法错」这个够用的水平（靠复用句式 + 工具辅助 + 多读多写），而不是追求文采。真正让你论文出彩的，永远是扎实的工作本身。对你这个持续产出的人，学术英语会随着写得越多越熟练（第二篇就比第一篇顺），这又是一项随产出积累的复利能力。

## 一、合格范例 — Method/Experiment/Intro/Abstract 写作范例（照着改）

> 说明：以下范例以「SAR 旋转舰船检测 + speckle-aware 模块」为具体例子演示**写法和句式骨架**（你换具体题目时，结构照搬、内容全换成你第二课题真实的）。**复用结构，重写内容——别直接抄。**

**【范例 1：Method Overview 段（3.1）】**
> Given a SAR image, our goal is to detect arbitrarily-oriented ships robustly under speckle noise. We propose **XXX**, which consists of two key components: (i) a **speckle-aware feature module** that suppresses multiplicative noise while preserving target structures, and (ii) an **orientation-robust detection head** that handles the azimuth sensitivity of SAR targets. Given an input image, multi-scale features are first extracted by the backbone, then refined by component (i) to obtain noise-robust representations, and finally decoded by component (ii) into oriented bounding boxes. In contrast to prior methods that directly adapt optical detectors and ignore SAR-specific physics, XXX explicitly models the speckle and orientation characteristics. An overview is shown in Figure 2.

**【范例 2：核心组件「三段式」（动机→方法→直觉）】**
> *(动机)* SAR images are corrupted by multiplicative speckle noise, which conventional convolutions—designed for additive-noise natural images—handle poorly, as the noise can dominate weak target signals.
> *(方法)* To address this, we design the speckle-aware module. Let \(F \in \mathbb{R}^{C \times H \times W}\) denote the input feature. We first estimate a noise-attentive map \(M = \sigma(\text{Conv}(F))\), then modulate the feature as \(F' = F \odot (1 + M)\), where \(\odot\) is element-wise multiplication and \(\sigma\) is the sigmoid function. ...
> *(直觉)* Intuitively, the module learns to **amplify reliable target responses and suppress noise-dominated regions**, so that downstream detection focuses on genuine target structures rather than speckle artifacts. This directly tackles the motivation above.

**【范例 3：4.2 主表分析文字（有 insight，不是念数字）】**
> 平庸写法（念数字，别这样）：~~Our method achieves 78.5 mAP on SSDD and 71.2 on HRSID...~~
> 合格写法（有 insight）：As shown in Table 2, XXX consistently outperforms all baselines across the three SAR datasets, surpassing the strongest competitor by **+1.8 mAP** on average. Notably, the improvement is **larger on datasets with stronger speckle noise** (e.g., +2.6 on Dataset-B), which corroborates our motivation that explicitly modeling speckle is crucial for SAR detection. Moreover, XXX attains this accuracy with **fewer parameters and higher FPS, using only a single RTX 4090**, demonstrating its efficiency.

**【范例 4：Introduction 四段结构骨架】**
> *(段1 背景)* SAR ship detection plays a vital role in maritime surveillance, working day-and-night and through clouds...
> *(段2 Gap)* However, most existing methods directly adapt detectors designed for optical images, **overlooking two SAR-specific challenges: the multiplicative speckle noise and the azimuth sensitivity of targets**, which leads to degraded accuracy under strong noise...
> *(段3 方法)* To bridge this gap, we propose XXX, which explicitly models speckle and orientation via two dedicated components...
> *(段4 贡献)*
> • We propose a speckle-aware module that suppresses multiplicative noise while preserving target structures.
> • We design an orientation-robust head tailored to SAR azimuth sensitivity.
> • XXX achieves state-of-the-art results on three SAR benchmarks **using only a single RTX 4090**, demonstrating both effectiveness and efficiency.

**【范例 5：Abstract 骨架（四件事，150–250 词）】**
> *(问题)* SAR ship detection is crucial yet challenging due to speckle noise and azimuth sensitivity. *(方法)* We propose XXX, comprising a speckle-aware feature module and an orientation-robust detection head that explicitly model SAR-specific physics. *(结果)* Extensive experiments on three SAR benchmarks show that XXX surpasses the strongest baseline by +1.8 mAP on average, with the gains being most pronounced under heavy speckle. *(亮点)* Remarkably, all experiments are conducted on a single consumer-grade RTX 4090, highlighting the method's efficiency and accessibility.

**【范例 6：Limitation 段（诚实 + 带未来方向）】**
> While XXX achieves strong results, it has limitations. First, the gains diminish on extremely low-resolution targets, where speckle and signal are hard to separate; **a physically-grounded denoising prior may help in future work**. Second, although efficient, processing very large SAR scenes still requires tiling; **an end-to-end large-scene design is left for future exploration**. (注：每条局限带一句未来方向——既显远见，又为你第三篇埋伏笔。)

## 二、实用模板 — 论文写作流程 SOP + 自检清单

**【模板 1：第二篇论文「一周写完 v0.5」的写作顺序 SOP】**
1. **先写「肉」（D253–D255）**：Method（Overview→组件→训练策略→伪代码）→ Experiment（4.1 数据集/实现 → 4.2 主表 → 4.3 消融 → 4.4 可视化 → 4.5 讨论/Limitation）。**为什么先写肉**：这是你已有结果的客观描述，最好写、最硬。
2. **再写「壳」（D256）**：Intro（四段）→ RW（增量更新）→ Conclusion → **Abstract（最后写）**。
3. **整合（D257）**：组装全文 → v0.5 → 通读自审（假装审稿人，先标记）→ 修改（先硬后软）。
4. **打磨（D258）**：英文润色（工具辅助你把关）+ 图表最终版 → v0.6。
5. **收尾（D259）**：复盘（记录写作质变）+ 发外部 review + 计划 W38。
> 核心心态：**复用结构重写内容**；**先完整后完美**；**全文数字始终一致**。

**【模板 2：投稿前论文全文 self-check 清单（W38 v1.0 定稿用，提前知道）】**
- [ ] Method：符号都定义 / 公式文字一致 / 图文一致 / 伪代码与代码一致 / 每个设计有直觉解释
- [ ] Experiment：数据集写清规模划分 / 实现细节可复现（含单张 4090）/ 主表加粗最优 / 消融配「为什么」/ 可视化含负面案例 / 讨论有洞察 / Limitation 诚实带方向
- [ ] **全文数字一致**（Abstract/Intro/Experiment 所有数字统一——通查）
- [ ] 术语统一（同一东西同一词）/ 章节图表编号连续 / 每图表被正文引用 / 引用 `[x]` 在 References 有对应
- [ ] Intro：四段齐 / Gap 具体真实 / 贡献是「新东西/效果」/ 含效率卖点
- [ ] Abstract：四件事齐（问题/方法/结果数字/亮点）/ 精准有吸引力 / 数字与正文一致
- [ ] 英文：无语法错 / 句子清楚 / 时态一致（方法现在时、实验过去时）/ 术语准确
- [ ] 复用 ≠ 抄袭：复用第一篇结构句式，但内容全部重写（无自我抄袭）

| Method 读者看不懂方法全貌 | 没先写 Overview、一上来扎进组件细节 | 先写 Overview 给「地图」，再展开组件 |
| 审稿人觉得「不知道方法为什么 work」 | 组件只给公式、省了「直觉解释段」 | 每个组件三段式，必写「为什么这么设计 work」 |
| 论文被指「自我抄袭」 | 直接抄第一篇句子改几个词 | 复用结构/句式骨架，内容全部重写 |
| 把 lr/batch 写进了 Method | 没分清「方法细节」vs「实现细节」 | 方法本质放 Method、可调配置放 Experiment 实现细节 |
| 4.2 分析文字像废话 | 只把表格数字念了一遍 | 写 insight：赢多少/在哪赢更多+联系方法设计/效率 |
| 审稿人怀疑数据可信度 | 正文数字和表格不一致 | 整合/图表/定稿三次通查全文数字一致 |
| 可视化显得「在挑好的展示」 | 只放成功案例 | 放几张诚实的负面/失败案例 + 分析 |
| Intro 动机不可信 | Gap 写得泛（只说「不够好」） | Gap 具体（什么缺陷→什么后果），来自第一篇 Limitation/调研 |
| Abstract 写不准 | 一开始就写、还没定稿 | Abstract 最后写（全文齐了才好浓缩） |
| 卡在「每段写完美」、没有完整草稿 | 没遵循「先完整后完美」 | 先快速拉通 v0.5，再迭代打磨 |
| 自己审不出问题 | 用作者视角读（脑补缺失逻辑） | 切换「挑剔审稿人」视角；并发外部 review 补盲点 |
| 英文被工具改偏了技术意思 | 盲目全盘接受工具修改 | 工具辅助查语法，你逐条把关技术准确性 |
