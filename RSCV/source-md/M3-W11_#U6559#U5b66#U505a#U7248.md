# D71 周一 · 设计仓库结构 + git/GitHub 私仓初始化

## 上午段 · 设计代码仓库目录结构

**① 先垫概念(为什么要自己搭框架,而不是把代码堆一个文件)**
- 做研究要有一套**可复用的实验框架**,而不是把所有代码堆在一个 `main.py` 里。标准目录:`configs/`(配置)`datasets/`(数据加载)`models/`(模型)`utils/`(工具:日志/指标)`scripts/`(训练/评估脚本)`experiments/`(实验记录)`docs/`(文档)。
- **和"直接改别人代码"对比**:改别人的代码快,但你不理解底层、出 bug 难定位、想加自己的模块处处掣肘;**自己搭框架(哪怕只是在 MMRotate 上封一层)能让你对每一行代码负责**——这是工程能力的分水岭,也是你后面快速迭代方法的前提。
- **为什么现在需要**:你 W12 要做 5 组消融、M5 要做几十组实验。没有 `configs/` + `experiments/` 的组织,几十组实验会乱成一团("这个结果是哪个配置跑的?")。框架是为后面的规模化实验铺路。

**② 手把手带做**:画出目录树(标注每个文件夹用途),在工作区 `mkdir` 建好这套结构;在 `docs/结构说明.md` 写清每个目录放什么;在 `models/` 里预留 `baseline.py` 和 `your_method.py` 两个空文件,在 `configs/` 放一个示例 config。
**③ 这一步合格的样子**:一棵清晰的目录树 + 每个目录的用途说明;空壳文件和示例 config 就位,结构一眼能看懂。
**④ 最常踩的坑**
- 所有代码堆 `main.py` → 后面无法复用/扩展,改一处牵动全身。
- 目录过度设计(建一堆用不到的空壳、嵌套五层)→ 够用即可,六块起步,按需再加。

**⑤ 卡住怎么自救(决策树)**:不知怎么分? → 就按"配置/数据/模型/工具/脚本/实验"六块起步;纠结某个文件放哪? → 按"它属于哪一层职责"放(数据相关进 datasets,通用工具进 utils),实在拿不准先放着,后面重构。
**⑥ 今天(这一步)你同时学会了什么**:你学会**设计可复用的实验框架结构**——这是规模化实验的前提。**做了**(目录树 + 结构说明)、**学了**(标准实验仓库的组织)、**会了**(为一个研究项目规划工程结构)。

> **技能卡｜可复用实验框架结构**:`configs/`(配置)`datasets/`(数据+transforms)`models/`(baseline + your_method)`utils/`(logger + metric)`scripts/`(train + eval)`experiments/`(每实验一目录)`tests/`(单测)`docs/`。原则:够用即可、按职责分层、为规模化实验(几十组)预留组织方式。

## 中午段 · 初始化 git + GitHub 私仓 + 写 .gitignore

**① 先垫概念(git / 私仓 / .gitignore 各是什么)**
- **git** 是代码的"存档 + 时光机"(随时回到任意历史版本);**GitHub 私仓**是云端存档(私有,别人看不到,防丢);**`.gitignore`** 写明"哪些不纳入版本管理"。
- **为什么数据/权重/日志绝不进仓库**:这些是大文件(几个 G),提交进去会**撑爆仓库、push 极慢、还可能泄露数据**。代码进仓库,数据/权重/日志留本地——这是铁律。
- **为什么现在就要做**:从框架第一天起就版本管理,后面任何一次"改坏了"都能回滚;等代码多了再补 git,丢失的历史就找不回了。

**② 手把手带做**:`git init` → 建 GitHub 私仓并关联 → 写 `.gitignore`(排除 `data/ checkpoints/ *.log work_dirs/ __pycache__/ *.pth`)→ 第一次 `git add . && git commit -m "feat: init repo structure" && git push`。
**③ 这一步合格的样子**:私仓建好、首次提交成功;`.gitignore` 正确排除了大文件目录(用 `git status` 确认 data/checkpoints 不在待提交列表里)。
**④ 最常踩的坑**
- 把数据/权重 commit 进去 → 仓库爆炸,且可能泄露;提交前务必 `git status` 检查。
- 仓库设成 public(未发表代码)→ 设 **private**(你的方法还没发表,公开有被抢跑风险)。

**⑤ 卡住怎么自救(决策树)**:push 报权限错 → 配 SSH key 或用 personal access token;不小心 add 了大文件 → `git rm --cached <file>` 移除并补进 `.gitignore`,再 commit。
**⑥ 今天(这一步)你同时学会了什么**:你学会**用 git/GitHub 管理研究代码 + 正确配 .gitignore**。**做了**(私仓 + 首次提交 + .gitignore)、**学了**(git 版本管理、忽略大文件)、**会了**(把研究代码纳入可追溯的版本管理)。

> **技能卡｜git + .gitignore 规范**:从项目第一天 `git init` + GitHub **私**仓。`.gitignore` 必排除 `data/ checkpoints/ *.pth *.log work_dirs/ __pycache__/`。提交前 `git status` 确认无大文件。commit message 带 `feat:/fix:/exp:` 前缀,便于回溯。

# D72 周二 · 写数据层 + 单元测试

> **预期管理**:今天写"数据层"——把磁盘上的图和标注读成模型能吃的张量,还要做单元测试验证它对不对。数据层是最容易藏 bug 的地方(标注解析、增强同步),所以今天的单元测试不是走形式,而是帮你在训练几小时前就抓住错误。

## 上午段 · 写 datasets 模块(支持 ≥2 个数据集的 loader)

**① 先垫概念(数据层是什么、为什么要统一接口)**
- **数据层**负责"把磁盘上的图/标注读成模型能吃的张量 `(image, target)`"。你 Proposal 里选了 ≥2 个数据集,最好**统一接口**(同一套调用方式加载不同数据集),后面换数据集零成本。
- **和通用 CV 对比**:通用 CV 数据集格式统一(COCO json),一个 loader 走天下;遥感数据集格式五花八门(DOTA 的 8 点旋转框 txt、HRSC 的 xml、不同分辨率),所以你更需要"为每个数据集写解析、但暴露统一接口"。

**② 手把手带做**:在 `datasets/` 写一个统一的 Dataset 类(或为每个数据集写一个、共享接口),实现"读图 + 读标注 → 返回 `(image_tensor, target)`";支持你选的 ≥2 个数据集。复用你 M1 写的旋转框解析逻辑。骨架:
```python
# datasets/base.py —— 统一接口，子类只实现 _load_anno
from torch.utils.data import Dataset
from PIL import Image
import numpy as np

class RSDetDataset(Dataset):
    """遥感旋转检测统一基类：不同数据集只需各自实现 _load_anno()。"""
    def __init__(self, root, split="train", transforms=None):
        self.root, self.split, self.transforms = root, split, transforms
        self.samples = self._scan_samples()          # [(img_path, anno_path), ...]

    def _scan_samples(self): raise NotImplementedError
    def _load_anno(self, anno_path): raise NotImplementedError   # → dict(boxes, labels)

    def __len__(self): return len(self.samples)

    def __getitem__(self, i):
        img_path, anno_path = self.samples[i]
        img = np.array(Image.open(img_path).convert("RGB"))
        target = self._load_anno(anno_path)          # {"boxes": [N,5(xc,yc,w,h,θ)], "labels":[N]}
        if self.transforms:
            img, target = self.transforms(img, target)   # 图与标注同步变换
        return img, target

# datasets/dota.py —— 子类只实现解析（复用你 M1 的 8 点→(xc,yc,w,h,θ) 逻辑）
class DOTADataset(RSDetDataset):
    def _scan_samples(self): ...                     # 扫描 images/ 与 labelTxt/
    def _load_anno(self, p):
        boxes, labels = parse_dota_txt(p)            # 你 M1 写过的解析
        return {"boxes": boxes, "labels": labels}
```
**③ 合格样例**:能用同一套接口加载 ≥2 个数据集,返回正确的 `(图, 标注)` 张量(`HRSCDataset` 只需再写一个 `_load_anno` 解析 xml)。
**④ 最常踩的坑**:① 每个数据集写一套完全不同的调用方式 → 难维护,尽量统一接口;② 标注解析错(回想 M1 的 8 点旋转框解析,顺序/弧度制易错)。
**⑤ 卡住怎么自救(决策树)**:标注格式不熟 → 回用 M1 写的解析逻辑,打印前几条标注核对;接口设计纠结 → **先让一个数据集能跑,再抽象共性**(别一上来就追求完美抽象)。
**⑥ 今天(这一步)你同时学会了什么**:你学会**写统一的多数据集数据层**。**做了**(datasets 模块)、**学了**(统一数据接口)、**会了**(把多个数据集封装成可复用 loader)。

## 中午段 · 写 transforms(数据增强)

**① 先垫概念(数据增强是什么、遥感的特殊之处)**:**数据增强(transforms)**= 训练时对图做随机变换(裁剪/翻转/旋转/颜色抖动),让模型见更多变化、更鲁棒。**遥感的特殊性**:遥感目标**无固定朝向**(俯视拍摄),所以随机 0/90/180/270 旋转特别有用(通用 CV 一般不大角度旋转,因为地面物体有"上下");还有多尺度(遥感目标尺度悬殊)。
**② 手把手带做**:在 `datasets/transforms.py` 写增强:随机裁剪/翻转/旋转/颜色抖动 + 遥感特有(多尺度、90° 倍数旋转);可视化几张增强后的图 + 标注框,确认效果合理。关键是几何增强要**图和框同步**:
```python
# datasets/transforms.py —— 90° 倍数旋转，图和旋转框同步
import numpy as np, random

class RandomRot90:
    """遥感目标无固定朝向：随机转 0/90/180/270°，标注框同步旋转。"""
    def __call__(self, img, target):
        k = random.randint(0, 3)                 # 转 90*k 度
        if k == 0:
            return img, target
        img = np.rot90(img, k).copy()            # 图旋转
        H, W = img.shape[:2]                      # 旋转后的新尺寸
        boxes = target["boxes"].copy()           # [N,5]: xc,yc,w,h,θ
        for _ in range(k):                       # 每 90° 更新中心坐标和角度
            xc, yc = boxes[:, 0].copy(), boxes[:, 1].copy()
            boxes[:, 0], boxes[:, 1] = yc, W - xc - 1   # 坐标系随旋转变换
            boxes[:, 4] = (boxes[:, 4] + np.pi / 2) % np.pi  # 角度 +90°
            W, H = H, W
        target["boxes"] = boxes
        return img, target
```
**可视化自检**:转完把框画回图上,目标应仍被框住(框没"飞走"=同步对了)。
**③ 合格样例**:增强可配置、可视化后效果合理(目标没被增强没了、框跟着转对了)。
**④ 坑**:增强太猛(把目标裁出画面 / 旋转后标注没同步)→ **几何增强必须同步变换标注**(框/mask 跟着转)。
**⑤ 自救**:增强后框对不上 → 检查标注是否跟图做了同样的几何变换;**先关掉几何增强跑通,再逐个加回来**定位是哪个增强出的问题。
**⑥ 今天(这一步)你同时学会了什么**:你学会**写(含遥感特有的)数据增强并验证**。**做了**(transforms)、**学了**(增强的作用、几何增强要同步标注、遥感无固定朝向)、**会了**(配置并可视化检查数据增强)。

## 晚上段 · 写数据层单元测试

**① 先垫概念(单元测试是什么、为什么数据层必须测)**:**单元测试**= 用一小段代码验证你写的函数是否正确。例:输入一张 512×512 图,经 DataLoader 输出应是 `(batch, 3, 512, 512)` 张量;形状不对 = 有 bug。**为什么数据层尤其要测**:数据 bug(标注错位、增强没同步)在训练几小时后才以"指标异常低"的形式暴露,极难倒查;单元测试能在**训练前几秒**就抓住它。
**② 手把手带做**:写 `tests/test_dataset.py`:验证 ① DataLoader 输出张量形状正确 ② 标注数量/范围合理(框坐标在图内、角度在合法范围)③ 增强可视化无误;用 pytest 运行确保通过。
**③ 合格样例**:单元测试通过(形状/标注/增强都对)。
**④ 坑**:① 不写测试直接训 → bug 在训练几小时后才暴露,更难查;② 测试只测"能跑"不测"对不对"(只看不报错,不断言形状/数值)。
**⑤ 自救**:测试失败 → **正是它的价值**(早抓 bug);按报错定位是读图/解析/增强哪一步出的问题。
**⑥ 今天(这一步)你同时学会了什么**:你学会**写单元测试守护数据层**。**做了**(数据层单元测试)、**学了**(单元测试的意义)、**会了**(用测试在早期抓住数据层 bug)。

> **技能卡｜单元测试守护**:用一小段代码 `assert` 关键函数的输出(形状/数值/标注范围)。数据层和模型层都要测——bug 在训练前几秒被抓,胜过训练几小时后倒查。测"对不对"(断言),不只测"能跑"(不报错)。

# D73 周三 · 写模型层 + 你的方法 v1

> **预期管理**:今天把 baseline 和"你的方法 v1"都搭进框架。**重点心态:v1 不求完美,只求"能跑、能输出正确形状"**——你第一次把自己的 idea 变成可运行的模型,能跑通就是巨大胜利,性能和美化是后面的事。

## 上午段 · 写 models 模块(先把 baseline 搭起来)

**① 先垫概念**:**模型层**先把 baseline 搭起来(可直接调用 MMRotate/torchvision 的现成模型,或封装你 M2 复现的 SOTA)。**先有一个能跑的 baseline**,你的方法才有对比对象;而且用你 M2 sanity-check 过的那个 baseline,可比性和正确性都有保障。
**② 手把手带做**:在 `models/baseline.py` 实现/封装 baseline(复用你 M2 复现并 sanity-check 过的 Oriented R-CNN,最稳),保证它能 `forward` 出正确形状。封装模式(把现成模型包成统一接口):
```python
# models/baseline.py —— 不重写算法，只把 MMRotate 现成模型包成统一接口
import torch.nn as nn
from mmrotate.models import build_detector
from mmcv import Config

class Baseline(nn.Module):
    """封装 Oriented R-CNN：暴露 extract_feat / head / forward 统一接口，
    让 your_method 能在同一接口上插模块、用同一套 train/eval 对比。"""
    def __init__(self, cfg):
        super().__init__()
        mm_cfg = Config.fromfile(cfg["mm_config"])     # 复用你 M2 跑通的官方 config
        self.det = build_detector(mm_cfg.model)        # 现成实现，正确性有保障
    def extract_feat(self, x):                         # 统一接口①：出多尺度特征
        return list(self.det.extract_feat(x))
    def head(self, feats):                             # 统一接口②：检测头
        return self.det.bbox_head(feats)
    def forward(self, x, target=None):
        return self.det.forward_train(x, target) if target is not None \
               else self.head(self.extract_feat(x))

def build_model(name, cfg=None):                       # models/__init__.py 用它分发
    from .your_method import YourMethod
    return {"baseline": Baseline, "your_method": YourMethod}[name](cfg)
```
**关键**:不重写算法、只封装,既省事又保证 baseline 正确;`extract_feat/head` 这两个口子就是你 D73 中午给 your_method 插模块的地方。
**③ 合格样例**:baseline 能实例化、forward 出正确输出形状。
**④ 最常踩的坑**:① 从零手写 baseline → 没必要也易错,封装现成的;② forward 形状错 → print 中间张量形状逐层排查。

```python
# models/your_method.py —— 在 baseline 上"包一层"，只加你的模块
import torch.nn as nn
from .baseline import build_baseline

class HighResBranch(nn.Module):
    """创新模块 v1：保留浅层高分辨率特征，缓解下采样丢小目标。最简实现先打通链路。"""
    def __init__(self, in_ch, out_ch):
        super().__init__()
        self.fuse = nn.Conv2d(in_ch, out_ch, 3, padding=1)  # v1 先用一个卷积验证有效性
    def forward(self, low_feat, high_feat):
        high = nn.functional.interpolate(low_feat, size=high_feat.shape[-2:],
                                         mode="bilinear", align_corners=False)
        return self.fuse(high + high_feat)            # 把高分辨率细节融回主特征

class YourMethod(nn.Module):
    def __init__(self, cfg):
        super().__init__()
        self.baseline = build_baseline(cfg)           # 复用 baseline，保持同接口
        self.hr = HighResBranch(in_ch=256, out_ch=256)
    def forward(self, x):                             # 与 baseline.forward 同签名
        feats = self.baseline.extract_feat(x)         # 拿到多尺度特征
        feats[0] = self.hr(feats[1], feats[0])        # 在最高分辨率层注入你的模块
        return self.baseline.head(feats)              # 走原 head，输出同 baseline 格式
```
**先验证"能跑"**:`YourMethod(cfg)(torch.randn(2,3,1024,1024))` 不报错、输出与 baseline 同格式即可——性能留到 D75 比、W12 调。
**③ 合格样例**:`your_method` 能实例化、forward 出正确形状(和 baseline 同接口)。
**④ 坑**:① 上来追求完美/复杂 → 先 v1 能跑;② 你的模块接错维度 → print 形状对齐。
**⑤ 自救**:forward 报维度错 → 在你模块前后 print 张量形状,逐处对齐;模块写不出 → 先用最简实现(哪怕只是一个额外卷积/一层注意力)验证框架通,确认链路后再换成你真正的设计。
**⑥ 今天(这一步)你同时学会了什么**:你**第一次把自己的 idea 实现成可跑的模型**。**做了**(方法 v1 代码)、**学了**("先能跑再优化"、最小改动实现)、**会了**(在 baseline 上实现自己的创新模块)。

**① 先垫概念**:**训练脚本** = 把数据层 + 模型 + 优化器 + loss 串成训练循环(M1 学的五步);**评估脚本** = 在 val/test 上算指标。把它们写成**可配置**(通过 config 指定模型/数据/超参),才能复用——换实验只改 config,不改代码。

```python
# scripts/train.py —— config 驱动，换实验只改 yaml 不改代码
import yaml, torch, argparse
from datasets import build_dataset
from models import build_model
from utils.logger import Logger
from utils.seed import set_seed

def main(cfg_path):
    cfg = yaml.safe_load(open(cfg_path))
    set_seed(cfg["seed"])                              # 固定 seed（多 seed 只改 cfg）
    loader = build_dataset(cfg)                        # 数据层
    model = build_model(cfg["model"]).cuda()          # baseline 或 your_method
    opt = torch.optim.SGD(model.parameters(), lr=cfg["lr"], momentum=0.9)
    scaler = torch.cuda.amp.GradScaler()              # 混合精度，省显存（单卡友好）
    logger = Logger(cfg)                              # 自动记超参 + commit hash
    for epoch in range(cfg["epochs"]):
        for it, (img, target) in enumerate(loader):
            opt.zero_grad()
            with torch.cuda.amp.autocast():           # AMP 前向
                loss = model(img.cuda(), target)
            scaler.scale(loss).backward()
            torch.nn.utils.clip_grad_norm_(model.parameters(), 35)  # 防梯度爆炸
            scaler.step(opt); scaler.update()
            if it % 50 == 0: logger.log({"loss": loss.item(), "epoch": epoch})
        torch.save(model.state_dict(), f"{logger.dir}/epoch_{epoch}.pth")

if __name__ == "__main__":
    p = argparse.ArgumentParser(); p.add_argument("--cfg"); p.add_argument("--seed", type=int)
    a = p.parse_args(); main(a.cfg)   # --seed 可覆盖 cfg，便于多 seed 脚本批量调
```
**③ 合格样例**:`train.py`/`eval.py` 能通过 config 驱动,跑通一个小实验(几个 iter,不报错、能存/读 checkpoint)。

**⑥ 今天(这一步)你同时学会了什么**:你搭起了**可配置的训练/评估框架**。**做了**(train/eval 脚本)、**学了**(config 驱动的训练流程)、**会了**(把训练/评估写成可复用脚本)。

## 中午段 · 写日志系统(TensorBoard + wandb)

**② 手把手带做**:在 `utils/logger.py` 接入 TensorBoard/wandb,训练时自动记录超参 + loss 曲线 + 指标;**把当前 git commit hash 也记进日志**(这样每个结果都能对应到确切的代码版本)。每个实验一个独立目录(时间戳 + 实验名命名)。
```python
# utils/logger.py —— 每个实验独立目录 + 记超参 + commit hash（可回溯的关键）
import os, time, subprocess, json
from torch.utils.tensorboard import SummaryWriter

class Logger:
    def __init__(self, cfg):
        stamp = time.strftime("%Y%m%d-%H%M%S")
        self.dir = f"experiments/{stamp}_{cfg['model']}_seed{cfg['seed']}"
        os.makedirs(self.dir, exist_ok=True)
        commit = subprocess.getoutput("git rev-parse --short HEAD")  # 记下代码版本
        meta = {**cfg, "commit": commit, "time": stamp}
        json.dump(meta, open(f"{self.dir}/meta.json", "w"), indent=2)  # 超参+commit 存盘
        self.tb = SummaryWriter(self.dir); self.step = 0
    def log(self, d):
        for k, v in d.items(): self.tb.add_scalar(k, v, self.step)
        self.step += 1
```
**为什么记 commit**:三个月后看到一个好结果,`meta.json` 里的 commit 让你能 `git checkout` 回那一版代码,精确复现。
**③ 合格样例**:训练时自动产生可查看的 loss 曲线和超参记录(TensorBoard/wandb 里能看到),且记录了 commit hash。

> **技能卡｜实验日志该记什么**:每个实验自动记录 ① 超参(全部)② 时间戳 ③ loss/指标曲线 ④ 最终指标 ⑤ **git commit hash**(对应确切代码版本)。每实验独立目录(时间戳+名)。没有这些 = 黑箱,结果无法复现。

```python
# ===== ① 固定随机种子（可复现的前提）=====
import random, numpy as np, torch
def set_seed(seed):
    random.seed(seed); np.random.seed(seed)
    torch.manual_seed(seed); torch.cuda.manual_seed_all(seed)
    torch.backends.cudnn.deterministic = True
    torch.backends.cudnn.benchmark = False

# ===== ② 多 seed 运行器：同一配置跑多个 seed，收集 mean±std =====
import numpy as np
def run_multi_seed(eval_fn, cfg_name, seeds=(0, 1, 2)):
    """eval_fn(seed) 应训练+评估并返回该 seed 的指标(float)。"""
    results = []
    for s in seeds:
        metric = eval_fn(s)            # 实际项目里调用 train.py/eval.py
        results.append(metric)
        print(f"  [{cfg_name}] seed={s}: {metric:.2f}")
    arr = np.array(results)
    print(f"→ {cfg_name}: {arr.mean():.2f} ± {arr.std():.2f}  (seeds={seeds})")
    return arr.mean(), arr.std()

# ===== ③ 数据层单元测试（验证形状/标注；pytest 可跑）=====
def test_dataloader_shape(MyDataset):
    from torch.utils.data import DataLoader
    ds = MyDataset(split="train")
    loader = DataLoader(ds, batch_size=2)
    img, target = next(iter(loader))
    assert img.ndim == 4 and img.shape[1] == 3, f"图像形状错: {tuple(img.shape)}"
    assert len(target) == 2, "标注数量与 batch 不符"
    print("数据层单元测试通过:", tuple(img.shape))

def test_model_forward(build_model):

        model = build_model(name).eval()
        with torch.no_grad():

        assert out is not None, f"{name} 前向输出为空"
        print(f"{name} forward OK")
```

```python
# ===== ⑤ eval.py + metric：算任务指标 + 参数量/FPS（你的"高效"卖点）=====
import time, torch

def count_params(model):
    return sum(p.numel() for p in model.parameters()) / 1e6      # 单位 M

@torch.no_grad()
def measure_fps(model, img_size=1024, warmup=10, runs=50):
    model.eval().cuda()
    x = torch.randn(1, 3, img_size, img_size).cuda()
    for _ in range(warmup): model(x)                            # 预热，避免首跑偏慢
    torch.cuda.synchronize(); t0 = time.time()
    for _ in range(runs): model(x)
    torch.cuda.synchronize()
    return runs / (time.time() - t0)                            # 张/秒

def evaluate(model, loader, metric_fn):
    model.eval()
    preds, gts = [], []
    with torch.no_grad():
        for img, target in loader:
            preds.append(model(img.cuda())); gts.append(target)
    return metric_fn(preds, gts)                                # mAP / mIoU / F1

# 汇报：把任务指标 + 参数 + FPS 一起打印，直接进 Table 1
def report(model, loader, metric_fn, name):
    m = evaluate(model, loader, metric_fn)
    print(f"{name}: metric={m:.2f} | params={count_params(model):.0f}M "
          f"| FPS={measure_fps(model):.1f}")
```

| 训练几小时后才发现数据 bug | 没写单元测试 | 先写 test_dataset/test_model 再训 |
| v1 "加了等于没加" | 模块没真正接进前向/参数没更新 | print 模块输出;把权重放大/置零看输出变不变;查 requires_grad 与前向路径 |
| 对比不公平/提升说不清来源 | v1 改了方法以外的东西 | 同一 config 只换 model;`diff` 核对只差一处 |
| 实验无法复现/记不清超参 | 没记 config/commit | 日志自动记超参 + git commit hash;每实验独立目录 |
| 提升在 std 之内被误判无效/有效 | 只看 mean 不看 std | 报 mean±std;提升 > std 才算初步可信;不够就靠后续迭代加强 |
| 训练 OOM | batch/分辨率过大 | 降 batch、降输入分辨率、开混合精度(AMP) |

## 六、对比分析范例（D77 中午交付物的范本，200–400 字）
> 给你一个"好的对比分析长什么样"的样板——不是只报数,而是有数字、有规律、有下一步。

```markdown
# 第一组对比分析（Ours v1 vs Baseline，DOTA-v1.0，3 seeds）

总体：v1 mAP 76.3±0.4 vs baseline 75.5±0.3，平均 +0.8。提升幅度
略大于两者 std，初步判定"方向有效但尚不稳健"——符合 v1 的预期
（最简实现、未调参）。参数仅 +1M、FPS 16→15 基本持平，说明高分
辨率分支没有牺牲效率，这点对我们"单卡高效"的定位是好信号。

分类观察（翻了 30 张预测图）：
- 小目标密集区（如港口的密集小船）：v1 召回明显高于 baseline，
  漏检的小船少了一圈——和我们"高分辨率分支保留小目标特征"的动机吻合。
- 大目标（操场、大型建筑）：两者基本持平，v1 没有额外收益（符合预期，
  大目标本就不依赖高分辨率细节）。
- 失败案例：密集区相邻小目标仍有粘连/错框，说明仅靠特征融合不够，
  后续可能需要在 label assignment 或 NMS 上再做文章。

下一步（W12 消融指向）：
1) 消融"高分辨率分支"确认其贡献是否就来自小目标召回；
2) 针对相邻粘连，准备 v2 的改进方向（如更细的分配策略）；
3) 在第二个数据集（HRSC）上验证该规律是否泛化。
```

**这段为什么合格**:① 有数字且和 std 比(判断显著性);② 带了参数/FPS(扣住高效卖点);③ 分类找规律(小目标↑、大目标持平)并和动机对应;④ 写了失败案例;⑤ 明确指向 W12 消融和 v2 改进——把"一组数字"变成了"下一步的行动清单"。这正是从"会跑实验"到"会做研究"的关键一跃。
