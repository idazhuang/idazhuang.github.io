# D155 周一 · 改论文 Intro + 竞赛 TTA

> 上午把 Intro 的 motivation 改强(审稿常见意见);中午晚上上第一个竞赛 Trick——TTA。
>
> **预期管理**:M6 收官周,本周双线并行——上午改论文(慢思考)、中午晚上刷竞赛(快迭代)。今天改 Intro motivation + 上 TTA。提醒:论文和竞赛节奏完全不同(论文要安静深入、竞赛要快试快交),**别混在一起做**否则两边都做不好;强化motivation要用具体场景/数据/后果说话,别只堆"非常重要"这类形容词;TTA无需重训,但翻转的预测要翻回原图坐标再融合。

## 上午段 · 据 mock review 改 Intro(强化 motivation)

**① 先垫概念**:若审稿说"**motivation 不够强**"——要**加强问题的重要性论述**:为什么这个 Gap 值得解决?不解决有什么后果(漏检会怎样、误判会怎样)?用具体场景/数据/后果说话。这是录用的关键(审稿人要先认同"问题值得做")。
- **为什么"motivation不够强"是常见且致命的审稿意见**:审稿人评判一篇论文,首先要被说服"**这个问题值得解决**"——如果他读完Intro觉得"这问题没什么意义/不重要/已经解决得差不多了",那后面你方法再好他也提不起兴趣,可能直接拒。**motivation(动机)就是论证"为什么这个问题重要、值得做"**。很多论文方法不错但被拒,就是因为motivation没讲透,审稿人没被说服问题的价值。所以"motivation不够强"是必须认真对待的A级意见。
- **怎么把motivation改强(三个抓手)**:① **具体应用场景**——这个问题在什么真实场景中重要(如"遥感小目标检测在灾害评估、军事侦察、城市规划中至关重要");② **不解决的后果**——如果这个问题解决不好会怎样(如"漏检密集小目标会导致灾情评估遗漏受灾区域,延误救援");③ **量化的影响**——用数据说明问题的规模/严重性(如"现有方法在小目标上漏检率高达X%")。**用"具体场景+严重后果+量化数据"三管齐下,让审稿人认同问题确实重要、确实该解决**。
- **最忌讳"只堆形容词"**:改motivation时,新手常犯的错是堆砌空洞的强调词——"这是一个非常重要、极具挑战性、意义重大的问题"。**这些形容词不传递任何实质信息,审稿人不会被说服**。真正有说服力的是具体的东西:一个真实的应用场景、一个具体的失败后果、一个量化的数据。**用事实和场景说话,而非用形容词喊口号**。比如不说"小目标检测极其重要",而说"在洪涝灾害评估中,漏检一片被淹的车辆和房屋,会导致该区域的受灾程度被严重低估"——后者让人真切感到问题的分量。
- **改motivation别偏离主线**:强化motivation时要**紧扣你论文实际解决的那个Gap**——别为了"显得重要"扯太远(泛讲整个遥感领域多重要),那样反而稀释了焦点。motivation要精准地论证"你解决的这个具体问题"的价值,和你的方法、贡献形成一条线。
**② 手把手带做**
1. 据 mock review,在 Intro 强化"问题重要性"(加具体应用场景、量化数据、不解决的后果)。
2. 让读者读完认同"这个问题该解决",且紧扣你实际解决的那个Gap(别扯太远)。
**③ 合格样例**:Intro 的 motivation 更有力(读者认同问题价值,有具体场景/后果)。
**④ 常踩的坑**:**只堆形容词**("非常重要、极具挑战")→ 用具体场景/数据;改过头偏离主线 → 紧扣你的 Gap。
**⑤ 卡住自救**:不知怎么强化?→ 举一个具体应用(如灾害评估漏检的代价)+ 一个数据(该问题影响多少)。
**⑥ 今天(这一步)你同时学会了什么**:你学会**强化 motivation**。**做了**(Intro 修改)、**学了**(论证问题重要性用场景/后果)、**会了**(让 motivation 更有说服力)。

## 中午段 · 竞赛改进 2:TTA(测试时增强)

**① 先垫概念(TTA)**:**TTA = 测试时对同一张图做多种变换(翻转/多尺度/旋转),分别预测再融合**(平均/投票)。**类比**:同一道题让几个"略有不同视角的自己"各做一遍再综合,通常更稳、更准。**最大优点:无需重训**(只在推理时做)。
- **为什么TTA能稳定提分(原理)**:模型对同一目标的不同视角(原图、翻转、不同尺度)的预测,各自可能有些误差,但**误差方向不完全一致**——把多个视角的预测融合(平均/投票),随机误差会相互抵消,系统性的正确信号会被强化,结果更稳更准。这就像"多个略有不同视角的自己各做一遍题再综合答案",比单次判断可靠。**TTA是竞赛里性价比极高的一招**:不用重新训练(只在推理时多做几次变换),就能稳定提升一点分数。
- **TTA的关键:翻转预测要"翻回原图坐标"再融合**:这是TTA最容易出错、也最关键的一点。对于检测/分割任务,如果你对图做了水平翻转再预测,**得到的框/掩膜是在翻转后的图上的坐标——必须把它翻转回原图坐标,才能和原图的预测对齐融合**。如果忘了翻回去就直接融合,框/掩膜的位置就全错了,结果反而变差。**做TTA时,每做一种变换,预测后都要做对应的逆变换把坐标还原**,再融合。这一步务必小心。
- **TTA变换怎么选(别太多)**:常用的TTA变换有水平翻转、垂直翻转、多尺度(几个不同输入尺寸)、旋转等。**别一次上太多变换**——变换越多,推理越慢(每种变换都要前向一次)。**先用2-3种最有效的(如水平翻转+多尺度)**,看效果。检测任务的多个框融合,简单平均不够好,要用WBF(Weighted Box Fusion,下周详解)正确合并。
- **TTA和训练阶段的改进互补**:TTA是推理阶段的提分招(不改训练),它和训练阶段的改进(多尺度训练、更强backbone等)是**互补**的——可以叠加使用(训练时多尺度训练 + 推理时多尺度TTA,效果往往更好)。所以TTA是个"几乎总能加一点、且不影响其他改进"的稳妥招,竞赛冲刺常用。
**② 手把手带做**
1. 推理时加 TTA(先做水平翻转 + 多尺度两种,代码见补充包)。
2. **关键**:翻转的预测要**翻回原图坐标**再融合(检测/分割尤其要对齐)。
3. 本地验证有无提升。
**③ 合格样例**:TTA 推理跑通,本地有提升(或持平)。
**④ 常踩的坑**:**翻转预测没翻回**就融合 → 结果错乱;TTA 太多变换 → 推理太慢,先用 2-3 种。
**⑤ 卡住自救**:TTA 后反而变差?→ 检查融合方式(检测要正确合并框,见下周 WBF);太慢 → 减少变换数。
**⑥ 今天(这一步)你同时学会了什么**:你学会 **TTA 提分**。**做了**(TTA)、**学了**(测试时增强=多视角综合、无需重训、要对齐坐标)、**会了**(用 TTA 免重训提分)。

> **技能卡｜TTA**:推理时多变换(翻转/多尺度)分别预测→对齐回原图→融合。无需重训、通常稳定提分;检测的框融合用 WBF。

## 晚上段 · 跑竞赛 TTA 版本 → 提交

**① 先垫概念**:用 TTA 生成提交,看线上排名变化(本地涨不等于线上涨,以线上为准)。**为什么强调"以线上为准"**:你的TTA改进可能在本地验证集上涨了,但提交到线上排行榜——这才是真正的评判。**本地涨不等于线上涨**:有时本地的提升是过拟合了你的本地验证划分(改进恰好迎合本地验证集的特点,不泛化到线上测试集)。所以**每个Trick都要实际提交、看线上分数变化来判断它真有用没**,别只看本地。这也是为什么竞赛要"快试快交快看排名"——线上反馈才是真相。把TTA的线上Δ分记入Trick日志(改了什么/Δ分/是否保留);明显涨就保留TTA,线上没涨就记录、可能和别的Trick组合才显效(先留着或标记,组合阶段再试)。**用线上分数作为每个Trick去留的依据**,这是竞赛迭代的基本准则。
**② 手把手带做**
1. 用 TTA 生成提交文件(翻转的预测先翻回原图坐标再融合)。
2. 提交,看线上排名(本地涨不等于线上涨,以线上为准)。
3. 记入 Trick 日志(Δ分 / 是否保留);线上没涨先留着,组合阶段再试。
**③ 合格样例**:竞赛 TTA 提交,排名变化记录。
**④ 常踩的坑**:本地涨就以为线上涨 → 看线上;线上没涨就删 TTA → 记录,可能和别的 Trick 组合才显效。
**⑤ 卡住自救**:线上没涨?→ 记录,试下一招;明显涨 → 保留 TTA。
**⑥ 今天(这一步)你同时学会了什么**:你提交并验证了 TTA。**做了**(TTA 提交)、**学了**(线上验证为准)、**会了**(以排名衡量 Trick)。

## 上午段 · 改论文 Method(表述不清→加图/公式)

**① 先垫概念**:若审稿说"**某处表述不清**"——**加图或加公式**把它讲清(图/公式常比纯文字更清楚)。读者卡住的地方,往往一张小示意图就解决。
- **为什么"加图/公式"比"改文字"更能解决表述不清**:有些概念(尤其方法的结构、数据流、模块如何工作)用纯文字描述很难讲清楚——读者要在脑子里重建你说的结构,容易卡住。**而一张示意图能直接把结构展示出来,一眼就懂("一图胜千言")**;一个公式能精确地定义操作(消除文字的歧义)。所以审稿人说"某处看不懂"时,**与其反复改文字,不如加一张针对那个难点的小示意图或一个精确的公式**,往往立刻就讲清了。
- **加图/公式的要点**:① **图要直指卡点**——加的图必须针对读者卡住的那个具体地方(如某模块的内部结构、某个数据流的走向),别加一张泛泛的总览图(那不解决具体的卡点);② **公式要定义清楚符号**——加公式时,公式里的每个符号都要在首次出现时定义,否则公式本身也成了新的"看不懂";③ **图文配合**——图旁边配文字说明它展示了什么,文字里引用图("如图X所示"),图和文相互支撑。
- **重点改朋友"看不懂"的那几处**:mock review里朋友指出"看不懂"的地方,就是你Method表述不清的客观信号(尤其不同方向的朋友看不懂,说明真的不够清楚)。**针对这些具体的卡点,逐一加图/加公式/加直觉解释**。判断方法有效没有:想"读者到底卡在哪一步",针对那一步精准地补充。改完让朋友再看一眼那几处,确认卡点消除。
**② 手把手带做**
1. 据 mock review,对 Method 不清楚处加示意图 / 补公式 / 加直觉解释。
2. 重点改朋友"看不懂"的那几处。
**③ 合格样例**:Method 表述更清晰(加了图/公式,卡点消除)。
**④ 常踩的坑**:加的图没指向那个难点 → 图要直指卡点;符号没定义 → 补。
**⑤ 卡住自救**:加图没帮助?→ 想"读者到底卡在哪一步",针对那一步画。
**⑥ 今天(这一步)你同时学会了什么**:你提升了 Method 清晰度。**做了**(Method 修改)、**学了**(用图/公式讲清、针对卡点)、**会了**(消除表述歧义)。

## 中午段 · 竞赛改进 3:多尺度训练

**① 先垫概念(多尺度训练)**:训练时**随机用不同输入尺度**(如 512/768/1024),让模型对尺度更鲁棒。**遥感目标尺度悬殊**(同图里有巨型建筑和小车),多尺度训练尤其有效。
- **为什么多尺度训练能提升鲁棒性**:如果训练时模型只见过固定尺度(如都是1024)的图,它对其他尺度的目标可能不够鲁棒。**训练时随机用不同输入尺度,相当于让模型见过同一目标在不同大小下的样子,学到尺度不变的特征**——测试时无论目标多大多小,模型都能较好地识别。这是一种"通过数据多样性提升泛化"的技巧,简单有效。
- **为什么多尺度对遥感"尤其"有效**:遥感图像有个突出特点——**同一张图里目标的尺度差异巨大**:可能同时有占据大片像素的巨型建筑/机场,和只有几个像素的小车/小船。这种悬殊的尺度跨度,对检测/分割是很大的挑战(模型要同时handle大目标和小目标)。**多尺度训练正好针对这个痛点**:通过在不同尺度上训练,模型对大小目标都更鲁棒。所以多尺度训练在遥感任务里特别值得用,提分往往明显。这也呼应你方法可能就是冲着"多尺度/小目标"这个遥感痛点设计的。
- **多尺度训练的注意点**:① **显存波动/OOM**——不同尺度输入的显存占用不同,大尺度(1024)可能OOM。应对:限制最大尺度,或大尺度时降batch;② **一次只加这一招**——别在加多尺度的同时改别的(否则不知道是多尺度起的作用),保持"一次一处改"的纪律,看清多尺度的真实效果。训练时随机采样尺度(每个batch或每隔几个iter随机选一个尺度),实现简单。
**② 手把手带做**
1. 给竞赛训练加多尺度(每个batch/隔几个iter随机选一个尺度,如512/768/1024)。
2. 重训(只加这一招,别同时改别的)。
3. 记录,与其他Trick区分开看效果。
**③ 合格样例**:多尺度训练完成。
**④ 常踩的坑**:显存随尺度波动/OOM → 限制最大尺度或降 batch;改多尺度时连带改别的。
**⑤ 卡住自救**:OOM?→ 限制最大尺度;没提升 → 记录换下一招。
**⑥ 今天(这一步)你同时学会了什么**:你学会多尺度训练。**做了**(多尺度训练)、**学了**(多尺度鲁棒性、对遥感尤有效)、**会了**(用多尺度提分)。

## 晚上段 · 竞赛提交 + 看排名

**② 手把手带做**

## 中午段 · 竞赛改进 4:更多 epoch + lr 衰减策略

**① 先垫概念**:训练更充分(更多 epoch)+ 更好的学习率衰减(如 **cosine**)常能再榨出一点分。**类比**:cosine 衰减像"先大步快走、后小步精修"——前期快速逼近、后期细调收敛。
- **为什么"训练充分性 + lr调度"能榨分**:① **更多epoch**——有时模型还没训到最优就停了,适当增加epoch让它训得更充分,可能再提升一点(但要警惕过拟合,见下);② **学习率衰减策略**——学习率怎么随训练变化,影响模型收敛的好坏。好的衰减策略能让模型既快速逼近好的区域、又在后期精细收敛到更优的点。这两个都是"不改模型结构、只调训练过程"的提分招,简单且常有效。
- **cosine衰减为什么好(原理直觉)**:cosine(余弦)学习率衰减,让学习率按余弦曲线从大平滑地降到小——**前期学习率大,模型大步快走、快速逼近好的区域;后期学习率小,模型小步精修、细致收敛到更优的点**。相比step衰减(阶梯式突降),cosine的平滑下降往往收敛更好、更稳。这就像"先大步快走接近目标、再小步精修到位"。cosine是目前很常用的lr调度策略,值得试。
- **警惕过拟合(更多epoch的副作用)**:增加epoch不是越多越好——**训太久,模型可能开始过拟合训练集(train loss还在降,但val指标反而下降)**。这时增加epoch有害无益。应对:① 监控val指标,**val开始下降就早停(early stopping)**;② 加更强的数据增强抑制过拟合。**找到"训练充分但不过拟合"的平衡点**。竞赛里可以试几个不同的epoch数,看哪个val/线上最好。
- **这招的定位:稳妥的"微调"提分**:epoch/lr调整属于"稳妥但收益有限"的提分招——它通常能榨出一点分,但不会有质的飞跃(质的飞跃靠Ensemble、伪标签这类)。它的好处是简单、风险低、几乎总能试。**作为竞赛迭代的常规一招,一次只调这一处(epoch或lr),看清效果再叠其他**——这和"一次只改一处"的迭代纪律一致。
**② 手把手带做**
1. 竞赛模型增大 epoch + 换/调 lr 衰减(cosine 优先,先快后精)。
2. 重训,监控 val(开始下降就早停,防过拟合)。
3. 提交看线上排名,记 Trick 日志。
**③ 合格样例**:更多 epoch + lr 衰减版提交,排名记录。
**④ 常踩的坑**:过拟合(训太久 val 反降)→ 加增强/早停;时间长 → 错峰跑。
**⑤ 卡住自救**:过拟合?→ 早停 + 加增强;没提升 → 记录换下一招。
**⑥ 今天(这一步)你同时学会了什么**:你学会用训练充分性 + lr 调度提分。**做了**(epoch/lr 改进)、**学了**(cosine 衰减=先快后精)、**会了**(调 epoch/lr 榨分)。

## 中午段 · 竞赛改进 5:Ensemble(两模型集成)

**① 先垫概念(Ensemble)**:**集成 = 用多个不同模型(不同 backbone / 不同 seed)的预测取平均/融合**。**类比**:几个不同专长的专家会诊,综合判断通常比单个准。**竞赛最常用、最稳的提分手段**,代价是推理更慢。
- **为什么Ensemble是"竞赛最稳的提分手段"**:不同的模型(不同backbone、不同训练设置、不同seed)会犯**不同的错误**——模型A在某些样本上错、模型B在另一些样本上错。把它们的预测融合,**每个模型的错误被其他模型纠正,共同的正确判断被强化**,综合结果几乎总是比任何单个模型更准更稳。这就是"多个专家会诊优于单个专家"。**在竞赛排行榜上,几乎所有top方案都用了Ensemble**——它是冲刺阶段最可靠的提分招(代价是推理慢,但竞赛只看最终分数,慢点无妨)。
- **Ensemble的关键:模型要"不同"(diversity)**:集成的提分效果,取决于被集成的模型有多"不同"(diverse)。**如果两个模型几乎一样(同backbone、同设置、同数据),它们犯的错误也一样,集成起来没什么收益**(相当于把同一个判断重复了一遍)。**要用真正不同的模型**:不同的backbone(Swin + ConvNeXt + ResNet)、不同的训练设置、甚至不同的数据增强——差异越大,集成收益往往越大(因为它们的错误更互补)。这是用好Ensemble的核心。
- **怎么融合(按任务)**:① **分类/分割**——可以直接对多个模型的输出概率取平均;② **检测**——框的融合更复杂,不能简单平均(框的位置、数量都不同),要用**WBF(Weighted Box Fusion)**正确合并多个模型的框(下周详解)。融合方式要对,否则集成反而变差。
- **只有一个模型怎么办**:如果时间/资源有限只训了一个模型,**用不同seed训的两三个模型也能集成**(虽然diversity不如不同backbone,但仍有收益);或者用同一个模型的不同checkpoint(训练后期的几个epoch)。**总之尽量凑出几个有差异的模型来集成**。当然,Ensemble推理慢,要权衡——竞赛冲刺值得,但如果论文要讲"高效",主结果还是用单模型(Ensemble可作为竞赛/附加结果)。
**② 手把手带做**
1. 训练/选两个**不同 backbone** 的模型(如 Swin + ConvNeXt,差异越大集成收益往往越大)。
2. 融合预测(分类/分割可平均概率;检测用框融合 WBF,见下周)。

**③ 合格样例**:Ensemble 提交,排名记录(通常提升)。
**④ 常踩的坑**:两模型太相似(同 backbone 同设置)→ 集成收益小,用**不同** backbone;融合方式错。

**⑥ 今天(这一步)你同时学会了什么**:你学会 **Ensemble 提分**。**做了**(Ensemble)、**学了**(集成=多专家会诊、要用不同模型、最稳提分)、**会了**(融合多模型提分)。

## 晚上段 · 竞赛改进 6:伪标签(Pseudo Labeling)

**① 先垫概念(伪标签)**:**用当前最好模型给无标注(或测试)数据打"伪标签",再把高置信度的加入训练**,扩充训练数据。**类比**:老师(强模型)先给没批改的卷子打分,只把"很有把握"的当标准答案教学生。**关键:控制置信度阈值**(低质伪标签会带噪、反而掉分)。
- **伪标签为什么能提分(原理)**:深度学习的性能很大程度受训练数据量限制。如果你有大量**无标注数据**(或竞赛的测试集),可以用当前最好的模型给它们打上"伪标签"(模型的预测当作标签),再把这些伪标注数据加入训练——**相当于扩充了训练集**,模型见到更多样本,泛化能力可能提升。这是半监督学习的经典思路,在竞赛里常用来榨取额外的分数。
- **伪标签的命门:置信度阈值(必须控好)**:伪标签是模型自己打的,**不一定对**——模型预测错的伪标签,会把错误信息"教"给模型,反而带噪掉分。**所以关键是只用模型"很有把握"的伪标签**:设一个置信度阈值(如conf > 0.9),**只把高置信度的预测当伪标签并入训练**,低置信度的(模型自己都不确定的)丢弃。阈值是命门:阈值太低→带噪掉分;阈值合适→只用可靠的伪标签,提分。这就像老师只把"很有把握"的批改当标准答案,模棱两可的不教给学生。
- **伪标签掉分的应对**:如果加了伪标签反而掉分,首先**提高置信度阈值**(只保留最有把握的);如果提高阈值后还掉,说明这个数据/任务可能不适合伪标签(或伪标签质量太差),**果断放弃这招**,换别的。伪标签不是万能的,要看效果决定用不用。
- **伪标签的规范问题(论文 vs 竞赛)**:伪标签用测试集打标会**过拟合测试分布**——在竞赛里这通常允许(竞赛就是要在测试集上得高分),但**在论文里要谨慎**:如果你的论文方法用了测试集的伪标签,可能违反"测试集不可见"的学术规范(审稿人会质疑)。**所以伪标签更适合用在竞赛冲刺,论文的主结果要避免用测试集信息**。如果论文要用伪标签,应该用额外的无标注数据(而非测试集),并说明清楚。竞赛和论文的规范不同,要分清。
**② 手把手带做**
1. 用当前最好模型对无标注/测试集打伪标签。
2. **只选高置信度的**(如 conf > 0.9)并入训练——阈值是命门,低了带噪掉分。
3. 重训,提交看线上分;掉分就提高阈值,仍掉就放弃这招。
**③ 合格样例**:伪标签版提交,排名记录。
**④ 常踩的坑**:**伪标签带噪掉分** → 提高置信度阈值、只用高置信;过拟合测试分布 → 竞赛可、论文需谨慎(注意规范)。
**⑤ 卡住自救**:掉分?→ 提高阈值(只要最有把握的);仍掉 → 该数据/任务可能不适合伪标签,放弃这招。
**⑥ 今天(这一步)你同时学会了什么**:你学会 **伪标签提分**。**做了**(伪标签)、**学了**(伪标签=强模型给高置信样本打标 + 阈值控噪)、**会了**(用伪标签扩数据提分)。

> **技能卡｜伪标签**:强模型给无标注数据打标→**只取高置信度**(阈值如 0.9)→并入训练。阈值是命门,低了带噪掉分。

## 二、竞赛 Trick 详解 + 代码骨架
```python
import torch
# ① TTA：多变换预测后融合（推理时，无需重训）；关键是翻转预测要翻回原图坐标
def tta_predict(model, img):
    preds = [model(img)]
    flipped = torch.flip(img, dims=[-1])          # 水平翻转
    p = model(flipped)
    # p 要翻回原图坐标后再融合(分割:翻回特征图;检测:翻回框坐标)
    preds.append(unflip(p))                        # unflip 按任务实现
    return sum(preds) / len(preds)

# ② Ensemble：多模型(不同 backbone)预测平均
def ensemble_predict(models, img):
    return sum(m(img) for m in models) / len(models)

# ③ 伪标签：只取高置信度
def make_pseudo(model, unlabeled_loader, conf_thr=0.9):
    pseudo = []
    for img in unlabeled_loader:
        prob = model(img).softmax(-1)
        conf, cls = prob.max(-1)
        keep = conf > conf_thr                     # 命门:阈值
        pseudo.append((img[keep], cls[keep]))
    return pseudo                                  # 并入训练集重训
```
**预期**:TTA/Ensemble 通常稳定提分(注意 TTA 对齐坐标、Ensemble 用不同模型);伪标签靠 conf_thr 控噪。检测框融合见下周 WBF。
> **三招怎么配合用**:① 先各自单独验证(一次一招、看线上Δ分、有效的保留);② 再把保留的有效招组合(如多尺度训练的模型 + 推理时TTA + 多模型Ensemble),组合常比单招更强;③ 每招/每组合都记进Trick日志(改了什么+Δ分+是否保留),既指导下一步、又是M8竞赛技术报告的现成素材。注意:伪标签用测试集会过拟合测试分布,竞赛可用但论文需谨慎(论文应用额外无标注数据并说明)。
