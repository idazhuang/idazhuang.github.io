## 上午段 · 查审稿状态 + 决定走哪条线

**① 先垫概念(优先级判断:审稿响应有时限,优先级最高)**:
- 查第一篇论文的审稿状态。**如果收到审稿意见 → 本周优先处理(中断第二篇写作);如果还没收到 → 继续正常节奏(启动第二篇)。**
- **为什么审稿意见来了要优先处理(中断第二篇)**:① **响应审稿有时限**(期刊/会议通常给几周到一两个月改稿),错过时限可能影响录用;② 第一篇论文是你已有的成果,推进它录用的优先级高于刚启动的第二篇;③ 趁审稿意见新鲜、记忆清晰时处理效率高。**所以审稿意见一来,它就是本周的最高优先级,第二篇写作让路。** 这是科研中的优先级判断:已投出的论文的关键节点(审稿响应),优先于新工作的早期推进。
- **如果还没收到(常见)**:审稿周期长(尤其期刊,可能 2-4 个月),很可能本周还没回来。**那就按计划启动第二篇论文写作**(论文线)——不必干等审稿。
- **两条线都要会**:你现在不知道审稿什么时候回,所以本周两条线都学——审稿来了能处理,没来能推进第二篇。**这种"根据情况灵活切换"也是科研的常态。**

**② 手把手带做**:

2. 收到意见 → 走【审稿线】(本周优先,暂停第二篇);未收到 → 走【论文线】(启动第二篇)。
3. 明确本周主线。

**③ 合格样例**:查了审稿状态,明确本周走审稿线(优先处理)还是论文线(启动第二篇)。

**④ 常踩的坑**:收到审稿意见还按原计划写第二篇 → 审稿响应有时限,优先处理;干等审稿不启动第二篇 → 没收到就推进第二篇(不空等)。

## 中午段 · 【如收到】逐条读意见、标三类、列需补实验 / 【未收到】准备 Intro

**① 先垫概念(★ 如何读审稿意见:情绪与实质分开)**:
- **【审稿线】如果收到意见**:逐条阅读,标记为"同意/部分同意/不同意"三类;列出所有需要补做的实验。
- **★ 如何读审稿意见(关键心法,管理情绪)**:审稿意见经常措辞严厉,**读三遍**:① **第一遍——感受情绪,然后放下**(承认"看到批评会不舒服"是正常的,但别让情绪主导);② **第二遍——提取实质问题**(他到底指出了什么具体问题?要补什么实验?);③ **第三遍——制定回复方案**(每条怎么回应/怎么改)。**核心:重要的是"他说的对不对(有没有指出真问题)",而不是"他说得好不好听"**——把审稿人的语气和他指出的实质问题分开,只关注实质。
- **为什么这个"情绪与实质分开"的能力对你的科研长跑特别重要**:你要走学术这条路,意味着你这辈子会反复收到审稿意见——而审稿意见里相当一部分会让人不舒服(措辞尖锐、否定你的工作、有时甚至显得不耐烦或带偏见)。**如果你每次都被审稿意见的语气伤到、陷入"他怎么能这么说我"的情绪内耗,你会非常痛苦,甚至可能因此对科研产生畏惧或自我怀疑**。但如果你能练就"把语气和实质分开"的本事——承认看到批评不舒服(这很正常,不必假装无所谓),但迅速把情绪放到一边,冷静地问"抛开他说话的方式,他指出的问题成立吗?对我改进论文有用吗?"——你就能从每一次审稿(哪怕是被拒)中获得成长,而不是受伤。**一个残酷但真实的事实是:很多审稿意见即使语气难听,指出的问题确实存在;而把这些问题解决了,你的论文会更好**。所以审稿人某种意义上是在免费帮你改进工作(哪怕方式让人不爽)。把"对不对"和"好不好听"分开,你就能心平气和地吸收有用的、礼貌地回应不认同的——这种心态的成熟,和你的研究能力一样,是支撑你在学术路上走远的基本功。对你这个独自转型、没有导师托底的人,更要学会自己消化审稿压力、不被它击垮。
- **标三类的意义**:① **同意**(他说得对 → 照改);② **部分同意**(部分有理 → 部分改 + 解释);③ **不同意**(他理解有误或要求不合理 → 礼貌反驳/澄清,但要有理有据)。**不是所有意见都得无条件接受——同意的改、不同意的礼貌据理回应。** 列出需补的实验(审稿线后两天补)。
- **【论文线】如果未收到**:准备启动第二篇 Intro(基于 W34 的 outline),今晚开始写。

**② 手把手带做**:
1. 【审稿线】逐条读意见,标"同意/部分同意/不同意",读三遍(情绪→实质→方案)。
2. 【审稿线】列出所有需补的实验。
3. 【论文线】(如未收到)准备 Intro 写作(基于 outline)。

**③ 合格样例**:【审稿线】意见标三类 + 需补实验清单;或【论文线】Intro 写作准备就绪。

**④ 常踩的坑**:被审稿语气带走情绪 → 读三遍(情绪→实质),关注"对不对"非"好不好听";无条件接受所有意见 → 标三类(同意改、不同意据理回应)。

**⑤ 卡住自救**:意见看着很凶很沮丧?→ 正常(学术常态、不针对你),深呼吸放下情绪、提取实质;某条意见不知同不同意 → 想"他指出的是真问题吗",是→同意,误解→澄清。

**⑥ 今天(这一步)你同时学会了什么**:你学会**专业地读审稿意见(情绪与实质分开)**。**做了**(标三类 + 列补实验 / 准备 Intro)、**学了**(读三遍管理情绪、关注实质非语气、标三类分类回应)、**会了**(以专业心态处理审稿意见)。

## 上午段 · 【审稿线】补实验 1（补 baseline）/ 【论文线】写 Intro 段 1-2

## 上午段 · 【审稿线】写 Response Letter / 【论文线】写 Related Work

**① 先垫概念(★ Response Letter 格式 / RW 写法)**:
- **【审稿线】写 Response Letter——逐条回复审稿意见**。**格式(关键)**:每条回复包含——① **审稿人原文**(蓝色);② **你的回复**(黑色);③ **论文中修改的位置**(红色,标页码和行号)。**态度要诚恳,语气要专业**——典型开头:"We thank the reviewer for this insightful comment. We have addressed this concern by..."。
- **★ 为什么 Response Letter 这样写(让审稿人容易认可)**:① **逐条对应**(审稿人能清楚看到你回应了每一条);② **颜色区分**(原文/回复/修改位置一目了然,审稿人不用翻找);③ **标修改位置**(审稿人能去论文里核对你确实改了);④ **诚恳专业的语气**("感谢您的意见""我们已通过……解决")——即使是反驳,也礼貌有据。**Response Letter 的目标是让审稿人觉得"我的意见被认真对待、被妥善回应了"**,从而愿意接受。
- **为什么"诚恳专业的语气"在 rebuttal 里如此关键(审稿人也是人)**:技术上你把实验补了、问题改了固然重要,但 Response Letter 的语气同样影响结果——因为**评判你修改的还是那位审稿人(一个有情绪的人)**。如果你的回复语气傲慢、对抗、或显得不耐烦("审稿人显然没读懂""这个要求毫无道理"),即使你技术上对,也容易激怒审稿人、让他更挑剔;反之,诚恳专业的语气("感谢您的宝贵意见""我们已认真考虑并修改")会让审稿人感到被尊重、更愿意正面看待你的修改。**这不是虚伪客套,而是有效沟通的智慧:你的目标是让论文被接收,而不是在 Response 里"赢"一场辩论**。即使是回应你不认同的意见,也用"我们尊重地澄清(We respectfully clarify)...因为...(给出理由)"这种有礼有据的方式,而非生硬反驳——既维护了你的立场,又不失风度。记住:rebuttal 是说服,不是对抗;诚恳专业的语气,是让审稿人愿意被你说服的润滑剂。
- **不同意的意见怎么回应**:礼貌、有据地解释(为什么你的做法是合理的/审稿人可能的误解),而非生硬反驳。"We respectfully clarify that..." 之类。**有理有据 + 礼貌,而非对抗。**

## 二、实用工具 — 读审稿意见的SOP + 补实验
```text
① 读审稿意见 SOP（管理情绪、关注实质）
第一遍：感受情绪 → 承认不舒服是正常的 → 放下（措辞严厉是学术常态，不针对你）
第二遍：提取实质 → 他指出了什么具体问题？要补什么实验？（忽略语气）
第三遍：定方案 → 每条标"同意/部分同意/不同意" → 对应回复+修改方案
核心：重要的是"他说的对不对"而非"好不好听"

② 补实验（最常见两类，复用框架快速补）
补baseline：复用实验框架，加新baseline的config → 同设置跑 → 记录
           （你的方法通常仍优；接近则Response里讲效率/泛化优势）
补数据集：复用跨数据集流程，加新数据集解析 → 跑你的方法+baseline
           （回应泛化质疑，契合跨域泛化卖点）
```
**预期**:① 读审稿意见的 SOP 把"情绪"和"实质"分开(读三遍),专业不内耗;② 补实验复用框架快速响应最常见的两类要求(baseline/数据集)。

## 四、本周报错速查表
| 现象 | 根因 | 解法 |
|---|---|---|
| 收到审稿意见还按原计划写第二篇 | 优先级错 | 审稿响应有时限，优先处理(暂停第二篇) |
| 被审稿语气带走、沮丧内耗 | 情绪主导 | 读三遍(情绪→放下→实质)，关注"对不对"非"好不好听" |
| 无条件接受所有审稿意见 | 不分类 | 标三类：同意改/部分同意部分改/不同意礼貌据理回应 |
| Response Letter不逐条/无格式 | 不规范 | 逐条+三色(原文蓝/回复黑/修改红标页码行号)+诚恳专业 |
| 语气生硬对抗 | 不专业 | "We thank...We have addressed..."；不同意也"respectfully clarify" |
| 改了论文不标红 | 审稿人难核对 | 红色标记所有变更处(对应意见，方便复审) |
| Response说改了论文没真改 | 言行不一 | 言行一致：都真改+标红 |
| 为赶时限草草提交 | 质量打折 | 质量优先(改不完下周续，通常有期或可短延) |
| 借GitHub维护又陷入大量运营 | 没守住副线 | ★适度维护(回issue/更新文档)，核心是研究(第二篇) |
| 月报只盘点不战略检视 | 缺战略视角 | ★战略检视：审稿/第二篇/开源/对接空天院准备 |
| star没达50就焦虑 | 把运营当目的 | 理性看(运营副线、好项目持续被发现)，不被数字绑架 |
