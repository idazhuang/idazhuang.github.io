# D162 周一 · 读者体验通读 → v1.5

> **预期管理**:今天换一个全新视角通读论文——不抠语法,只问"一个第一次读的人能不能顺畅看懂"。提醒:你太熟内容会不自觉脑补,读不出卡点;放慢、假装不懂,或隔一晚再读。今天产出 v1.5(读者体验更顺的版本)。

## 上午段 · 最终版通读（只关注"读者体验"）

**① 先垫概念(读者体验通读是什么、为什么这轮重要)**
- 这次通读换个视角——**"一个第一次读这篇论文的人能否流畅理解?"** 不抠语法,只看"读着顺不顺、懂不懂"。
- **为什么到投稿前还要专门做这一轮**:前几周你反复改的是"内容对不对、逻辑严不严";但审稿人是第一次读你的论文,他的"读者体验"直接影响评审印象——一篇内容好但读着处处卡顿的论文,审稿人会读得烦躁、容易给低分。**投稿前最后一轮,要从"作者视角"(内容对)切到"读者视角"(读着顺)。**
- **和你 W15 学的自审一脉相承,但更进一步**:W15 是查"逻辑断点";这轮是查"阅读流畅度"——哪怕逻辑没断,如果某段读起来费劲、某个图看不懂、某个术语突然冒出来,都是要修的"读者体验"问题。

**② 手把手带做**:从头以"陌生读者"身份通读全文(可隔一晚让自己生疏些),边读边体会哪里卡顿/困惑,先不改、只标记。
**③ 这一步合格的样子**:一次完整的"读者视角"通读,标记出所有让你(假装第一次读)卡顿的地方。
**④ 最常踩的坑**:① 太熟会脑补(读到不清楚处自动补上脑内信息)→ 放慢、强迫自己只读纸面写的;② 边读边改(陷入细节,丢了整体流畅感)→ 这轮只通读标记,改放到晚上;③ 只读自己擅长/喜欢的章节(如跳过 Related Work)→ 审稿人会通读全文,每一章都要以读者视角过一遍。
**⑤ 卡住怎么自救(决策树)**:读不出问题(太熟)? → 隔一晚再读,或用 TTS 朗读(听出拗口处);不确定算不算卡点? → 凡是"需要回头重读一遍才懂"的地方都算;时间紧? → 至少完整读一遍 Intro+Method(审稿人最先细看的)。
**⑥ 今天(这一步)你同时学会了什么**:你学会以读者视角审全文。**做了**(读者视角通读)、**学了**(读者体验、从作者视角切到读者视角、投稿前这轮的价值)、**会了**(站在读者角度看论文)。

> **技能卡｜读者视角通读**:投稿前最后一轮通读,从"作者视角(内容对不对)"切到"读者视角(读着顺不顺)"。审稿人第一次读你的论文,阅读流畅度直接影响评审印象。只通读标记不改(改放后面);太熟读不出就隔夜再读或 TTS 朗读。凡"需回头重读才懂"处都是卡点。

## 中午段 · 标"可能让读者困惑"处

**① 先垫概念**:把上午通读时的感受落成一张具体的"困惑点清单"——术语没解释就用了、某步跳过了推导、某个图表难懂、某段逻辑跳跃。**清单化的好处**:把模糊的"读着不顺"变成一条条可执行的修改项,晚上逐条消除,不遗漏。**困惑点通常集中在几类**:① 术语/符号首次出现没定义;② 从 A 到 B 缺过渡(读者跟不上);③ 图表本身不清楚或正文没讲怎么读;④ 贡献/方法的"为什么"没说清。
**② 手把手带做**:把所有可能让读者困惑/卡顿的地方列成清单(标注在第几页第几段、什么问题、怎么改)。
**③ 合格样例**:困惑点清单(每条:位置+问题+修改方向)。
**④ 坑**:① 清单太笼统("Method 不清楚")→ 具体到"3.2 节公式 2 的符号 σ 没定义";② 只标问题不想改法 → 顺手记"怎么改",晚上直接动手。
**⑤ 自救**:困惑点太多无从下手 → 按"影响理解程度"排序,优先改让人看不懂的(逻辑断、术语没定义)而非小瑕疵(个别措辞);拿不准某处算不算问题 → 标上,晚上判断;清单里有些自己也不知怎么改 → 标"待想",可问导师/同行或参考类似论文怎么处理;同一类问题反复出现(如多处术语没定义)→ 建一个术语表统一定义,一次性解决一类。
**⑥ 今天(这一步)你同时学会了什么**:你定位了读者卡点。**做了**(困惑点清单)、**学了**(把"读着不顺"清单化、困惑点的常见类型)、**会了**(识别并记录读者困惑处)。

## 晚上段 · 逐一修改 → v1.5

**① 先垫概念**:按困惑点清单逐条消除(补解释/加过渡/改图/讲清"为什么")→ 论文 v1.5。**修改的优先级**:先改"影响理解"的(术语没定义、逻辑跳跃),再改"不够顺"的(措辞、过渡)。**改完要再快读一遍确认**:确保改动真的解决了卡点,且没引入新的不连贯。**有一类卡点要特别注意——结构性的**:如果改了半天某段还是读着费劲,问题可能不在措辞而在结构(顺序不对、该合并的拆开了、该分点的挤成一段)。这种情况下,调整段落顺序/拆分合并,比抠字句更有效。**判断标准**:措辞问题改一两句就顺了;结构问题改了字句还是别扭——后者要动结构。
**② 手把手带做**:逐条消除困惑点(补解释/加过渡/改图)→ 论文 v1.5;改完快速通读一遍确认更顺了。
**③ 合格样例**:论文 v1.5(读者体验明显更顺,清单上的卡点已消除)。
**④ 坑**:① 改不完就焦虑 → 先改最影响理解的,小瑕疵可留;② 改了某处引入新的不连贯 → 改完再快读确认。
**⑤ 自救**:某个卡点不知怎么改 → 问"读者卡在这里是因为缺了什么信息",补上那个信息;改完仍觉得不顺 → 可能是结构问题,考虑调整段落顺序。
**⑥ 今天(这一步)你同时学会了什么**:你迭代到 v1.5。**做了**(v1.5)、**学了**(据读者卡点改、改完再确认)、**会了**(优化论文可读性到投稿线)。

> **今日交付**:✅ 困惑点清单 ✅ 论文 v1.5(读者体验更顺)。

# D163 周二 · supplementary material + 竞赛自定义增强

> **预期管理**:今天准备 supplementary(把正文塞不下的细节/可视化/完整消融放进附录),并给竞赛加遥感特有增强。提醒:supplementary 是"加分空间"不是"凑数"——放审稿人可能想看的细节;竞赛的几何增强一定要让标注同步跟着转。

## 上午段 · 准备 supplementary（附录）

**① 先垫概念(为什么写 supplementary)**:正文有页数限制(通常 8–10 页),但审稿人可能想看更多细节。**Supplementary 是"加分空间"**——放更多实验细节、更多可视化、超参搜索结果、完整消融表、证明细节。**为什么值得认真做**:① 正文受页数限制只能放最核心的,很多你辛苦做的实验(完整超参搜索、更多数据集的定性图)放不下,supplementary 给它们一个去处;② 审稿人想深究时,详尽的 supplementary 能打消他的疑虑(显得你工作扎实、经得起追问);③ 它不占正文页数,纯加分。**正文 vs 附录的取舍原则**:正文放"支撑核心论点必需的",附录放"有了更好、没有也不影响主线的"。
**② 手把手带做**:整理 supplementary 内容:更多实验细节 + 更多可视化 + 超参搜索结果 + 完整消融表(你阶段一的实验日志/消融素材正好用);列一个 supplementary 提纲。
```markdown
# Supplementary 提纲（不占正文页数的加分空间）
S1 实现细节：完整超参表、训练细节、数据预处理(正文只给关键的)
S2 更多消融：每个组件在各数据集的完整消融(正文只放主数据集)
S3 更多定性结果：各数据集的检测可视化(含更多负面案例,诚实)
S4 推理超参分析：Soft-NMS sigma 等的完整扫描曲线
S5 (可选)失败案例分析：方法在什么情况下还不行(展示你理解局限)
```
**③ 合格样例**:supplementary 内容齐备 + 提纲(每节对应正文哪里"详见 supplementary X")。
**④ 坑**:① 正文塞太满超页数 → 把次要细节移到 supplementary;② supplementary 放无关内容凑数 → 只放审稿人可能想看的;③ 素材散落 → 用你阶段一已归档的实验日志。
**⑤ 自救**:不知哪些进正文哪些进附录 → 问"删掉它正文主线还成立吗",成立就移到附录;supplementary 太长 → 抓审稿人最可能追问的(完整消融、更多定性、超参扫描);担心 supplementary 没人看白做 → 它的价值在"审稿人想深究时能打消疑虑",哪怕只有一位审稿人看,也可能是你通过的关键;不确定某实验该不该放 → 凡是"支撑你结论但正文塞不下"的证据都值得放进附录。
**⑥ 今天(这一步)你同时学会了什么**:你学会**用 supplementary 加分**。**做了**(supplementary 内容+提纲)、**学了**(正文 vs 附录的取舍、附录是加分空间)、**会了**(把次要细节放进附录)。

> **技能卡｜supplementary 取舍**:正文受页数限,supplementary 是不占页数的加分空间。取舍原则:正文放"支撑核心论点必需的",附录放"有了更好、没有也不影响主线的"(完整消融/更多定性/超参扫描/失败案例)。审稿人想深究时,详尽附录打消疑虑。判断:删掉它正文主线还成立吗?成立就移附录。

## 中午段 · 把 supplementary 整理成独立 PDF

**① 先垫概念**:把 supplementary 排成独立 PDF(图清晰、编号规范,用 S1/S2 或 A1/A2 区别于正文编号),与正文呼应("详见 supplementary Fig. S3")。**为什么独立成册**:多数期刊要求 supplementary 作为单独文件提交;独立 PDF 也方便审稿人对照。**编号要和正文区分**:supplementary 的图表用 S 前缀(Fig. S1、Table S1),避免和正文 Fig. 1 混淆。**supplementary 的定位要摆正**:它是"想深入的审稿人/读者才看"的补充,所以正文必须能独立成立(不依赖 supplementary 才能看懂);supplementary 是锦上添花,不是把正文该讲的藏进去。**一个常见误区**:为了正文显得简洁,把方法的关键细节塞进 supplementary——这会让审稿人读正文时一头雾水(关键信息要去附录找)。正确做法:正文自包含、能完整理解方法;supplementary 放"有兴趣可深究"的额外证据和细节。
**② 手把手带做**:把 supplementary 排成独立 PDF(图清晰、S 前缀编号);在正文相应处加"详见 supplementary X"的指引,同时确保正文不依赖附录也能看懂。
**③ 合格样例**:supplementary PDF 成形(独立、编号规范、与正文呼应)。
**④ 坑**:① supplementary 图表编号和正文混(都叫 Fig. 1)→ 用 S 前缀;② 正文没指向 supplementary → 在相应处加"详见 supplementary"。
**⑤ 自救**:不确定期刊对 supplementary 的格式要求 → 看 Author Guidelines(D164 会读);图不清晰 → 导出高分辨率矢量图。
**⑥ 今天(这一步)你同时学会了什么**:你产出了附录 PDF。**做了**(supplementary PDF)、**学了**(附录独立成册、S 前缀编号、与正文呼应)、**会了**(制作规范的独立附录)。

## 晚上段 · 竞赛改进 7:自定义数据增强（针对遥感特性）

**① 先垫概念**:针对遥感特性的增强常对遥感竞赛有效——**随机旋转 0°/90°/180°/270°**(遥感目标无固定朝向,90°倍数旋转不引入插值失真)+ **多尺度裁剪**(遥感目标尺度差异大)。**为什么这类增强对遥感特别有效**:通用 CV 的增强(如随机小角度旋转、颜色抖动)未必契合遥感;而"90°倍数旋转"利用了遥感"目标朝向均匀分布"的先验,等于免费扩充了训练数据的朝向覆盖。**这是用领域知识设计增强**——你的遥感理解在这里变成竞赛分数。
**② 手把手带做**:给竞赛加遥感特有增强(90°倍数旋转 + 多尺度裁剪,几何增强时标注同步转),重训提交。
```python
# 遥感特有增强：90°倍数旋转（无插值失真）+ 标注同步
import random
def rot90_with_boxes(img, boxes, k=None):
    """k∈{0,1,2,3} 旋转 90°*k；boxes 是旋转框，需同步旋转。"""
    k = random.randint(0, 3) if k is None else k
    img = np.rot90(img, k).copy()
    boxes = rotate_oriented_boxes(boxes, k * 90, img.shape)  # 框中心/角度同步转
    return img, boxes
# 关键：几何增强后框/mask 必须跟着变换，否则标注错位、训练崩
```
**③ 合格样例**:遥感增强版提交,排名记录(对比加增强前)。
**④ 坑**:① 几何增强但标注没同步转 → 框/mask 跟着转(否则标注全错);② 没提升 → 记录,换下个 Trick(增强对某些任务收益有限);③ 增强过猛把图变得不真实(如极端尺度裁剪只剩局部)→ 增强幅度要在"仍像真实遥感图"的范围内,过度增强反而伤性能。
**⑤ 自救**:加增强后掉点 → 检查标注是否真同步转了(可视化几张确认框还在目标上);提升不明显 → 90°旋转对已经旋转鲁棒的模型收益小,试多尺度裁剪。
**⑥ 今天(这一步)你同时学会了什么**:你用遥感特有增强提分。**做了**(自定义增强)、**学了**(用领域先验设计增强、几何增强标注同步)、**会了**(用领域知识设计增强)。

> **今日交付**:✅ supplementary PDF ✅ 竞赛遥感增强版提交。

# D164 周三 · 选目标期刊 + 调模板

> **预期管理**:今天为论文选定投稿出口、读懂目标期刊的格式要求、把论文套进它的模板。提醒:第一篇别冲顶会(CVPR/ICCV 单卡难支撑、周期长、拒率高),优先 GRSL/JSTARS 这类对遥感/增量工作友好、周期短的期刊——先发表建立信用。

## 上午段 · 选择投稿目标期刊/会议

**① 先垫概念(第一篇投哪里)**:优先级 **GRSL(快,2–3 月出结果)> JSTARS(中,3–4 月)> TGRS(慢但含金量高,4–6 月)> IGARSS workshop**。**对结果有信心→GRSL(周期短反馈快);结果特别好→可冲 TGRS;不要第一篇就冲 CVPR/ICCV**(先建信用)。**为什么第一篇尤其要选对出口**:① 你是单卡选手,工作偏"高效特化/增量改进",这类工作在顶会(追求新颖性/SOTA 大幅刷新)容易被拒,但在遥感期刊(看重扎实、对领域有用)很受认可;② 第一篇的目标是"成功发表、建立信心和信用",而非"一鸣惊人";③ 周期短的期刊(GRSL)反馈快,即使被拒也能快速改投,试错成本低。**选刊是策略,不是越高越好**——匹配你的工作类型和实力,成功率最高。

## 上午段 · 写 Cover Letter（≤1 页）

**① 先垫概念(Cover Letter 是什么、写什么)**:给编辑的信(≤1 页):编辑您好 + 论文标题与一句问题/方法 + 核心贡献 3 点 + 为什么适合本刊 +(可选)建议/回避审稿人 + 原创性声明。模板见补充包。**Cover Letter 的作用**:它是编辑读你论文前的第一印象,决定编辑是否觉得"这篇值得送审、适合本刊"。**关键是"为什么适合本刊"**:让编辑看到你的工作和期刊的范围/读者契合(如"本刊关注遥感图像处理的高效方法,我们的单卡高效检测正契合")。**别写成摘要的复制**:Cover Letter 是"推介信"(为什么该发在这),摘要是"内容概括"(做了什么),侧重点不同。
**② 手把手带做**:按模板写 Cover Letter(标题+问题/方法一句+3 点贡献+为何适合本刊+原创声明);见补充包模板。
**③ 合格样例**:Cover Letter(≤1 页,要素齐全,突出贡献与契合度)。
**④ 坑**:① 写太长/太泛(把摘要复制过来)→ ≤1 页、突出贡献与"为何适合本刊";② 没说契合度 → 明确点出工作和期刊范围的契合;③ 贡献写空 → 用真实数字。
**⑤ 自救**:不知怎么写契合度 → 看期刊 Aims & Scope,找你工作命中的关键词(如"efficient""remote sensing""object detection"),用它点出契合;贡献提炼不出 → 用 Intro 段 4 的贡献列表直接精简;Cover Letter 英文没把握 → 套补充包模板,只换中括号里的内容,模板句式是标准的;不确定要不要推荐审稿人 → 可选项,若你了解领域里几位合适的专家可列(避免列你的合作者/导师,以免利益冲突)。
**⑥ 今天(这一步)你同时学会了什么**:你学会写 Cover Letter。**做了**(Cover Letter)、**学了**(投稿信结构、突出契合度、与摘要的区别)、**会了**(向编辑推介你的论文)。

> **技能卡｜Cover Letter 结构**:给编辑的推介信(≤1 页):标题+问题/方法一句 + 核心贡献3点(真实数字)+ **为什么适合本刊**(对照期刊 Aims & Scope 找契合点)+ 原创性声明 +(可选)建议/回避审稿人。它是"为什么该发这"(推介),不是摘要复制(内容概括)。决定编辑送不送审的第一印象。

## 中午段 · 最终检查参考文献格式

**① 先垫概念**:按目标期刊格式最终核对参考文献(cite↔bib 一致、格式统一、无缺失/重复)。**为什么单独核对参考文献**:参考文献是格式问题的重灾区——引用了 bib 里没有的、bib 有但正文没引的、格式不统一(有的有 DOI 有的没有)、作者名/年份错。这些虽小,但反映论文的严谨度,审稿人会注意。**用工具辅助**:LaTeX 的 cite/bib 机制能帮你查"引用了但 bib 没有"的(编译会警告)。**参考文献还有两个"内容层面"的检查点**(不只是格式):① 该引的有没有引全——尤其是你 D110 找到的"最接近的相关工作",必须引并在 Related Work 里讨论差异,否则审稿人会质疑你不了解前沿;② 引用是否恰当——别为凑数量乱引不相关的,也别只引自己人。**审稿人常从参考文献判断你对领域的熟悉度**:一个相关工作引得全、引得准的参考文献列表,本身就传递"作者懂行"的信号。

**④ 坑**:① cite 了 bib 里没有的(编译警告 undefined citation)→ 补 bib 条目;② 格式不统一(期刊/会议名缩写不一致)→ 统一;③ 漏引关键相关工作 → 补上(尤其 D110 那篇最接近的工作)。

**⑥ 今天(这一步)你同时学会了什么**:你定稿了参考文献。**做了**(参考文献最终版)、**学了**(按期刊格式核对、cite↔bib 一致、工具辅助)、**会了**(规范引用至投稿标准)。

## 晚上段 · 竞赛：训练更大模型（如 Swin-Large）

**① 先垫概念**:竞赛冲刺期可上更大模型(如 Swin-Large backbone)榨更高分。**单卡怎么训得动大模型**:① 降 batch size(大模型单样本就占很多显存);② 梯度累积(用多个小 batch 累积梯度,等效大 batch);③ 混合精度(AMP,省显存又提速);④ 必要时梯度检查点(gradient checkpointing,用时间换显存)。**竞赛 vs 论文的不同取舍**:论文里你强调"单卡高效、小模型"(那是卖点);但竞赛只看分数,可以上大模型堆性能——两者目标不同,策略也不同(这点要分清,别把竞赛的大模型策略写进强调高效的论文)。
**② 手把手带做**:训练更大模型(降 batch + 梯度累积 + 混合精度适配单卡),提交看排名。
```python
# 单卡训更大模型：小 batch + 梯度累积 + 混合精度
accum_steps = 4                                   # 等效 batch = batch_size * 4
scaler = torch.cuda.amp.GradScaler()
for i, batch in enumerate(loader):
    with torch.cuda.amp.autocast():               # 混合精度，省显存提速
        loss = model(batch) / accum_steps
    scaler.scale(loss).backward()
    if (i + 1) % accum_steps == 0:                # 累积够了再更新
        scaler.step(optimizer); scaler.update(); optimizer.zero_grad()
# 仍 OOM：加 torch.utils.checkpoint（梯度检查点，用时间换显存）
```
**③ 合格样例**:更大模型版提交,排名记录(对比小模型)。
**④ 坑**:① OOM → 降 batch + 梯度累积 + 混合精度(+ 梯度检查点);② 太慢 → 竞赛冲刺期值得,但权衡时间;③ 把竞赛的大模型策略混进强调高效的论文 → 两者分开;④ 大模型轻易过拟合竞赛训练集 → 加强正则/增强、用早停,以本地验证为准。
**⑤ 自救**:还是 OOM → 上梯度检查点(gradient checkpointing,用算力换显存,能再省一大截),或换稍小的大模型(Swin-Base);训太慢 → 减 epoch、用更激进的学习率调度(如 OneCycle)、冻结浅层只微调深层;显存极度紧张 → 减小输入分辨率训练(推理时再用大分辨率);权衡不来 → 算一下"上大模型的预期提分 vs 花的时间",竞赛冲刺末期分数边际收益递减时,把时间留给更稳的招(WBF/集成)可能更划算。
**⑥ 今天(这一步)你同时学会了什么**:你学会单卡上更大模型。**做了**(更大模型)、**学了**(梯度累积/混合精度/梯度检查点、竞赛vs论文的策略区别)、**会了**(单卡训更大模型冲分)。

> **技能卡｜单卡训更大模型**:单卡跑大模型靠"降 batch + 梯度累积(等效大 batch)+ 混合精度(AMP 省显存提速)+ 梯度检查点(用时间换显存)"。**竞赛只看分可上大模型堆性能;但论文强调单卡高效用小模型(卖点)——两者目标不同,策略别混**(竞赛大模型策略勿写进高效论文)。

> **今日交付**:✅ Cover Letter(≤1 页) ✅ 参考文献最终版 ✅ 竞赛更大模型提交。

## 中午段 · 检查所有图表引用编号

**① 先垫概念**:核对正文"如 Fig. 3 所示"实际指的是不是 Fig. 3(增删图表后编号常错位)。**为什么容易错**:你改论文时增删过图表,如果用手动编号,"如图 3"可能因为前面插了新图而实际变成了图 4,正文却没改——读者按图索骥找错图,很困惑。**根治办法是 LaTeX 自动编号(\ref)**:用 \label/\ref 让编号自动维护,增删图表时引用自动更新;但仍要手动核对一遍(确保每个 \ref 指向对的 label)。
**② 手把手带做**:逐一核对图表引用编号 ↔ 实际图表(用补充包的图表引用检查脚本);LaTeX 用 \ref 自动编号。

# D167 周六(集中日)· 竞赛冲刺（WBF）

> **预期管理**:今天竞赛线集中冲刺,核心是用 WBF(加权框融合)替代 NMS 来融合多模型/多次预测的框、再提一波分。提醒:WBF 用于 Ensemble/TTA 的框融合(不是单模型后处理),框要先归一化到 [0,1];每次提交记 Trick 日志。

## 上午段 · 竞赛冲刺：WBF 替代 NMS

**① 先垫概念(WBF 是什么、为什么比 NMS 好)**:**WBF(Weighted Box Fusion,加权框融合)**——检测里融合多个模型/多次预测的框时,**比 NMS 更好**。**区别**:NMS 是"删冗余框"(重叠的只留得分最高的,丢掉其他);WBF 是"加权融合"(把重叠的多个框按得分加权平均成一个更准的框,信息没浪费)。**为什么 WBF 在 Ensemble/TTA 时更优**:当你有多个模型(或同模型多次 TTA)的预测,同一目标会有多个略有差异的框;NMS 只保留一个、丢掉其余的信息,WBF 把它们融合成更精确的框,通常涨点。**适用场景**:模型集成、测试时增强(TTA)的框融合;单模型单次预测的后处理仍用 NMS/Soft-NMS。
**② 手把手带做**:把检测的框融合从 NMS 换成 WBF(用于你的 Ensemble/TTA),框归一化到 [0,1],提交看排名;见补充包代码。WBF 与 NMS 在密集场景的差异尤其明显:
```text
# 直观对比（同一目标被 3 个模型预测出 3 个略偏的框）
NMS：  只保留得分最高的那个框，丢掉另外 2 个的位置信息 → 框可能略偏
WBF：  把 3 个框按得分加权平均 → 融合出一个更居中、更准的框
密集相邻目标场景：WBF 因不"硬删"，相邻目标更不易被误合并，召回更稳
```
**③ 合格样例**:WBF 版提交,排名记录(对比 NMS 融合)。
**④ 坑**:① WBF 参数(iou_thr/weights)不当 → 调(iou_thr 控制多近的框算同一目标);② 框没归一化到 [0,1] → ensemble_boxes 要求归一化坐标;③ 用在单模型单次预测 → WBF 是融合多来源的,单次用 NMS/Soft-NMS。
**⑤ 自救**:WBF 没提升 → 调 iou_thr/各模型 weights(强模型权重高,弱模型权重低甚至剔除);报错 → 检查框是否归一化到 [0,1]、各 list(boxes/scores/labels)长度是否对齐;融合后框反而变差 → 可能某个弱模型拖累了融合,把它权重调低或移出集成;只有单模型没法集成 → 用同模型的 TTA(翻转/多尺度)产生多组预测再 WBF,也能受益。
**⑥ 今天(这一步)你同时学会了什么**:你学会 **WBF 框融合**。**做了**(WBF)、**学了**(WBF vs NMS、加权融合 vs 删冗余、适用 Ensemble/TTA)、**会了**(用 WBF 提升检测融合效果)。

> **技能卡｜WBF 框融合**:WBF(加权框融合)融合多模型/多 TTA 的框时比 NMS 好——NMS 删冗余只留一个(丢信息),WBF 把重叠框按得分加权融合成更准的框(不浪费)。用于 Ensemble/TTA 的框融合(单模型单次仍用 NMS/Soft-NMS);框需归一化到 [0,1];调 iou_thr 与各模型 weights(强模型权重高)。

## 中午段 · 竞赛提交 + 看排名变化

**① 先垫概念**:提交 WBF 版,看排名变化,记录。**冲刺期的提交策略**:竞赛通常每天提交次数有限,要把每次提交用在"有把握提升"的改动上(如验证集上确认涨了再提交),别浪费提交次数试没把握的。**看排名也要看验证集**:public 榜可能和你的本地验证集不完全一致,以本地验证为主、public 榜为参考,避免过拟合 public 榜。**为什么不能只盯 public 榜**:很多竞赛最终排名按 private 榜(你看不到)算;如果你一味追 public 榜(反复提交、挑 public 榜最高的),很可能过拟合到 public 榜的那部分数据,private 榜反而掉。**靠谱做法**:建一个可信的本地验证集(和测试分布接近),用它选改进;public 榜只作为"本地验证和线上是否一致"的粗略参考。**这也是科研素养在竞赛里的体现**——相信经过良好验证的本地结果,而非线上榜单的即时反馈。
**② 手把手带做**:提交 WBF 版(先本地验证确认涨再提交),看排名变化,记录;以本地验证为主、public 榜为参考。
**③ 合格样例**:竞赛提交,排名记录(本地验证 + public 榜)。
**④ 坑**:① 浪费提交次数试没把握的 → 本地验证确认再提交;② 只看 public 榜过拟合 → 以本地验证为主。

def check_fig_refs(tex_path, max_fig, max_tab):
    text = open(tex_path, encoding="utf-8").read()
    fig_refs = set(int(n) for n in re.findall(r'Fig(?:ure)?\.?\s*(\d+)', text))
    tab_refs = set(int(n) for n in re.findall(r'Tab(?:le)?\.?\s*(\d+)', text))
    print("引用了但超出现有图编号:", {n for n in fig_refs if n>max_fig} or "无")

## 三、投稿后会发生什么 + 审稿意见应对预备（M7 用得上）
> 投稿不是终点。提前了解投稿后的流程和怎么应对审稿意见,M7 收到回复时不慌。

```markdown
# 投稿后流程（以期刊为例）
提交 → 编辑初审（desk check，几天到几周；可能直接拒/送审）→ 外审（2-3 位审稿人，
GRSL 约 2-3 月）→ 决定：
  - Accept（少见，通常要小改）
  - Minor Revision（小改，大概率能中）✅ 好结果
  - Major Revision（大改+重审，仍有机会）← 最常见，别气馁
  - Reject（被拒，可改投下一个期刊）

# 收到审稿意见怎么应对（M7-M8 会做，先有心理准备）
1. 先冷静：Major Revision 不是失败，是"有机会"；逐条看意见，别被语气影响。
2. 逐条回复（Response Letter）：每条意见 → "感谢→我们怎么改了→改在第X页"。
   - 同意的：照改，说明改动。
   - 不同意的：礼貌、有据地解释（用数据/文献），而非硬刚。
   - 要补实验的：能补就补（你有可复现 pipeline，补实验不难）。
3. 标注修改：在论文里把改动标色，方便审稿人看到你认真回应了。
4. 原则：尊重审稿人、有理有据、能补则补、诚实。审稿人是来帮你改好论文的。

# 心理预期
第一篇论文走到 Major Revision 很正常甚至算不错；按意见认真改，中稿率会明显提升。
被拒也别灰心——改投下一个期刊（你选了周期短的 GRSL，试错成本低）。
```
**为什么现在就看**:很多人第一次收到 Major Revision 会被打击("这么多意见,是不是很差")。其实 Major Revision 是常态、是机会;提前知道流程和应对原则,M7 收到意见时你就能冷静、专业地逐条回应,而不是慌乱或情绪化。**你的可复现 pipeline 在这里又派上用场**:审稿人要补实验,你能快速补出来,这是很大的优势。

## 五、本周报错速查表（现象 → 根因 → 解法）
| 现象 | 根因 | 解法 |
|---|---|---|
| 论文超页数 | 内容太多 | 次要内容移 supplementary;精简冗余;或选篇幅宽松的 JSTARS |
| 第一篇就冲顶会被拒 | 出口不匹配(单卡增量工作) | 选 GRSL/JSTARS(快、对遥感友好);先建信用 |
| 图表引用编号错位 | 改动后没核对 | 用 \ref 自动编号 + 脚本/手动核对 |
| 参考文献 undefined citation | cite 了 bib 没有的 | 补 bib 条目;查 unused/undefined |
| 更大模型 OOM | 单卡显存不足 | 降 batch + 梯度累积 + 混合精度 + 梯度检查点 |
| WBF 没提升/报错 | 参数不当/框没归一化 | 调 iou_thr 与 weights;框归一化到 [0,1];仅用于多来源融合 |
| 把竞赛大模型策略写进高效论文 | 两条线混了 | 竞赛堆性能、论文强调高效,策略分开 |
| 投稿漏文件 | 没对清单 | 按期刊 submission checklist 备齐;提前一晚准备 |
| proofreading 漏错别字 | 屏幕看麻木 | 打印/换字体/TTS 朗读;倒着读;改完再确认 |
| supplementary 藏了正文该讲的 | 为正文简洁过度精简 | 正文须自包含可懂,附录只放"想深究才看"的 |
| 只追 public 榜最终 private 掉分 | 过拟合 public 榜 | 建可信本地验证集为主,public 榜仅参考 |
| 收到 Major Revision 被打击 | 误以为是失败 | Major Revision 是常态是机会,逐条认真回应中稿率高 |
| 双盲投稿暴露身份 | 正文/致谢留了作者信息 | 匿名版去掉作者名/单位/可识别信息/自引措辞 |
