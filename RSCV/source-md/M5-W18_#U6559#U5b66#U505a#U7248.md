## 上午段 · 数据集 2 你的方法 seed 2–3 → 3-seed → 完整大表

**① 先垫概念**
- 补齐数据集 2 上你的方法的 **seed 2、3**,算 **3-seed mean±std**,做数据集 2 完整大表。
- **关键纪律——格式必须和数据集 1 完全一致**(同列、同指标、同小数位、同呈现方式)。**为什么**:下周(其实就是 D123)要把三个数据集**整合**成一张大表,如果各表格式不一,整合时你会被对齐问题折磨;现在统一,后面零摩擦。这跟写代码统一接口是一个道理。
- **为什么"现在多花两分钟统一格式"能省后面几小时**:如果数据集1的表是"方法|mAP|参数|FPS"、数据集2的表是"方法|参数|mAP±std"(列序不同、有的报std有的不报、小数位不同),等 D123 整合时,你要逐个核对、手动对齐、补算缺的std——又慢又容易出错。而如果三个表从一开始就用**完全相同的表头和格式**,整合就是简单的拼接(甚至代码自动合并)。**这是"前期一点纪律换后期大量省心"的典型**,也是专业研究者和新手的区别之一:专业的人在产出每个中间结果时就考虑了"它后面怎么被用"。
- **"统一格式"的具体清单**:① 列的顺序和名称完全一致;② 指标的小数位一致(都保留1位或都2位);③ 都报 mean±std(不能有的报有的不报);④ 最优值的标记方式一致(都加粗);⑤ baseline 和你的方法都整理进去(整合表的每一行都要有数据)。照这个清单产出每个数据集的表,D123 整合时零摩擦。

**② 手把手带做**
1. 评估数据集 2 的 seed 2、3(用 W17 的 eval 套路)。
2. 算 3-seed mean±std(用补充包的聚合函数)。
3. 整理数据集 2 完整大表,**列结构直接复制数据集 1 的表头**,只改数字:
   ```markdown
   | 方法 | 主指标(mean±std) | 参数量 | FPS |
   ```
4. 最优加粗;baseline 也整理成同格式。

**③ 合格样例**:数据集 2 完整大表(你的方法呈现为 `69.4±0.4` 这样的 mean±std),列结构与数据集 1 一模一样。

**④ 常踩的坑**
- **格式和数据集 1 不一致**(列序不同、有的报 std 有的不报)→ 整合时对不齐,白费功夫。
- **只跑 1 个 seed 就当结果** → 不可信。
- **忘了把 baseline 也整理成同格式** → 整合大表里 baseline 行没法填。

**⑤ 卡住自救(决策树)**:数据集 2 某个 seed 结果异常(明显偏离另两个)?→ 单独看那条 wandb 曲线,大概率是训练异常,重跑该 seed。格式忘了长啥样?→ 直接打开数据集 1 的大表,复制表头改数字。

**⑥ 今天(这一步)你同时学会了什么**:你产出了**第二个数据集的完整结果,且与第一个格式严格统一**。**做了**(数据集 2 完整表)、**学了**(跨数据集统一格式的重要性、为整合铺路)、**会了**(产出可信且可直接整合的第二数据集表)。

> **技能卡｜多数据集结果管理**:每个数据集的大表**用同一套表头**(同列、同指标、同小数位),且 baseline 与你的方法都整理进去——整合大表时直接拼接,零对齐成本。

## 中午段 · 数据集 2 可视化对比图(5 张)

**① 先垫概念**

## 晚上段 · 分析数据集 1 vs 2 的结果差异

**① 先垫概念(本周第一件烧脑活——非常重要)**
- 这是论文 **Discussion 的核心素材之一**。典型问题:"**为什么我的方法在数据集 1 上 +3% 但数据集 2 上只 +1%?**"
- **不同数据集的分辨率、类别分布、目标尺度、场景(城市 vs 农村)都不同**,方法表现自然不同。**把差异归因到这些数据特性上,就是学术深度**——而不是简单说"数据集 2 更难"。
- **为什么现在做**:趁数据集 1、2 结果都新鲜,分析最准;也为 D123 整合后的总分析打底。
- **为什么"跨数据集差异分析"是审稿人眼里的高级感**:一个只会报"我的方法在三个数据集上都提升了"的作者,和一个能说清"我的方法在小目标多的数据集1上提升显著(+3%,因为我的多尺度模块专治小目标),但在大目标为主的数据集2上提升有限(+1%,这类样本本就不是我方法的强项)"的作者——后者明显**更懂自己的方法、更有研究深度**。审稿人通过这种分析判断你是"碰运气调出来的"还是"真正理解方法机理的"。差异分析做得好,直接提升论文档次。
- **"换数据集掉点"是金矿而非灾难(本周核心心法)**:新手看到"我的方法在某数据集上提升很小甚至不如baseline"会慌、会怀疑方法不行。**但这恰恰是最好的 Discussion 素材**——你去分析"为什么在这个数据集上不行",答案(数据特性和你方法强项不匹配)就是深刻的洞察。一篇只报"处处都好"的论文反而可疑(像 cherry-pick);一篇能解释"在哪好、在哪一般、为什么"的论文更可信、更有价值。**把掉点从恐慌变成分析素材,是这一周最重要的心态转变**。
- **怎么做归因(可操作的四问)**:对比两个数据集,逐一问:① 分辨率差多少?② 类别分布(哪类多哪类少)有何不同?③ 目标尺度(大目标多还是小目标多)?④ 场景(城市/农村/某类地物)有何差异?然后问"我的方法的强项(我的组件治什么)正好对应上面哪个差异?"——**你方法强项对应的那个数据特性,就解释了提升幅度的差异**。这个对应关系,就是你 Discussion 的逻辑。

**② 手把手带做**

    gains = {c: ours_percls[c] - base_percls[c] for c in ours_percls}
    print("总提升 D:", round(sum(gains.values())/len(gains), 2))
    top = sorted(gains.items(), key=lambda x: -x[1])
    print("提升最大的类:", top[:3], "| 提升最小/下降的类:", top[-3:])

# 对 D1、D2 各跑一遍，对比"提升最大的类"——往往揭示你方法的强项对应的数据特性

# D125 周六(集中日)· 跨数据集迁移实验(加分项)

> 今天做一个"加分实验"——跨数据集迁移(A 训 B 测)。它不是必需,但做了能让论文显得"考虑得很全",审稿人好感度↑。重点学会**看相对优势而非绝对值**。
>
> **预期管理**:今天做加分实验——跨数据集迁移(A训B测,评估泛化)。提醒:迁移设置下绝对分数通常明显下降(跨域本来就难),这是正常的——**重点看你的方法相对 baseline 是否仍领先**(相对优势),别盯绝对值。领先=泛化好(加分);不领先=诚实写进 Limitation(也加分)。选类别可对应的两个数据集,否则评测无意义。

## 上午段 · 跨数据集迁移实验(A 训 B 测)

**① 先垫概念(迁移实验是加分项)**
- **在数据集 A 上训练 → 在数据集 B 上测试**,评估**泛化性**(模型没见过 B 的训练数据,能做多好)。
- **不是所有论文都做,但做了显著提升"完整度"**——审稿人会觉得"作者考虑得很全面"。时间不够可跳过,但建议做。
- **心理预期**:迁移设置下**绝对分数通常会明显下降**(跨域本来就难),这正常;**重点看你的方法相对 baseline 是否仍有优势**。
- **为什么迁移实验能"加分"**:常规实验是"在每个数据集上分别训练和测试",而迁移实验测的是"模型在没见过的新数据上能不能用"——这更接近**真实部署场景**(你训好一个模型,拿去用在新地区/新传感器的数据上)。做了迁移实验,说明你考虑了方法的**实用泛化性**,而不只是在标准数据集上刷分。审稿人会觉得"这作者想得很全面、很实际",好感度提升。这是一个性价比高的加分项(用已训好的权重直接测,不用重新训练)。
- **为什么"绝对分会降"是正常的、不必恐慌**:跨域(在A上训、在B上测)本质上违反了"训练和测试同分布"的假设——B 的数据和 A 不同(分辨率、场景、传感器),模型在 A 上学的东西不完全适用于 B,所以分数下降是**必然的、符合预期的**。新手看到迁移分数比正常训练低一大截会以为方法崩了——错。**跨域掉点是这个设置本身决定的,不是你方法的问题**。
- **正确的解读方式:看相对优势,不看绝对值**:迁移设置下,你的方法和 baseline **都会掉点**(都面对跨域难题)。关键看:**在都掉点的情况下,你的方法是否仍然领先 baseline?** 如果你 49.2、baseline 45.1(都比正常训练低,但你仍 +4.1),说明**你的方法泛化性更好**——这是很有价值的结论(你的方法不只在见过的数据上好,在新数据上也更robust)。如果你的方法迁移后不再领先,就诚实写进 Limitation(也是诚实加分)。**永远比相对优势,不盯绝对值**。
- **设计要点:类别要可对应**:A 训 B 测,前提是 A 和 B 的**类别能对应**(否则模型输出的类别在 B 上没有对应的真值,评测无意义)。选两个类别体系相近的数据集,或只评估它们的共有类别。这是迁移实验有效的前提。

**② 手把手带做**
1. 设计迁移实验:A 训 B 测,你的方法 vs baseline,**选类别可对应的两个数据集**(否则评测无意义)。
2. 启动(用 A 训好的权重直接在 B 的测试集上评估)。
3. 记录设置。

**③ 合格样例**:迁移实验设计清晰(选了类别可对应的 A、B)+ 启动。

- **看到迁移绝对分低就以为方法差** → 跨域本难,**看相对优势**。

## 二、完整可运行代码 — 三数据集整合表（含平均排名）
```python
import numpy as np
def integrated_table(data, datasets):   # data={"method":{"D1":[3seed],...}}
    means = {m: {d: float(np.mean(data[m][d])) for d in datasets} for m in data}
    # 每个数据集内排名(1=最好),再对各数据集求平均排名
    ranks = {m: 0.0 for m in data}
    for d in datasets:
        order = sorted(data, key=lambda m: means[m][d], reverse=True)
        for r, m in enumerate(order, 1):
            ranks[m] += r
    for m in ranks:
        ranks[m] /= len(datasets)
    print("| 方法 | " + " | ".join(datasets) + " | 平均排名↓ |")
    print("|" + "---|" * (len(datasets) + 2))
    for m in sorted(data, key=lambda x: ranks[x]):       # 按平均排名升序(最好在上)
        cells = " | ".join(f"{means[m][d]:.1f}" for d in datasets)
        print(f"| {m} | {cells} | {ranks[m]:.1f} |")

if __name__ == "__main__":
    integrated_table(
        {"baseline1": {"D1":[75,74.7,75.3], "D2":[67,66.7,67.3], "D3":[70,69.8,70.2]},
         "baseline2": {"D1":[76.3,76.1,76.5], "D2":[68.1,67.9,68.3], "D3":[71,70.8,71.2]},
         "Ours":      {"D1":[78.1,77.9,78.3], "D2":[69.4,69.1,69.7], "D3":[72.6,72.4,72.8]}},
        ["D1","D2","D3"])
```
**预期**:输出竖表 + 自动算的平均排名,你的方法应排在最上(平均排名最小)。
