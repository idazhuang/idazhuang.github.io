# D57 周一 · 从 Limitation 里挖 Gap + 配通用 CV 解法

> 今天是"找题"的第一天。新手最大的误区是"凭空想一个很酷的 idea"——**别**。今天教你一个**稳、不靠灵感**的方法:从论文作者**自己承认的不足**里挖 Gap,再用你的通用 CV 优势去补。
>
> **预期管理**:今天正式从"读"转向"做"——开始找你自己的研究 Gap。提醒:别凭空想"酷 idea"(多半要么被做过要么不是真问题),今天用最稳的方法——从 A 级论文自己写的 Limitation/Future Work 里挖 Gap。关键是"抓本质而非现象"(写出"为什么有这个问题"),写不出本质说明还没真读懂,回去再看。这是从"读者"到"作者"惊险一跳的第一步,慢一点、扎实一点。

## 上午段(1.5h)· 从 A 级论文的 Limitation/Future Work 挖出 ≥10 条 Gap

**① 先垫概念(假设你第一次听说"Gap")**
- **Gap = 现有方法的不足 / 未解决的问题**。一篇科研论文的 Introduction,本质就在回答三句话:**前人做了什么 → 还没做什么(=Gap)→ 我来做这个**。所以**Gap 就是你整篇论文存在的理由**;你论文的价值 ≈ 你填的这个 Gap 有多大、多硬、多少人在乎。
- **最稳、最不容易"想当然"的 Gap 来源**,是 A 级论文自己写的 **Limitation(局限)** 和 **Future Work(未来工作)**——这是作者亲口承认"我们还没解决的"。你站在他们的肩膀上,顺着他们指的方向走,比自己拍脑袋安全得多。
- 为什么现在做:你 W8 已经把这个方向的 A 级论文读穿了,手里有 ~10 篇笔记和每篇的"第 4 段(启发/没解决)"——今天就是把这些"没解决的"系统地汇成一张表。

**② 手把手带做**
1. 打开你 W8 写的所有 A 级论文笔记,逐篇翻到它的 **Limitation / Future Work** 段落(在论文里通常在 Conclusion 附近,或单独一节)。
2. 新建 `10-论文笔记/{方向}_Gap表.md`,建一张表,逐条把局限性抄进去,**每条 1 句话 + 标注出处**。要求 **≥10 条**。
3. 表头用这五列:`编号 | 局限性(1句话) | 出自哪篇 | 这个问题的本质是什么 | 严重程度(高/中/低)`。

**③ 这一步合格的样子(给你一个真实示例,照着填)**
> 以"遥感旋转目标检测"方向为例,你的 Gap 表可能长这样(**这是示范,你要填你自己方向的**):
>
> | 编号 | 局限性 | 出自 | 本质 | 严重程度 |
> |---|---|---|---|---|
> | G1 | 密集排列的小目标(如停车场的车)易漏检/粘连 | Oriented R-CNN | 小目标特征在下采样后丢失 + 框重叠 | 高 |
> | G2 | 跨数据集(A 训 B 测)性能大幅下降 | ReDet | 域差异、传感器差异未建模 | 高 |
> | G3 | 角度回归在 0°/180° 边界不稳定 | Gliding Vertex | 角度的周期性导致回归不连续 | 中 |
> | G4 | 标注成本高,全监督依赖大量旋转框标注 | DOTA 系 | 旋转框标注比水平框贵得多 | 高 |
> | ... | ... | ... | ... | ... |
>
> **合格标准**:≥10 行;每行能溯源到具体论文;"本质"列写出"为什么会有这个问题"(不是只重复现象)。**写不出"本质"= 你还没真正读懂这个 Gap,回去再看那篇论文的相关段落。**

**④ 最常踩的坑**
- **凭空想 Gap、不从 Limitation 挖**:新手最爱"我觉得 XX 会很酷"——但你"觉得"的往往要么早被做过、要么根本不是真问题。**先从作者自陈的不足挖**,这是有据可依的起点。
- **只抄现象、不写本质**:"小目标检测不好"是现象;"小目标特征在下采样后丢失"才是本质。**只有抓住本质,后面才知道往哪改**。
- **贪多凑数、每条都很泛**:10 条具体的 > 30 条空泛的。宁可少而准。

**⑤ 卡住怎么自救(决策树)**
- 某篇论文**没写 Limitation/Future Work**?→ 看它实验表里**哪一类样本/哪个数据集上它掉点最多**,那就是它的隐藏局限;或问自己"它在什么极端条件下会失效"。
- 10 条凑不齐?→ 把每篇 A 级论文的"未来工作"逐条拆开(一篇常提 2-3 个方向),很快超过 10 条。
- 不确定某条算不算"真 Gap"?→ 今天先全收进来,标"待核实",明天 D58 查重时再判断真假。

**⑥ 今天(这一步)你同时学会了什么**
你学会了**从文献系统性地挖 Gap**(而非拍脑袋),并养成"抓本质而非现象"的习惯。这是写出有说服力 Introduction 的源头——你未来每篇论文的"立论"都从这一步来。**做了**(≥10 条 Gap 表)、**学了**(Gap 的定义、Limitation 是最稳的 Gap 来源)、**会了**(从论文自陈不足里提炼"可做的问题"并写清其本质)。
> **技能卡｜挖 Gap 三步**:① 翻 A 级论文的 Limitation/Future Work → ② 一句话记下局限 + 出处 → ③ 追问"它的本质/根因是什么"(本质 = 你后面改进的着力点)。

## 中午段(1h)· 给每条 Gap 配"通用 CV 里的现成解法"(≥5 条可迁移)

**① 先垫概念**:你这个人**最独特的优势,是通用 CV 的积累**(你转型前的底子 + M1–M2 学的通用视觉知识)。遥感圈很多人不熟通用 CV 最新进展;而你能把"通用 CV 里已经验证有效、但还没进遥感"的招数搬过来。**"遥感的 Gap × 通用 CV 的现成解法"= 别人不容易做、你却能做的题**。这正是你"通用 CV 巧技嫁接"这条发力线的具体操作。
- **为什么这是转型者最强的找题姿势**:纯遥感背景的研究者,熟悉遥感但可能不了解通用 CV 的最新进展;纯 CV 背景的人,熟悉通用方法但不懂遥感的真问题。**而你两边都沾——既通过 M1-M2 了解了遥感的 Gap,又有通用 CV 的底子**。这个"交叉地带"正是你的甜区:你能看到"通用 CV 里有个好方法,正好能治遥感的某个痛点,但还没人这么做"——这种题别人不容易想到(单边背景的人看不全),你却能做。**别浪费你这个跨领域的独特优势**。
- **怎么具体操作(可复制的动作)**:① 拿一条遥感 Gap(如"跨域掉点");② 在脑子里过一遍通用 CV 的"工具箱"(域自适应、测试时适配、对比学习、自监督、LoRA、半监督、各种注意力机制……)——问"哪个能治这条 Gap";③ 搜 `通用CV方法名 + remote sensing` 确认遥感圈有没有人搬过——**没人搬,就是你的机会**(你做了就是"第一个把 X 引入遥感的")。这个流程可以对每条 Gap 重复,源源不断产出"嫁接型"选题。
- **为什么"通用 CV 有、遥感还少见"的招最值钱**:如果你想到的解法遥感圈已经在用,那就不是你的独特优势了(谁都能做)。**要刻意找"通用 CV 已验证有效、但遥感还没怎么用"的方法**——这种"时间差/信息差"正是你作为跨领域者的红利。通用 CV 发展快,很多好方法还没扩散到遥感,这个窗口期就是你的机会。

**② 手把手带做**:在 Gap 表里新增一列 `可借鉴的通用 CV 解法`。逐条想:"通用 CV 里有没有现成方法能缓解这个 Gap?"至少给 **≥5 条** Gap 配上。
> 接着上面的示例:
> - G1 密集小目标 → 通用 CV 里的"小目标专用检测头 / 高分辨率特征(如 HRNet 思路)/ 查询式检测(DETR 系对密集目标的处理)"。
> - G2 跨域下降 → 通用 CV 的"域自适应(domain adaptation)/ 测试时适配(TTA、TENT)"。
> - G4 标注贵 → 通用 CV 的"半监督 / 自监督 / 少样本学习"。

**③ 合格样例**:≥5 条 Gap 旁边写清"通用 CV 里有 XX 方法可借鉴(它原本解决什么、为什么可能迁过来)"。

**④ 坑**:① 写的"解法"太笼统("用深度学习")→ 要具体到某类方法/某个代表工作;② 只想到遥感圈已经在用的招(那就不是你的独特优势了)——尽量想**通用 CV 有、遥感还少见**的。

**⑤ 自救**:想不出通用 CV 解法?→ 回顾你 M2 读过的通用视觉概念(注意力、对比学习、LoRA、半监督…),逐个问"它能不能治这条 Gap";或搜 "通用CV方法名 + remote sensing" 看有没有人搬过(没人搬 = 你的机会)。

**⑥ 学会了什么**:你学会**用"优势×真问题"的交叉找题**——这是跨领域转型者最强的找题姿势(你比纯遥感背景的人多了一整套通用 CV 弹药)。

## 晚上段(2.5h)· 给 10 条 Gap 各配一个"解决思路雏形"(2–3 句)

**① 概念**:有了 Gap + 可借鉴解法,现在把它们捏成"思路雏形"——用 2-3 句话说"我打算怎么做"。这还不是完整方法,只是"如果做,大概往哪个方向"。

**② 手把手带做**:Gap 表再加一列 `解决思路雏形(2-3句)`。逐条写,**句式**:"针对【Gap】,借鉴【通用 CV 解法】,我打算【具体做法】,预期【效果】。"
> 示例:"针对密集小目标漏检(G1),借鉴通用 CV 的高分辨率特征思路,我打算在检测头前加一个轻量高分辨率分支专门保留小目标特征,预期在 small-vehicle 类上提升 AP。"

**③ 合格样例**:10 条 Gap 都有 2-3 句的思路雏形,每条能让人看懂"你想干嘛"。

**④ 坑(★校准)**:思路雏形清一色"做更大的模型/用更多数据"——你做不了,这些会在后面被筛掉,别浪费。**优先写"小而巧"的思路**(加个轻量模块、换种表示、引入一个通用 CV 技巧、做个评测)。

**⑤ 自救**:某条 Gap 想不出思路?→ 跳过,标"暂无思路";10 条里有 6-7 条有思路就够进下一步。

**⑥ 今天(这一步)你同时学会了什么**:你把"别人没解决的问题"转化成了"我可能怎么解决的思路"——完成了从"读者"到"潜在作者"的视角切换。**做了**(带思路雏形的 Gap 表)、**学了**("优势×Gap→思路"的造题公式)、**会了**(把抽象 Gap 落成具体可做的思路方向)。

> **今日交付**:✅ 局限性—思路对照表(≥10 条,含"通用 CV 解法"列 + "思路雏形"列)。

> **技能卡｜造题公式(转型者最强姿势)**:`你独有的东西(通用 CV 积累)× 遥感里一个真问题(Gap)= 别人不容易做、你却能做的题`。遥感圈很多人不熟通用 CV 最新进展;你把"通用 CV 已验证有效、但还没进遥感"的招搬过来填遥感的 Gap,天然差异化。搜 `通用CV方法名 + remote sensing`,没人搬=你的机会。

# D58 周二 · 查重(这个 idea 是不是已经被做过了)

> 想到 idea 后,**第一件事不是兴奋,是查重**。新手最痛的经历就是:闷头做了三个月,投稿前发现去年已经有人发过一模一样的。今天教你怎么高效查重、怎么判断"撞车了"还是"还有空间"。

> **预期管理**:今天做查重——想到 idea 先别兴奋,先确认没人做过(避免白干三个月)。提醒:查重有三态——"一模一样→弃"、"类似但不同→好(有空间,记下差异点)"、"完全没人→警惕陷阱再验证"。中英文都要搜(顶会多英文);看到"类似"别慌着放弃,类似恰恰说明方向对、你有差异化空间。

## 上午段(1.5h)· 逐个思路在 Google Scholar 查重

**① 先垫概念**:
- 查重 = 确认"你的 idea 是不是已经有人做了"。**怎么判断结果**:
  - 找到**一模一样**的论文(同任务+同方法+同模态)→ 这个 idea **放弃**(或必须找到明确的差异点)。
  - 只找到**"类似但不完全一样"**的 → **很好**!说明这方向有人关注(证明它重要、不是冷门死路),但还有空间让你做得更好/不同。
  - **完全没人做** → 别急着狂喜,可能是真空白(机会),也可能是"没意义/做不动"的陷阱(回想 M1 学的真假空白),今晚要进一步判断。
- **为什么"查重"是动手前的保命动作**:科研最痛的不是"做不出",而是"做出来了才发现别人去年发过一模一样的"——几个月白费。**查重花半天,能省你几个月**,是性价比最高的一步。养成"想到 idea 先查重、别先兴奋着手"的习惯。
- **为什么"类似但不同"反而是最好的结果(反直觉,但重要)**:新手看到"有人做过类似的"会慌、想放弃——这是错的。**"有类似工作"恰恰证明了三件好事**:① 这个方向是真问题(有人愿意花精力做、能发表);② 它不是无人问津的死胡同(有受众);③ 而"类似但不完全一样"说明还有空间——你可以做得更好、用不同的角度、解决他们没解决的子问题。**真正可怕的是"完全没人做"**(可能是陷阱)和"一模一样"(撞车),而"类似"是甜区。记得把"最相关的已有工作"链接存下来,写论文的 Related Work 和"讲清自己的差异点"时正好用。
- **为什么"完全没人做"要先警惕而非狂喜**:一个看起来"全新、没人碰"的方向,要先问"为什么没人做?"——可能是真空白(确实是好机会,大家还没注意到),但更可能是陷阱:① 这问题其实没意义/没人在乎;② 它需要海量数据/算力,普通人做不动(只有巨头能做);③ 它有隐藏的、大家都知道的死结。**回想 M1 学的真假空白三标准(小而硬/单卡可做/有人在乎)**,用它筛——三个都满足才是真机会。

**② 手把手带做**:对每个有思路的 Gap,在 **Google Scholar** 搜:`你的方法关键词 + 遥感/SAR/remote sensing`(中英文各搜一遍)。
> 示例搜法:G1 的思路 → 搜 "small object rotated detection remote sensing"、"high-resolution feature aerial small object" 等;按时间筛**近 2 年(2024-2025)**,看有没有人做了。
- 在 Gap 表加一列 `查重结论`,标:**已被做(弃)/ 类似(可做得更好)/ 没人做(待核实真假)**。

**③ 合格样例**:每个有思路的 Gap 都有明确查重结论 + 1-2 篇"最相关的已有工作"链接(留着,后面写 Related Work / 讲差异点要用)。

**④ 坑**:① **只搜中文、只搜一个关键词**→ 漏掉英文同类工作(顶会顶刊多是英文);② 搜到"类似"就慌着放弃→ 类似不等于撞车,**类似恰恰说明方向对、且你有差异化空间**;③ 看到"完全没人做"就狂喜→ 先怀疑是不是陷阱。

**⑤ 自救**:某个 idea 搜出一堆"类似"的,分不清撞没撞→ 用 **Connected Papers / Semantic Scholar** 看那篇的"引用网络"(下午做),能快速看清"这一簇做类似事的论文",再判断你的差异点够不够。

**⑥ 学会了什么**:你掌握了 **idea 查重**这个保命动作,并学会判断"撞车/有空间/真假空白"——这一步省下你未来几个月可能白费的力气。
> **技能卡｜查重三态**:一模一样→弃;类似但不同→好(有空间,记下差异点);完全没人→警惕陷阱,再验证。

## 中午段(1h)· 用 Connected Papers / Semantic Scholar 查引用网络

**① 概念**:**Connected Papers / Semantic Scholar** 能把一篇论文的"相关论文网络"可视化——输入一篇,它给出一簇"做类似事"的论文。这比单纯关键词搜更能发现"已经有人做过类似的"。

**② 手把手带做**:对每个"类似/没人做"的 idea,把最相关的那篇丢进 Connected Papers,看它周围一簇论文里有没有和你 idea 重合的;把发现的重要相关工作补进 Gap 表。

**③ 合格样例**:每个候选 idea 周围的"相关工作簇"摸清,确认没有完全撞车的。

**④/⑤ 坑与自救**:工具打不开/需登录→ Semantic Scholar 免费可用;或直接看那篇相关论文的"被引/引用"列表手动找。

**⑥ 学会了什么**:你学会用**引用网络工具**高效摸清"谁做过类似的"——比关键词搜更全面,降低撞车风险。

## 晚上段(2.5h)· 排除已做过的 → 得到"去重后候选思路"

**① 概念**:把查重结论是"已被做(弃)"的划掉,剩下"类似(可做更好)+ 没人做(已验证是真空白)"的,就是你的**去重后候选思路池**。**这一步是"安全筛查"**:经过查重,你手里剩下的每条思路都满足"没撞车"——这意味着你后面做它,不会出现"投稿才发现别人做过"的悲剧。**对"没人做"的要格外用真假空白三标准(小而硬/单卡可做/有人在乎)再筛一遍**,把"看似空白实为陷阱"的(如要海量算力的大方向)剔除。最稳的其实是"类似但不同"的那些——有人验证了方向、你又有差异化空间。

**② 手把手带做**:在 Gap 表里**划掉/标灰**已被做的;对"没人做"的,逐条判断真假空白(问:它是真没人做,还是因为没意义/要海量算力才没人做?);整理出一份干净的"去重后候选思路"清单。

**③ 合格样例**:一份去重后的候选清单(通常 5-8 条),每条都"没撞车 + 是真问题 + 单卡可做"。

**④ 坑(★校准)**:把"完全没人做的大方向"(如"做个更大的遥感基础模型")当成真空白留下→ 那是巨头的赛道、你的陷阱,划掉。

**⑤ 自救**:去重后候选太少(<3 条)?→ 回 D57 再从 Limitation 多挖几条;或把"类似但不同"的多保留几条(它们其实最稳)。

**⑥ 今天(这一步)你同时学会了什么**:你完成了 idea 的"安全筛查",手里是一份**没撞车、是真问题、自己能做**的候选池。**做了**(去重后候选清单)、**学了**(引用网络查重、真假空白再判断)、**会了**(把一堆原始 idea 筛成"安全可做"的少数候选)。

> **今日交付**:✅ 去重后思路列表(5–8 条)。

# D59 周三 · 成功路径预演 + 实验成本评估(选题的杀手锏)

> 今天用两把"尺子"给候选思路称重:一把是"**成功路径预演**"(能不能想象出做成后的论文长相),一把是"**实验成本**"(1 张 4090 做不做得起)。这两把尺子能把"听起来酷但做不出"的 idea 当场筛掉。

> **预期管理**:今天用两把尺子筛 idea——"成功路径预演"(想象论文长什么样:标题/teaser图/主结果表)和"实验成本"(4090 做不做得起)。提醒:想得出论文长相=idea 够成熟可做,想不出=还太模糊或做不出(这是极灵敏的成熟度检测器);实验成本要对单卡诚实,凡需海量算力/标注的直接判低分。这两把尺子专治"听着酷但做不出"。

## 上午段(1.5h)· Top 5 思路各做"成功路径预演"

**① 先垫概念(为什么这是杀手锏)**:
- **成功路径预演**= 对每个 idea,**想象它已经做成了**——这篇论文长什么样?标题是什么?第一页那张"teaser figure"(吸睛大图)画的是什么?主结果表大概什么样?
- **为什么管用**:如果你能**清楚想象出论文的样子**,说明这个 idea 够具体、够可行;如果你**怎么也想象不出来**(画不出 teaser、说不清主结果),说明它还太模糊或根本做不出——这是一个极灵敏的"成熟度检测器"。
- **为什么"画不出 teaser"是强烈的危险信号**:teaser figure 是论文第一页那张"一图说清你做了什么、好在哪"的图。如果你连这张图画什么都想不出,说明**你的 idea 还没具体到"有一个能展示的、看得见的改进"**——要么太模糊(不知道具体改什么),要么改进不可视化/不明显(没有能拿出来给人看的效果)。审稿人和读者第一眼看的就是 teaser,你自己都想象不出,这个 idea 大概率还不成熟。
- **它为什么比"觉得这个 idea 不错"可靠**:"觉得不错"是模糊的直觉,容易自我欺骗;"能不能想象出标题+teaser+主结果表"是**具体的、可操作的检验**——你要真去想这三样,想得出就是真的想清楚了,想不出就是真的没想清楚。**把模糊的"可行性判断"变成具体的"想象论文三件套"**,这是资深研究者下意识在做的事(他们看一个 idea,脑子里立刻浮现"这能做成什么样的 paper")。
- **预演还能帮你提前发现"做出来也没人看"的 idea**:有些 idea 你能想象出论文,但那张 teaser 和主结果"平平无奇"(提升 0.2 点、没有亮眼对比)——这说明即便做出来,也是篇没人在乎的水文。**预演让你提前看到"成品的吸引力"**,从而避开那些"能做但不值得做"的。

**② 手把手带做**:从去重后候选里挑 **Top 5**(凭直觉初选),每个写三样:
1. **假想标题**(具体、点出方法+任务,如"HRFormer-Lite: 面向遥感密集小目标的轻量高分辨率旋转检测")。
2. **teaser figure 画什么**(一句话,如"左:baseline 漏掉一片密集小车;右:我的方法全检出")。
3. **主结果表长什么样**(一句话,如"3 个数据集上 small-vehicle AP 比 SOTA 高 2-4 点")。

**③ 合格样例**:5 个候选都能写出具体的"假想标题 + teaser + 主结果"。**有 1-2 个你怎么也想象不出 teaser/主结果的——把它标记为"不成熟/待调研",这正是预演帮你筛出来的。**

**④ 坑(★校准)**:预演出来的论文是"我提出一个更大的模型/更大的数据集"——那张 teaser 你画不出、那些实验你跑不起,**预演时就该感到"不对劲"**。这正是预演在帮你识别陷阱。

**⑤ 自救**:某 idea 想不出 teaser?→ 两种可能:(a)idea 太模糊,需再调研;(b)idea 其实不适合可视化(如纯理论改进),那就想"它的主结果表/曲线"能不能说清。两样都想不出 → 这个候选暂时搁置。

**⑥ 今天(这一步)你同时学会了什么**:你学会用**"成功路径预演"反向检验 idea 的成熟度与可行性**——想得出论文长相 = 可做;想不出 = 还不行。这是资深研究者选题时的下意识动作。**做了**(Top 5 的预演)、**学了**(预演法、teaser 的作用)、**会了**(用"能否想象论文长相"判断 idea 成熟度)。
> **技能卡｜成功路径预演三问**:① 标题是什么?② teaser 图画什么?③ 主结果表/曲线长什么样?三个都答得出 = 成熟可做。

## 中午段(1h)· 评估每个 idea 的实验成本(对 1 张 4090 诚实)

**① 概念**:每个 idea 做起来要花多少资源?**这是个人研究者的生死线**。要诚实评估:需要多少 GPU 时间?什么数据集(下载/标注成本)?什么开源代码可复用?

**② 手把手带做**:Top 5 每个估算:`需要的 GPU 时间(粗估) | 需要的数据集(有现成的吗) | 可复用的开源代码 | 单张 4090 能否做`。
> 红线:凡是"需要预训练大模型/几十张卡/海量标注"的,**单卡可行性直接判低分**。

**③ 合格样例**:5 个候选都有诚实的成本估算 + "4090 能否做"的判断。

**④ 坑**:对成本盲目乐观("应该能跑吧")→ 要具体:你的方法要训几个模型?每个多久?数据多大?

**⑤ 自救**:估不准 GPU 时间?→ 参考你 M2/M3 跑过的类似实验耗时(你已有体感);数据集不确定有没有→ 回 W8 的数据集表查。

**⑥ 学会了什么**:你学会**对算力/数据成本诚实估算**——把"想做"和"做得起"分开,这是个人研究者避免中途卡死的关键。

## 晚上段(2.5h)· 完善 Top 5 评估表

**① 概念**:把"成功路径预演 + 实验成本"汇成一张 Top 5 评估表,为明天找人讨论、后天收敛做准备。

**② 手把手带做**:建表 `idea | 创新性(1-5) | 可行性(1-5) | 实验成本(越低越好) | 与空天院方向匹配(1-5) | 发文目标(GRSL/JSTARS/TGRS) | 成熟度(能否预演)`,5 行填满。

**③ 合格样例**:一张 5 行评估表,每列都填了,能看出"哪几个又可行又匹配又成熟"。

**④/⑤ 坑与自救**:某项不知怎么打分→凭你已有的体感粗打 1-5 即可,这是为收敛排序服务,不求精确。

**⑥ 学会了什么**:你产出了一张**可比较的 Top 5 评估表**——把"凭感觉选"变成"按维度比",决策更靠谱。

> **今日交付**:✅ Top 5 评估表。

# D60 周四 · 找人当"审稿人"挑刺 → 收敛到 3 个候选

> 今天请外人帮你"挑刺"。一个人想 idea 容易陷入"自我确认偏误"——你越喜欢的 idea 越看不见它的漏洞。今天用别人的眼睛,把 Top 5 收敛到 3 个最扛得住的候选。

> **预期管理**:今天找人当"审稿人"挑刺,把 Top 5 收敛到 3 个候选。提醒:破解"自我确认偏误"(越喜欢越看不见漏洞)的办法就是找人挑刺,越狠越好——别只想听夸奖,被问住恰恰是收获。一个灵敏测试:给非遥感的聪明朋友 1 分钟讲清"为什么重要",讲不清=动机不够强。收敛要狠,留"能做出来且有意义"的,不是"最炫"的。

## 上午段(1.5h)· 找 1–2 个朋友以"审稿人"身份讨论 Top 5

**① 先垫概念**:
- **自我确认偏误**:你倾向于只看见支持自己 idea 的证据、忽略反对的。**破解办法 = 找人挑刺**。
- **一个灵敏的测试**:找一个**非遥感背景**的朋友,给他讲你的 idea,问他"**这个为什么重要?**"。**如果你 1 分钟讲不清动机 → 说明动机不够强**(连聪明的外行都说服不了,怎么说服审稿人)。
- **为什么"动机"是论文的命根子**:审稿人拒稿最常见的理由不是"方法不对",而是"**so what?**"(你做这个有什么意义?谁在乎?)。一个方法再精巧,如果解决的问题没人关心,论文就没价值。**动机(为什么这个问题重要、值得解决)决定了论文的天花板**——动机强,方法一般也能发;动机弱,方法再炫也容易被拒。所以在投入几个月做之前,先确认动机够强,是性价比极高的一步。
- **为什么用"给外行讲清"来测动机**:如果一个问题真的重要,它的重要性应该能用大白话讲清楚(如"现在的方法在密集小目标上漏检很多,而停车场车辆计数、灾后建筑评估都需要准确检测密集小目标")——连聪明的外行都能听懂"哦这确实有用"。**如果你只能用一堆术语绕、讲不清它到底为什么重要,那动机多半是你自己想象的、站不住的**。外行听不懂不是他笨,是你的动机不够实在。
- **为什么必须找别人、不能只靠自己**:你对自己的 idea 有感情(花了时间想出来的),会不自觉地放大它的优点、忽视它的硬伤——这是人性,无法靠"我客观一点"克服。**外人没有这层感情滤镜,能一眼看到你看不见的漏洞**。尤其要请他们"挑刺"而非"鼓励"——你需要的是 W9 就暴露问题(还能改/换),而不是做了三个月被审稿人暴露(来不及了)。
- **被问住是收获不是打击**:朋友问"这不是 XX 已经做了吗?""你凭什么能做出来?""最大的风险是什么?"——你答不上来的每个问题,都是这个 idea 的一处真实弱点。**现在被问住,总比投稿被拒强**。把被问住的点记下来,正是收敛和改进的依据。

**② 手把手带做**:找 1-2 个朋友/同学,线上语音/视频 30min;先用 1-2 句给他讲每个候选 idea,请他以"审稿人/挑刺者"身份问:"为什么重要?""是不是已经有人做了?""你凭什么能做出来?""最大的风险是什么?"

**③ 合格样例**:每个候选都被问了"为什么重要/有没有人做/风险是什么";你记下了哪些 idea 你"讲不清动机"或"被问住"。

**④ 坑**:① 找人时只想听夸奖→ 明确请他们挑刺、越狠越好;② 被问住了就辩解→ 被问住恰恰是收获(暴露了 idea 的弱点)。

**⑤ 自救**:找不到人?→ 用"假装给完全外行写一段 200 字的科普介绍"代替:写不顺、讲不清的那个 idea,动机就不够强。

**⑥ 学会了什么**:你学会**用外部视角检验 idea**,尤其用"能不能给外行讲清动机"测动机强度——动机是论文的命根子。

## 中午段(1h)· 整理讨论反馈

**① 概念**:讨论收到一堆零散质疑,得**结构化整理**才能用——把质疑分两类:**致命质疑**(动机弱/已被做/单卡做不起,这类直接决定 idea 去留)和**可改进质疑**(细节/方法问题,这类是优化点不是否决点)。分清两类,收敛时才知道"哪些 idea 该砍、哪些只是要改进"。

**② 手把手带做**:把讨论中每个 idea 收到的质疑逐条记下,分"致命质疑(动机弱/已被做/做不起)"和"可改进质疑(细节问题)"两栏;每个 idea 旁标注"致命质疑数"。

**③ 合格样例**:每个候选 idea 都有一份分类质疑清单,致命/可改进分开,一眼看出哪些 idea 带着致命伤。

**④ 常踩的坑**:① 把"细节可改进"误当致命而错杀好 idea → 致命的只有"动机弱/撞车/做不起"三类;② 把致命质疑当细节而硬留 → 动机弱是绝症,别自欺。

**⑤ 卡住自救**:分不清某质疑是致命还是可改进?→ 问"这个问题能靠改进方法解决吗?"能(如"loss 设计不好")=可改进;不能(如"这问题没人在乎""已经有人做了")=致命。

**⑥ 学会了什么**:你学会**结构化整理反馈**(分致命/可改进),为收敛提供依据。**做了**(分类质疑清单)、**学了**(致命 vs 可改进的区分)、**会了**(把零散反馈整理成可用于决策的结构)。

## 晚上段(2.5h)· 据反馈精修 → 排除明显不可行 → 收敛到 3 个候选

**① 概念**:综合评估表分数 + 讨论反馈,**砍掉有致命质疑的**,收敛到 **3 个候选**(最值得花 toy 实验去验证的)。

**② 手把手带做**:对每个 idea 做"去留判断"——有致命质疑(动机弱/撞车/单卡做不起)的砍掉;剩下评分高、动机强、单卡可做的,留 3 个。写一句话说明"为什么留这 3 个"。

**③ 合格样例**:**3 个候选确定**,每个都"动机讲得清 + 没撞车 + 4090 能做 + 能想象出论文"。

**④ 坑(★校准)**:为了"听起来更创新"留下一个动机弱或做不起的→ 收敛要狠,留的是"能做出来且有意义"的,不是"最炫的"。

**⑤ 自救**:3 个里有 2 个很像?→ 保留更具体/更可行的那个,换一个差异化的进来(3 个候选最好覆盖不同角度,toy 验证才有比较价值)。

**⑥ 今天(这一步)你同时学会了什么**:你学会**用外部反馈 + 评分把 Top 5 收敛到 3 个候选**——从"想了一堆"到"锁定值得验证的少数",这是选题从发散到收敛的关键一跳。**做了**(讨论纪要 + 3 候选)、**学了**(自我确认偏误、动机强度测试)、**会了**(综合评分与质疑做收敛取舍)。

> **今日交付**:✅ 讨论纪要 ✅ 3 个候选确定。

# D61 周五 · 候选 1 详细技术方案 + 架构草图

> 接下来三天(D61-D63)聚焦候选 1:今天把它写成详细方案、画出架构、设计好"最小可行实验",明天开跑。这是你第一次把一个 idea "做实"。

> **预期管理**:今天把候选 1 从"2-3 句思路"做实成详细方案+架构图+toy 实验设计。提醒:方案的核心是"创新点和 Gap 必须对得上"(为创新而创新是大忌);画架构图会逼你想清每一步(模糊处一画就暴露);toy 实验要设计成"2 天能跑通的最小验证",且明确"和谁比、怎么算有信号"。这是你第一次把想法落成可执行的实验。

## 上午段(1.5h)· 候选 1 详细技术方案(≥500 字)

**① 概念**:把候选 1 从"2-3 句思路雏形"扩成"详细技术方案"——讲清**输入是什么、输出是什么、核心创新点是什么、用什么 loss、在什么数据集验证**。这是 toy 实验和后面 Proposal 的底稿。
- **为什么要"写下来"而非"想清楚就行"**:你以为想清楚了,一动笔写就会发现一堆模糊处——"我的模块具体加在哪?""输入输出的维度对得上吗?""创新点到底是哪一点?"**写作是最严格的思考检验**:能写清楚才是真想清楚,写不清楚说明还有没想透的地方。而且这份方案是 toy 实验的施工图、后面 Proposal 的底稿,现在写好,后面省力。
- **核心创新点必须和 Gap 严丝合缝(本周反复强调)**:最常见的毛病是"为创新而创新"——为了显得新,加一堆花哨模块,但它们和你要解决的 Gap 没关系。**正确的逻辑链是:Gap(什么问题)→ 通用 CV 解法(借鉴什么)→ 你的创新点(怎么把解法落到这个 Gap 上)**,三者一条线。检验方法:你的创新点应该能一句话说清"它怎么治那个 Gap"(如"加高分辨率分支保留小目标特征,所以能治密集小目标漏检")——说不清这个因果,创新点就是无的放矢。
- **检验标准很具体**:写完后,想象"一个懂通用 CV 但不懂你这个具体 idea 的人"读这份方案——**他读完能不能复述出"你要加什么、解决什么"?** 能,说明方案清楚;不能(他读完一脸懵),说明你没写清楚,回去改。这个"假想读者复述"的检验,适用于你以后写的所有方案/论文。
- **四要素缺一不可**:问题与输入输出(定位 Gap 和任务)、核心创新点(你的新东西)、关键设计(怎么实现)、验证方案(怎么证明有用)——少了任何一个,方案都不完整。尤其"验证方案"新手常漏(只想方法不想怎么证明),但**一个方法如果说不清"在哪个数据集、和谁比、用什么指标证明它好",就等于没法验证、没法发表**。

**② 手把手带做**:写 ≥500 字方案,按这个结构:
1. **问题与输入输出**:解决哪个 Gap;输入(什么图/什么模态)→ 输出(框/mask/类别)。
2. **核心创新点**:你加的那个新东西是什么(一句话说清),它怎么治那个 Gap。
3. **关键设计**:用什么 backbone/loss/模块;和 baseline 的差异在哪。
4. **验证方案**:在哪个(些)数据集、和谁比、用什么指标。

**③ 合格样例**:≥500 字方案,**一个懂通用 CV 但不懂你具体 idea 的人读完,能复述出"你要加什么、解决什么"**。

**④ 坑**:① 方案只说"我用注意力/transformer"不说"加在哪、为什么、怎么治 Gap"→ 等于没说;② 创新点和 Gap 对不上(为创新而创新)。

**⑤ 自救**:写不清创新点?→ 回到"它治的是哪条 Gap、用的是哪个通用 CV 解法",把这两者接起来就是创新点。

**⑥ 学会了什么**:你学会把一个 idea **落成可执行的详细技术方案**(输入输出/创新点/设计/验证四要素)——这是从"想法"到"可做的实验"的桥。

## 中午段(1h)· 候选 1 架构草图

**① 概念**:**架构图**= 把你的方法画成"数据怎么从输入流到输出、你的新模块加在哪"的框图。画图会逼你想清楚每一步(很多模糊之处一画图就暴露)。

**② 手把手带做**:用手绘或 draw.io,画候选 1 的架构:输入图 → backbone → (你的新模块,标红)→ head → 输出。标清你的创新模块的位置和数据流。

**③ 合格样例**:一张能看懂"你的新模块加在哪、输入输出是什么"的草图。

**④/⑤**:画不出新模块内部→先画它在整体里的位置(黑盒),内部细节做 toy 时再定。

**⑥ 学会了什么**:你学会**用架构草图把方法可视化**——画图即思考,暴露并理清模糊之处。

## 晚上段(2.5h)· 评估候选 1 的"最小可行实验(toy)"

**① 先垫概念(toy 实验)**:
- **最小可行实验 / toy 实验**:用**最小数据集**(如 10% 训练集)、**最简配置**(如 ResNet-18 backbone)、**最少 epoch**(如 5),快速看核心想法**有没有"信号"**。
- **"有信号"的标准**:哪怕只比 baseline 好 **0.1%** 也算有信号——说明**方向对了**,后面可以加码。**toy 不是验证"方法好不好",是验证"方向对不对"**(成本极低、结论极有用,是个人研究者对抗算力劣势的核心武器)。
- **为什么 toy 实验是单卡选手的"核武器"**:大组可以"广撒网"——同时跑十几个 idea 的完整实验,哪个好用哪个。你单卡做不到(一个完整实验就要几天)。但 toy 让你用几小时、极小成本就能判断一个方向"有没有戏"——**用最小代价探方向,只在有信号的方向上才投入完整实验**。这样你虽然算力少,但不会把宝贵的算力浪费在没信号的方向上,效率反而可能更高。**toy 思维是算力劣势者最重要的生存技能**。
- **为什么"看方向不看高低"是 toy 的灵魂**:toy 用的是小数据、小模型、少 epoch,它的绝对指标必然很低(远不如完整训练)——所以**看 toy 的绝对高低毫无意义**。要看的是"在同样的 toy 条件下,加了你的创新模块 vs 不加(baseline),有没有正向差异"。只要稳定为正(哪怕 0.5 点),就说明你的想法在起作用、方向大概率对,值得放大到完整实验;如果持平或为负,要么方向不对、要么代码有 bug(先查 bug)。**toy 是个"方向对不对"的指南针,不是"性能多高"的标尺**。
- **toy 的两个常见误区(避开)**:① **把 toy 做大**(用全量数据、训 100 epoch)——那就失去了"最小快速"的意义,几小时变几天,toy 的价值没了;② **没设 baseline 对照**——toy 结果没有参照,你看不出"有没有信号"(信号是相对 baseline 的差异,不是绝对值)。**toy 必须小、必须有对照**,这两点是它有效的前提。
- **toy 结果差时的正确反应**:toy 跑出来比 baseline 差,**第一反应应该是"是不是代码 bug 或 toy 没搭对",而非"idea 死了"**。因为你刚改的代码很可能有接错(模块输入输出形状不对等)、或 toy 设置不当(数据太少、epoch 太少没学到东西)。**先在 10 张图上过拟合验证代码通不通**(能过拟合=代码通),排除 bug 后再判断方向。很多好 idea 被新手在 toy 阶段因为一个 bug 误杀了。

**② 手把手带做**:写清候选 1 的 toy 怎么搭:用哪个小数据子集、多简的模型、跑几个 epoch、和谁比、看哪个指标、**预计 2 天内能跑通**。

**③ 合格样例**:一份"2 天内能跑通的极简实验方案",明确"怎么算有信号"(比 baseline 好任意正值)。

**④ 坑**:① 把 toy 搞得很大(用全量数据、训 100 epoch)→ 失去"最小快速"的意义;② 没设"和谁比"→ toy 结果没参照,看不出有没有信号。

**⑤ 自救**:不确定 toy 用多小?→ 原则是"小到能在你 4090 上几小时内跑完一轮",通常 10% 数据 + ResNet-18 + 几个 epoch。

**⑥ 今天(这一步)你同时学会了什么**:你掌握了**"最小可行实验(toy)"思维**——用最小成本探方向,避免在没信号的方向上砸几个月。这是贯穿你整个研究生涯、尤其适合算力有限者的核心习惯。**做了**(候选 1 详细方案 + 架构草图 + toy 方案)、**学了**(toy 实验的定义、"有信号"的判据)、**会了**(把一个 idea 拆成 2 天能跑通的最小验证)。
> **技能卡｜toy 实验四要素**:最小数据(10%)+ 最简模型(小 backbone)+ 最少 epoch(几轮)+ 明确的"和谁比"。好坏不看高低,只看"有没有正信号"。

> **今日交付**:✅ 候选 1 详细方案(≥500 字)✅ 架构草图 ✅ toy 方案。

> **技能卡｜详细技术方案四要素**:① **问题与输入输出**(填哪个 Gap、输入什么→输出什么)② **核心创新点**(你加的新东西一句话说清,它怎么治那个 Gap)③ **关键设计**(backbone/loss/模块、和 baseline 的差异)④ **验证方案**(哪些数据集、和谁比、什么指标)。检验标准:**懂通用 CV 但不懂你 idea 的人读完能复述"你要加什么、解决什么"**。红线:创新点必须和 Gap 对得上,别为创新而创新。

## 上午段 · 准备数据 + 改代码(在 M2 复现的 SOTA 代码上改最小改动)

**① 概念**:不要从零写——**在你 M2 复现过的 SOTA 代码基础上,做最小改动**实现你的创新模块。复用现成框架,改动越小越快。
- **为什么"复用 > 重写"是工程铁律**:从零写一个完整 pipeline(数据加载、训练循环、评估、日志)要好几天,而且到处是 bug。而 baseline 的代码已经把这些都调通了——你只需在它基础上加你的一个创新模块。**改动越少,出错越少、定位越快**:如果实验出问题,你知道"问题一定在我改的那几行",不用在整个 pipeline 里大海捞针。这就是为什么 M2 让你认真复现 SOTA 代码——那些代码现在成了你做实验的"现成底座"。
- **改动要"集中"而非"散落"**:把你的创新模块尽量做成一个独立的、低侵入的组件(如残差式接入:`return x + my_module(x)`),只在一两处接进 baseline,而不是把改动散布到代码各处。**集中改动的好处**:① 好排查(出错就看那一处);② 好做消融(把你的模块一行注释掉就是 baseline,对照清晰);③ 好迁移(以后换个 baseline 也能快速接上)。

**② 手把手带做**:① 准备 toy 用的小数据子集(取 10%);② 在复现代码里**只加你的创新模块**(其余不动);③ 配好 toy 的超参(小模型、几个 epoch)。

**③ 合格样例**:代码改完、数据备好,准备启动;改动集中在"你的新模块"那几处。

**④ 坑**:① 一上来重写整个 pipeline→慢且易错,要在现成代码上最小改动;② 改动散落多处→ 集中改、好排查。

**⑤ 自救**:不知道在哪改?→ 找到 baseline 代码里"backbone 输出 → head 输入"之间(你的模块多半加在这),或 loss 计算处。

**⑥ 学会了什么**:你学会**在现成代码上最小改动实现自己的 idea**——这是把 idea 快速变实验的工程技巧(复用 > 重写)。

## 中午段 · 启动 toy 实验

**① 概念**:把上午改好的代码正式启动训练。toy 的精髓是"快"——小数据、小模型、几个 epoch,目标是几小时内出个初步结果,所以启动后挂后台、记好命令即可,不用守着。

**⑥ 学会了什么**:你把自己改的 idea 代码正式跑了起来。**做了**(toy 启动+命令归档)、**学了**(toy 挂后台的高效习惯)、**会了**(启动并记录一个可复现的最小实验)。

## 晚上段 · 监控实验

**① 概念(toy 心态,务必端正)**:**不要期望 toy 效果好**——它只验证"方向对不对"。比 baseline 差 5% 以内→正常,继续观察;差 20%→可能方向有问题(或代码 bug),考虑排查/换候选。

## 三、模板 + 代码 — toy 实验脚手架（D61–D62 直接套）

> toy 的精髓是"最小快速"。下面是一个把"在现成代码上最小改动跑 toy"标准化的脚手架：

```python
# toy_runner.py —— 标准化 toy：小数据子集 + 小模型 + 几 epoch + 和 baseline 比
import random
def make_toy_subset(full_list, frac=0.1, seed=0):     # 取 10% 数据做 toy
    random.seed(seed); idx = list(range(len(full_list)))
    random.shuffle(idx); keep = idx[:int(len(idx)*frac)]
    return [full_list[i] for i in keep]

# 你的创新模块——只加这一块，其余复用 baseline 代码
import torch.nn as nn
class MyModule(nn.Module):          # 例：轻量高分辨率小目标分支（占位，按 idea 实现）
    def __init__(self, in_ch):
        super().__init__()
        self.branch = nn.Conv2d(in_ch, in_ch, 3, padding=1)  # 真实实现替换这里
    def forward(self, x):
        return x + self.branch(x)    # 残差式接入，最小侵入

# 信号判断：toy 只看"和 baseline 比有没有正信号"，不看绝对高低
def has_signal(my_metric, base_metric):
    diff = my_metric - base_metric
    tag = "正信号✓" if diff > 0 else ("噪声/持平" if abs(diff) < 0.3 else "负信号✗")
    print(f"my={my_metric:.2f} base={base_metric:.2f} diff={diff:+.2f} → {tag}")
    return diff > 0
# 用法：跑 baseline 和"+MyModule"两版 toy（其余完全一致），比 diff
```
> **代码 bug 自检**（toy 跑出来差先怀疑 bug，不是 idea 死）：在 10 张图上把"baseline+你的模块"过拟合——**能过拟合到接近 100%** 说明代码通、是 toy 设置问题；**过拟合不了**说明模块接错（print 输入输出形状排查）。

## 五、本周常见错误（不是报错，是"找题/做题的思路坑"）

| 常见错误 | 为什么错 | 正确做法 |
|---|---|---|
| 凭灵感等一个"酷 idea" | 多半被做过或不是真问题 | 从 A 级论文 Limitation 系统挖 Gap |
| 只抄现象不写本质 | 不知往哪改 | 每条 Gap 追问"根因是什么" |
| 想到 idea 先兴奋着手做 | 可能撞车白干几个月 | 先查重（中英文+引用网络） |
| 看到"类似"就放弃 | 类似=方向对+有空间 | 记下差异点，类似最稳可做 |
| 把"没人做的大方向"当机会 | 多是巨头赛道/陷阱 | 用"小而硬+单卡可做+有人在乎"筛 |
| idea 成本盲目乐观("应该能跑") | 中途算力卡死 | 诚实估 GPU 时间/数据/代码，对4090诚实 |
| 一个人闷头想、不找人挑刺 | 自我确认偏误看不见漏洞 | 找人当审稿人，越狠越好 |
| toy 跑出来差就否定 idea | 多半是代码 bug 或 toy 设置 | 先 10 图过拟合验证代码，再判方向 |
| toy 搞成大实验（全量+百 epoch） | 失去"最小快速"意义 | 10%数据+小模型+几 epoch |
