# 第一层 · 神经网络凭什么能学会

全书把 `backbone` 解释成"负责从图像提特征"。**但从没说过什么叫"特征"。** 从这里开始。

## 1.1 特征（feature）

**① 一句话**：特征就是**从原始像素里提炼出来的、对当前任务有用的数字**。

**② 打个比方**：让你判断一张图里有没有飞机。你不会去看"第 3721 个像素是不是 R=128"，你看的是"有没有细长的机身""有没有对称的两翼""尾部有没有分叉"。**这些"你实际在看的东西"就是特征。** 原始像素是 3×1024×1024 个数字，特征是从中提炼出的、更抽象也更有用的一小把数字。

**③ 底层在发生什么**：

早期 CV 靠**人工设计**特征——有人坐下来想"边缘怎么算""角点怎么定义"，写出 SIFT、HOG 这类算子。问题是**人想不全**：飞机在遥感图上可以是任意朝向、任意大小、被云挡住一半，手工规则永远漏掉一些情况。

深度学习的做法是**让网络自己学出特征**。你不告诉它"要看机身"，你只给它几万张"这是飞机 / 这不是飞机"的例子，让它自己调整内部参数，直到能分对。**调完之后，网络内部那些中间结果，就是它自己学出来的特征。**

**特征是分层的**，这一点非常重要：

```text
浅层（靠近输入）  → 边缘、颜色块、纹理        ← 通用，任何图像都需要
中层             → 角点、条纹、简单形状
深层（靠近输出）  → 机翼状结构、车顶状结构、整个目标  ← 任务专属
```

**这个分层结构解释了后面很多事**：

- **为什么能用预训练权重**：浅层学的边缘和纹理，在自然照片和遥感图上是通用的。所以拿 ImageNet 上训好的 ResNet 当起点，比从随机数开始快得多。这就是 W1-D1 你下载那个 `.pth` 的意义。
- **为什么小目标难**：深层特征虽然语义强，但**分辨率已经被压得很小**（见 §1.2）。一辆 16 像素的车，到深层可能只剩不到 1 个像素——**信息物理上已经没了**。这直接引出 §2.3 的 FPN。

**④ 在代码里长什么样**：ResNet-50 吃进 `(3, 1024, 1024)`，吐出四个不同尺度的特征图：

```text
C2: (256,  256, 256)   ← 1/4  分辨率，浅层
C3: (512,  128, 128)   ← 1/8
C4: (1024,  64,  64)   ← 1/16
C5: (2048,  32,  32)   ← 1/32 分辨率，深层
```

**读这四行**：往下走，**空间尺寸每层减半（分辨率变粗）、通道数每层翻倍（语义变强）**。这就是"分辨率换语义"的取舍，是整个 CNN 设计的主线。

**⑤ 不懂它会卡在哪**：`backbone`、`neck`、`head`、`FPN`、`多尺度` 这些词全部建立在"特征"之上。不懂特征，W2 读 Oriented R-CNN 时每一段都在雾里。

## 1.2 卷积与感受野（全书出现 16 次和 5 次，从未真正解释）

**① 一句话**：卷积是"用一个小窗口在图上滑动，每滑一步算一次加权和"；感受野是"最终输出里的一个点，实际看到了原图多大一块区域"。

**② 打个比方**：卷积像用一个 3×3 的小印章在图上一格一格盖过去，每盖一次得到一个数。印章里的 9 个权重不是人定的，是**训练学出来的**——学到最后，有的印章专门对横边缘敏感，有的对红色块敏感。

**③ 底层在发生什么**：

一个 3×3 卷积核，输出位置 (i,j) 的值 = 输入上以 (i,j) 为中心的 3×3 区域，和 9 个权重逐个相乘再求和。

**关键性质有三个**：

1. **局部性**：一次只看一小块，不看全图。符合"图像里相邻像素才相关"的直觉。
2. **权重共享**：同一个印章在整张图上滑，参数量极小。这也意味着**它在左上角学会认边缘，右下角自动也会**（平移不变）。
3. **堆叠涨感受野**：这是最关键的。

**感受野怎么涨**：一层 3×3 卷积，输出一个点看到原图 3×3。再叠一层 3×3，这个点看到的是上一层的 3×3，而上一层每个点又看 3×3 —— **等效看到原图 5×5**。再叠一层是 7×7。

```text
1 层 3×3          → 感受野 3×3
2 层 3×3          → 感受野 5×5
3 层 3×3          → 感受野 7×7
加一次下采样(stride 2) → 感受野直接翻倍
```

**④ 为什么你必须懂这个**：

**感受野决定了网络"能不能看见"一个目标。** 如果一座桥在图上跨了 800 像素，而你这一层的感受野只有 200 像素，**这一层物理上不可能理解"这是一座完整的桥"**——它只看得到桥的一小段。

这直接解释了 W2 你会遇到的现象：**`bridge` 这一类的 AP 通常特别低。** 桥又细又长，跨越多个 patch，感受野还不够。**知道原因之后，"怎么增大有效感受野"就成了一个具体的、你能做的研究方向**（空洞卷积、可变形卷积、注意力机制都是冲这个去的）。

**⑤ 想深入去哪看**：斯坦福 CS231n 的卷积那一讲（课程笔记公开，搜 `CS231n convolutional networks notes`），配图是全网最好的。看那一讲就够，不用看整门课。

## 1.3 训练三件套：损失函数 / 梯度下降 / 学习率

全书把 `学习率` 解释成"每步调多大，太大→震荡/NaN"。**对，但没说为什么。** 这三个词必须一起讲才通。

**① 一句话**：损失函数是"打分器"，梯度下降是"改错的方法"，学习率是"每次改多少"。

**② 打个比方**：你在浓雾里下山，看不见山谷在哪，只能感觉脚下的坡度。

- **损失函数** = 你现在的海拔（越低越好）
- **梯度** = 脚下最陡的下坡方向
- **学习率** = 你每一步迈多大

**③ 底层在发生什么**：

网络有几千万个参数。训练就是不停重复这四步：

```text
① 前向：把一批图喂进去，得到预测
② 算损失：预测和真值差多少 → 一个数
③ 反向传播：算出"每个参数该往哪个方向调、调多少能让损失变小" → 梯度
④ 更新：参数 = 参数 − 学习率 × 梯度
```

第 ④ 步那个减法就是**梯度下降**，学习率就是那个乘数。

**④ 学习率为什么是最关键的超参**（回到那个下山的比方）：

| 学习率 | 下山会发生什么 | 训练日志上长什么样 |
|---|---|---|
| 太大 | 一步迈过山谷，弹到对面山坡更高处，越走越高 | **loss 变成 `nan` 或 `inf`** |
| 略大 | 在山谷两侧来回横跳，下不去 | loss 上下震荡，不收敛 |
| 合适 | 稳步下降 | **loss 平滑下降** ← 你要的 |
| 太小 | 一步挪一厘米 | loss 降得极慢，或卡在半山腰 |

**这张表就是你 W2 判断训练健不健康的全部依据。** 现在你知道为什么《W2 实操》里说"盯前 200 个 iter，看到 nan 就把 lr 减半"了。

**⑤ 为什么 lr 要跟着 batch 变（线性缩放规则的真正原因）**：

梯度是在一个 batch 上算平均得到的。**batch 越大，这个平均越稳、噪声越小**，你就敢迈更大的步子。batch 翻倍 → 梯度可信度提高 → lr 也翻倍。这就是 W2 那条规则背后的道理，不是玄学。

**⑥ warmup 是什么**（W2 的 config 里有，原文没解释）：训练最开始参数是随机的，梯度方向极不可靠，这时候迈大步很危险。所以**前几百个 iter 用很小的 lr，然后线性升到设定值**——这就是 warmup。你在 W2 的日志里看到 `lr: 1.978e-03` 而 config 写的是 `0.005`，就是因为还在 warmup 期。

## 1.4 epoch / iteration / batch（全书出现 216 次和 158 次）

**① 一句话**：

- **batch**：一次喂给网络多少张图
- **iteration**：完成一次"前向+反向+更新"，即处理完一个 batch
- **epoch**：训练集完整过一遍

**② 三者的换算**（W2 你会用到）：

```text
iteration/epoch = 训练集图片数 ÷ batch
```

W2 切完的 DOTA 有约 2.16 万张，`samples_per_gpu=2`：

```text
每 epoch = 21600 ÷ 2 = 10800 iterations
12 epoch = 129600 iterations
```

**这就是为什么你在 W2 日志里看到 `Epoch [1][50/10800]`** —— 第 1 个 epoch 的第 50/10800 个 iteration。

**③ 用它来估算训练时间**（原文说"记下启动时间好估算"，但没教怎么估）：

```text
看日志里两条相隔 50 iter 的时间戳 → 得到每 iter 秒数
总时间 = 每iter秒数 × 10800 × 12
```

比如每 iter 0.35 秒：`0.35 × 10800 × 12 ÷ 3600 ≈ 12.6 小时`。**现在你能在训练开始 2 分钟内知道它明早几点跑完。**

**④ `1×` schedule 是什么**：MM 系约定 **1× = 12 epoch，2× = 24，3× = 36**。这不是什么定理，就是 COCO 时代传下来的惯例，方便大家横向对比。

## 1.5 过拟合 / 训练集-验证集-测试集

**① 一句话**：过拟合 = 把训练数据背下来了，但换新数据就不行。

**② 打个比方**：学生把去年的期末试卷答案背得滚瓜烂熟，今年换套题就傻了。**背题 = 过拟合，真会 = 泛化。**

**③ 三个集合各自干嘛**（这个区分在 W2 会直接害你）：

| 集合 | 干什么 | 能不能拿它调参 |
|---|---|---|
| **train** | 更新参数用 | — |
| **val** | 训练中途看效果、选超参、挑最好的 checkpoint | ✅ 可以 |
| **test** | **最终报告数字，只用一次** | ❌ **绝对不能** |

**④ 为什么 test 不能碰**：如果你用 test 挑模型（"这个 epoch 在 test 上高，就用它"），**你已经把 test 的信息泄漏进了选择过程**，报出来的数字就是虚高的。这在学术上是硬性规范。

**⑤ 这直接解释了 W2 的两件事**：

1. DOTA 把 test 标注扣着不公开——**就是为了防止所有人拿 test 调参**，保证榜单公平。
2. 《W2 实操》里说"第一次复现允许 train/val 混着切，但这时的 mAP 偏高、不能写进论文"——因为混着切就是数据泄漏，你在拿见过的数据评自己。

# 第二层 · 目标检测是怎么工作的

**这是全书最大的空白。** W2-D8 直接就让你精读 Oriented R-CNN，但从没讲过检测器长什么样。这一层补齐。

## 2.1 检测任务本身

**① 一句话**：分类是回答"这张图是什么"，检测是回答"**图里有哪些东西，各自在哪**"。

**② 输出长什么样**：

```text
分类的输出：  "飞机"                                （一个标签）
检测的输出：  [(飞机, 0.95, x=120,y=88,w=64,h=40),
              (飞机, 0.87, x=310,y=205,w=58,h=44),
              (车,   0.71, x=52, y=430,w=12,h=9), ...]   （一个列表）
```

**每个框有三样东西**：类别、置信度（0–1，模型有多确定）、位置。

**③ 遥感的特殊之处**：位置在通用 CV 里是**水平框** `(x, y, w, h)`；遥感因为俯视、目标任意朝向，用**旋转框** `(x, y, w, h, θ)`，多一个角度。**这就是 MMRotate 存在的全部理由。**

**④ GT 是什么**（全书 73 次，原文只有 13 个字）：**Ground Truth，真值**，也就是人工标注的正确答案。W2 评测时"预测框 vs GT 框"算 IoU，就是拿你的答案和标准答案对。DOTA 的 `labelTxt/` 里那些 txt 就是 GT。

## 2.2 检测器的三段式结构：backbone / neck / head

**几乎所有现代检测器都是这个结构**，认准它，你以后读任何检测论文都能立刻定位作者改了哪一段。

```text
输入图 →  [backbone 主干]  →  [neck 颈部]  →  [head 头部]  →  框
          提特征             融合多尺度特征      预测类别和位置
          ResNet/Swin        FPN               分类头+回归头
```

| 部件 | 干什么 | 常见选择 | 换掉它意味着什么 |
|---|---|---|---|
| **backbone** | 从像素提特征（§1.1） | ResNet-50/101、Swin、ConvNeXt | 换 = 提特征能力变强/变弱。**W2-D12 的第一个消融就是把 R50 换成 R101** |
| **neck** | 把不同层的特征融合起来 | **FPN**、PAFPN、BiFPN | 换 = 多尺度处理方式变了 |
| **head** | 在特征上输出框 | RPN + RoI head（两阶段）；单个卷积头（一阶段） | 换 = 检测范式变了 |

**★ 现在回头看 W2 的 config，那些字段全部对上了**：

```python
model = dict(
    type='OrientedRCNN',
    backbone=dict(type='ResNet', depth=50, ...),      # ← 第一段
    neck=dict(type='FPN', in_channels=[256,512,1024,2048],
              out_channels=256, num_outs=5),          # ← 第二段
    rpn_head=dict(type='OrientedRPNHead', ...),       # ← 第三段（第一阶段）
    roi_head=dict(type='OrientedStandardRoIHead',...))# ← 第三段（第二阶段）
```

**原文让你"逐行读 config"却没给这张地图。有了它，config 就从天书变成了填空题。**

## 2.3 FPN（全书出现 49 次，从头到尾没有一句解释）

这是全书最离谱的遗漏——FPN 出现了 49 次、写在 W2 每一个 config 里，却从没解释过。

**① 一句话**：FPN（Feature Pyramid Network，特征金字塔网络）**把深层的"语义强但分辨率低"的特征，送回给浅层的"分辨率高但语义弱"的特征，让每一层都既清晰又懂语义。**

**② 为什么需要它**（回到 §1.1 那个矛盾）：

```text
C5 深层：语义强（知道这是飞机）  但  分辨率只有 32×32（小车已经没了）
C2 浅层：分辨率高 256×256（小车还在）但  语义弱（只知道有边缘，不知道是什么）
```

**大目标该用深层检测，小目标该用浅层检测。但浅层不认识东西。** 这就是死结。

**③ FPN 怎么解**：**自顶向下，把深层特征上采样后加到浅层上。**

```text
C5 ─────────────────→ P5   （语义强）
     ↓ 上采样2倍 + 相加
C4 ─────────────────→ P4   （C4的分辨率 + C5的语义）
     ↓ 上采样2倍 + 相加
C3 ─────────────────→ P3
     ↓ 上采样2倍 + 相加
C2 ─────────────────→ P2   （高分辨率 + 语义也强了）
```

**结果**：P2–P5 **每一层都既有分辨率又有语义**。然后按目标大小分配——小目标交给 P2，大目标交给 P5。

**④ 在 config 里长什么样**（`num_outs=5` 是什么意思，原文没说）：

```python
neck=dict(type='FPN',
          in_channels=[256, 512, 1024, 2048],  # 对应 backbone 的 C2~C5
          out_channels=256,                     # 统一成 256 通道
          num_outs=5)                           # 输出 5 层：P2,P3,P4,P5,P6
```

`num_outs=5` 比输入多一层，多的 P6 是在 P5 上再下采样一次，专门检测超大目标。

**⑤ 为什么这对遥感特别重要**：遥感的**尺度悬殊**是核心难题之一（同一张图里有机场和小汽车）。**FPN 就是通用 CV 里对付尺度问题的标准答案**，而遥感把这个问题放大了十倍。**所以"怎么把 FPN 改得更适合遥感的极端尺度分布"，是一个成熟且仍在出论文的方向**——BiFPN、PAFPN、各种遥感专用 neck 都在做这件事。**这是你 M3 找 Gap 时的一个现成候选。**

## 2.4 anchor、正负样本、标签分配

**① anchor 是什么**（原文："预设的一堆候选框，网络在其上微调"——对，但没说为什么）：

**直接让网络凭空回归出框的坐标，太难了**（坐标可以是 0 到 1024 之间任意数）。所以换个思路：**先在图上密密麻麻铺一堆预设框（anchor），让网络只回答两件容易的事**：

1. 这个 anchor 里有没有目标？（分类，二选一）
2. 如果有，真实框相对这个 anchor 该往哪偏一点？（回归，只需微调）

**把"从零画框"变成了"选框 + 微调"，难度大幅下降。** 这就是 anchor 的全部意义。

**② 铺多密**：特征图上**每个位置**铺 k 个不同尺度、不同长宽比的 anchor。P2 是 256×256，光这一层就有 `256×256×k` 个 anchor。全部加起来通常十几万个。

**③ 正负样本分配**（全书出现 1 次，从未解释，但它是现代检测的核心）：

十几万个 anchor，绝大多数是背景。**训练时必须先决定哪些算"正样本"（该学着预测目标）、哪些算"负样本"（该学着预测背景）。** 规则通常是：

```text
与某个 GT 的 IoU ≥ 0.7  → 正样本
与所有 GT 的 IoU < 0.3  → 负样本
在 0.3~0.7 之间          → 忽略，不参与训练
```

**④ 为什么这件事在遥感里特别难**（★ 这是个真正的选题富矿）：

- 遥感目标**极小**，anchor 和小目标的 IoU 天然就低 → **小目标很难被分到正样本 → 学不到 → AP 低**。这就是 W2 你会看到 `small-vehicle` AP 偏低的深层原因之一。
- 遥感目标**任意朝向**，斜框之间的 IoU 计算本身就更复杂，阈值该设多少也不清楚。

**"怎么给旋转的小目标做更好的标签分配"是近几年旋转检测的热点方向之一**（ATSS、DAL、SASM 等工作都在这条线上）。**W2 你读到这些论文时，回来看这一节。**

**⑤ anchor-free 是什么**：干脆不铺预设框，直接让网络预测"这个点到框四条边的距离"。少了一堆超参（anchor 尺度、比例怎么设），但小目标上不一定更好。**两条路线现在并存，没有绝对优劣。**

## 2.5 IoU（原文 71 字，出现 195 次）

**① 一句话**：两个框的**交集面积 ÷ 并集面积**，取值 0–1，衡量它们重合得有多好。

**② 为什么用这个而不是别的**：因为它**对框的大小不敏感**。两个 1000 像素的框差 10 像素，和两个 20 像素的框差 10 像素，绝对误差一样，但显然后者错得离谱。IoU 自动处理了这件事。

**③ ★ 动手 5 分钟，把 IoU 变成直觉**：

```python
def iou(a, b):
    """a, b 格式 [x1, y1, x2, y2]（左上角、右下角）"""
    x1, y1 = max(a[0], b[0]), max(a[1], b[1])     # 交集左上角
    x2, y2 = min(a[2], b[2]), min(a[3], b[3])     # 交集右下角
    inter = max(0, x2 - x1) * max(0, y2 - y1)     # max(0,·) 处理不相交的情况
    union = (a[2]-a[0])*(a[3]-a[1]) + (b[2]-b[0])*(b[3]-b[1]) - inter
    return inter / union

gt = [100, 100, 200, 200]                          # 一个 100×100 的真值框
for pred, name in [([100,100,200,200], '完全重合'),
                   ([110,110,210,210], '每边差 10 像素'),
                   ([150,150,250,250], '偏了半个框'),
                   ([300,300,400,400], '完全没挨着')]:
    print(f'{name:<14} IoU = {iou(gt, pred):.3f}')
```

**输出**：

```text
完全重合           IoU = 1.000
每边差 10 像素      IoU = 0.681
偏了半个框          IoU = 0.143
完全没挨着          IoU = 0.000
```

**★ 盯住第二行**：一个 100×100 的框，每条边只偏 10 像素（看起来几乎重合），**IoU 就掉到 0.68 了**。

**这个数字解释了两件你后面天天遇到的事**：

1. **为什么检测阈值常用 IoU 0.5** —— 0.5 已经是"框得挺准"了，不是"随便挨着"。
2. **为什么小目标那么难** —— 一个 16×16 的小车，只要偏 3 个像素，IoU 就掉到 0.5 以下，直接算漏检。**大目标偏 3 像素毫无影响。** 把上面代码里的框改成 16×16 自己试一次，这个体感非常重要。

**④ 旋转框的 IoU 更麻烦**：两个斜框的交集是个不规则多边形，要用几何算法求。**这就是 mmcv 里那个 `box_iou_rotated` CUDA 算子的作用**——W1-D1 你装 `mmcv-full` 而不是 `mmcv`，就是为了它。**现在你知道那一步在装什么了。**

## 2.6 NMS（原文出现 149 次）

**① 一句话**：同一个目标会被预测出好多个重叠的框，NMS（Non-Maximum Suppression，非极大值抑制）**只留分最高的那个，把和它重叠太多的其他框删掉**。

**② 为什么需要**：§2.4 说了，图上铺了十几万个 anchor。一架飞机周围的十几个 anchor 都会说"我这有飞机"。不去重的话，一架飞机会输出 15 个框。

**③ 算法就三步**（简单到你可以背下来）：

```text
① 所有框按置信度从高到低排序
② 取出当前最高分的框，放进"保留"列表
③ 把剩下的框里，和它 IoU > 阈值的全部删掉
   → 回到 ②，直到没框可取
```

**④ ★ 动手实现（10 行）**：

```python
import numpy as np

def nms(boxes, scores, thr=0.5):
    idx = np.argsort(scores)[::-1]          # 按分数从高到低
    keep = []
    while len(idx):
        i = idx[0]
        keep.append(i)                      # 最高分的一定留
        idx = np.array([j for j in idx[1:] if iou(boxes[i], boxes[j]) <= thr])
    return keep

boxes  = [[100,100,200,200], [105,105,205,205], [110,98,210,198], [400,400,500,500]]
scores = np.array([0.9, 0.85, 0.8, 0.7])
print('保留的框索引:', nms(boxes, scores, thr=0.5))
```

**输出**：`保留的框索引: [0, 3]`

**读这个结果**：前三个框互相高度重叠（都在框同一个目标），**只留了分最高的第 0 个**；第 3 个框在很远的地方，独立保留。**这就是从 4 个框变成 2 个目标的过程。**

**⑤ 阈值怎么调，会怎样**：

| NMS 阈值 | 效果 | 什么时候用 |
|---|---|---|
| 低（0.3） | 删得狠，重复框少，但**挨得近的两个真目标会被误删** | 目标稀疏 |
| 高（0.7） | 保留得多，密集目标不误删，但**重复框变多** | **密集停车场、密集船只 ← 遥感常见** |

**⑥ 为什么这在遥感里是个真问题**：停车场里几十辆车紧挨着，**它们之间的 IoU 天然就高**。阈值设低了会把真车删掉，设高了满屏重复框。**"密集场景下的 NMS"是遥感检测一个具体的、有人在做的小方向**（Soft-NMS、Cluster-NMS 等）。**这是一个门槛低、适合第一篇的口子。**

## 2.7 两阶段 vs 一阶段 / proposal / RoI

**① 两阶段**（Oriented R-CNN、Faster R-CNN 属于这类）：

```text
第一阶段（RPN）：在全图上粗筛，输出约 1000 个"可能有东西"的候选框（proposal）
                 只管有没有，不管是什么
第二阶段（RoI head）：把每个 proposal 对应的特征抠出来，做精细的分类 + 框微调
```

**② 一阶段**（YOLO、RetinaNet 属于这类）：跳过粗筛，**直接在特征图上一次性输出类别和位置**。

**③ 对比**：

| | 两阶段 | 一阶段 |
|---|---|---|
| 精度 | 更高（尤其小目标） | 略低 |
| 速度 | 慢 | 快 |
| 遥感学术界 | **主流，DOTA 榜单基本是它** | 工程部署常用 |

**④ proposal 和 RoI 是什么**：`proposal` = 第一阶段输出的候选框。`RoI`（Region of Interest，感兴趣区域）= 这些候选框在特征图上对应的那块区域。**`RoI Align` 就是"把不规则大小的那块特征，抠出来变成固定大小（如 7×7）"的操作**，因为后面的全连接层要求输入尺寸固定。

**⑤ 现在回看 W2 的 config**，`rpn_head` 和 `roi_head` 两个字段就是这两个阶段。**Oriented R-CNN 那篇论文的全部创新，就在于"怎么让第一阶段高效地产出旋转的 proposal"**——原文说它"创新在高效地生成旋转候选框"，现在你真的懂这句话了。

# 第三层 · 评测：mAP 到底怎么算出来的

原文说 `mAP` "现在记住越高越好即可，D11 评估时细讲"——**但 D11 也没细讲。** 这里补上。

## 3.1 从一个框对不对，到一个数字

**判定单个预测框对不对**：

```text
它和某个同类 GT 框的 IoU ≥ 0.5   →  TP（真阳性，检对了）
IoU < 0.5，或那个 GT 已被更高分的框认领 →  FP（假阳性，虚警）
一个 GT 没有任何框认领           →  FN（漏检）
```

**两个基础指标**：

```text
Precision（精确率）= TP / (TP + FP)   你报出的框里，有多少是对的
Recall   （召回率）= TP / (TP + FN)   该找到的目标里，你找到了多少
```

**② 为什么不能只看一个**：把置信度阈值调到 0.99，你只报最有把握的几个框 → Precision 很高但 Recall 很低。调到 0.01，报出一万个框 → Recall 高但 Precision 惨不忍睹。**单看任何一个都能作弊。**

## 3.2 P-R 曲线与 AP

**③ 所以要看两者的权衡**：把置信度阈值从高到低滑动，每个阈值算一对 (Recall, Precision)，画出来就是 **P-R 曲线**。

**AP（Average Precision）= 这条曲线下的面积。** 面积越大 = 在各种权衡下都表现好。

**④ mAP = 所有类别 AP 的平均**（m = mean）。DOTA 有 15 类，就是 15 个 AP 求平均。

## 3.3 ★ 动手：VOC07 和 VOC12 两种算法差多少

W2 复现时"数字对不上"，第一嫌疑人就是这个。亲手算一次：

```python
import numpy as np

def ap(rec, prec, use07=False):
    if use07:                                    # VOC07：11 点插值
        s = 0
        for t in np.arange(0, 1.01, 0.1):        # 0, 0.1, ..., 1.0 共 11 个点
            p = prec[rec >= t].max() if (rec >= t).any() else 0
            s += p / 11
        return s
    mrec  = np.concatenate([[0], rec,  [1]])     # VOC12：连续积分
    mpre  = np.concatenate([[0], prec, [0]])
    for i in range(len(mpre) - 2, -1, -1):
        mpre[i] = max(mpre[i], mpre[i + 1])      # 让精度曲线单调不增
    idx = np.where(mrec[1:] != mrec[:-1])[0]
    return float(((mrec[idx+1] - mrec[idx]) * mpre[idx+1]).sum())

rec  = np.array([0.10,0.20,0.30,0.40,0.50,0.60,0.70,0.75,0.80,0.82])
prec = np.array([1.00,1.00,0.90,0.85,0.80,0.70,0.60,0.50,0.40,0.30])
print(f'AP (VOC07 11点插值) = {ap(rec, prec, True):.4f}')
print(f'AP (VOC12 连续积分) = {ap(rec, prec, False):.4f}')
```

**输出**：

```text
AP (VOC07 11点插值) = 0.6364
AP (VOC12 连续积分) = 0.6360
```

**这个例子里两者只差 0.04 个点**，但**换一条形状不同的 P-R 曲线，差距可以到 1–2 个点**——足够让你以为复现失败。**在 MMRotate 里这个开关叫 `use_07_metric`，DOTA 传统上用 VOC07。**

> **所以《W2 实操》里那条"复现对不上先查评测协议"不是空话**：同一个模型、同一组预测，换个 AP 算法数字就变。**报告里不写协议的数字是没有意义的。**

## 3.4 per-class AP 怎么读（W2-D11 晚上段的核心动作）

W2 评测会打印一张 15 行的表。**原文让你"分析 per-class AP"，但没说怎么分析。** 按这三步：

**第一步：找最低的 3 类。** 典型是 `small-vehicle`、`bridge`、`roundabout`。

**第二步：对每一类问"为什么低"，答案通常在这张表里**：

| 低分类别 | 大概率原因 | 对应本页哪一节 |

| `small-vehicle`、`ship` | 目标太小，anchor 匹配不上、深层特征已丢失 | §1.1、§2.4、§2.5 |

# 第四层 · 实验方法

## 4.1 config（全书 443 次，原文 73 字）

**① 一句话**：config 是一个 Python 文件，**把"这次实验的所有选择"写在一处**——模型结构、数据路径、训练策略、评测方式，全在里面。

**② 为什么要有它**：如果这些参数散落在代码各处，你改三次就说不清自己跑的到底是什么。**config 的本质是"让实验可复现"**：给别人一个 config + 一个权重，他就能得到和你一样的结果。

**③ 一个 config 分四块，认准这四块你就能读任何 MM 的 config**：

```python
model    = dict(...)   # 模型：backbone / neck / head（§2.2）
data     = dict(...)   # 数据：路径、batch、数据增强流水线
optimizer / lr_config  # 训练：优化器、学习率、schedule（§1.3）
evaluation = dict(...) # 评测：多久评一次、用什么指标（§3）
```

**④ 继承机制**（W2 会用）：`_base_ = [...]` 表示"继承这些基础配置，我只写要改的"。**好处是你的 config 只有十几行，一眼看清你和基线的差异在哪。**

**⑤ 必须养成的纪律**：**永远新建自己的 config 去继承官方的，绝不直接编辑 `configs/` 下的官方文件。** 理由见《W2 实操》§4.1。

## 4.2 消融实验与控制变量（原文 76 字和 77 字）

**① 一句话**：消融实验（ablation study）= **把你方法里的某个部件拿掉，看性能掉多少**，以此证明这个部件真的有用。

**② 打个比方**：一道菜好吃，你说是因为加了某种香料。**证明方式是做一份不加香料的，让人对比。** 这就是消融。

**③ 控制变量是它的前提**：**一次只改一处，其他全部保持不变。**

W2-D12 让你把 ResNet-50 换成 ResNet-101，**这时候你只能改 backbone**。如果你顺手把 lr 也调了、epoch 也加了，那最后涨的那 1.2 个点，**你永远说不清是谁的功劳**——这次实验就废了。

**④ 消融表长什么样**（M3–M4 你会做很多张）：

```text
| 方法                    | mAP   | Δ     |
|-------------------------|-------|-------|
| Baseline                | 73.2  |  —    |
| + 组件 A                 | 74.5  | +1.3  |
| + 组件 B                 | 74.1  | +0.9  |
| + 组件 A + B（完整方法）  | 75.8  | +2.6  |
```

**⑤ ★ 一个新手必踩的坑**：深度学习有随机性，**同一个 config 跑两次，结果可能差 0.3–0.5 个点**。

**所以：涨了 0.3 个点不能算"组件有效"，那可能只是噪声。** 严谨做法是跑 3 个不同随机种子，报均值和标准差。**判断标准**：

```text
提升 < 0.5 点   → 可能是噪声，必须跑多 seed 才敢说
提升 0.5–1 点   → 需要多 seed 支撑
提升 > 1 点     → 比较可信
```

**这条现在就要记住**，否则你 M3 会拿一堆噪声当成果，M6 写论文时被审稿人一句话打回。
