# 第一部分 · W13–W14 方法迭代

## ★ D88 的真问题：三个改进单独都有效，合起来却不涨

原文 D88 说"启动 v2 完整训练（所有有效改进合并）+ 验证不冲突"。**"验证不冲突"这四个字背后是方法迭代最常遇到的情况**，原文没展开。

### 为什么会不叠加

| 原因 | 表现 | 怎么判断 |
|---|---|---|
| **改进解决的是同一个问题** | A 单独 +1.0，B 单独 +0.9，合起来只有 +1.1 | 看 per-class AP：**A 和 B 提升的是不是同一批类别** |
| **改进互相干扰** | 合起来反而低于单个 | 常见于两个都改标签分配 / 都改 NMS |
| **超参不再适配** | 合起来训练不稳定 | loss 曲线抖动明显变大 |
| **只是噪声** | 单独的 +0.9 本来就在噪声范围内 | 回到 [M3 的配对判定](m3-full.html) 重新审 |

### ★ 冲突时的处理顺序（原文没有）

```text
① 先确认单独的提升是真的
   → 用 M3 的 compare() 重新判定 A 和 B 各自的 3-seed 结果
   → 很多"冲突"其实是"两个改进本来就没用"

② 看 per-class：A 和 B 提升的是不是同一批类别
   → 是 → 它们在解决同一个问题，重复了。★ 保留更简单的那个
   → 否 → 继续第 ③ 步

③ 逐对组合，而不是一次全上
   → 跑 A+B、A+C、B+C 三个组合（各 1 seed 先筛）
   → ★ 这一步能定位到底是哪两个在打架

④ 找到打架的那一对，看是不是超参问题
   → 合并后重新小范围搜一下 lr
   → 还是不行，就只保留一个
```

> **★ 一个重要的心态**：**"三个改进只有两个能合并"不是失败，是发现。**
>
> 而且这个发现**本身就是论文素材**——在消融表里如实展示"A+B 有效但 A+B+C 不叠加"，比藏起来更有说服力。**审稿人见得多了，一个所有组件都完美叠加的消融表反而可疑。**

## ★ D94 第三个数据集怎么选（原文没给标准）

加第三个数据集的目的是**证明泛化**。**所以它必须和前两个"足够不同"**，否则加了等于没加。

### 三条选择标准

| 标准 | 说明 | 反例 |
|---|---|---|
| **① 分布要有实质差异** | 传感器 / 分辨率 / 场景 / 类别体系至少差一样 | DOTA-v1.0 和 DOTA-v1.5 —— **几乎是同一批数据，不算** |
| **② 有公认的 baseline 结果可比** | 别人在上面报过数字，你才能证明自己没跑歪 | 冷门数据集没人用过，你的数字没有参照 |
| **③ 规模适中** | 单卡跑得完，别选比前两个大 5 倍的 | |

### 具体怎么搭配（按你的方向）

| 你的方向 | 数据集 1 | 数据集 2 | ★ 数据集 3 该选什么 |
|---|---|---|---|
| 光学旋转检测 | DOTA | DIOR-R | **HRSC2016**（单类船舶、场景差异大）或 **UCAS-AOD** |
| SAR 检测 | SSDD | HRSID | **SAR-Ship-Dataset**（不同传感器/分辨率） |
| 变化检测 | LEVIR-CD | WHU-CD | **SYSU-CD** 或 **S2Looking**（视角/分辨率不同） |
| 语义分割 | LoveDA | Potsdam | **Vaihingen** 或 **iSAID** |

> **★ 一句会被审稿人问到的话**：*"你的方法在三个数据集上都有效"* 只有在这三个数据集**确实不同**时才成立。**如果三个都是同一来源的光学航拍图，那你证明的只是"在这一类数据上有效"** —— 这一点要在论文的 Limitation 里诚实写出来。

## D96 · "确定 v3 是否为最终版本"的判据

原文没给标准。**用这三条**：

```text
① v3 在【三个数据集】上都不输 v2      → 否则不能叫"最终版"
② v3 的复杂度增加是可接受的（参数量/FPS）  → 涨 30% 参数换 +0.3 mAP，不划算
③ v3 的消融是干净的（每个组件都有独立贡献） → 否则应该砍掉没贡献的组件
```

**★ 第 ③ 条最常被忽略**：**做到 v3 时，你的方法可能已经堆了 4-5 个组件。** 如果消融显示其中一个只贡献 +0.1，**砍掉它**——更简洁的方法更容易被接受，也更容易被别人用。

# 第二部分 · ★ W15 的基础设施（全书零字）

## 2.1 用什么排版：LaTeX，不是 Word

| | Word | **LaTeX** |
|---|---|---|
| 公式 | 难写、难改 | ✅ 天生为此设计 |
| 参考文献 | 手工维护，改一处全乱 | ✅ **BibTeX 自动编号和格式化** |
| 图表交叉引用 | 手工，容易错 | ✅ `\ref{}` 自动 |
| 期刊模板 | 少数有 | ✅ **IEEE / Elsevier 都提供官方 LaTeX 模板** |
| 投稿接受度 | 部分接受 | ✅ **几乎所有 CV / 遥感期刊会议都要 LaTeX** |

**★ 你的方向（TGRS / GRSL / CVPR）基本都要 LaTeX。现在就学，不要拖到投稿前。**

## 2.2 用 Overleaf（在线，不用装环境）

**地址**：`overleaf.com`

**为什么用它而不是本地装 TeX Live**：
- 装 TeX Live 要好几 GB 和不少时间，**你现在的时间应该花在研究上**
- Overleaf 自带所有期刊模板
- 云端保存，随时能给导师/朋友看

**免费版够用**（单人写作、有限的协作者数量）。**编译超时的话**，把图片压缩一下通常就够。

## 2.3 模板去哪拿

| 目标期刊/会议 | 去哪拿模板 |
|---|---|
| **IEEE TGRS / GRSL / JSTARS** | Overleaf 首页搜 **"IEEE Transactions"**，或去 **IEEE Author Center** 下载官方 LaTeX 模板包 |
| **CVPR / ICCV / ECCV** | 各会议官网每年发布 `Author Kit`，里面有 `.tex` 模板；Overleaf 也有 |
| **ISPRS J / RSE（Elsevier）** | Overleaf 搜 "Elsevier"，或用 `elsarticle` 文档类 |

**★ 一定要用目标期刊的官方模板**，不要用通用模板凑合——**页数、字号、图表格式都是按模板算的**，换模板会导致超页。

## 2.4 参考文献：Zotero + BibTeX（全书提 Zotero 1 次，0 个说明）

**为什么现在就要建**：你已经读了 30+ 篇论文，**再攒下去手工管理就来不及了**。

```text
① 装 Zotero（zotero.org，免费）+ 浏览器插件
② 在论文页面点插件图标 → 自动抓取题录（作者/标题/期刊/年份/DOI）
③ 建一个分组叫"我的论文-引用"
④ 右键分组 → Export Collection → 格式选 BibTeX → 存成 refs.bib
⑤ 把 refs.bib 传到 Overleaf 项目里
⑥ 正文里 \cite{条目key} 即可
```

**★ 一个能省你大量时间的习惯**：**从今天起，每读一篇论文就顺手用 Zotero 存一次题录**（10 秒）。等到写论文时，`refs.bib` 已经现成了。

**BibTeX 的常见坑**：
- **条目 key 不要用中文或空格**，用 `xie2021oriented` 这种格式
- **从 Google Scholar 复制的 BibTeX 常常缺字段**（缺页码、缺卷号），**以 IEEE Xplore / 出版社官网的为准**
- 会议论文别写成 `@article`，要用 `@inproceedings`

## 2.5 架构图用什么画（D103 让你画，没说工具）

| 工具 | 适合 | 说明 |
|---|---|---|
| **draw.io / diagrams.net** | ★ **推荐**，免费、能导出 PDF/SVG 矢量图 | 学习成本最低 |
| **PowerPoint / Keynote** | 很多人真的用这个 | 能导出 PDF；注意导出时选"矢量" |
| **Inkscape** | 需要精细控制时 | 免费，专业矢量编辑 |
| **TikZ（LaTeX 内置）** | 追求极致一致性 | ★ 学习成本高，**第一篇论文不建议** |

**★ 画架构图的三条规范**：
1. **必须导出矢量格式（PDF / SVG）**，不要 PNG 截图——**放大会糊，审稿人会注意到**
2. **图里的字号，缩到论文栏宽后要和正文字号相当**（约 8pt），不能更小
3. **数据流方向统一**（一般左→右或上→下），箭头不要交叉打结

# 第三部分 · ★ 图表规范（D99 "收集图表素材"缺的标准）

**论文的图是审稿人最先看的东西之一。** 图做得业余，会拉低对整篇工作的印象。下面这套设置我实测跑过，直接可用。

新建 `utils/paper_figs.py`：

```python
"""paper_figs.py —— 出版级图表的统一设置 + 两个常用图。"""
import matplotlib
matplotlib.use('Agg')
import matplotlib.pyplot as plt
import numpy as np


def set_paper_style(col='single'):
    """col='single' 单栏(约3.5in宽) / 'double' 双栏通栏(约7.16in)。

    ★ 关键：字号按"图缩到论文里之后仍能看清"来定，不是按屏幕上好看来定。
    """
    plt.rcParams.update({
        'figure.figsize': (3.5, 2.6) if col == 'single' else (7.16, 3.0),
        'figure.dpi': 150,
        'savefig.dpi': 600,            # 位图导出时用；矢量图无所谓
        'font.size': 8,                # ★ 论文图注常是 8pt，图内字号不应小于它
        'axes.labelsize': 8, 'axes.titlesize': 9,
        'xtick.labelsize': 7, 'ytick.labelsize': 7, 'legend.fontsize': 7,
        'axes.linewidth': 0.8, 'lines.linewidth': 1.2, 'lines.markersize': 3.5,
        'axes.grid': True, 'grid.alpha': 0.3, 'grid.linewidth': 0.5,
        'savefig.bbox': 'tight', 'savefig.pad_inches': 0.02,
        'pdf.fonttype': 42, 'ps.fonttype': 42,   # ★ 字体嵌入为 TrueType，避免出版社报错
    })


# 色盲友好配色（Okabe-Ito），避免纯红绿对比
CB = ['#0072B2', '#D55E00', '#009E73', '#CC79A7', '#E69F00', '#56B4E9']


def ablation_bar(names, means, stds, out='fig_ablation.pdf', ylabel='mAP (%)'):
    """消融柱状图，带误差棒。"""
    set_paper_style('single')
    fig, ax = plt.subplots()
    x = np.arange(len(names))
    ax.bar(x, means, yerr=stds, capsize=2.5, color=CB[:len(names)],
           edgecolor='black', linewidth=0.6)
    ax.set_xticks(x); ax.set_xticklabels(names, rotation=20, ha='right')
    ax.set_ylabel(ylabel)
    lo = min(np.array(means) - np.array(stds)); hi = max(np.array(means) + np.array(stds))
    ax.set_ylim(lo - (hi - lo) * 0.5, hi + (hi - lo) * 0.3)   # ★ 不从0开始要在图注声明
    for xi, m in zip(x, means):
        ax.text(xi, m + max(stds) * 1.3, f'{m:.1f}', ha='center', fontsize=6.5)
    fig.savefig(out); plt.close(fig)
    return out


def seed_curve(steps, series, out='fig_curve.pdf', ylabel='mAP (%)'):
    """多 seed 训练曲线：均值线 + ±std 阴影带。★ 这才是正确的画法。"""
    set_paper_style('single')
    fig, ax = plt.subplots()
    for i, (name, runs) in enumerate(series.items()):
        arr = np.asarray(runs, float)          # (n_seed, n_step)
        m, s = arr.mean(0), arr.std(0, ddof=1)
        ax.plot(steps, m, label=name, color=CB[i])
        ax.fill_between(steps, m - s, m + s, color=CB[i], alpha=0.18, linewidth=0)
    ax.set_xlabel('Epoch'); ax.set_ylabel(ylabel); ax.legend(frameon=False)
    fig.savefig(out); plt.close(fig)
    return out
```

**实测**：生成的是 `%PDF-1.4` 矢量文件、字体已嵌入，约 10 KB。

## ★ 八条图表规范（每条都有具体理由）

| # | 规范 | 为什么 |
|---|---|---|
| 1 | **导出矢量（PDF/SVG）**，不用 PNG | 放大不糊；出版社偏好；文件还更小 |
| 2 | **图内字号 ≥ 7pt**（缩放后） | 缩到单栏 3.5 英寸后，小于这个印出来看不清 |
| 3 | **`pdf.fonttype = 42`** | 字体嵌入为 TrueType，**否则部分出版社系统会报错退回** |
| 4 | **用色盲友好配色**，不用纯红绿对比 | 约 8% 男性有红绿色觉障碍，**IEEE 明确建议** |
| 5 | **不靠颜色单独区分**，配合线型/标记 | 打印成黑白也要能读 |
| 6 | **多 seed 画均值线 + std 阴影带**，不画单条 | 单条曲线不诚实；阴影带一眼看出稳定性 |
| 7 | **y 轴不从 0 开始时，图注必须声明** | 不声明是误导性作图，审稿人会挑 |
| 8 | **表格用三线表**（顶线/表头线/底线，无竖线） | 学术出版惯例；LaTeX 用 `booktabs` 宏包 |

**三线表的 LaTeX 写法**（`\usepackage{booktabs}`）：

```latex
\begin{tabular}{lccc}
\toprule
Method & mAP & Params (M) & FPS \\
\midrule
Baseline      & 73.0 & 41.1 & 15.1 \\
Ours          & \textbf{75.7} & 42.3 & 14.2 \\
\bottomrule
\end{tabular}
```

**★ 表格里的数字规范**：
- **最好的结果加粗**（`\textbf{}`），次好的下划线
- **小数位数统一**（都保留 1 位或都 2 位，不要混）
- **主结果表要报 mean±std**（你 M3 学的），不要只报单次
