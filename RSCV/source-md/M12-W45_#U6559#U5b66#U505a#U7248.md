## 上午段 · 设计作品集 PDF 的 10 页结构

**① 先垫概念（作品集 PDF 的标准结构）**
- **作品集 PDF = 一份图文并茂、集中展示你全部成果的 PDF**（区别于简历的纯文字、PPT 的汇报）。标准 10 页结构：Page 1 封面（姓名 + 方向 + 联系 + 标语）；Page 2 个人简介（300 字）；Page 3–4 论文 1（摘要 + 核心图 + 结果亮点）；Page 5–6 论文 2（同）；Page 7 竞赛成果；Page 8 开源项目（GitHub 截图 + star + Colab）；Page 9 技能 + 学术活动；Page 10 未来规划 + 联系方式。**每页一个亮点**，整体 2 分钟可读完。
- **和简历/PPT 的不同**：简历=纯文字速览（招聘/申请用）；PPT=口头汇报的视觉辅助（你讲）；**作品集 PDF=自带说明的图文展示板（对方自己翻，看图就懂）**。它最直观、最适合作邮件附件（对方点开就被"成果墙"震撼到）。对你这种没有名校光环、没有现成人脉的人，作品集尤其重要：当对方对你一无所知时，一份制作精良、成果扎实的作品集，能在 2 分钟内把"这个人靠谱、能干、有特点"的印象建立起来——它替你完成了"自我证明"这件最难的事。很多有真本事的人吃亏，恰恰是因为不会展示；作品集就是把你的真本事，变成对方一眼能识别的形式。

**② 手把手带做**：设计作品集 10 页结构（见补充包范例 1 逐页骨架）——按标准结构规划每页放什么：封面（标语突出定位）、简介（复用 W43 的 1 页自我介绍）、两篇论文（各 2 页：摘要精简 + 核心架构图 + 结果亮点 + 单卡高效卖点）、竞赛（排名 + 报告截图）、开源（repo 截图 + star + Colab）、技能 + 学术活动（poster/知乎）、未来规划 + 联系；确定每页的"一个亮点"。
**③ 这一步合格的样子**：作品集 10 页结构设计完成，每页明确放什么、突出什么亮点，逻辑顺（你是谁→两篇论文→竞赛→开源→技能→未来）。
**④ 最常踩的坑**
- 每页塞太多（像论文/报告）→ 每页一个亮点、图文并茂、2 分钟可读完。
- 没突出差异化 → 每页（尤其论文页）突出单卡高效/SOTA（你的卖点）。
- 结构混乱无主线 → 按"你是谁→成果→未来"主线，逻辑清晰。

**⑤ 卡住怎么自救（决策树）**：不知每页放什么？→ 按标准 10 页结构（封面/简介/论文×2/竞赛/开源/技能/未来），参考补充包骨架；内容多 10 页放不下？→ 精选最亮的，每页一个核心亮点。
**⑥ 今天（这一步）你同时学会了什么**：你**设计出了作品集 PDF 的 10 页结构**。**做了**（10 页结构 + 每页定亮点 + 主线清晰）、**学了**（作品集是图文展示板、每页一亮点 2 分钟可读、和简历/PPT 不同、突出差异化）、**会了**（把全部成果组织成一份有冲击力的展示结构）。

> **技能卡｜作品集 PDF（10 页·每页一亮点）**：图文并茂的成果展示板（区别于简历纯文字、PPT 汇报辅助）。10 页结构：封面（标语）/简介 300 字/论文 1（摘要+图+亮点）/论文 2/竞赛/开源（截图+star+Colab）/技能+学术活动/未来+联系。每页一个亮点、2 分钟可读完、突出差异化（单卡高效）。用途：邮件附件（对方点开被成果墙震撼）/面试/主页下载。守核心延后（第二篇核心标"接收后开源"）。

- **建议**：若要快速做出好看的，Canva（模板）或 PPT（熟悉）更快；若追求学术精致排版，Beamer。**够用就好，别在选工具上纠结。**

**② 手把手带做**：选一个工具开始制作——① 选模板/设定统一的版式（配色简洁专业、字体统一）；② 按设计好的结构搭页面框架（10 页占位）；③ 开始往里填素材（先填封面 + 简介 + 论文页）；④ 保持每页"一个亮点 + 图文并茂"；今天启动、搭好框架 + 填几页即可（D303 继续做完）。

## 晚上段 · 通读检查（设计一致性、字体统一、配色和谐）

**① 先垫概念**：10 页做完要**整体通读检查设计一致性**——字体是否统一、配色是否和谐、版式是否一致、整体是否专业。**设计的一致性=专业度**：东一个字体西一个配色会显得业余，统一的视觉风格让作品集专业可信。这是 v1 完成前的整体把关。有个朴素的判断：把 10 页缩略图并排放在一起看——如果它们"像一套"（字体、配色、版式一脉相承），就专业；如果看着像东拼西凑的几张图，就业余。专业的视觉一致性会潜移默化地传递"这个人做事认真、有品味"，而这正是你希望老师对你形成的第一印象。

## 二、完整可运行代码 · 年度数据汇总器（生成 Year in Review，+ 预期输出）

> 这个脚本把你这一年的关键数据（论文/star/release/内容/竞赛）汇总成一段格式化的 "Year in Review" 摘要，可直接用于 README、作品集封面/简介、转型博客的成果段。填入真实数字即可。

```python
#!/usr/bin/env python3
# year_in_review.py —— 年度数据汇总器（生成 Year in Review 摘要）
data = {
    "papers":      [("旋转检测(DOTA)", "投稿/arXiv"), ("SAR speckle-aware", "投稿/arXiv")],
    "stars":       70,      # 填真实数
    "forks":       12,
    "clones":      300,
    "releases":    ["v1.0 第一课题", "v2.0 含第二课题框架"],
    "blog_posts":  5,       # 知乎长文数
    "competition": "Top 5%",
    "months":      12,
}

def render(d):
    lines = [f"## 🎉 Year in Review（{d['months']} 个月）\n"]
    lines.append(f"- 📄 论文：{len(d['papers'])} 篇")
    for name, status in d['papers']:
        lines.append(f"    · {name}（{status}）")
    lines.append(f"- ⭐ Stars {d['stars']}+ ｜ 🍴 Forks {d['forks']} ｜ ⬇️ Clones {d['clones']}")
    lines.append(f"- 🚀 Releases：{' → '.join(d['releases'])}")
    lines.append(f"- 📝 技术长文：{d['blog_posts']}+ 篇（综述/方法/观察/教程/转型）")
    lines.append(f"- 🏆 竞赛：{d['competition']}")
    lines.append(f"- 🔭 未来：第三课题（SAR难题/跨域）；第二篇核心接收后开源")
    return "\n".join(lines)

def headline(d):
    # 一句话战绩（作品集封面/简介用）
    return (f"{d['months']} 个月：从零基础到 {len(d['papers'])} 篇论文 + "
            f"开源 {d['stars']}+ stars + 竞赛 {d['competition']}")

if __name__ == "__main__":
    print(render(data))
    print("\n--- 一句话战绩（封面/简介用）---")
    print(headline(data))
```
