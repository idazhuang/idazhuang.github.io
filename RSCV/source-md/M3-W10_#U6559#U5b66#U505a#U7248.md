# D64 周一 · 候选 1 信号定稿 + 启动候选 2

> **预期管理**:本周开头三天(D64–66)是"穷人验证"——三个候选**各跑一天 toy、各出一份信号报告**,用统一格式横向比。今天收口候选 1、启动候选 2。**重点提醒:toy 实验看的是"方向对不对",不是"分数高不高"——涨 0.4% 也是正信号,别因为涨得少就否定一个 idea。**

## 上午段(1.5h)· 候选 1 toy 完成 → 写"信号报告"

**① 先垫概念(穷人验证 + 信号报告是什么)**
- **穷人验证(poor-man's validation)**:没有大算力把每个 idea 都做完整,就用 toy 实验(10% 数据 + 小 backbone + 少 epoch)**低成本给每个候选"测一次脉"**,看有没有"信号"。**这是个人研究者对抗算力劣势的核心策略**——不赌运气、不一上来就 all-in,而是用最小成本快速试错,再把宝贵的 4090 时间压到最有信号的那一个候选上。
- **和通用 CV / 大组对比**:大组可以并行把 5 个 idea 都跑全量实验,挑最好的;你不行,只有一张卡。所以你必须先用 toy 筛掉明显没戏的,集中火力。**这不是将就,而是更聪明的资源分配。**
- **"穷人验证"背后是一种可迁移的稀缺资源思维(对你长期有用)**:你现在用 toy 实验对抗算力劣势,本质是在练一种更普适的能力——**在资源有限的条件下,如何用最小的探测成本,把有限的资源押到最有把握的方向上**。这种思维不只在单卡做实验时有用,它贯穿研究乃至职业生涯:时间有限时,如何先快速判断哪个方向值得投入;精力有限时,如何不在没希望的事上空耗。**大组/大厂的打法是"资源换确定性"(并行全试、挑最好),而你的打法是"用智慧换效率"(小成本探测、精准投入)**——后者要求你更会判断、更会取舍,反而锻炼出更强的"资源调度"能力。等你将来即便有了更多资源,这种"先低成本验证、再加码投入"的习惯,仍会让你比"一上来就 all-in、赌错了血本无归"的人走得更稳。所以别把单卡当纯粹的劣势——它逼你养成的精准试错、资源精算的习惯,是一笔长期财富。
- **信号报告(固定格式,三个候选共用同一张表)**:`候选 | baseline 指标 | toy 指标 | 差值 | 信号判断(正/中/负) | 改进空间分析`。

**② 手把手带做**:候选 1 toy 完成 → 看初步指标 → 写"候选 1 信号报告"(~200 字),套上面格式 + 一句"改进空间"(如"toy 已有 +0.4% 正信号,且只用了 10% 数据和 ResNet-18;全量 + 大 backbone 后预期 +1~2")。

**③ 这一步合格的样子(给你一个填好的示例)**
> | 候选 | baseline(toy) | ours(toy) | 差值 | 信号 | 改进空间 |
> |---|---|---|---|---|---|
> | 候选1: 高分辨率小目标分支 | 62.1 mAP | 62.5 mAP | **+0.4** | **正** | 仅 10% 数据/ResNet-18;全量+大 backbone 预期 +1~2 |
>
> **合格标准**:差值有了、信号判断有了、改进空间一句话。**关键认知**:toy 上 +0.4% 就算"正信号"——toy 看方向不看高低。

**④ 最常踩的坑**
- 把 toy 的"涨幅小"当"idea 不行":toy 用了 1/10 数据和小模型,涨幅天然被压缩,**正值即有信号**。
- 信号报告只写一个数字、不写"改进空间":改进空间是判断"值不值得加码"的关键(同样 +0.4,"还没调过 + 只用小模型"和"已经调到头了"含义完全不同)。

**⑤ 卡住怎么自救(决策树)**
- 候选 1 toy 是负信号? → 先排查是不是 bug:**在 10 张图上能不能过拟合到接近 100%**?能 → 代码通,确实是 idea 在 toy 上没信号;不能 → 是代码/接线 bug,先修。确认无 bug 仍为负 → 如实记"负",今天照常启动候选 2(你有三个候选,不依赖任何单一个)。

**⑥ 今天(这一步)你同时学会了什么**:你学会**写统一格式的信号报告**,并理解了**穷人验证**这套"小成本测脉 + 横向比 + 压资源到有信号者"的打法——这是你整个研究生涯对抗算力劣势的看家本领。**做了**(候选 1 信号报告)、**学了**(穷人验证逻辑、信号报告格式、toy 看方向不看高低)、**会了**(用最小成本给一个 idea 测脉并判断信号)。

> **技能卡｜穷人验证**:算力不足时,用 toy(10%数据+小backbone+少epoch)给每个候选低成本测脉 → 横向比信号 → 把全量算力只压到最有信号的那个。toy 看方向(正/中/负)不看绝对分数。
> **技能卡｜信号报告**:`候选 | baseline | toy | 差值 | 信号(正/中/负) | 改进空间`。三候选必须同一 toy 设置(同数据量/同 backbone/同 epoch/同 baseline)才可横向比。

## 中午段(1h)· 调试 / 小改进

**① 先垫概念**:toy 阶段的"调试"和"小改进"是两件事:**调试**是修明显的错(loss 异常、接线错);**小改进**是在低成本上多试一两下(挪一下模块位置、改一下维度),看能不能让信号更稳/更强。toy 阶段最适合做这种"快速多试"。
**② 手把手带做**:若候选 1 toy 有明显问题(loss 不降/NaN/形状接错),花这一小时修;若正常,做个小改进试试能否把信号变强(如调你模块的插入位置或通道数),记录"改了什么、信号怎么变"。
**③ 合格样例**:要么修好了一个 bug、要么记录了 1–2 次小改进的信号变化。
**④ 坑**:把"调一次没涨"当"idea 不行"——toy 阶段一次微调不代表全部,信号判断看的是"有没有正方向",不是"这次调有没有用"。
**⑤ 自救**:小改进越改越差? → 退回到出正信号的那个配置存好,别越调越乱;toy 阶段以"确认信号存在"为目标,精调留到选定后。
**⑥ 今天(这一步)你同时学会了什么**:你练了"toy 阶段的快速微调"——在小成本上多试,确认信号稳不稳。**做了**(候选 1 调试/小改进)、**学了**(toy 阶段调试 vs 小改进的区别)、**会了**(低成本快速试错并保住有信号的配置)。

## 晚上段(2.5h)· 候选 2 toy 准备 + 启动

**① 先垫概念(控制变量是穷人验证的命门)**:候选 2 的 toy **必须和候选 1 用完全相同的 toy 设置**(同样 10% 数据、同样小 backbone、同样 epoch、同一 baseline)——否则三个候选的信号没法横向比,前面的功夫全废。这就是科学实验的"控制变量":只改"候选的创新模块"这一个变量,其余全部固定。
**② 手把手带做**:在同一套 toy 框架上,把候选 2 的创新模块换进去(**最小改动**,只动该动的)→ 启动 → 记命令到实验日志。
**③ 合格样例**:候选 2 toy 启动,设置与候选 1 逐项一致(数据量/backbone/epoch/baseline)。
**④ 坑(★控制变量)**:候选 2 顺手改了数据量/epoch/baseline → 信号没法和候选 1 比。务必逐项核对 toy 设置一致。
**⑤ 自救**:候选 2 改动比候选 1 大很多(框架不兼容)? → 说明候选 2 和现有框架差异大,**记下"实现成本高"**(这本身是它的一个减分项,D67 三选一要算进去),但仍尽量在统一设置下跑。
**⑥ 今天(这一步)你同时学会了什么**:你学会**在统一 toy 框架上换不同 idea**(保证可比),并体会到"实现成本"也是候选的一个评价维度。**做了**(候选 2 toy 启动)、**学了**(控制变量 = 穷人验证命门)、**会了**(只改创新模块、固定其余,保证横向可比)。

> **今日交付**:✅ 候选 1 信号报告 ✅ 候选 2 toy 启动(设置与候选 1 一致)。

# D65 周二 · 候选 2 toy + 信号报告

> **预期管理**:今天专注候选 2——看结果、必要时调试、出信号报告。流程和候选 1 一模一样,你已经熟了,会比昨天顺。守住"同设置、同 baseline"这条线就行。

## 上午段 · 候选 2 toy(看结果 / 继续训 / 读懂 toy 曲线)

**① 先垫概念(怎么"读"一次 toy 跑、信号要结合机制解读)**
- 候选 2 的 toy 若已跑完就看结果,若没跑完就继续监控。判断"信号"和候选 1 同标准:**看 ours(toy) 相对同一 baseline 的差值方向**(正/中/负),不看绝对分。
- **怎么读 toy 的 loss / mAP 曲线**:10% 数据 + 小 backbone 下,loss 通常下降快但很快进入"小数据过拟合"(train loss 继续降、val 上不去),这是**正常的**——toy 不追求泛化,只看"在同样这点数据/模型下,我的模块相对 baseline 有没有把指标往上推"。**所以你比的是"我的 toy val 指标 vs baseline 的 toy val 指标",两者在同样的过拟合程度下对比**,差值方向才是信号。
- **关键:信号要结合"这个候选的机制"解读**。候选 2 是**跨域特征对齐**——它的收益本质上只在"训练域≠测试域"时才显现。而你的 toy 如果是**单域**(同一数据集切 10%),跨域对齐根本没有用武之地,**信号被压平是预期之中的,不代表 idea 不行**。这种"机制需要特定条件才显效"的候选,toy 要么补一个最小跨域设置(用 A 域 10% 训、B 域少量测),要么就在报告里注明"单域 toy 无法体现其跨域收益"。

**② 手把手带做**:监控候选 2 toy(loss 是否正常下降、train/val 走向);若已出结果,记下"候选 2 vs 同一 baseline"的差值;若候选 2 是"需特定条件才显效"型(如跨域),尽量补一个**最小跨域 toy**(A 域训、B 域测),否则在报告注明局限。
**③ 合格样例**:候选 2 toy 跑完或正常进行中;差值已记录;若机制需跨域,已补最小跨域 toy 或注明"单域 toy 看不出"。
**④ 坑**:① 候选 2 和候选 1 不在同一 baseline 下比 → 不可比,核对 baseline 一致;② 候选 2 在单域 toy 上信号平就判它"死刑"——先想清它的机制需不需要特定条件。
**⑤ 自救**:候选 2 toy loss 不降? → 同昨天:先在 10 张图上验证能否过拟合,区分"idea 没信号"与"代码 bug";若是跨域型且单域信号平 → 补最小跨域 toy 再判。
**⑥ 今天(这一步)你同时学会了什么**:你学会**读懂一次 toy 跑**,并且学会**把信号放回"候选的机制"里解读**——避免误杀那些"需要特定条件才显效"的好 idea。**做了**(候选 2 toy 结果 + 必要时最小跨域 toy)、**学了**(读 toy 曲线、信号结合机制解读)、**会了**(判断一个候选的 toy 信号是否被实验条件压制)。

> **技能卡｜toy 信号解读**:① 比"我的 toy val vs baseline 的 toy val"在同等过拟合程度下的差值方向(不看绝对分)。② **信号必须结合机制**:跨域/小样本/特定场景的 idea,通用单域 toy 可能压平其收益——要么补最小对应设置(如跨域 toy),要么注明"此 toy 看不出"。别用错条件的 toy 误杀好 idea。

## 中午段 · 调试(含"过拟合 10 张图"完整走查)

**① 先垫概念(过拟合自检为什么是 toy 阶段最值钱的一招)**:toy 阶段最怕的不是"没信号",而是"**分不清没信号是 idea 的问题还是代码的 bug**"——后者会让你冤枉一个好 idea。**过拟合 10 张图**就是切开这个二义性的刀:如果你的模型 + 新模块连 10 张图都过拟合不了(loss 降不到接近 0、train 指标上不去),那一定是**代码/接线/学习率**有问题,而不是 idea 不行;能过拟合,代码就是通的,信号问题才归因于 idea/数据。
**② 手把手带做(完整走查)**:
1. 取训练集前 10 张图,做成一个极小 loader(不做随机增强,固定);
2. 关掉正则(weight decay→0、dropout 关),学习率适当调大;
3. 反复训几百个 step,**盯 train loss 是否降到接近 0、train mAP 是否冲到接近 100**;
4. 能 → 代码通,候选 2 的"信号平"是 idea/数据问题(或上午说的机制条件问题);不能 → 按"打印模块输入输出形状 → 查接线 → 查 lr / 初始化"的顺序排 bug。
(可直接用补充包代码 ③ `overfit_check`。)
**③ 合格样例**:完成一次过拟合自检,得到明确结论"代码通 / 代码有 bug",并据此决定下一步。
**④ 坑**:把 bug 导致的"没信号"误判成 idea 不行——**先过拟合自检再下结论**,这是铁律。
**⑤ 自救**:10 张图都过拟合不了又找不到 bug? → 先把"你的新模块"摘掉、只跑 baseline 过拟合:baseline 能过拟合而加了你模块就不能 → 问题在你的模块接线/前向;baseline 也不能 → 问题在更底层(数据/loss/lr)。
**⑥ 今天(这一步)你同时学会了什么**:你掌握了 toy 阶段最值钱的排错招——**过拟合 10 张图切开"idea 问题 vs 代码 bug"**,并学会用"摘模块对比"进一步定位。**做了**(候选 2 过拟合自检 + 必要排错)、**学了**(过拟合自检的完整流程与归因逻辑)、**会了**(用过拟合 + 摘模块对比精确定位问题层)。

## 晚上段 · 候选 2 信号报告(含"中/负信号怎么如实写")

**① 先垫概念(信号不强的候选,报告怎么写才有决策价值)**:用 D64 的统一格式出候选 2 信号报告。此时你手里有两份**同格式、同设置**的报告,能初步横向比。**重点:中/负信号的报告同样要写清楚、写诚实**——决策矩阵需要的是"每个候选的真实信号 + 改进空间",一个写"中"但注明"机制需跨域才显效、单域 toy 看不出"的报告,比硬写成"正"有用得多,因为它让 D67 的决策有据。
**② 手把手带做**:看候选 2 toy 结果 → 写候选 2 信号报告(`候选|baseline|toy|差值|信号|改进空间`);**改进空间列要写清"为什么是这个信号、在什么条件下可能更好"**(如"单域 toy +0.0;其机制针对跨域,需在跨域设置验证,潜在收益未体现");和候选 1 的报告并排,初步感受谁信号更强。
**③ 合格样例**:候选 2 信号报告(与候选 1 同格式、同 toy 设置);中/负信号也写清了原因和潜在条件。
**④ 坑**:① 候选 2 和候选 1 的 toy 不在同一 baseline/数据量下 → 不可比;② 为了"好看"把中/负硬写成正 → 自欺,会让 D67 决策建立在假信号上。
**⑤ 自救**:候选 2 信号是"中/负"? → 如实记录,不慌——三个里只要有一个正信号就够推进;若它是"机制需特定条件"型,在改进空间里写清,留给决策矩阵权衡(它可能创新分高,但信号/可行分低)。
**⑥ 今天(这一步)你同时学会了什么**:你完成第二个候选的"测脉",并学会**如实写中/负信号报告**(写清原因和潜在条件),让弱信号也能为决策提供真实依据。**做了**(候选 2 信号报告)、**学了**(中/负信号的诚实写法)、**会了**(产出第二份对决策有用的可比信号报告)。

> **今日交付**:✅ 候选 2 信号报告(含原因/潜在条件)。

# D66 周三 · 候选 3 toy + 信号报告（穷人验证收口）

> **预期管理**:今天测最后一个候选,然后把三份信号报告汇成一张横向对比表——穷人验证收口。明天就靠这张表 + 决策矩阵拍板。**守住"三个候选同 toy 设置"这条命门到最后一刻。**

## 上午段 · 候选 3 toy(在统一框架上跑第三个候选)

**① 先垫概念**:这是穷人验证的最后一个候选。**toy 设置必须和候选 1/2 完全一致**(同样 10% 数据、同样小 backbone、同样 epoch、同一 baseline),否则三份信号没法横向比——这是穷人验证的命门。把三个候选放进同一套"测脉"流程,你才能拿到可以并排比较的信号,明天的三选一才有客观依据;任何一处设置不一致,都会让横向对比失真、让决策失去依据。所以哪怕再赶时间,这一条纪律也不能松。
**② 手把手带做**:在同一套 toy 框架上,把候选 3 的创新模块换进去(最小改动)→ 启动训练 → 记命令。
**③ 合格样例**:候选 3 toy 启动,设置与候选 1/2 一致(可比)。
**④ 常踩的坑**:候选 3 顺手改了数据量/epoch/baseline → 三份信号不可比,前功尽弃。
**⑤ 卡住自救**:候选 3 改动比前两个大很多(框架不兼容) → 记下"实现成本高"(这本身是它的减分项,明天三选一要算进去)。
**⑥ 今天(这一步)你同时学会了什么**:你坚持了"统一 toy 设置"的可比性纪律到最后一个候选。**做了**(候选 3 toy 启动)、**学了**(可比性 = 穷人验证命门)、**会了**(在统一框架上换不同 idea 并保持设置一致)。

## 中午段 · 调试 / 监控候选 3 toy

**① 先垫概念**:toy 阶段的快速排错——loss 是否正常下降(用 M1 的三曲线诊断:train/val loss 走向)、有没有接错(打印你的模块输入输出形状)。
**② 手把手带做**:监控候选 3 toy 的 loss;若异常(不降/NaN),花这段时间排查(先在 10 张图上过拟合验证代码通不通)。
**③ 合格样例**:候选 3 toy 正常训练、loss 在降(结果晚上看)。
**④ 常踩的坑**:一出问题就以为"候选 3 这个 idea 不行" → 先排除是 bug(在小数据上能过拟合 = 代码通)。

**⑥ 今天(这一步)你同时学会了什么**:你又练了一次"区分 idea 不行 vs 代码有 bug"的判断。**做了**(候选 3 调试/监控)、**学了**(toy 排错的快速手段)、**会了**(用过拟合小数据法定位代码问题)。

## 晚上段 · 候选 3 信号报告 + 穷人验证收口

**① 先垫概念**:出第三份信号报告(同 D64 的统一格式),至此**三份信号报告齐全**,可一张表横向比——这是明天(D67)三选一的依据。这一整轮就是完整的"**穷人验证**":用最小成本给多个 idea 测脉、再把资源压到有信号者。

# D67 周四 · 三选一,锁定最终课题(锁定后不再动摇)

> **预期管理**:三个候选都测过脉了,今天**拍板**。这不是凭兴趣一拍,而是用三份信号报告 + 决策矩阵做有据可依的决定。**重点心态:决定之后就不再回头想"选另一个会不会更好"——选题的好坏不在选了什么,而在做得多深。**

## 上午段(1.5h)· 三选一决策(决策矩阵)

**① 先垫概念(决策矩阵是什么、为什么不能凭感觉选)**
- **决策矩阵** = 把"凭感觉选"变成"按维度 + 权重 + 证据打分比较"。维度和权重:`创新性×3 + 可行性×3 + 信号强度×2 + 空天院匹配×2 + 9 月内完成×2`(各项 1–5 分,乘权重求和)。
- **为什么可行性/信号权重要够高(都给到 ×3/×2)**:你是单卡、9 个月要出成果的个人研究者。**一个 70 分但有信号、单卡能做完的 idea,远胜一个 90 分但你做不出来的**。所以矩阵里"可行性""信号强度""9 月内完成"的权重必须压得住"创新性",否则你会被一个炫但做不出的题拖死。
- **★ "选对题"比"努力做"更决定成败(个人研究者最该想清的一件事)**:这是整个转型计划里最关键的战略判断之一,值得你停下来想透。很多人(尤其聪明、有追求的人)在选题时被"创新性/听起来高大上"吸引,选了一个很炫但超出自己条件的题——结果是:数据拿不到、算力不够、难度太大,几个月卡死,最后无果而终。**对你这种单卡、无导师支持、要在有限时间内做出成果的处境,"选一个做得出来的题"远比"选一个最炫的题"重要**。原因很现实:① 一篇"小而硬、做完了、有扎实结果"的论文,价值无穷大于一个"很炫但烂尾、什么都没产出"的方向——前者是你的成果、是你对接空天院的筹码,后者是浪费的几个月;② 做得出来的题能让你建立正反馈(完成→信心→继续),做不出的题会持续打击你、甚至让你怀疑转型本身(这是可持续性的大敌);③ 你的差异化优势本来就不在"拼最难最大",而在"把一个具体问题做扎实、做高效"。**所以这张决策矩阵把可行性/信号压过创新性,不是降低标准,而是符合你处境的、最理性的战略**。记住:对个人研究者,真正的失败不是"题不够炫",而是"题做不出来、颗粒无收"——选一个你能把它做完、做好的题,就是成功的一半。

**② 手把手带做**:建表,三候选逐项打分、算加权总分、选定。
> 示例:
> | 候选 | 创新×3 | 可行×3 | 信号×2 | 匹配×2 | 9月内×2 | 总分 |
> |---|---|---|---|---|---|---|
> | 候选1:高分辨率小目标分支 | 4(12) | 5(15) | 4(8) | 4(8) | 5(10) | **53** |
> | 候选2:跨域特征对齐 | 5(15) | 3(9) | 2(4) | 3(6) | 3(6) | 40 |
> | 候选3:轻量化+LoRA 适配 | 3(9) | 4(12) | 3(6) | 5(10) | 4(8) | 45 |
>
> → 选候选 1(53 分:可行性高、有信号、9 月内能做完)。

**③ 这一步合格的样子**:一张三候选评分表 + 明确当选项 + 每项打分有一句依据(不是拍脑袋给分)。

**④ 最常踩的坑(★战略校准)**:让"创新性"压倒"可行性/信号"——这是个人研究者最容易犯的致命错。**可行性和信号权重要够**,宁可选"小而硬、做得出、有信号"的。

**⑤ 卡住怎么自救(决策树)**:两个候选总分接近? → ① 看"哪个 toy 信号更强"(信号是最硬的证据);② 看"哪个你更想做、做起来最不觉得累"(9 个月的事,内驱力重要);仍难定 → 选可行性/信号更高的(做得出来比更炫重要)。
**⑥ 今天(这一步)你同时学会了什么**:你学会**用决策矩阵 + 信号证据做选题终决**——把"凭感觉选"变成"按维度 + 证据比"。**做了**(三候选评分表 + 当选项)、**学了**(决策矩阵、可行性/信号权重的战略意义)、**会了**(用加权打分 + 证据做重大决策)。

## 中午段(1h)· 写《最终选题决策书》(≥800 字)

**① 先垫概念(为什么要把决策写成文档)**:把决策写成《选题决策书》——选了什么、为什么选、为什么不选另两个。它既是给自己的"承诺书"(防止日后反复动摇),也是未来跟老师沟通、写阶段总结的现成素材。

**④ 坑**:决策书写得含糊("感觉候选 1 比较好")→ 要有具体依据(信号 +0.4、可行性 5 分、9 个月能做完)。
**⑤ 自救**:不选另两个的理由写不出? → 直接对照评分表:它们输在哪一项(候选 2 输在信号弱、候选 3 输在创新略低),把那项展开成一段。
**⑥ 今天(这一步)你同时学会了什么**:你学会**把重大决策写成有据可依的决策书**——这是负责任决策的体现,也避免日后反复动摇。**做了**(选题决策书 ≥800 字)、**学了**(决策书的结构)、**会了**(把"为什么选/为什么不选"论证成文)。

**③ 合格样例**:战略卡上有"课题锁定"声明;另两候选已存档。
**④ 坑(★心态)**:锁定后还反复刷"另一个会不会更好"→ 这是选择焦虑,会拖垮执行。锁定 = 承诺。
**⑤ 自救**:锁定后突然对选定课题不安? → 看你的决策书理由还成不成立;若只是"畏难"而非"理由失效",就继续(**区分"畏难"和"真不行"**:畏难是正常的,理由失效才需要重新考虑)。
**⑥ 今天(这一步)你同时学会了什么**:你用决策矩阵 + 证据做出了**有据可依的选题终决**,并立下"选定即深耕、不反复"的纪律——这是把精力从"选择焦虑"转向"产出"的关键开关。**做了**(评分表 + 选题决策书 + 锁定声明)、**学了**(决策矩阵、"做得深胜过选得好")、**会了**(用证据拍板 + 决策后承诺不反复)。

## 上午段(1.5h)· Section 1 Title + Section 2 Motivation(≥600 字)

**① 先垫概念(Motivation 怎么写、它是整篇的立论)**:Motivation 回答三件事——**① 这个问题为什么重要?② 现有方法有什么不足(你的 Gap)?③ 你要怎么解决(一句话)?** 它就是把你 W9 的 Gap 分析"成文",是论文 Introduction 的核心、整篇的"立论"。**和写课程作业的区别**:作业是"介绍一个已知话题",Motivation 是"论证一个值得解决的新问题"——重心在"为什么值得做",不在"科普背景"。

**② 手把手带做(给你可填的模板)**:

- **Motivation(≥600 字,三段)**,套这个骨架填:
  > 段1(重要性):"{任务}在{应用场景:城市监测/灾害评估}中至关重要。然而,遥感图像具有{独特挑战:小目标/尺度悬殊/方向任意},使其比通用 CV 更难。"

  > 段3(你的思路):"为此,本文提出 {一句话方法},借鉴 {通用 CV 解法},以 {预期} 解决上述问题。"

**③ 合格样例**:Motivation ≥600 字,读完一个不懂你课题的人能明白"为什么这事值得做、你要补哪个口子、你大概怎么做"。

**④ 坑**:Motivation 写成泛泛背景(整段讲"遥感很重要")→ 背景 3–4 句即可,**快速收敛到你具体要解决的那个 Gap**。

**⑤ 自救**:写不出段 2 的"根本原因"? → 回 W9 Gap 表的"本质"列,那就是根因。
**⑥ 今天(这一步)你同时学会了什么**:你学会写 **Motivation**(重要性→Gap→思路 三段)——论文 Introduction 的核心。**做了**(Title + Motivation ≥600 字)、**学了**(Motivation 三段法)、**会了**(把 Gap 分析写成论文式立论)。

> **技能卡｜Motivation 三段**:① 任务为何重要 + 遥感独特挑战 → ② 现有方法的不足(你的 Gap)+ 根本原因 → ③ 你的思路(一句话)。背景 3–4 句快速收敛到 Gap,重心在"为什么值得做"。

## 中午段(1h)· 画 teaser figure 草图

**① 先垫概念**:**teaser figure**(论文第一页大图)要一眼展示你的方法/优势——审稿人常常先看图再决定读不读。常见构图:左=问题(baseline 失败案例),右=你的方法(成功);或中间放方法概览 + 一个"我们更快/更准"的小图。
**② 手把手带做**:草拟 teaser:画出"baseline 在你针对的 Gap 上失败 vs 你的方法成功"的对比示意(此时是草图,最终版后面画);若卖点是"高效",可加一个"精度 vs FPS"散点示意你在右上角。
**③ 合格样例**:一张能表达"我解决了什么、效果如何/多高效"的 teaser 草图。
**④ 坑**:teaser 画得太满、信息过载——一张图传达一个核心卖点即可,别塞满细节。
**⑤ 自救**:不知道画什么? → 就画"你的 Gap 上,baseline 错 / 你对"的一组对比图,这是最直接的 teaser。
**⑥ 今天(这一步)你同时学会了什么**:你建立了 **teaser figure 意识**——论文第一印象的关键图。**做了**(teaser 草图)、**学了**(teaser 的构图逻辑)、**会了**(用一张图传达核心卖点)。

## 晚上段(2.5h)· Section 3 Related Work(≥800 字)

**① 先垫概念(Related Work 不是流水账)**:Related Work **不是"A 做了…B 做了…"的罗列**,而是**分类总结**:把前人工作分 2–3 个子方向,每类"先讲共同思路 → 列代表作 → 指出不足(引向你的 Gap)"。用你 W8 的技术演进图谱当骨架,它天然就是分好类的。

- 最后一段做过渡:"综上,现有方法普遍 {共性局限},而这正是本文要解决的。"

**③ 合格样例**:Related Work ≥800 字,分类清晰,每个子节末尾都自然引向"还缺 X"。
**④ 坑**:堆砌"A 做了…B 做了…"不归类、不点不足 → 读者看不出你和前人的关系,也看不出你的 Gap。
**⑤ 自救**:不知怎么分子方向? → 用你 W8 的"流派/家族"划分(如旋转检测的"角度表示派/特征对齐派/label assignment 派")。
**⑥ 今天(这一步)你同时学会了什么**:你写出了 Proposal 的前三节,掌握了 **Motivation 三段法**和 **Related Work 分类总结法**——直接对应论文的 Intro 和 RW。**做了**(Proposal 前 3 节)、**学了**(RW 分类总结法)、**会了**(把文献综合成论文式的背景并引向 Gap)。

## 上午段 · Section 4 Proposed Method(≥1200 字)

**① 先垫概念(Method 怎么写、核心原则)**:核心原则——**让一个不认识你的人读完也能实现你的方法**。用"**总分**"结构:先 Overview(全局架构图),再逐个讲核心组件。**每个组件三件套**:① 直觉解释(为什么用它、治哪条 Gap)② 公式(严谨定义,定义清所有符号)③ 图示。再加训练策略 + Algorithm 1 伪代码。**和"我用了 attention"式写法的区别**:后者无法复现、也看不出价值;前者让别人看懂"你为什么这么设计、怎么接、解决了什么"。
**② 手把手带做(骨架)**:写 ≥1200 字:
1. **Overview**:一段话 + 架构图引用,讲清数据怎么从输入流到输出、你的新模块在哪。
2. **核心组件 1**:① 直觉(为什么用,治哪条 Gap)② 公式(定义清所有符号)③ 图示。
3. **核心组件 2**:同上三件套。
4. **训练策略 / 损失函数**。
5. **Algorithm 1 伪代码**(≤20 行,训练/推理流程)。

**③ 合格样例**:Method ≥1200 字,**每个组件都有"为什么用它"的直觉(不只公式)**;一个懂通用 CV 的人读完能复现。
**④ 坑**:① 只写"我用了 attention"不解释为什么、怎么接、治哪条 Gap → 无法复现也看不出价值;② 组件堆砌不说动机。
**⑤ 自救**:公式写不出? → 先用文字 + 伪代码精确描述,公式后补;组件直觉说不清? → 回到"它治哪条 Gap、借鉴哪个通用 CV 解法"。
**⑥ 今天(这一步)你同时学会了什么**:你学会写 **Method**(总分结构 + 组件三件套 + 伪代码)——论文最硬核一章的写法。**做了**(Method ≥1200 字)、**学了**(总分结构、组件三件套、伪代码)、**会了**(把方法写到"别人能复现"的程度)。

# ===== ① 三份信号报告汇总成横向对比表（纯 Python，可直接跑）=====
def signal_table(cands):
    print(f"{'候选':<26}{'base':<7}{'ours':<7}{'差值':<8}{'信号':<6}")
    print("-" * 54)
    for c in cands:
        diff = c["ours"] - c["base"]
        sig = "正" if diff > 0.05 else ("负" if diff < -0.05 else "中")
        print(f"{c['name']:<26}{c['base']:<7}{c['ours']:<7}{diff:+.2f}    {sig:<6}")

# ===== ② 决策矩阵加权评分（权重可调；返回排序结果）=====
def decide(cands, weights):
    # weights 例：{"创新":3,"可行":3,"信号":2,"匹配":2,"9月内":2}
    scored = []
    for c in cands:
        total = sum(c["scores"][k] * w for k, w in weights.items())
        scored.append((c["name"], total))
    scored.sort(key=lambda x: -x[1])
    for i, (n, t) in enumerate(scored):
        print(f"{'★' if i==0 else ' '} {n:<26} 总分 {t}")
    return scored

#       若怎么训都不降 → 是代码/接线 bug，不是 idea 不行。
def overfit_check(train_one_epoch_fn, tiny_loader, model, optimizer, steps=200):
    model.train()
    last = None
    for i in range(steps):
        loss = train_one_epoch_fn(model, tiny_loader, optimizer)  # 返回标量 loss
        last = loss
        if i % 50 == 0:
            print(f"step {i:>3}  loss={loss:.4f}")
    ok = last is not None and last < 0.05
    print("→ " + ("✅ 能过拟合：代码通，信号问题归因于 idea/数据" if ok
                  else "⚠️ 无法过拟合：先查代码/接线/学习率，不是 idea 不行"))
    return ok

## 五、本周报错速查表（现象 → 根因 → 解法）
| 现象 | 根因 | 解法 |
|---|---|---|
| toy 涨幅小就否定 idea | 误把"绝对分低"当"方向错" | toy 看方向不看高低,正值即正信号 |
| 三份信号报告没法横向比 | toy 设置不一致(数据量/baseline/epoch) | 三候选严格同一 toy 设置,只改创新模块 |
| toy loss 不降 | 不确定是 idea 还是 bug | 在 10 张图上过拟合:能降=代码通,不能=查代码/接线/lr |
| 选题反复动摇 | 锁定后还刷"另一个更好" | 锁定=承诺;区分"畏难"(继续)与"理由失效"(才重议) |
| Motivation 写成科普背景 | 没收敛到 Gap | 背景 3–4 句,快速收敛到你要补的那个具体 Gap |
| Related Work 像流水账 | 只罗列不归类不点不足 | 分 2–3 子方向,每类共同思路+代表作+不足→引向 Gap |
| Method 别人看不懂/复现不了 | 只写"用了 X"不说为什么怎么接 | 总分结构 + 组件三件套(直觉/公式/图) + 伪代码 |
| Experiment Plan 后面返工 | baseline 漏公认基准/消融<5/无 timeline | 五要素齐全,每个组件配一个消融,timeline 到周 |
| Risks 回避算力 | 不愿写单卡现实 | 诚实写"算力有限→LoRA/小模型/单卡设计",反显清醒 |
