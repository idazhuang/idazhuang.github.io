# 1. 本周你要装的第三套框架

## ① 先垫概念：这次和前两次有什么不同

你已经装过 MMRotate（W1）和用过裸 PyTorch（W3）。**这周会同时碰到三种代码组织方式**，先分清：

| 代码 | 框架基础 | 特点 | 本周在哪用 |
|---|---|---|---|
| **BIT / ChangeFormer** | **裸 PyTorch**（各自独立的仓库） | 轻量、单文件脚本、自己写训练循环 | D29、D31 变化检测 |

> **判断方法（30 秒）**：
> ```text
> 有 configs/ + tools/train.py          → MM 系
> 有 pytorch_lightning 的 import        → Lightning

> ```

# 2. ★ D32 的问题：UNetFormer 不在 MMSegmentation 里

原文写的是："**跑 UNetFormer baseline（LoveDA，体验 MMSegmentation）**"。

**这一句把两件不兼容的事拼在了一起：**

- **UNetFormer** 的官方实现在 **GeoSeg**（`github.com/WangLibo1995/GeoSeg`），基于 **PyTorch Lightning + timm**。
- **MMSegmentation** 里**没有** UNetFormer。

**照原文做，你会在 MMSegmentation 的 configs 里翻半天找不到 UNetFormer，然后不知道自己错在哪。**

## ★ 两条路，先想清楚你今天要什么

| | 路线 A：跑 UNetFormer 本体 | 路线 B：体验 MMSegmentation |
|---|---|---|
| 用什么 | **GeoSeg**（PyTorch Lightning） | **MMSegmentation** |
| 和你上午读的论文对得上吗 | ✅ 就是那篇 | ❌ 换成别的模型 |
| 复用你 W1 学的 config 技能吗 | ❌ 又是一套新约定 | ✅ 完全复用 |
| 参考成绩 | UNetFormer 在 LoveDA 上 **52.4% mIoU** | 看你选的模型 |

**★ 我的建议：走路线 B，用 MMSegmentation 内置模型在 LoveDA 上跑。**

理由：**今天的教学目的是"体验语义分割这个任务、拿到第一个 mIoU"，不是"复现 UNetFormer 这一篇"。** 用 MMSegmentation 能复用你已有的 config 技能，40 分钟就能出结果，而学 GeoSeg 那套 Lightning 约定要额外花两三小时——**这两三小时这周不值当**。

**如果你就是想跑 UNetFormer**（比如你打算做分割方向），**把它挪到 W5 之后的机动时间**，别占用 D32。

## 路线 B 的具体做法

MMSegmentation 0.x **内置支持 LoveDA 数据集**，configs 里有现成的配置。


# 4. ★ 亲手实现 F1 和 mIoU（原文只讲不做）

原文把"为什么用 F1 不用准确率"讲清楚了。**但有一件事它只在"卡住自救"里提了半句、没展开**：

> "是否用了**变化检测专门的 F1 计算**（只在'变化'类上算，不是两类平均）"

**这两种算法差多少？** 下面这段代码回答它。**我实测跑过。**

新建 `20-代码实验/utils/metrics.py`：

```python
"""metrics.py —— 亲手实现 F1 / IoU / mIoU，看清指标在算什么。"""
import numpy as np


def confusion(pred, gt, num_classes, ignore_index=None):
    """混淆矩阵。行 = 真值类别，列 = 预测类别。"""
    pred, gt = np.asarray(pred).ravel(), np.asarray(gt).ravel()
    if ignore_index is not None:
        m = gt != ignore_index
        pred, gt = pred[m], gt[m]
    k = (gt >= 0) & (gt < num_classes)
    return np.bincount(num_classes * gt[k].astype(int) + pred[k],
                       minlength=num_classes ** 2).reshape(num_classes, num_classes)


def binary_prf(pred, gt, positive=1):
    """二分类的 P / R / F1 / IoU —— 变化检测用这个。"""
    tp = int(((pred == positive) & (gt == positive)).sum())
    fp = int(((pred == positive) & (gt != positive)).sum())
    fn = int(((pred != positive) & (gt == positive)).sum())
    p = tp / (tp + fp) if tp + fp else 0.0
    r = tp / (tp + fn) if tp + fn else 0.0
    f1 = 2 * p * r / (p + r) if p + r else 0.0
    iou = tp / (tp + fp + fn) if tp + fp + fn else 0.0
    return dict(P=p, R=r, F1=f1, IoU=iou, TP=tp, FP=fp, FN=fn)


def miou(cm):
    """从混淆矩阵算逐类 IoU 和 mIoU。"""
    inter = np.diag(cm).astype(float)
    union = cm.sum(1) + cm.sum(0) - np.diag(cm)
    iou = np.divide(inter, union, out=np.full_like(inter, np.nan), where=union > 0)
    return iou, float(np.nanmean(iou))


if __name__ == '__main__':
    rng = np.random.default_rng(0)

    # ---- 场景1：极不平衡的变化检测，验证"准确率会骗人" ----
    gt = np.zeros(10000, int); gt[:200] = 1            # 只有 2% 是变化
    lazy = np.zeros(10000, int)                        # 全猜"没变"的废物模型
    print('【全猜没变的废物模型】')
    print('  准确率 =', (lazy == gt).mean())
    print('  ', binary_prf(lazy, gt))

    real = gt.copy()
    fn_idx = rng.choice(np.where(gt == 1)[0], 40, replace=False); real[fn_idx] = 0   # 漏检 40
    fp_idx = rng.choice(np.where(gt == 0)[0], 30, replace=False); real[fp_idx] = 1   # 误检 30
    print('【一个真的在干活的模型】')
    print('  准确率 =', (real == gt).mean())
    print('  ', {k: (round(v, 4) if isinstance(v, float) else v)
                 for k, v in binary_prf(real, gt).items()})

    # ---- 场景2：★ F1 只在变化类算 vs 两类平均，差多少 ----
    r  = binary_prf(real, gt, positive=1)
    r0 = binary_prf(1 - real, 1 - gt, positive=1)      # 把"不变"当正类再算一次
    print('\n【F1 的两种算法】')
    print(f'  只算变化类 F1 = {r["F1"]:.4f}   ← 变化检测论文报的是这个')
    print(f'  两类平均  F1 = {(r["F1"] + r0["F1"]) / 2:.4f}   ← 算错会虚高一大截')

    # ---- 场景3：mIoU 与 ignore_index ----
    g = rng.integers(0, 8, (64, 64)); p = g.copy()
    mask = rng.random(g.shape) < 0.25                   # 25% 的像素预测错
    p[mask] = rng.integers(0, 8, int(mask.sum()))
    g[:8, :] = 0                                        # LoveDA: 0 = ignore（无标注区）
    print('\n【mIoU 与 ignore】')
    print(f'  不排除 ignore 类: mIoU = {miou(confusion(p, g, 8))[1]:.4f}')
    print(f'  排除 ignore 类  : mIoU = {miou(confusion(p, g, 8, ignore_index=0))[1]:.4f}'
          f'   ← LoveDA 官方口径')
```

## ③ 合格样例 —— 实测输出

```text
【全猜没变的废物模型】
  准确率 = 0.98
   {'P': 0.0, 'R': 0.0, 'F1': 0.0, 'IoU': 0.0, 'TP': 0, 'FP': 0, 'FN': 200}
【一个真的在干活的模型】
  准确率 = 0.993
   {'P': 0.8421, 'R': 0.8, 'F1': 0.8205, 'IoU': 0.6957, 'TP': 160, 'FP': 30, 'FN': 40}

【F1 的两种算法】
  只算变化类 F1 = 0.8205   ← 变化检测论文报的是这个
  两类平均  F1 = 0.9085   ← 算错会虚高一大截

【mIoU 与 ignore】
  不排除 ignore 类: mIoU = 0.5483
  排除 ignore 类  : mIoU = 0.5752   ← LoveDA 官方口径
```

## ★ 从这三组数字读出四件事

1. **准确率 98% 的废物模型，F1 = 0。** 原文举了这个例子，现在你亲手算出来了。
2. **真正干活的模型准确率只高了 1.3 个点（98% → 99.3%），F1 却从 0 到 0.82。** ——**准确率在不平衡任务里几乎没有分辨力**。
3. **★ F1 的两种算法差 8.8 个点（0.8205 vs 0.9085）。** 如果你误用了"两类平均"，会以为自己的模型比论文强很多，**实际是算法用错了**。BIT 在 LEVIR-CD 上报的 ~89–91% 是"只算变化类"的口径。
4. **ignore 类排不排除，mIoU 差 2.7 个点。** LoveDA 必须排除。

> **★ 这就是 [W2-D13 那条纪律](w2-d10-d14-full.html)的第二次应用**：**任何你要用的度量，先用手算案例对拍一遍。** 指标算错不会报错，只会给你一个错误的自我认知——**而且会一路错到论文里**。

```markdown
# 变化检测 vs 语义分割 vs 目标检测

## 一、任务定义
| | 目标检测 | 语义分割 | 变化检测 |
|---|---|---|---|
| 输入 | 单张图 | 单张图 | **同一地点两个时相** |
| 输出 | 框 + 类别 | 每像素一个类别 | 变化掩膜（变/没变） |
| 本质 | 定位 + 分类 | 逐像素分类 | **双时相对比** |

## 二、数据与标注
| | 检测 | 分割 | 变化检测 |
|---|---|---|---|
| 标注形式 | 四点/五参数框 | 逐像素 mask | 逐像素二值 mask |
| 标注成本 | 中 | **高** | 高（还要配准两个时相） |
| 遥感特有的坑 | 大图要切、目标任意朝向 | 类别极不均衡、有 ignore 区 | **两时相必须配准** |

## 三、指标（★ 核心）
| | 指标 | 为什么是它 |
|---|---|---|
| 检测 | **mAP** | 综合各类、各置信度阈值的定位+分类精度 |
| 分割 | **mIoU** | 逐类算 IoU 再平均，小类和大类同权重 |
| 变化检测 | **F1（只算变化类）+ IoU** | 变化像素极少，准确率会骗人 |

★ 三者的共同思想：**不让多数类蒙混过关**。

| | 我用的 | 组织方式 |
|---|---|---|
| 检测 | MMRotate | MM 系 config 继承 |
| 分割 | MMSegmentation | 同上，手感一致 |
```
