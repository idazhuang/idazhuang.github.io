# D267 周一 · 第二篇论文正式投稿 🎉 + arXiv 同步 + 查第一篇审稿状态

> **预期管理**：今天是第二篇的**投稿里程碑日**——把上周备齐的文件传上去、点 Submit。提醒：你第一篇投过稿（ScholarOne 全流程走过），**第二篇会顺很多**，昨天文件也都备齐了，今天主要是"执行 + 核对"，不会手忙脚乱。点完 Submit 同步 arXiv，再查第一篇审稿状态——这决定本周后半是"处理审稿"还是"读论文"。★ 投稿后会有点患得患失很正常，但记住：**投出去那一刻，结果就不由你控制了，你能做的已经做完了。**

## 上午段 · 登录投稿系统 → 上传 → Submit

**① 先垫概念（第二篇投稿为什么比第一篇快）**
- IEEE 系期刊（GRSL/JSTARS/TGRS）投稿走 **ScholarOne Manuscripts**——你第一篇（M7-W27）已经走过完整流程：注册、填元数据、上传各类文件、预览、Submit。**第二篇是同一个系统、同样的步骤**，你已经熟了。
- **和第一篇的不同**：第一篇你边学系统边投（陌生、慢）；第二篇你**照着上周备好的投稿文件清单逐项上传即可**（文件齐、流程熟）。今天的活儿是"执行 + 核对"，不是"学"。

**② 手把手带做**：登录 ScholarOne（或目标刊投稿系统）→ 新建投稿 → 按字段填元数据（标题、摘要、关键词、作者信息/单位/ORCID）→ 逐项上传文件（正文 PDF、Cover Letter、supplementary、源文件、graphical abstract 如需）→ **预览系统生成的 PDF**（确认图表无错位、公式正常、页码对）→ 核对无误后点 **Submit** → 截图/记录投稿确认号（manuscript ID）。
**③ 这一步合格的样子**：第二篇投稿成功，拿到 manuscript ID 和确认邮件；系统里状态显示"Submitted / Under Review"流程已启动。
**④ 最常踩的坑**
- 上传后不看系统生成的 PDF 直接 Submit → 系统转换可能出错（图错位/公式乱），**必须预览确认**再提交。
- 传错版本（传了中间版而非 v1.0 定稿）→ 上周文件夹只留了定稿版，上传时再核对文件名版本号。

**⑤ 卡住怎么自救（决策树）**：系统某字段不会填？→ 回顾第一篇投稿的流程笔记，或看系统的字段说明；预览 PDF 发现图表错位？→ 多为图源格式/分辨率问题，换矢量图重传；不确定选哪个 manuscript type？→ 按目标刊对你这篇的定位选（Regular Paper / Letter 等，看 Author Guidelines）。
**⑥ 今天（这一步）你同时学会了什么**：你**独立完成了第二篇的正式投稿**。**做了**（填元数据+传文件+预览+Submit）、**学了**（第二篇投稿=执行已备好的清单、预览生成 PDF 必做）、**会了**（熟练地把一篇论文投进 IEEE 投稿系统）。

> **技能卡｜第二篇投稿（复用流程）**：IEEE 系走 ScholarOne，步骤同第一篇（元数据→上传→预览→Submit）。第二篇快在"文件齐+流程熟"，今天是执行+核对。**铁律：Submit 前预览系统生成的 PDF**（转换可能出错）；只传 v1.0 定稿版（核对文件名版本号）；记下 manuscript ID。

## 中午段 · 同步上传到 arXiv

**① 先垫概念（为什么投稿同时挂 arXiv）**
- **arXiv** 是预印本平台：投稿的同时把论文挂上去，**让工作尽早公开、可被检索引用**（审稿要几个月，arXiv 让你的成果不被这段时间埋没）。第一篇你已经挂过，流程熟。
- **为什么"两篇 arXiv 更有说服力"**：你后面对接老师/求职时，**两篇 arXiv 预印本 = 可点开看的实打实成果**（比"我在做研究"具体得多）。这也是人脉预热的弹药——联系老师时能附上 arXiv 链接。

**② 手把手带做**：登录 arXiv → 选对分类（如 `cs.CV` + 交叉 `eess.IV`）→ 上传论文（用投稿版或 arXiv 版，注意符合 arXiv 格式要求）→ 填标题/作者/摘要/comments → 提交等待 moderation（通常 1–2 天放出）；**注意核对**：arXiv 版和投稿版一致（或标注差异）、作者信息正确、不违反目标刊的预印本政策（IEEE 一般允许 arXiv）。
**③ 这一步合格的样子**：第二篇已提交 arXiv，等待放出；分类、作者、摘要正确。
**④ 坑**：① arXiv 分类选错 → 影响被相关领域的人看到，选准 `cs.CV`/`eess.IV`；② 不查目标刊预印本政策就挂 → 绝大多数允许，但投稿前确认一下（避免冲突）；③ arXiv 版和投稿版差异大却不标注 → 保持一致或在 comments 说明。
**⑤ 自救**：arXiv 编译报错？→ 上传 LaTeX 源让它编译，按报错修（常见缺包/图路径）；不确定分类？→ 看你第一篇挂的分类，或同方向论文的分类。
**⑥ 今天（这一步）你同时学会了什么**：你**把第二篇同步到了 arXiv**。**做了**（选分类+上传+提交 moderation）、**学了**（arXiv 让成果尽早公开、两篇预印本是对接弹药）、**会了**（投稿同时把论文挂上预印本平台）。

> **技能卡｜arXiv 同步**：投稿同时挂 arXiv，让成果尽早公开可引用。分类选准（`cs.CV`+交叉 `eess.IV`）。两篇 arXiv 预印本=对接老师/求职时可点开的硬成果。注意：符合 arXiv 格式、作者信息正确、不违反目标刊预印本政策（IEEE 一般允许）。

## 晚上段 · 检查第一篇审稿状态（定本周走向）

**③ 这一步合格的样子**：明确了本周后半的走向（审稿处理 or 读论文）；若有意见，已下载存档并读过一遍、初步标了三类。
**④ 坑**：① 看到审稿意见情绪上头、当晚就慌乱回复 → 别急，读三遍、明天再动手（管理情绪是第一步）；② 没意见就以为"凉了"瞎担心 → Under Review 是正常状态，审稿周期长，耐心等。

**⑥ 今天（这一步）你同时学会了什么**：你**查清了第一篇状态、定好了本周走向**。**做了**（查状态+下载意见/确认无意见+定 D268-270 走向）、**学了**（审稿线有时限优先级最高、读三遍管理情绪、Under Review 是正常态）、**会了**（根据审稿进展灵活规划本周）。

> **技能卡｜两篇同时在审的心态**：第二篇刚投、第一篇在审——两篇都进入"不可控"（审稿结果不由你定）。**不要同时焦虑两篇**：能控制的只有论文质量（已做到位）和"下一步"（人脉预热）。把注意力从"等结果"转到"做对接的功课"。审稿有意见就专业处理、没意见就读论文，都比干等强。

> **今日交付**：✅ **第二篇论文正式投稿**（manuscript ID 已记录）✅ arXiv 同步 ✅ 第一篇审稿状态已查（定好本周走向）。

# D268 周二 · 【审稿线】集中修改 Day 1（处理最重要意见）/【论文线】读论文

> **预期管理**：今天按昨晚定的走向走。**【审稿线】**（第一篇有意见）：集中修改第一天，先啃**最重要、最难的 Major Revision 意见**（通常是要补实验或回应核心质疑的那条）。**【论文线】**（第一篇无意见）：读论文、跟踪领域。提醒：审稿处理**先难后易**——最难的意见最花时间、最影响成败，先动手；别把时间耗在好回应的小意见上、把硬骨头留到最后。

## 上午段 ·【审稿线】啃最重要的意见 /【论文线】读第 1 篇

**① 先垫概念（审稿意见为什么先处理最重要的）**
- 审稿意见有轻重：**Major（要补实验、回应核心质疑、改结构）vs Minor（改措辞、补引用、修 typo）**。处理顺序应**先 Major 后 Minor**——Major 决定论文能否被接收、最花时间，必须先动手；Minor 留到后面快速扫掉。
- **和"从第一条改到最后一条"对比**：审稿意见的编号顺序≠重要性顺序。**按重要性而非编号处理**，把精力先投到决定成败的硬意见上——这和你改稿、做实验时"先解决最关键问题"一脉相承。
- 【论文线】若第一篇无意见：今天起读 3 篇新论文，重点是**领域最新进展**（和你两个课题相关的方向、可能的第三课题线索）。

**② 手把手带做**：**【审稿线】**从标了"三类"的意见里挑出**最重要的 1–2 条 Major**（通常是补实验/核心质疑）→ 先想清回应策略（同意补 or 据理回应）→ 若需补实验，今天就启动（复用现成框架，快）→ 开始动手改对应章节。**【论文线】**选 1 篇近期高相关论文精读 → 记笔记（解决什么问题/方法/对你的启发）→ 更新阅读清单。
**③ 这一步合格的样子**：【审稿线】最重要的 Major 意见已有明确回应方案、对应改动/补实验已启动；【论文线】1 篇精读笔记完成。
**④ 最常踩的坑**
- 【审稿线】先改好回应的小意见、把最难的留最后 → 时间不够时硬骨头没啃完；**先难后易**。
- 【审稿线】对 Major 质疑无条件认怂全改 → 标三类的意义就是：同意的改、不同意的据理专业回应（审稿人也会错）。
- 【论文线】读论文只读不记 → 记笔记+提炼对你的启发，才不白读。

**⑤ 卡住怎么自救（决策树）**：【审稿线】某条 Major 不知怎么回应？→ 分"要不要补实验"（缺证据就补）和"要不要改观点"（他对就改、他误解就澄清）；补实验来不及？→ 用小数据集/现成框架最快验证，能回应质疑即可。【论文线】论文读不懂？→ 先抓"问题+方法+结果"主线，细节略过。
**⑥ 今天（这一步）你同时学会了什么**：你学会**按重要性优先处理审稿意见（先 Major 后 Minor）**/（论文线）**持续跟踪领域最新**。**做了**（啃最重要 Major+启动补实验 / 精读 1 篇）、**学了**（Major/Minor 分轻重先难后易、标三类有判断地回应 / 读论文记启发）、**会了**（专业地推进审稿修改 / 高效跟踪领域）。

> **技能卡｜审稿修改先难后易**：审稿意见按重要性处理（Major→Minor），不按编号顺序。**先啃最重要的 Major**（补实验/核心质疑，决定成败、最花时间），Minor 留后面快速扫。标三类有判断地回应：同意的改、不同意的据理专业回应（审稿人也会错）。需补实验用现成框架最快验证。

## 中午段 ·【审稿线】继续改 /【论文线】读第 2 篇

**① 先垫概念**：审稿修改中，**每处改动都要能对应到一条意见**（让审稿人复审时一眼看到"你按我说的改了"）。改的同时**记录"哪条意见→改了哪里"**，为明天写 Response Letter 攒素材。【论文线】继续读，注意几篇之间的**关联**（领域趋势、共同未解问题）。
**② 手把手带做**：**【审稿线】**继续处理 Major 意见的改动；边改边在一个表里记"意见编号→对应改动位置→一句说明"。**【论文线】**精读第 2 篇 + 笔记 + 和第 1 篇对照（趋势/共性问题）。
**③ 合格样例**：【审稿线】Major 意见的改动推进过半，"意见→改动"记录表同步在更新；【论文线】第 2 篇笔记完成。
**④ 坑**：① 【审稿线】改了但不记"对应哪条意见" → 明天写 Response 时倒查费劲，边改边记；② 【论文线】每篇孤立读、不找关联 → 关联起来才看得出领域趋势。
**⑤ 自救**：【审稿线】改动牵一发动全身？→ 做波及检查、全文同步（尤其数字/术语）；【论文线】论文太多读不完？→ 优先读最高相关的，次要的略读摘要。

## 中午段 ·【审稿线】写 Response Letter（逐条 + 三色）/【论文线】沉淀

**① 先垫概念（Response Letter 是什么，怎么写）**
- **Response Letter（回复信）= 逐条回应审稿人意见的信**，随修改稿一起提交。结构：对**每一条**意见——① 引用原意见、② 你的回应（同意并已改 / 部分同意 / 不同意+理由）、③ 指出在论文哪里改了。**三色排版**（复用 W36）：原意见**蓝**、你的回复**黑**、引用的论文修改处**红**，让审稿人一眼分清。
- **核心原则：诚恳、专业、逐条**——同意的明确说"已按建议修改，见 X"；不同意的**据理而非情绪**地回应（"我们理解审稿人的关切，但……，原因是……"）。**让审稿人感到被尊重、每条都被认真对待**，这本身就提高接收概率。

**② 手把手带做**：**【审稿线】**新建 Response Letter → 开头礼貌致谢审稿人 → **逐条**：贴原意见（蓝）+ 写回应（黑：同意/部分/不同意+理由）+ 指出修改位置（红：引用改后的句子/表）→ 同意的写清改了什么、不同意的给充分理由。**【论文线】**整理这几篇论文的共性/趋势，记第三课题候选线索。
**③ 合格样例**：【审稿线】Response Letter 逐条成形（三色清晰、每条有回应+定位）；语气诚恳专业。
**④ 坑**：① 【审稿线】回应笼统（"已修改"但不说改了啥/在哪）→ 每条都要具体+定位；② 对不同意的意见情绪化反驳 → 据理、礼貌、专业（"我们理解…，但…"）；③ 漏回某条意见 → 逐条核对，一条不漏。
**⑤ 自救**：【审稿线】不知某条怎么回应措辞？→ 套"感谢指出→我们的处理（改了/解释）→见论文 X"三段式；不同意又怕得罪审稿人？→ 礼貌+充分理由即可，审稿人尊重有理有据的回应。
**⑥ 今天（这一步）你同时学会了什么**：你学会**写逐条、三色、专业的 Response Letter**。**做了**（逐条贴意见+回应+定位、三色排版 / 论文线沉淀）、**学了**（Response 逐条具体定位、同意明说不同意据理、诚恳专业提高接收率）、**会了**（为修改稿配一封让审稿人满意的回复信）。

> **技能卡｜Response Letter（三色逐条）**：随修改稿提交的回应信。逐条：原意见（**蓝**）+ 回应（**黑**：同意已改/部分/不同意+理由）+ 论文修改处（**红**）。原则：诚恳、专业、逐条、具体定位。同意的明说改了啥+在哪；不同意的据理礼貌回应（"我们理解…，但…"，审稿人也会错）。一条不漏。让审稿人感到每条都被认真对待=提高接收率。

## 晚上段 ·【审稿线】完善 Response /【论文线】收尾

## 二、完整可运行代码 · 人脉预热追踪器（+ 预期输出）

> 这个脚本帮你管理"目标联系人清单"：存联系人（姓名/组/方向/对接点/优先级/下一步），按优先级排序输出 markdown 表，并能筛选"待核实方向"的人。人脉预热是长期过程，用它持续维护清单比手记表格更不易乱。

```python
#!/usr/bin/env python3
# contact_tracker.py —— 人脉预热联系人清单管理器
PRIORITY = {"最高": 0, "高": 1, "中": 2, "低": 3}

contacts = [
    {"name": "王超", "group": "空天院", "field": "SAR/文本-SAR跨模态",
     "link": "第二课题(SAR speckle/跨模态)★最佳", "recent": "TACMT",
     "priority": "最高", "next": "精读TACMT等近作"},
    {"name": "孙显", "group": "空天院", "field": "遥感基础模型/检测",
     "link": "第一课题(旋转检测/基础模型应用)", "recent": "RingMo系列",
     "priority": "高", "next": "读近两年论文+关注"},
    {"name": "付琨", "group": "孙显组", "field": "待核实",
     "link": "同组,第一课题方向", "recent": "",
     "priority": "高", "next": "做功课核实方向"},
    {"name": "刁文辉", "group": "空天院", "field": "待核实",
     "link": "待核实", "recent": "", "priority": "中", "next": "做功课核实方向"},
    {"name": "张正", "group": "空天院", "field": "待核实",
     "link": "待核实", "recent": "", "priority": "中", "next": "做功课核实方向"},
]

def sort_by_priority(cs):
    return sorted(cs, key=lambda c: PRIORITY.get(c["priority"], 9))

def to_markdown(cs):
    head = "| 姓名 | 组 | 方向 | 对接点 | 近作 | 优先级 | 下一步 |\n"
    head += "|---|---|---|---|---|---|---|\n"
    rows = "".join(
        f"| {c['name']} | {c['group']} | {c['field']} | {c['link']} | "
        f"{c['recent'] or '—'} | {c['priority']} | {c['next']} |\n"
        for c in cs)
    return head + rows

def need_homework(cs):
    return [c["name"] for c in cs if "待核实" in c["field"] or "待核实" in c["link"]]

if __name__ == "__main__":
    ordered = sort_by_priority(contacts)
    print("=== 目标联系人清单（按优先级）===\n")
    print(to_markdown(ordered))
    todo = need_homework(contacts)
    print(f"\n⚠ 待做功课核实方向（{len(todo)} 人）: {', '.join(todo)}")
    print(f"总计 {len(contacts)} 位目标联系人；最高优先级 = "
          f"{[c['name'] for c in contacts if c['priority']=='最高']}")
```

**预期输出**：
```
=== 目标联系人清单（按优先级）===

| 姓名 | 组 | 方向 | 对接点 | 近作 | 优先级 | 下一步 |
|---|---|---|---|---|---|---|
| 王超 | 空天院 | SAR/文本-SAR跨模态 | 第二课题(SAR speckle/跨模态)★最佳 | TACMT | 最高 | 精读TACMT等近作 |
| 孙显 | 空天院 | 遥感基础模型/检测 | 第一课题(旋转检测/基础模型应用) | RingMo系列 | 高 | 读近两年论文+关注 |
| 付琨 | 孙显组 | 待核实 | 同组,第一课题方向 | — | 高 | 做功课核实方向 |
| 刁文辉 | 空天院 | 待核实 | 待核实 | — | 中 | 做功课核实方向 |
| 张正 | 空天院 | 待核实 | 待核实 | — | 中 | 做功课核实方向 |

⚠ 待做功课核实方向（3 人）: 付琨, 刁文辉, 张正
总计 5 位目标联系人；最高优先级 = ['王超']
```
> 解读：脚本按优先级排好清单、自动列出"待核实方向"的人（提醒你去读论文核实），并高亮最高优先级对接人（王超组对接第二课题）。随人脉预热进展，往 contacts 里补 recent/field、更新 next 即可。
