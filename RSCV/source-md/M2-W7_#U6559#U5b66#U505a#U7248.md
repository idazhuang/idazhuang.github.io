> 今天搞懂"自监督预训练"和 MAE——不用人工标注,用数据自身结构训练。这是基础模型的基石。
>
> **预期管理**:今天入门自监督/MAE(基础模型的基石),产物是 SatMAE 笔记+MAE 代码注释。提醒:自监督的核心是"用数据自身结构造监督信号,不靠人工标注"——这点想通了 MAE 就懂了一半。MAE 推理/下游微调单卡能跑,别担心算力(真正吃算力的是从零预训练大基础模型,那是后面才讲的"你做不了"的部分)。

## 上午段 · 精读 SatMAE(Cong 2022, NeurIPS)

**① 先垫概念(假设你没接触过自监督)**:**自监督 = 不需要人工标注,用数据本身的结构当监督信号**。**MAE(Masked Autoencoder)**的做法:把图像**遮住 75%**,让模型预测被遮住的部分——能补全,说明它"看懂"了图像结构。**类比**:像做完形填空,遮住大半句话还能填对,说明你懂这门语言。**好处**:可以用**海量无标注遥感图**做预训练(标注贵,无标注图便宜),再在下游任务(分类/检测)上微调。**SatMAE** = 把 MAE 用于遥感(还利用了时序/多光谱结构)。
- **为什么自监督对遥感价值巨大**:遥感图像有个特点——**图极多但标注极少**(全球每天产出海量卫星图,但人工标注又贵又慢)。监督学习吃标注,这是瓶颈;自监督**不需要标注**,正好能把"海量无标注遥感图"这座金矿利用起来。这就是为什么遥感基础模型(RingMo 等)都用自监督预训练——它能消化遥感最丰富的资源(无标注图)。
- **自监督 ≠ 无监督,别搞混**:无监督(如聚类)是"完全没有监督信号、自己找规律";自监督是"**用数据自身结构造出监督信号**"——MAE 里"被遮的真实像素"就是监督信号(模型预测它、和真值比)。所以自监督其实是"自己给自己出题、自己对答案",有明确的训练目标,这比无监督有效得多。
- **为什么遮 75% 这么狠(而不是遮一点点)**:遮太少(如 15%),模型靠周围没遮的部分"抄"就能补上,学不到真东西;遮 75% 逼模型必须**真正理解图像的全局结构和语义**才能补全大片缺失——难度大,学到的表征才强。**这个"高遮挡比例"正是 MAE 区别于早期方法的关键洞见**(图像信息冗余度高,遮大半仍可推断,所以能遮很狠)。
- **"预训练→下游微调"这套范式要记牢**:先用海量无标注数据自监督预训练一个通用 encoder(学到好的图像表征),再在你的具体下游任务上用少量标注微调。**好处是下游只需很少标注就能达到好效果**(因为 encoder 已经"见多识广")——这对标注稀缺的遥感尤其重要,也是基础模型范式的核心价值。

2. 记 MAE 核心三问:遮多少(75%)、重建什么(像素)、为什么有用。
**③ 合格样例**:SatMAE 笔记,能讲清"MAE=遮住重建、SatMAE 把它用于遥感"。

**⑤ 卡住自救**:不懂重建 loss?→ 抓直觉"预测被遮像素、和真值算 MSE",细节后面看代码。

> **技能卡｜MAE 一句话**:遮住图像 75% → 让模型重建被遮部分 → 学到图像结构表征。用海量无标注数据预训练,再迁到下游。遥感版还会利用时序/多光谱。

## 中午段 · MAE 代码精读(masking / 重建 loss / encoder-decoder)

**① 先垫概念**:看 MAE 代码三个核心:① **patch masking**(怎么随机遮 patch)② **重建 loss**(只在被遮 patch 上算 MSE)③ **非对称 encoder-decoder**(encoder 只看可见 patch,decoder 重建全图——省算力的关键)。
**② 手把手带做**
1. 读 MAE 代码,定位 masking、loss、encoder/decoder。
2. 注释:为什么 encoder 只处理可见 patch(省算力)、loss 为什么只算被遮部分。
```python
# MAE 的核心三步（伪代码，对照官方 models_mae.py 理解）
def random_masking(x, mask_ratio=0.75):           # ① 随机遮 75% 的 patch
    N, L, D = x.shape                              # L=patch 数
    len_keep = int(L * (1 - mask_ratio))           # 只保留 25%
    noise = torch.rand(N, L, device=x.device)
    ids_shuffle = torch.argsort(noise, dim=1)      # 随机打乱，取前 len_keep 个作"可见"
    ids_keep = ids_shuffle[:, :len_keep]
    x_visible = torch.gather(x, 1, ids_keep.unsqueeze(-1).repeat(1,1,D))
    return x_visible, ids_shuffle                  # 返回可见 patch + 还原顺序的索引

def forward(self, imgs):
    x = self.patch_embed(imgs)                     # 图→patch 序列
    x_vis, ids = random_masking(x)                 # ① 遮 75%
    latent = self.encoder(x_vis)                   # ② encoder 只看可见的 25%（省算力的关键！）
    pred   = self.decoder(latent, ids)             # ③ decoder 补全所有 patch（含被遮的）
    loss   = (pred - target)**2                    # ④ 重建 MSE
    loss   = loss[mask].mean()                     # ★只在"被遮"的 patch 上算 loss
    return loss
# 妙处：encoder 只处理 25% 的 patch → 比处理全图快得多，这是 MAE 能高效预训练的关键
```
**③ 合格样例**:MAE 代码注释,能指出三个核心模块。
**④ 常踩的坑**:以为 encoder 处理全部 patch → MAE 的妙处是 encoder 只看可见的(快);loss 在所有 patch 上算 → 只在被遮 patch 上算。
**⑤ 卡住自救**:代码绕?→ 只看 forward:random_masking → encoder(可见)→ decoder(全)→ loss(被遮)。
**⑥ 今天(这一步)你同时学会了什么**:你读懂了 MAE 实现。**做了**(MAE 代码注释)、**学了**(masking/重建 loss/非对称结构)、**会了**(看懂自监督预训练代码)。

## 晚上段 · 跑 SatMAE 推理 demo(预训练权重→下游微调)

state = ckpt.get("model", ckpt)

for p in model.head.parameters(): p.requires_grad = True   # 先只训分类头
# ... 训几轮后再 for p in model.parameters(): p.requires_grad = True 全微调

## 上午段 · 精读 Scale-MAE(Reed 2023)

**① 先垫概念**:遥感图像**尺度变化极大**(同一物体在不同分辨率/高度下差异大)。**Scale-MAE** = 让 MAE 显式处理多尺度,使学到的表征对尺度更鲁棒。
- **为什么尺度是遥感的核心痛点**:同一个目标(如一栋楼),在 0.5 米分辨率下是几百像素的清晰建筑,在 10 米分辨率下可能只是几个像素的点;不同卫星、不同拍摄高度,分辨率天差地别。**一个对尺度不鲁棒的模型,换个分辨率就失效**——这在遥感里是个大问题(你不可能只在一种分辨率上用模型)。
- **Scale-MAE 的核心思路(抓一句)**:普通 MAE 不区分尺度;Scale-MAE 在预训练时**显式地让模型见识不同尺度的输入/重建目标**(如把图缩放到不同分辨率分别处理),逼模型学到"尺度无关的本质表征"。这样下游换个分辨率,模型也能稳定工作。
- **它体现了一个通用的好选题套路**:**找到遥感的一个特性痛点(尺度/speckle/方位角/类别不平衡…),针对它改进一个通用方法(MAE)**——SatMAE 针对"遥感的时序/多光谱"改 MAE,Scale-MAE 针对"遥感的尺度"改 MAE。**这正是你"通用 CV 巧技嫁接遥感"定位的范本**:不发明全新方法,而是把通用方法针对遥感特性做精准改造。你以后做题完全可以套这个模式(针对某个遥感痛点改进某个通用方法)。
- **对你的启示**:Scale-MAE 这类"针对遥感特性改进自监督"的工作单卡也未必能完整复现(仍要预训练),但它展示的"特性痛点×通用方法"的选题思路,你可以用在更轻量的场景(如不做预训练、只在下游任务上针对尺度做改进)。

**③ 合格样例**:Scale-MAE 笔记,能说清"它给 MAE 加了多尺度"。

## 中午段 · 整理"自监督遥感 5 大流派"表

**① 先垫概念**:自监督有多条路线。整理 **5 大流派**:① MAE 系(遮住重建)② 对比学习系(拉近正样本)③ DINO 系(自蒸馏)④ 多模态自监督(光学-SAR 等跨模态)⑤ 时序自监督(利用时间序列)。每种写代表论文 + 核心思路。
- **为什么要建"流派全景"而非只记一个 MAE**:自监督是个大领域,只懂 MAE 你会以为"自监督=遮住重建",视野太窄。建一张 5 大流派表,你就有了整个领域的地图——读到任何自监督工作能归类、想自己的题时知道有哪些可选路线、判断某个方向是否饱和。**这和你之前给变化检测/分割建 SOTA 表是同一个思路:先建全景,再谈选择**。
- **5 大流派核心思路一句话区分**:① **MAE 系**=遮住一部分让模型重建(学"补全"能力);② **对比系**(SimCLR/MoCo)=同一张图的两个增强视角拉近、不同图推远(学"区分"能力);③ **DINO 系**=老师模型和学生模型互相学习(自蒸馏,无需负样本);④ **多模态自监督**=用"同场景的光学和 SAR"互相作监督(天然配对当信号);⑤ **时序自监督**=用"同地不同时"的图序列作监督(利用时间一致性)。**重建 vs 对比 vs 自蒸馏是三种不同的"造监督信号"哲学**,别混。
- **哪两派和你最契合(重点)**:**多模态自监督**(光学-SAR-IR)和**时序自监督**——这两派正好对接你的多模态兴趣和遥感的时序特性。如果你想把自监督结合进你的方向,这两派是切入点(如"用光学-SAR 配对做跨模态自监督预训练"),而且它们相对 MAE/对比系**更新、做的人更少**,机会更大。
- **这对你选题的意义**:自监督本身你单卡做不了大规模预训练,但**"在某个小问题上改进自监督方法"或"把自监督用于某个特定场景"是可做的**——尤其多模态/时序这两派还有空间。今天建的流派表,是你判断"要不要把自监督纳入方向"的依据。

2. 填 5 大流派。
**③ 合格样例**:自监督 5 大流派表(每派有思路 + 代表作)。

## 上午段 · 精读 SpectralGPT + DOFA(多模态基础模型)

**① 先垫概念**:**SpectralGPT**(光谱)、**DOFA**(多模态统一)是更前沿的多模态遥感基础模型,试图统一处理多种传感器/模态。了解"基础模型往多模态走"的趋势。
- **为什么基础模型在往"多模态统一"走**:早期基础模型大多只处理一种数据(如光学 RGB);但遥感的数据是多样的(光学多光谱、SAR、红外、高光谱…),理想的基础模型应该能"统一理解所有这些"。SpectralGPT(统一光谱)、DOFA(统一多模态)就是这个方向的探索——一个模型吃多种传感器,学到跨模态的通用表征。**这是基础模型的前沿趋势**。

- **为什么"反复犹豫"是新手最大的时间黑洞**:每换一次方向,前面在旧方向上读的论文、跑的实验、攒的判断就大幅贬值,你又要在新方向从头积累。**频繁换方向的人,两年下来可能在每个方向都只是浅尝,哪个都没做深**。而做研究要出成果,必须在一个方向上积累到足够深——这需要稳定地投入,而非东张西望。

## 二、完整可运行代码 — MAE 预训练加载到下游(strict=False 排查)
```python
import torch, torch.nn as nn
# 把自监督预训练的 encoder 权重加载到下游模型(只加载主干,换分类头)
def load_pretrained_encoder(downstream_model, ckpt_path, num_classes):
    ckpt = torch.load(ckpt_path, map_location="cpu")
    state = ckpt.get("model", ckpt)
    # 只取 encoder 相关权重(去掉 decoder / mask token 等预训练专用部分)
    enc = {k: v for k, v in state.items() if k.startswith("encoder") or k.startswith("blocks") or k.startswith("patch_embed")}
    missing, unexpected = downstream_model.load_state_dict(enc, strict=False)
    print("未加载(缺):", missing[:5], "... 共", len(missing))
    print("多余(忽略):", unexpected[:5], "... 共", len(unexpected))
    # 换/初始化下游分类头
    downstream_model.head = nn.Linear(downstream_model.embed_dim, num_classes)
    return downstream_model
if __name__ == "__main__":
    print("用法:strict=False 加载主干;打印 missing/unexpected 确认主干真加载上;再换分类头微调")
```
