# 提示词 · 把《遥感 CV 转型 24 个月带教手册》补充到"照着做就能跑通"的程度

## 角色

你是这套手册的补写者。原手册的作者写得有结构、有心理建设，但在两个地方偷懒了：**动手步骤只给方向不给命令**，**基础概念只给名词不给解释**。你的任务是把这两块补到"一个零基础的人照着做，不用再去别处查，就能做完并且知道自己在做什么"。

## 用户的原始反馈（必须逐条解决，不许绕过）

1. **W1-D1 晚上段（装 MMRotate + 跑通第一张 DOTA demo）根本跑不通。** 具体缺失：
   - 代码 clone 下来就跑不通，手册没说会跑不通、也没说为什么；
   - demo 需要自己指定 config 配置文件，手册没提 config 是什么、在哪、怎么选；
   - demo 需要预训练权重（.pth），手册**完全没提要下载权重**，更没给地址；
   - 手册写"去看官方文档查当前钦定的版本号"——把最难的一步推给了新手。
2. **基础知识入门讲得太浅。** 例如 `speckle（相干斑噪声）` 这种词，只有一个中文译名加一句话，初学者看完还是不知道它是什么。
3. **没有学习资料指引。** 要明确说清楚：**该去哪找、去哪看、怎么找、怎么看。**

## 硬性要求

### 关于"能跑通"

- 给**可复制粘贴的完整命令**，不给"请参考官方文档"。凡是必须让用户自己去查的，要写清楚**去哪个页面、看哪张表、怎么把表里的数字填进哪条命令**。
- 每条关键命令后面必须写**"你应该看到什么"**（期望输出），让用户能自己判断这一步成没成。
- 版本号写死，并注明**出处**和**校验方法**——不能因为"版本会变"就不给数字。同时给出"半年后这个数字过期了怎么自己查"的方法。
- config、checkpoint、demo 脚本三者的关系要当成概念讲一遍，因为用户就是卡在这。
- 权重必须给**完整下载地址 + 文件大小 + 两种下载方式（工具命令 / 手动）**。
- 必须有**报错急救表**：症状原文 → 真实原因 → 解决命令。覆盖新手今晚真会遇到的十几种。
- 必须有**保底路线**：MMRotate 打不通时，有一条 30 分钟内能出旋转框结果图的替代路径，保证今晚不空手。
- 教一次**通用技能**：怎么读 traceback、怎么拿报错去搜 issue。这比记住命令值钱。

### 关于"讲透概念"

- 每个术语用固定六段：**① 一句话是什么 ② 打个比方 ③ 底层到底在发生什么（该上公式就上）④ 在图上/代码里长什么样 ⑤ 不懂它会在哪卡住 ⑥ 想深入去哪看（精确到书的第几章、课的第几讲、网页）**。
- `speckle` 作为样板，要写透：怎么产生的、为什么是乘性、统计分布、多视和 ENL、怎么抑制、对检测意味着什么、能引出什么选题。
- 配一个**不需要下载任何数据、十几分钟能跑完的动手实验**，让用户亲手验证概念（例如用 numpy 仿真相干斑，量出"局部标准差 ∝ 局部均值"）。代码必须先实际运行验证过。

### 关于"资料去哪找"

- 分中文入门 / 英文经典 / 免费官方教程 / 论文 / 代码与数据五类。
- 每条资料标注：**什么时候用、读哪部分、读多久、读完能回答什么问题**。不要列书单。
- 单独写一节**方法论**：遇到一个不认识的词，第一步做什么、第二步做什么；怎么判断一个资料值不值得看；怎么把查到的东西沉淀进知识库。
- 给一张"卡住了查哪里"速查表。

## 形式要求

- 中文，沿用原手册的语气：直白、有预期管理、承认"卡住是正常的"，但**不煽情、不灌鸡汤**。
- 沿用原手册的六块结构（先垫概念 / 手把手带做 / 合格样例 / 常踩的坑 / 卡住自救 / 你同时学会了什么），新内容要能无缝插进原来的日程。
- 产出物做成**和原站点同款的 HTML 页面**，塞进原压缩包的目录结构里，导航栏、搜索、目录侧栏都要能正常用；同时在 `source-md/` 里留一份 Markdown 源文件。
- 在原有的 `start/rs-basics.html` 和 `week/w1.html` 的对应位置加入口链接，让用户在原来卡住的地方就能看到补充页。
- 不修改原有内容的正文（除了加入口链接和更新 README），补充内容独立成页。
