## 上午段 · 检查两篇论文状态并按需处理

**① 先垫概念（两篇论文可能的状态与对应动作）**
- 两篇论文此时可能处于：① **Under Review**（在审，无需行动，耐心等）；② **Major/Minor Revision**（要修改，优先处理，复用 W36/W39 方法：读三遍、标三类、补实验、Response Letter）；③ **Reject/Resubmit 或需 rebuttal**（按要求处理）。**先查状态，再决定本周时间分配**。
- **为什么"在审就投人脉预热"**：审稿不可控、有它自己的节奏；你能主动推进的是人脉预热和产出。**论文在审的等待期，正是做连接功课的好时机**——不空等。

**② 手把手带做**：登录两篇论文的投稿系统查状态 → ① 都在审/无行动项 → 确认状态、本周专注人脉预热 + 内容输出；② 某篇要修改 → 评估工作量，优先安排（复用审稿处理方法），其余线相应压缩；③ 记录两篇当前状态（进 M11 跟踪）。建议建一个"论文状态跟踪"小表：每篇记 投稿日期/期刊/当前状态/下次该检查的时间/待办（如有 revision 的 deadline），一眼看清两篇各自走到哪、有没有时限要赶——避免两篇在审时漏掉某篇的关键节点。
**③ 这一步合格的样子**：两篇状态已查清、本周时间分配已定（无行动则全力人脉预热+产出；有修改则优先处理）。
**④ 最常踩的坑**
- 反复刷状态、焦虑结果 → 查一次、确认、转向能主动做的事（人脉预热）。
- 有修改项却拖着不处理 → 审稿响应有时限，要修改就优先安排。

**⑤ 卡住怎么自救（决策树）**：状态长期 Under Review 担心？→ 在正常审稿周期内耐心等（别频繁催）；收到 Revision 工作量大？→ 复用 W36 方法先难后易、用现成框架补实验。
**⑥ 今天（这一步）你同时学会了什么**：你**查清两篇状态、合理分配了本周时间**。**做了**（查两篇状态 + 定时间分配 + 记录跟踪）、**学了**（论文三种状态对应动作、在审等待期投入人脉预热、不空等）、**会了**（根据论文进展灵活安排、把等待期转化为连接功课）。

**① 先垫概念（行业观察帖写什么、为什么体现判断力）**

## 二、完整可运行代码 · 知乎内容数据追踪器（+ 预期输出）

> 这个脚本追踪你 3 篇知乎长文的数据（阅读/点赞/收藏），算总触达和互动率（(赞+藏)/阅读），找出表现最好的内容类型——指导后续内容方向。被动建立存在感是长期的，用它持续追踪比手记更清楚。

```python
#!/usr/bin/env python3
# zhihu_tracker.py —— 知乎内容数据追踪器
posts = [
    # 标题类型, 阅读, 点赞, 收藏
    {"type": "技术综述", "views": 3200, "likes": 180, "favs": 420},
    {"type": "方法解读", "views": 2100, "likes": 95,  "favs": 130},
    {"type": "行业观察", "views": 4500, "likes": 260, "favs": 310},
]

def engagement(p):
    # 互动率 =(赞+藏)/阅读，反映内容质量与共鸣
    return (p["likes"] + p["favs"]) / p["views"] if p["views"] else 0

def report(posts):
    print("=== 本周知乎 3 篇数据 ===\n")
    print("| 类型 | 阅读 | 赞 | 藏 | 互动率 |")
    print("|---|---|---|---|---|")
    for p in posts:
        print(f"| {p['type']} | {p['views']} | {p['likes']} | "
              f"{p['favs']} | {engagement(p)*100:.1f}% |")
    total_v = sum(p["views"] for p in posts)
    total_e = sum(p["likes"] + p["favs"] for p in posts)
    print(f"\n总触达：{total_v} 次阅读，{total_e} 次互动（赞+藏）")
    best_reach = max(posts, key=lambda p: p["views"])
    best_eng = max(posts, key=engagement)
    print(f"触达最高：{best_reach['type']}（{best_reach['views']} 阅读）")
    print(f"互动率最高：{best_eng['type']}（{engagement(best_eng)*100:.1f}%，"
          f"最能引发收藏/共鸣 → 后续可多写此类）")

if __name__ == "__main__":
    report(posts)
```

**预期输出**：
```
=== 本周知乎 3 篇数据 ===

| 类型 | 阅读 | 赞 | 藏 | 互动率 |
|---|---|---|---|---|
| 技术综述 | 3200 | 180 | 420 | 18.8% |
| 方法解读 | 2100 | 95 | 130 | 10.7% |
| 行业观察 | 4500 | 260 | 310 | 12.7% |

总触达：9800 次阅读，1395 次互动（赞+藏）
触达最高：行业观察（4500 阅读）
互动率最高：技术综述（18.8%，最能引发收藏/共鸣 → 后续可多写此类）
```
> 解读：把真实数据填进 posts，脚本算每篇互动率、总触达、并区分"触达最高"（观点帖易传播）和"互动率最高"（综述帖易被收藏=高价值留存）。互动率比纯阅读更反映内容质量——后续可多写互动率高的类型。
