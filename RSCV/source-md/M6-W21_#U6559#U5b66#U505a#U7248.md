## 上午段 · 据完整实验更新贡献列表

**① 先垫概念**:好的贡献列表带**具体数字**。**反例**:"我们提出一个有效的方法";**正例**:"我们提出的 X 方法在 DOTA 上达 78.5 mAP,超现有 SOTA 1.3 个点"。**为什么**:数字让贡献可验证、有说服力——审稿人靠贡献列表快速判断你工作的价值。你现在有完整实验,正好把阶段一写的占位贡献全部数字化。
- **为什么"贡献列表"是 Introduction 的命脉**:审稿人读你的论文,Introduction 末尾的贡献列表(通常是 bullet 形式的"我们的贡献:① … ② … ③ …")是他**快速判断"这工作值不值得发"的关键**。一个写满空话("提出一种新颖有效的方法""取得了优异的性能")的贡献列表,审稿人扫一眼就觉得"虚、没料";一个带具体数字、每条都可验证的贡献列表("在3个数据集平均提升1.8 mAP、参数量减少30%、推理速度提升至21 FPS"),审稿人立刻 get 到你工作的实质价值。**贡献列表的质量,很大程度决定审稿人对你论文的第一判断**。
- **怎么把贡献"数字化"(可操作)**:你现在手里有完整的实验数据(三数据集整合大表、消融表、效率对比),把阶段一写的占位贡献逐条填上真实数字——① 方法贡献配"提升多少"(从整合大表你vs最强baseline的差);② 效率贡献配"参数/FPS"(从效率对比);③ 如果有评测/分析类贡献,配相应的发现数字。**每条贡献 = "提出什么 + 解决什么 + 提升多少(真实数字)"**,三要素齐全。
- **数字一般怎么办(转到效率维度)**:如果你的精度提升数字不亮眼(比如只超SOTA零点几),别硬吹——**把贡献的重心转到"高效"维度**:"在显著更低的参数量和更高的推理速度下,达到与SOTA可比的精度"。这对你单卡路线是天然卖点:精度持平但更小更快,本身就是有力贡献。**贡献列表要诚实地突出你真正的优势在哪**(是精度还是效率),而非在不占优的维度上勉强夸大。
- **每条贡献必须能在实验里找到对应证据(铁律)**:你贡献列表里写的每个数字、每个声称,都必须能在你的Experiment章里找到支撑(那张表、那个消融)。**别写实验没验证的贡献**(如声称"鲁棒性强"但没做鲁棒性实验)——审稿人会逐条核对贡献和实验的对应,对不上就质疑。贡献列表是实验结果的"提炼",不是"愿望清单"。
**② 手把手带做**
1. 打开阶段一的 Intro 贡献列表(1/2/3)。
2. 每条改成带真实数字:"在 3 数据集平均提升 X% / 参数仅 Y M / FPS Z"。
3. 确保每条贡献都能在实验里找到对应证据。
**③ 合格样例**:贡献 1/2/3 都带具体数字,且每条可被你的实验表验证。
**④ 常踩的坑**
- **贡献写空话**(无数字)→ 用三数据集整合大表里最强的对比项填数字。
- **数字和实验对不上** → 用最终实验的真实数字(别凭印象)。
- **贡献和正文不呼应** → 每条贡献对应正文一处。
**⑤ 卡住自救(决策树)**:不知用哪个数字?→ 用整合大表里"你 vs 最强 baseline"的提升、参数/FPS 优势;数字一般、不亮眼?→ 强调"高效"维度(单卡、小参数、高 FPS)也是有力贡献。
**⑥ 今天(这一步)你同时学会了什么**:你学会**用数字强化贡献**。**做了**(贡献数字化)、**学了**(具体数字的说服力、贡献要可验证)、**会了**(把成果写成有数字的贡献)。

## 中午段 · 更新 teaser figure

**① 先垫概念**:**teaser figure**(第一页大图)是审稿人第一眼看到的,要反映**最终方法 + 关键结果**——经典布局:左=问题示意、中=方法概览、右=关键结果(你 vs SOTA 的提升)。
- **为什么 teaser 是论文的"第一印象担当"**:审稿人翻开你的论文,第一眼看到的往往是第一页右上角的 teaser figure(还没读正文)。**这张图在几秒内就给审稿人定下了对你工作的初步印象**——如果它清晰地讲出"什么问题、你怎么解决、效果多好",审稿人会带着正面预期读下去;如果它杂乱、看不懂、或显得平淡,第一印象就差了。**teaser 和 Abstract 一样,是"投入产出比极高"的部分**:一张图,影响审稿人对整篇论文的初始判断。
- **经典 teaser 布局(左-中-右)**:① **左=问题**(用一张图/示意展示你要解决的问题,如"baseline在密集小目标上漏检一片");② **中=方法**(你的方法概览/核心思路);③ **右=结果**(最亮眼的对比,如"Ours全检出"或一个突出的提升数字)。**这个"问题→方法→结果"的视觉叙事,让审稿人一眼看懂你做了什么、好在哪**。也可以是其他布局,但核心是"一眼讲清问题-方法-结果"。
- **teaser 必须反映最终方法(别用旧版)**:你经过 M5 的迭代删了组件、定了最终方法,teaser 也要同步更新——别还画着早期版本的方法。**图、文、码必须一致**(这是贯穿写作的铁律)。teaser 里展示的方法和结果,要和你 Method 章、Experiment 章里的最终版一致。
- **teaser 要"一眼能懂",别信息过载**:teaser 的目的是快速传达核心,不是塞满细节。**信息太多、太复杂反而让人看不懂、抓不住重点**。保持简洁:突出"问题-方法-结果"这条主线,删掉次要元素。不会设计就仿你读过的 A 级论文的 teaser 布局(它们的 teaser 通常都很精炼)。
**② 手把手带做**
1. 更新 teaser:左问题 / 中方法 / 右结果。
2. 右侧放一个最亮眼的结果数字或对比小图。
3. 确保反映的是最终方法(不是旧版)。
**③ 合格样例**:teaser 一眼讲清"问题→方法→结果",且是最终方法。
**④ 常踩的坑**:teaser 还停在旧方法 → 同步;太复杂(信息过载)→ 一眼能懂为佳。
**⑤ 卡住自救**:不会设计?→ 仿你读过的 A 级论文的 teaser 布局。
**⑥ 今天(这一步)你同时学会了什么**:你更新了论文门面图。**做了**(teaser 更新)、**学了**(teaser 的作用与布局)、**会了**(做一张"问题-方法-结果"一目了然的图)。

## 晚上段 · 完善 Introduction 最终版

**① 先垫概念**:确保 Intro 四段结构(背景→挑战→方法概述→贡献)完整、连贯、有力,与最新实验一致。
- **Introduction 四段结构(论文写作的经典套路)**:① **背景**——点明任务领域及其重要性(3-4句即收敛,别整段泛讲遥感);② **挑战/Gap**——现有方法的关键不足(你要解决的那个问题);③ **方法概述**——你怎么解决这个Gap(核心思路一段);④ **贡献列表**——你的贡献(带数字,bullet形式)。**这四段构成一个"漏斗":从宽泛的背景,逐步收窄到你的具体贡献**,引导读者自然地进入你的工作。
- **背景段最容易写错(太长太泛)**:新手写背景常常整段泛讲"遥感多重要、深度学习多火"——这是浪费,审稿人不需要被科普。**背景应该3-4句就快速收敛到你的具体问题**:点一下任务的重要性,然后立刻转向"但是有个问题没解决好"。**背景的作用是铺垫你的Gap,不是写综述**。收敛得越快越好。
- **四段要"一条线不断"**:背景引出挑战(这个领域重要,但有个Gap)→ 挑战引出方法(为解决这个Gap,我们提出…)→ 方法引出贡献(我们的贡献是…)。**段落之间要有过渡,逻辑承接,不能跳跃**。读者顺着这四段读下来,应该感觉"水到渠成"——为什么做这个问题、为什么这么解决、贡献是什么,一气呵成。
- **Intro 要"与最新实验一致"**:你的Intro是阶段一写的占位版,现在有了完整实验,要更新——尤其贡献列表要数字化(D141上午做的)、方法概述要反映最终版(删了组件的)。**Intro作为论文的"门面章",必须和最终的方法、实验一致**,别还停留在早期版本。通读Intro四段,润色到连贯有力、与最新成果一致,然后定稿。
**② 手把手带做**
1. 通读 Intro 四段,润色(逻辑连贯、删冗余、术语一致)。
2. 确保"背景→挑战→方法→贡献"一条线不断。
3. 定稿。
**③ 合格样例**:Introduction 最终稿(四段完整、贡献带数字、一条线连贯)。
**④ 常踩的坑**:背景太长(整段泛讲遥感)→ 3-4 句即收敛到你的 Gap;段落跳跃 → 加过渡。
**⑤ 卡住自救**:某段不顺?→ 用 Intro 4 段模板逐段对照补。
**⑥ 今天(这一步)你同时学会了什么**:你定稿了 Introduction。**做了**(Intro 最终稿)、**学了**(Intro 四段连贯)、**会了**(打磨引言到有力)。

## 上午段 · 升级 Related Work(补最新引用)

**① 先垫概念**:这几个月你跟进了新 arXiv,RW 要补 2–3 篇最新(尤其 2024–2025)引用,显示你了解前沿。补进对应子节(总结其思路 + 与你的差异)。
- **为什么 RW 要"跟上最新"**:你做实验、写论文的这几个月,你的方向一定有新论文出来。如果你的Related Work停留在一年前、缺了最近的重要工作,审稿人(领域专家,知道最新进展)会觉得"作者没跟上前沿、文献调研不够"——这是减分。**补上2-3篇最新的(尤其2024-2025)相关工作,显示你了解领域最新动态、文献功课做得足**。这也呼应了你W18做实验时跟进arXiv的习惯——那时记的最新方法,现在补进RW。
- **补引用要"归类+说差异",不是堆砌**:补最新工作不是简单加几个引用就完事——每篇要**①归类**(放进它所属的技术子方向,如"基于Transformer的检测方法"那一节)、**②一句话总结其思路**、**③说清和你工作的差异**。**RW的价值在于"梳理+定位",不是"罗列"**——你要让读者看到这些工作各属什么流派、你的工作和它们什么关系。堆一堆不归类、不说差异的引用,反而显得乱。
- **最新方法和你"撞车"了怎么办(别慌)**:有时你会发现最近出的某篇工作和你的idea比较接近——别慌。**这恰恰说明你的方向是热点、有价值**(大家都在做);你要做的是在RW里引用它,并**强调你和它的差异点**(你的角度/方法/侧重不同)。只要你有明确的差异化(不是完全一样),"有相似工作"不影响你发表,反而证明方向重要。这和你M3查重时学的"类似但不同是好事"是一个道理。
**② 手把手带做**
1. 把跟进到的最新方法补进 RW 对应子节。
2. 每篇:一句思路 + 与你工作的差异。
3. 确保归类(放进它该在的子方向)。
**③ 合格样例**:RW 含 2–3 篇最新引用,说清与你工作的关系/差异。
**④ 常踩的坑**:堆引用不归类 → 放进对应子类;最新方法和你撞 → 强调差异点(不慌)。
**⑤ 卡住自救**:不确定放哪子节?→ 按"它属于哪个技术流派"归。
**⑥ 今天(这一步)你同时学会了什么**:你让 RW 跟上了前沿。**做了**(RW 补引用)、**学了**(RW 保持时效)、**会了**(纳入最新工作并归类)。

## 中午段 · 确保 RW 末段自然引出你的方法

**① 先垫概念(RW 末段是关键)**:末段做"过渡"——先总结前人共性不足,再一句引出你的工作:"尽管上述方法在 X 取得进步,但普遍忽略 Y。为此,本文提出…" 这一段把 RW 和你的方法**焊接**起来。
- **为什么 RW 末段是整章的"灵魂"**:Related Work 不是为了"罗列前人做了什么"(那是文献综述),而是为了**论证"前人都没解决你要解决的那个 Gap",从而衬托出你工作的必要性**。而这个论证的落点就在末段——前面各子节介绍了各类前人方法,末段要**收口**:总结这些方法的共性不足(都忽略了 Y),然后引出"为此本文提出…"。**没有这个收口,RW 就只是一堆引用的堆砌,起不到"铺垫你的工作"的作用**。
- **末段的标准句式(套用)**:"尽管上述方法在 [X方面] 取得了进步,但它们普遍 [共性不足:忽略了Y / 依赖Z / 在W场景下失效]。为解决这一问题,本文提出 [你的方法]…"——这个句式把"前人不足"和"你的方法"焊接起来,形成自然过渡。**RW 末段不是戛然而止于最后一个引用,而是要有这个明确的"承上启下"**。
- **RW 的深层作用:为你的 Gap 做合法性背书**:你在 Intro 里声称"有个 Gap",凭什么读者信?**RW 就是证据**——通过系统梳理前人工作并指出它们的共性不足,你证明了"这个 Gap 确实存在、确实没被解决",从而你的工作"确实有必要"。所以 RW 末段总结的"共性不足",必须正好对应 Intro 提的 Gap、Method 解决的问题——**三者一致,逻辑链才闭合**(这也是 D142 晚上逻辑链检查要核对的)。
**② 手把手带做**
1. 打磨 RW 最后一段成上述过渡句式。
2. "共性不足 → 引出本文"。
**③ 合格样例**:RW 末段自然过渡到你的工作。
**④ 常踩的坑**:末段没过渡(戛然而止)→ 加"共性不足→引出本文";过渡生硬 → 用模板句式。
**⑤ 卡住自救**:不会写过渡?→ 套"尽管…取得进步,但…忽略…为此本文提出…"。
**⑥ 今天(这一步)你同时学会了什么**:你学会用 RW 末段衔接到自己工作。**做了**(RW 末段)、**学了**(过渡段写法)、**会了**(从 RW 引向 Method)。

## 晚上段 · 通读四章逻辑链

**① 先垫概念**:通读 Intro+RW+Method+Experiment,检查"**问题→前人工作→我的方法→实验验证**"是否流畅(一条线)。Intro 提的 Gap,Method 是否解决它,RW 是否为它铺垫,Experiment 是否验证它。
- **为什么"逻辑链一条线"是论文说服力的根基**:一篇有说服力的论文,四个主要章节应该串成**一条完整的论证链**:Intro 提出"有个 Gap(问题 X 没解决好)"→ RW 铺垫"前人确实没解决 X"→ Method"我们用 Y 解决 X"→ Experiment"实验证明 Y 确实解决了 X"。**这条线必须首尾呼应、环环相扣**——Intro 说要解决的问题,正是 Method 解决的问题,正是 Experiment 验证的问题。如果这条线断了(如 Intro 说要解决 A,但 Method 解决的是 B,Experiment 验证的又是 C),论文就散了、不可信。
- **逻辑链最常见的三种"断点"**:① **Gap 和 Method 对不上**——Intro 强调的问题,Method 其实没针对它(为创新而创新,加的组件和声称要解决的问题无关);② **贡献和实验对不上**——Intro 列的贡献,Experiment 里没有对应的验证;③ **术语前后不一致**——同一个东西在不同章节叫不同名字(Method 叫"多尺度融合模块",Experiment 叫"MSF",读者以为是两个东西)。**通读时重点抓这三种断点**,把它们对齐。
- **怎么检查逻辑链(可操作)**:把四章并排读一遍,边读边问:"Intro 提的那个 Gap,在 RW 里有没有说清前人为什么没解决?在 Method 里是不是真的针对它设计?在 Experiment 里有没有实验专门验证它解决了?"——**顺着这条线走一遍,卡住或对不上的地方就是逻辑断点**。最有效的方法是"假装第一次读"(放慢、不脑补),你太熟自己的工作,容易自动补全断裂处,反而发现不了。
- **为什么现在(写作中期)就要查逻辑链**:逻辑断点越早发现越好改——现在改可能只是调几句话、统一个术语;等论文都写完、投出去被审稿人指出"你的方法和你声称要解决的问题不符",那就是大返工甚至被拒。**逻辑链是论文的骨架,趁还在写作阶段就把骨架捋直**,后面填血肉(润色、补细节)才不会白费。
**② 手把手带做**
1. 并读四章。
2. 标逻辑断点/重复/前后不一致。
3. 列问题清单。
**③ 合格样例**:四章逻辑链检查 + 问题清单。
**④ 常踩的坑**:Gap 与 Method 对不上 → 调一致("提的问题=解决的问题");术语不统一 → 统一。
**⑤ 卡住自救**:看不出问题?→ 假装"第一次读"通读,卡住的地方就是问题。
**⑥ 今天(这一步)你同时学会了什么**:你练了全篇逻辑链审视。**做了**(逻辑链检查)、**学了**(四章一条线)、**会了**(把多章串成连贯论证)。

> **技能卡｜论文逻辑链**:Intro 提的 Gap → RW 铺垫(前人没解决它)→ Method 解决它 → Experiment 验证解决了。一条线不断,论文才有说服力。

# D143 周三 · Conclusion + Limitation + 参考文献

> 今天写 Conclusion(简洁有力、不重复 Intro)、Limitation,并把参考文献规范成 BibTeX。
>
> **预期管理**:今天写 Conclusion + Limitation + 规范参考文献(BibTeX)。提醒:Conclusion 要简洁有力、**不重复 Intro**(换角度精炼,不是复制粘贴);Limitation 要从 per-class 最差类/迁移掉点/负面案例提炼**具体**局限(别泛泛说"还有提升空间"),主动写局限=学术诚实=审稿人更信你;参考文献核对正文 \cite ↔ 文献列表一一对应(漏引/格式乱是低级失分)。

## 上午段 · 写 Conclusion(≥400 字)

**① 先垫概念(Conclusion 模式)**:段1 "本文提出 X 解决 Y,通过 Z 实现…";段2 "在 3 数据集实验表明…";段3 "然而在…仍有局限,未来计划…"。**简洁有力,不重复 Intro**(换角度精炼,不是复制粘贴)。
- **为什么 Conclusion 不能照抄 Intro(常见错误)**:很多新手的 Conclusion 就是把 Intro 的贡献列表复制过来、换几个词——这是浪费。**Conclusion 和 Intro 的视角不同**:Intro 是"我将要做什么"(展望式,引出工作);Conclusion 是"我已经做了什么、证明了什么"(总结式,带着实验结果回看)。**Conclusion 要站在"实验已经完成"的角度,精炼地总结你证明了什么、有什么价值、还有什么不足**,而非重复 Intro 的承诺。读者读到 Conclusion 时已经看过全文,你要给的是"回味式的总结",不是"重复式的复读"。
- **三段式各自的作用**:① **段1 总结贡献**——用一两句话概括"本文提出X、解决Y、怎么做的",这是浓缩版的核心;② **段2 实验佐证**——用关键数字回扣"实验证明了它有效"(如"在3个数据集上达到SOTA、且更高效");③ **段3 局限+展望**——诚实指出方法的不足和未来方向。**这三段构成一个完整的"收尾":说了做什么、证明了有效、也坦承了边界**,简洁有力。
- **Conclusion 要"简洁有力"**:它不是再写一遍正文,而是高度浓缩的收尾(≥400字但不宜太长)。每句话都要有信息量,别注水。读者读完Conclusion,应该对"这篇论文做了什么、值多少、还差什么"有一个清晰的整体印象。**好的Conclusion让读者合上论文时记住你工作的核心**。
**② 手把手带做**
1. 写 Conclusion(≥400 字):3-4 句总结贡献 + 2-3 句局限 + 2-3 句展望。
2. 用上面三段模式。
3. 检查不与 Intro 重复。
**③ 合格样例**:Conclusion 稿(≥400 字,三段式,不与 Intro 雷同)。
**④ 常踩的坑**:照抄 Intro → 换角度精炼;太长 → 收紧。
**⑤ 卡住自救**:写不出?→ 套三段模式填。
**⑥ 今天(这一步)你同时学会了什么**:你写了 Conclusion。**做了**(Conclusion 稿)、**学了**(Conclusion 三段式)、**会了**(简洁收尾全文)。

## 中午段 · 写 Limitation & Future Work

**① 先垫概念**:Limitation & Future Work(可并入 Conclusion 或单列):方法在什么场景不好 + 未来怎么改。**主动写局限 = 学术诚实与成熟**(审稿人更信你)。
- **为什么"主动写局限"反而让审稿人更信任你(反直觉)**:新手怕写局限——觉得"暴露弱点会让审稿人拒我"。**恰恰相反**:任何方法都有局限(没有完美的方法),审稿人心里清楚这一点。如果你**主动、诚实地指出自己方法的不足**,审稿人会觉得"这作者客观、清醒、了解自己工作的边界"——反而更信任你**其它**的结论(因为你不是个只会自吹的人)。而如果你回避局限、把方法吹得天花乱坠,审稿人反而会警惕、会主动去挑你的毛病。**主动认怂 = 学术成熟的标志,是加分而非减分**。
- **Limitation 要"具体到场景/类别",别泛泛**:最忌讳写"我们的方法还有提升空间""未来可以进一步改进"这类空洞的废话——这等于没写,审稿人一看就知道你在敷衍。**好的 Limitation 是具体的**:"我们的方法在[某类别,如极小目标]上提升有限(per-class显示仅+0.3),推测因为[原因];在跨域迁移设置下优势减弱(掉点X),表明[域适应能力不足]。"——具体到哪类、哪个场景、掉了多少、可能为什么。**具体的局限才显得你真的深入分析过自己的方法**。
- **Limitation 从哪里找(现成素材)**:你不用凭空想局限——**你的实验里就有现成的"不足证据"**:① per-class 分析里**提升最小甚至下降的那些类**;② 跨数据集迁移实验里**掉点明显的地方**;③ 可视化里的**失败案例(负面案例)**。这三处正是你方法的真实局限所在,把它们提炼成 Limitation 即可。**所以前面让你做 per-class、迁移、负面可视化,现在都成了写 Limitation 的素材**。
- **Future Work 要"针对局限"**:Future Work 不是随便列几个"未来方向",而是**针对你刚写的局限,提出对应的改进思路**——"针对极小目标提升有限的问题,未来可探索[某方法];针对跨域能力不足,未来可引入[域适应技术]。"**局限和展望要呼应**:你指出了什么不足,就展望怎么改进它。这样的 Limitation & Future Work 才是有机的整体,而非两段不相干的话。
**② 手把手带做**
1. 写 Limitation:从 per-class 最差类/迁移掉点/负面案例提炼具体局限。
2. 写 Future Work:针对局限的改进方向。
**③ 合格样例**:Limitation & Future Work 段(诚实、具体)。
**④ 常踩的坑**:回避局限 → 主动写;宽泛("还有提升空间")→ 具体到场景/类别。
**⑤ 卡住自救**:不知写啥局限?→ 看 per-class 最差类、迁移实验、负面可视化。
**⑥ 今天(这一步)你同时学会了什么**:你写了局限与展望。**做了**(Limitation 段)、**学了**(局限的价值、要具体)、**会了**(诚实写不足)。

## 晚上段 · 检查参考文献格式(BibTeX)

**① 先垫概念**:确保正文所有引用都在 reference list 里、格式统一(BibTeX)。漏引/格式乱是低级失分。
- **为什么参考文献是"低级但致命"的失分点**:参考文献本身不关于你的方法好坏,但**漏引、格式混乱会给审稿人留下"作者不严谨、不认真"的坏印象**——这是低级错误(本可以避免),但很影响观感。常见问题:正文`\cite`了某文献但reference list里没有(编译时显示`??`或报错)、不同文献格式不统一(有的全名有的缩写)、该引的没引(显得你没读够相关工作)。**这些都是"细节",但细节体现专业度**,而且很容易被审稿人注意到。
- **核心检查:正文 \cite ↔ 文献列表一一对应**:每个在正文里`\cite`的文献,都必须在reference list里有对应条目;反之列表里的每个条目,最好都在正文被引用过(没引用的可删)。**这个"双向对应"是参考文献正确的基本要求**。文献多时(几十篇),人工核对容易漏,用脚本自动找"引了但列表没有"和"列表有但没引"的,效率高。
- **用 BibTeX 管理(标准做法)**:学术论文用BibTeX管理参考文献——每个文献一个bib条目(含作者/标题/会议期刊/年份),正文用`\cite{key}`引用,LaTeX自动生成格式统一的reference list。**好处是格式自动统一**(不用手动排版每条文献)、引用和列表自动对应。整理bib条目时,从Google Scholar/DBLP直接导出BibTeX(别手敲,易错),核对关键信息(尤其会议/期刊名、年份)正确。
**② 手把手带做**
1. 整理 BibTeX 条目。
2. 核对正文 `\cite` ↔ 文献列表一一对应(用补充包脚本)。
3. 统一格式。
**③ 合格样例**:参考文献初步整理(无漏引、格式统一)。
**④ 常踩的坑**:引用了但列表没有(编译挂/漏引)→ 补;格式乱 → 统一 bib 条目。
**⑤ 卡住自救**:量大?→ 用补充包的 cite↔bib 检查脚本自动找漏。
**⑥ 今天(这一步)你同时学会了什么**:你规范了参考文献。**做了**(参考文献整理)、**学了**(BibTeX 规范、cite↔bib 一致)、**会了**(核对引用完整性)。

**① 先垫概念(Abstract 最重要)**:**90% 的读者只读 Abstract**。它要在 200 词内讲清:① 做什么任务 ② 现有方法什么问题 ③ 你怎么解决 ④ 效果如何。**4 句结构:背景→问题→方法→结果**。

- **Abstract 里一定要有数字**:很多新手的 Abstract 全是定性描述("取得了优异性能""显著优于现有方法")——没有数字就没有说服力。**至少放一个关键结果数字**(如"提升1.8 mAP"或"参数量减少30%"),让读者在摘要里就 get 到你工作的实质。数字是 Abstract 可信度的来源。
- **别堆形容词(每个词都要有用)**:Abstract 篇幅极有限(200词),容不下水分。"novel""effective""powerful"这类没有数字支撑的空洞形容词要删——它们不传递信息,只占字数。**每个词都要为"讲清4要素"服务**,删掉任何删了不影响理解的词。精炼到"每个词都有用"的程度。

## 中午段 · 写 Abstract v2(精简)

**① 先垫概念**:精简 v1,让**每个词都有用**(删冗余形容词、合并句子)。
- **为什么 Abstract 精简如此重要**:Abstract只有200词的预算,却要讲清4要素——**容不下任何水分**。v1往往啰嗦:有冗余的形容词(novel/effective/powerful 这类没数字撑的空词)、有可以合并的啰嗦句、有重复的意思。精简就是把这些挤掉,让**省下的宝贵字数用来讲清楚要素、放关键数字**。一个精简到"每个词都有用"的Abstract,信息密度高、读起来紧凑有力。

**④ 常踩的坑**:堆形容词无数字 → 用数字代替形容。
**⑤ 卡住自救**:砍不动?→ 问每句"删了影响理解吗?"不影响就删。
**⑥ 今天(这一步)你同时学会了什么**:你练了精简表达。**做了**(Abstract v2)、**学了**(精简、每词有用)、**会了**(去掉摘要水分)。

**① 先垫概念(润色的度)**:AI 工具(Grammarly/Claude)能改语法,但**不能替你改逻辑**——**先确保逻辑对了再润色**。**别把中文直译**成英文,学学术英语句式(建"句式库",下次复用)。
- **为什么润色要"先逻辑、后结构、最后语法"(顺序不能反)**:如果你逻辑还没理顺(论证有断点、章节有矛盾)就先猛抠语法,那是**本末倒置**——把一句逻辑有问题的话的语法改得再地道,它still逻辑有问题;而且你可能为了语法美化大改措辞,结果逻辑问题被措辞掩盖、更难发现。**正确顺序:① 先逻辑(论证对不对、四章一条线吗)→ ② 再结构(段落顺不顺、过渡好吗)→ ③ 最后语法(地道不地道、有没有语病)**。前两层是"硬伤",必须先解决;语法是"打磨",放最后。
- **AI 工具能做什么、不能做什么(摆正定位)**:Grammarly、Claude 这类工具**擅长**改语法错误、提升表达地道度、润色措辞——这些机械性的语言工作可以放心交给它们。**但它们不能替你把关逻辑**:它们不知道你的方法对不对、贡献和实验对不对、论证有没有断点——这些**必须你自己负责**。所以用 AI 润色时,定位清楚:**让它改语言层面,逻辑层面你自己守**。别指望 AI 帮你发现"你的 Method 和 Experiment 矛盾"。
- **为什么"别中译英"、要学地道句式**:很多人写英文论文是"先想中文、再逐字翻译"——结果是 Chinese English(中式英语):语法可能没错,但表达生硬、不像英文母语的学术写作,审稿人一读就觉得别扭。**正确做法是直接用英文的学术句式思考和写作**。怎么学?读你领域 A 级论文时,留意它们怎么表达常见意思(怎么说"我们提出"、怎么说"实验表明"、怎么做过渡),**把这些地道句式收进一个"句式库"**,下次写作直接套用。久而久之,你的英文学术表达就地道了。这是个长期积累、复利很高的习惯。
**② 手把手带做**
1. 用工具过一遍语法/表达。
2. 把好句式收进 `paper/句式库.md`。
3. 重点改"中式英语"处。
**③ 合格样例**:语法/表达润色完成 + 句式库新增几条。
**④ 常踩的坑**:逻辑没理顺就猛润色 → 先逻辑后语法;中式英语 → 学地道句式。
**⑤ 卡住自救**:某句不会写?→ 找 A 级论文同类句式仿写,存进句式库。
**⑥ 今天(这一步)你同时学会了什么**:你学会**润色顺序 + 积累句式**。**做了**(英文润色 + 句式库)、**学了**(先逻辑后语法、学术英语)、**会了**(打磨语言并沉淀句式)。

> **技能卡｜润色顺序**:先逻辑(对不对)→ 再结构(顺不顺)→ 最后语法(地道不地道)。AI 改语法,逻辑你自己把关;别中译英,建句式库。

## 二、实用工具 — 引用完整性检查 + 论文词数粗估
```python
import re
# ① 检查 \cite 的 key 是否都在 .bib(避免漏引/编译挂)
def check_citations(tex_path, bib_path):
    cited = re.findall(r'\\cite[tp]?\{([^}]+)\}', open(tex_path,encoding="utf-8").read())
    cited = {k.strip() for grp in cited for k in grp.split(",")}
    bib_keys = set(re.findall(r'@\w+\{([^,]+),', open(bib_path,encoding="utf-8").read()))
    print("引用但 bib 缺失:", cited - bib_keys or "无")
    print("bib 有但未引用:", bib_keys - cited or "无")
# ② 粗估正文词数(英文论文)
def count_en_words(tex_path):
    t = re.sub(r'%.*', '', open(tex_path,encoding="utf-8").read())
    t = re.sub(r'\\[a-zA-Z]+\*?(\[[^\]]*\])?(\{[^}]*\})?', ' ', t)
    print("正文词数(粗估):", len(t.split()))
if __name__ == "__main__":
    print("用法:检查 cite↔bib 一致性;粗估词数")
```

## 四、本周写作坑速查表
| 现象 | 根因 | 解法 |
|---|---|---|
| 贡献写空话 | 没用数字 | 用真实实验数字；数字一般主打"高效" |
| teaser/图还是旧方法 | 没同步 | 更新到最终方法 |
| Conclusion 重复 Intro | 没换角度 | 换角度精炼，加局限/展望 |
| Abstract 太长/太泛 | 没迭代 | 4 句结构、200 词内、迭代 5 版 |
| 图模糊/字小 | 低分辨率 | ≥300 DPI 或矢量；放大字号 |
| 漏引/bib 格式乱 | 没核对 | cite↔bib 一致性检查脚本 |
| 中式英语 | 直译 | 学学术句式，建句式库 |
| 各章拼一起不顺 | 没整合通读 | 整合后从头通读、查逻辑链与过渡 |
| RW 戛然而止不引出方法 | 末段没过渡 | 套"尽管…取得进步,但…忽略…为此本文提出" |
| 回避 Limitation | 怕暴露弱点 | 主动写(反增信任),从per-class最差类/迁移掉点/负面案例提炼 |
| 逻辑没理顺就猛润色 | 顺序反了 | 先逻辑→再结构→最后语法;AI改语法,逻辑你把关 |
| Intro 背景整段泛讲 | 没快速收敛 | 背景3-4句即收敛到你的Gap |
