# D10 · ReDet + 看懂三条曲线 + S²A-Net

## 上午段 · 精读 ReDet

### 0. 拿到论文

```text
Han, J., Ding, J., Xue, N., Xia, G.-S.
"ReDet: A Rotation-equivariant Detector for Aerial Object Detection"
CVPR 2021, pp. 2786-2795
```

arXiv 搜标题即可；CVPR 论文在 `openaccess.thecvf.com` 有免费官方 PDF。

### ★ 完整导读

**它要解决什么**（一句话）：

> 前面那些方法（含 Oriented R-CNN）都是**让网络自己从数据里学"旋转不变性"**。ReDet 的想法是：**别学了，直接把旋转不变性做进网络结构里。**

**核心概念：等变（equivariant）vs 不变（invariant）**——这是全书没解释过、但读这篇必须先懂的：

| 词 | 意思 | 例子 |
|---|---|---|
| **等变（equivariant）** | 输入转了，输出**跟着转** | 图转 90°，特征图也转 90° |
| **不变（invariant）** | 输入转了，输出**不变** | 图转 90°，识别结果还是"飞机" |

**ReDet 的两步设计**：

```text
① 旋转等变 backbone（ReResNet）
   → 图像旋转时，特征跟着旋转，网络"知道"发生了旋转
        ↓
② 旋转不变 RoI Align（RiRoI Align）
   → 从等变特征里，抽出"和朝向无关"的表示
        ↓
结果：同一个目标不管朝哪，提取到的特征一致 → 检测更稳，参数还更少
```

**★ 一个生活类比**：等变 backbone 像一个**装了指南针的相机**——你转动它，它知道自己转了多少度。不变 RoI Align 像**根据指南针读数把照片摆正**——不管你怎么转，最后得到的照片都是正的。

### ★ 自检三问

1. 等变和不变有什么区别？（答：见上表）
2. ReDet 为什么参数反而更少？（答：旋转不变性由结构保证，不用靠大量参数去"死记"各种朝向）
3. 它和 Oriented R-CNN 的思路差在哪？（答：Oriented R-CNN 优化的是"怎么高效生成旋转框"，ReDet 优化的是"怎么提取与朝向无关的特征"——**一个在框，一个在特征**）

### ★ 第 4 段（启发）可以这样写

```markdown
- 模板A：ReDet 的等变 backbone 需要专门设计和预训练（ReResNet），
  换 backbone 的成本很高。→ 如果我想用最新的 backbone（如 Swin、ConvNeXt），
  这套等变设计能不能迁移？这是个具体的口子。
```

| 病征 | 最可能原因 | 怎么确认 |

| loss 长期持平 | lr 太小，或标注为空 | 看 `acc` 是不是一直 100%（空标注的特征） |

## 晚上段 · S²A-Net 泛读 + 四大家族对比表

### S²A-Net 导读（泛读，20 分钟）

```text
Han, J. et al. "Align Deep Features for Oriented Object Detection"
IEEE TGRS 2022
```

**一句话**：它解决的是**特征和框对不齐**的问题。

**什么叫"对不齐"**（这是全书没解释的关键概念）：

> 检测头在特征图的某个位置做预测，但那个位置的特征是按**水平**的感受野提取的，而目标是**斜**的。**特征"看"的区域和目标实际占的区域不重合**——这就是 misalignment。

S²A-Net 用两个模块解决：先粗略生成旋转框（FAM），再**按这个框去对齐特征**（ODM），然后基于对齐后的特征做最终预测。

### ★ 四大家族对比表（原文让你画，这里给填好的骨架）

| 家族 | 代表 | 核心思路 | 优点 | 代价 | 一句话记忆 |
|---|---|---|---|---|---|
| **旋转 RoI 变换** | RoI Transformer (2019) | 先出水平 RoI，再学着转成旋转 RoI | 精度高，思路直观 | 多一个模块，慢 | **"先水平后掰弯"** |
| **高效旋转 proposal** | **Oriented R-CNN (2021)** | RPN 里多回归 2 个偏移，直接出旋转 proposal | 又快又准，实现简洁 | — | **"RPN 直接出斜框"** |
| **旋转等变** | ReDet (2021) | 把旋转不变性做进网络结构 | 特征更稳，参数更少 | backbone 要专门设计和预训练 | **"给网络装指南针"** |
| **特征对齐** | S²A-Net (2022) | 按预测的框去对齐特征 | 解决 misalignment，单阶段也能准 | 多一次特征变换 | **"让特征跟着框转"** |

**★ 这张表怎么用**：**M3 找 Gap 时，你要问的是"这四条路各自还剩什么没解决"。** 现在先把表建起来，D12 会再加两行凑成六大流派。

## 上午段 · R³Det 导读


**它和 S²A-Net 的关系**：**两者解决同一个问题（特征对齐），思路很像**。区别是 R³Det 强调"可以级联多次精修"。**读完这两篇，你就理解了"单阶段旋转检测"这条线的主要矛盾是什么。**

## 中午段 · 六大流派表

在 D10 那张四大家族表上，补两行：

| 家族 | 代表 | 核心思路 | 一句话记忆 |
|---|---|---|---|
| **单阶段精修** | R³Det (2021) | 粗框 → 特征精修 → 细框，可级联 | **"先画后描"** |
| **改表示 / 改 loss** | Gliding Vertex (2021)、GWD/KLD | **绕开角度回归本身的困难** | **"不回归角度，回归别的"** |

**★ 最后一行是重点**，因为它指向 [《名词逐个讲透》§5.2](../start/rs-basics-deep.html) 说的**角度周期性问题**：−89° 和 +89° 几何上几乎相同，数值上差 178°，直接回归角度会在边界处炸掉。

- **Gliding Vertex** 的解法：不直接回归角度，而是回归**水平框四条边上的滑动比例**。
- **GWD / KLD** 的解法：把框建模成**二维高斯分布**，用分布之间的距离当 loss——**角度周期性问题自然消失**。

> **★ 这一行是你 M3 最可能的选题来源之一。** 原因：它是纯方法层面的问题、有清晰的数学表述、不需要大算力、且至今没有公认最优解。**现在就把它标记出来。**

# D13 · vis_results.py（含旋转框 IoU 完整实现）

> **原文在这里明确放弃了**："IoU 算旋转框较复杂 → 第一次可先只画框、不算 IoU"。
>
> **但没有 IoU，你就分不清"检对"和"误检"**，那张图的价值就少了一半。**旋转框 IoU 其实不复杂**，OpenCV 有现成的求交函数。下面是完整实现，**我实测跑过，并用解析解对拍验证过**。

## ① 先垫概念

### 旋转框 IoU 为什么比水平框难

水平框求交很简单：`交集 = max(0, min(x2) - max(x1)) × max(0, min(y2) - max(y1))`。

**旋转框的交集是一个多边形**（可能是 3 到 8 条边），要先求出这个多边形，再算它的面积。

**好消息：OpenCV 自带这个功能。**

```python
cv2.rotatedRectangleIntersection(rect1, rect2)
```

它返回交集区域的顶点，再用 `cv2.contourArea` 算面积即可。**三行搞定，不需要装 shapely。**

### TP / FP / FN 是什么（全书没解释，但读 per-class AP 必须懂）

| 缩写 | 全称 | 含义 | 在图上 |
|---|---|---|---|
| **TP** | True Positive | 预测框和某个 GT 的 IoU ≥ 阈值 → **检对了** | 绿框 |
| **FP** | False Positive | 预测框找不到匹配的 GT → **误检** | 黄框 |
| **FN** | False Negative | GT 没有任何预测框匹配上 → **漏检** | 粗红框 |

**匹配规则**（这就是 mAP 计算的内核）：**按预测分数从高到低，每个预测去抢还没被占用的、IoU 最大的那个 GT。** 抢到就是 TP，抢不到就是 FP。剩下没被抢的 GT 就是 FN。

## ② 手把手带做：完整代码

新建 `20-代码实验/utils/vis_results.py`：

```python
"""vis_results.py —— 画 预测框(绿) vs GT框(红)，算旋转框 IoU，标出 对/错/漏。

框的格式统一为 (cx, cy, w, h, angle_deg)，预测框可多带一个 score：
    gt   = (cx, cy, w, h, angle)
    pred = (cx, cy, w, h, angle, score)
"""
import cv2
import numpy as np


def obb_to_corners(box):
    """(cx,cy,w,h,angle_deg) -> (4,2) 角点。直接用 OpenCV，不用自己写三角函数。"""
    cx, cy, w, h, ang = box[:5]
    return cv2.boxPoints(((float(cx), float(cy)), (float(w), float(h)), float(ang)))


def obb_iou(a, b):
    """旋转框 IoU。核心就是 rotatedRectangleIntersection 求交多边形。"""
    r1 = ((float(a[0]), float(a[1])), (float(a[2]), float(a[3])), float(a[4]))
    r2 = ((float(b[0]), float(b[1])), (float(b[2]), float(b[3])), float(b[4]))
    ret, region = cv2.rotatedRectangleIntersection(r1, r2)
    if ret == 0 or region is None:          # 完全不相交
        return 0.0
    inter = cv2.contourArea(cv2.convexHull(region))
    union = a[2] * a[3] + b[2] * b[3] - inter
    return float(inter / union) if union > 0 else 0.0


def match(preds, gts, iou_thr=0.5):
    """按分数降序贪心匹配 —— 这就是 mAP 计算的内核。

    返回 (TP的预测下标, FP的预测下标, 漏检的GT下标, {预测下标: IoU})
    """
    if preds and len(preds[0]) > 5:
        order = sorted(range(len(preds)), key=lambda i: -preds[i][5])
    else:
        order = list(range(len(preds)))

    used, tp, fp, ious = set(), [], [], {}
    for pi in order:
        best, best_iou = -1, iou_thr
        for gi, g in enumerate(gts):
            if gi in used:
                continue
            v = obb_iou(preds[pi], g)
            if v >= best_iou:
                best, best_iou = gi, v
        if best >= 0:
            used.add(best)
            tp.append(pi)
            ious[pi] = best_iou
        else:
            fp.append(pi)
    fn = [gi for gi in range(len(gts)) if gi not in used]
    return tp, fp, fn, ious


def draw(img, preds, gts, iou_thr=0.5):
    """GT 红（漏检的画粗）、检对 绿（标 IoU）、误检 黄。"""
    tp, fp, fn, ious = match(preds, gts, iou_thr)

    for gi in range(len(gts)):
        cv2.polylines(img, [obb_to_corners(gts[gi]).astype(np.int32)], True,
                      (0, 0, 255), 4 if gi in fn else 2)      # 漏检加粗
    for pi in tp:
        c = obb_to_corners(preds[pi]).astype(np.int32)
        cv2.polylines(img, [c], True, (0, 255, 0), 2)
        cv2.putText(img, f'{ious[pi]:.2f}', tuple(c[0]),
                    cv2.FONT_HERSHEY_SIMPLEX, 0.5, (0, 255, 0), 1, cv2.LINE_AA)
    for pi in fp:
        cv2.polylines(img, [obb_to_corners(preds[pi]).astype(np.int32)], True,
                      (0, 255, 255), 2)

    return img, dict(TP=len(tp), FP=len(fp), FN=len(fn))


if __name__ == '__main__':
    # 自测：不需要任何数据就能跑，先确认逻辑对
    img = np.full((400, 600, 3), 40, np.uint8)
    gts = [(150, 150, 80, 40, 20), (400, 150, 60, 60, 0), (300, 300, 70, 30, -45)]
    preds = [(155, 152, 78, 42, 22, 0.95),   # 和 gt[0] 高度重合 → 应判 TP
             (420, 160, 60, 60, 5, 0.88),    # 和 gt[1] 偏了一些 → IoU 可能不够
             (520, 320, 50, 50, 0, 0.60)]    # 没有对应 GT → 应判 FP
    img, stat = draw(img, preds, gts)
    cv2.imwrite('vis_results_selftest.jpg', img)
    print(stat)
```

## ③ 合格样例

**直接跑 `python vis_results.py`**（不需要任何数据），应输出：

```text
{'TP': 1, 'FP': 2, 'FN': 2}
```

**读这个结果**：第 1 个预测和第 1 个 GT 的 IoU 是 0.833 → 判 TP；第 2 个预测偏了，IoU 只有 0.389 < 0.5 → 判 FP，对应的 GT 变成 FN；第 3 个预测没有 GT → FP。**逻辑正确。**

然后读 pkl 取框。**MMRotate 的输出格式是**：`result[图片下标][类别下标]` 是一个 `(N, 6)` 数组，每行是 `(cx, cy, w, h, angle_rad, score)`。

**★ 两个坑**：
1. **角度单位是弧度，不是角度**。传给上面的函数前要 `np.degrees(angle)`。
2. **GT 是四点格式**（DOTA 原始标注），要先用 `cv2.minAreaRect` 转成 `(cx,cy,w,h,angle)`——你 D6 的 `poly_to_xywha` 就是干这个的，**直接复用**。

## ④ 常踩的坑

| 坑 | 症状 | 解 |
|---|---|---|
| 弧度当角度传 | 框全歪，IoU 全是 0 | `np.degrees()` |
| GT 和预测格式不统一 | 同上 | 统一转成 `(cx,cy,w,h,角度)` 再比 |
| 预测/GT 同色 | 看不出对错 | 绿/红/黄三色分开 |
| 忘了按 score 排序就匹配 | TP/FP 判定和官方 mAP 对不上 | `match()` 里已经排了 |
| 一张图几百个框，看不清 | 图太乱 | 加 `score_thr` 过滤，只画分数高的 |

## ⑥ 你同时学会了什么

**做了**：一个能判"对/错/漏"的定性分析工具。
**学了**：旋转框 IoU 怎么算、TP/FP/FN 的定义、贪心匹配规则（= mAP 的内核）。
**会了**：**用解析解对拍验证自己写的度量函数**——这个习惯比工具本身值钱。
