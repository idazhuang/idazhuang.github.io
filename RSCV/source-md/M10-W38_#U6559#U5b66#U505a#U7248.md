# D260 周一 · 收到朋友 review → 逐条处理 + 改稿

> **预期管理**：今天的任务是处理上周日发给朋友的那份 review，并据此改稿。提醒：**朋友 review 是"投稿前的自家质量门"**——和正式审稿不同，朋友是站在你这边的、目的是帮你在审稿人之前把问题修掉，所以心态可以放松（不用像读正式审稿那样先平复情绪）。但**处理的纪律要一样严**：逐条读、标三类（必改 / 可改 / 可不改）、按优先级动手。一个好用的认知：**朋友读不懂的地方，审稿人大概率也读不懂**——朋友 review 暴露的每个"卡壳点"，都是你投稿前白赚的一次修补机会。

## 上午段 · 逐条读朋友 review、标三类、列改稿清单

**① 先垫概念（投稿前的朋友 review 是干什么用的，和正式审稿有什么不同）**
- **朋友 review = 投稿前的"预审"**：投稿前找懂科研的朋友通读，提"哪里读不懂、逻辑跳、图表不清"。价值在于**用一次低成本的外部视角，提前发现你自己看不到的问题**——你写久了会"脑补"（自己知道的默认读者也知道），朋友不会，他卡住处就是你表达不清处。
- **和正式审稿的三个不同**：① **立场**——朋友帮你、审稿人挑你（所以不用先"管理情绪"，但要珍惜每条意见）；② **深度**——朋友给"可读性"反馈，正式审稿到"创新性/严谨性"；③ **时机**——朋友 review 在投稿前（从容改），正式审稿在投稿后（有时限）。这是你投稿前最舒服的一次修改机会，要用足——朋友能发现的问题现在全修掉，正式审稿时就能把审稿人注意力留给学术讨论而非"这句话什么意思"。

**② 手把手带做**：把朋友的 review 逐条列出来（一条一行）；给每条标三类——**【必改】**（朋友读不懂/明显错误/图表缺失，这类一定改）、**【可改】**（朋友建议但非必须，如换个表述更顺，权衡后改）、**【可不改】**（朋友的个人偏好或误解，你有充分理由保留，但要想清楚理由）；按"必改优先"排出改稿清单（每条写明：在论文哪个位置、怎么改）。
**③ 这一步合格的样子**：一张"review 处理表"——每条意见对应一个分类（必改/可改/可不改）+ 一句改稿方案 + 论文中的位置。判断标准：看着这张表就能直接动手改，不用再回去重读 review。
**④ 最常踩的坑**
- 朋友说什么都改 / 什么都不改 → 都不对。**标三类、有判断地改**：必改的认真改，可不改的想清楚保留理由（"我保留是因为……"）。
- 只在脑子里记着改、不落表 → 改着改着漏掉几条。**逐条落表、改一条勾一条**，才不遗漏。

**⑤ 卡住怎么自救（决策树）**：拿不准某条是"必改"还是"可不改"？→ 问自己"如果审稿人也这么说，我改不改？"——会改就是必改；朋友的意见你不认同？→ 不是无条件接受，但先想"他为什么会这么理解"（往往暴露你表述有歧义，即使不按他说的改、也该把那句话改得不产生歧义）。
**⑥ 今天（这一步）你同时学会了什么**：你学会**用投稿前的外部 review 提升论文质量（标三类、有判断地处理）**。**做了**（review 处理表 + 改稿清单）、**学了**（朋友 review 的价值与边界、必改/可改/可不改三分法）、**会了**（把外部反馈转化为可执行的改稿计划）。

> **技能卡｜投稿前朋友 review 怎么用**：投稿前找懂科研的朋友通读，提"读不懂/逻辑跳/图表不清"。逐条标三类：【必改】（读不懂/错误/缺图）/【可改】（建议非必须）/【可不改】（偏好或误解，但想清保留理由）。核心认知：**朋友读不懂处=审稿人大概率也读不懂**，是投稿前白赚的修补机会。和正式审稿不同（朋友帮你、给可读性反馈、在投稿前），心态放松但纪律照严。

## 中午段 · 按"必改优先"动手改稿

**① 先垫概念（改稿为什么要按优先级，不是从头改到尾）**
- 改稿不是"从第一页顺着改到最后一页"，而是**按影响优先级改**：先改【必改】（影响读者能否读懂的硬问题），再处理【可改】（锦上添花），【可不改】的只需在心里记着理由。这样即使时间不够，也保证最关键的问题先被解决。
- **和"逐字顺改"对比**：顺着改容易把时间花在无关紧要的措辞上，结果真正重要的"读者卡壳点"反而没时间改透。**按优先级改 = 把有限的精力投在回报最高的地方**——这和你做实验时"先验证最关键假设"是同一个道理。

**② 手把手带做**：打开 review 处理表，**从【必改】开始逐条改**：每改一条，定位到论文对应位置、按方案修改、改完在表上勾掉；改"读不懂"类问题时，重点是**把那段话拆得更清楚**（加一句过渡、补一个定义、拆一个长句）；改图表问题时，确保图注/坐标轴/图例完整。改完所有【必改】，再看时间决定处理多少【可改】。
**③ 这一步合格的样子**：所有【必改】已改完并在表上勾掉；改后的段落重读一遍确实更清楚了（最好的验证：想象朋友再读一遍，他还会卡在这里吗？）。
**④ 最常踩的坑**
- 改 A 处引入 B 处的不一致（如改了方法名称，但别处没同步）→ 改完做一次"波及检查"：这个改动还影响哪里？
- 把"读不懂"理解成"加更多术语显得专业" → 恰恰相反，读不懂往往是**话太绕**，要**改简单**（拆长句、去黑话、补一句大白话解释）。

**⑤ 卡住怎么自救（决策树）**：某段怎么改都觉得绕？→ 试着"用一句话先说结论，再展开"（先给读者锚点）；不确定改完是否更清楚？→ 放一会儿再读，或念出声（拗口=没改顺）。
**⑥ 今天（这一步）你同时学会了什么**：你学会**按优先级高效改稿**。**做了**（按必改优先逐条改 + 波及检查）、**学了**（改稿的优先级思维、"读不懂=改简单不是加术语"）、**会了**（把改稿清单落实成更清楚的论文）。

> **技能卡｜改稿三类优先级**：按影响排序，不顺着从头改到尾。**必改**（读不懂/硬错误/缺图表）先改透；**可改**（措辞）有余力再改；**可不改**（偏好/误解）记理由即可。改"读不懂"的正解是**改简单**（拆长句、补大白话、加过渡），不是堆术语。每改一处做"波及检查"（还影响哪里），避免新的不一致。

## 晚上段 · 继续改稿 + 通读一遍确认改顺了

**① 先垫概念**：改完【必改】后，**再通读一遍全文**很重要——单点修改容易顾此失彼（改了这段忘了那段的衔接），通读能发现"局部改对了但整体读起来卡"的问题。这一遍读的是**连贯性**（段落之间过渡顺不顺、改动有没有破坏原有逻辑流）。
**② 手把手带做**：处理剩余的【可改】项（挑回报高的改）；然后**从头通读一遍改后的论文**，重点看：改动处和上下文衔接顺不顺、有没有改出新的不一致（术语/数字/编号）、整体读下来是否比 v0.6 更清楚；把通读中新发现的小问题随手记下、顺手改掉。
**③ 合格样例**：一份处理完朋友 review 的改稿——【必改】全改、【可改】择优改、全文通读一遍连贯无新坑。这版可以叫 v0.7（比 v0.6 更清楚，但还没到定稿 v1.0）。
**④ 坑**：① 改完不通读 → 容易留下"局部对、整体卡"的衔接问题；② 通读时又开始大改结构 → 现在是打磨不是重写，发现结构性大问题先记下、别这周推翻重来（除非是硬伤）。
**⑤ 自救**：通读发现某处逻辑确实断了 → 加一两句过渡句承接（"基于上述……，我们进一步……"）；发现某个改动其实让原文更差了 → 回退到原版（git 留着 v0.6，可对比）。
**⑥ 今天（这一步）你同时学会了什么**：你学会**改稿后通读把关连贯性**。**做了**（处理可改项 + 全文通读 + 顺手修）、**学了**（单点修改易顾此失彼、通读看连贯性、打磨期不轻易推翻重来）、**会了**（把"改过的稿"收敛成"读起来顺的稿"）。

> **今日交付**：✅ 朋友 review 处理表（标三类）✅ 改稿（必改全改、可改择优）✅ 全文通读一遍（v0.7，连贯无新坑）。

# D261 周二 · 补充实验（如 review 指出需要）+ 更新表格文字

> **预期管理**：今天判断"要不要补实验、补什么"，并把补出来的结果更新进表格和文字。提醒：**补实验是"按需"的，不是"必须"**——如果朋友 review（或你自己 self-check）指出了可预见的审稿质疑（最典型："和最近的方法比过吗？"），那就补；如果没有明显缺口，**不要为补而补**（你 M8–M9 已经做了完整的实验矩阵，方法已是最终版，不需要再大改）。今天的活儿大概率是"小补"——加 1–2 个最新方法的对比、或补一个朋友提到的设置——**复用你 M8–M9 搭好的实验框架，半天到一天能搞定**。

## 上午段 · 判断要不要补实验 + 补什么

**① 先垫概念（投稿前"补实验"补的是什么，为什么大多是小补）**
- 投稿前补实验，补的是**"可预见的审稿质疑"对应的证据缺口**——最常见：① **和最新方法对比**（审稿人最爱问"为什么没和今年的 XXX 比？"）；② 一个被 review 点到的设置/数据集；③ 一个让结论更稳的额外验证（多加一个 seed/数据集）。它**不是**推翻方法重做（M8–M9 已定最终版）。
- **和主实验阶段对比**：M8–M9 是"从无到有跑出方法+baseline+完整消融"（大工程）；投稿前补实验是"在已完整实验上打补丁"（小工程）——框架和 baseline 现成，补一个对比往往只是改个 config 跑一次，这是你前面搭扎实框架的回报。
- **为什么"不为补而补"**：补实验有成本、而你下周要投稿。判断口诀：**这实验缺了，审稿人会不会用它拒稿？** 会就补；不会（只是"有更好"）→ 记进未来工作/supplementary，别卡住投稿。

**② 手把手带做**：列出"候选补实验清单"（来自朋友 review + 你自己 self-check 的疑虑）；逐条判断**【必补】**（不补会被审稿人当硬伤，如缺最新方法对比）/ **【可补】**（补了更好但非必须，时间够再补）/ **【不补】**（可放 supplementary 或未来工作）；对【必补】项，写清楚要跑什么（哪个方法、哪个数据集、什么设置）。如果判断下来"无必补项"（M8–M9 已足够完整），那就**跳过补实验，直接进入 D262 定稿**——这完全合理。
**③ 这一步合格的样子**：一张"补实验判断表"（候选项 + 必补/可补/不补 + 理由）；【必补】项有明确的执行方案（或明确判断"本周无必补项"）。
**④ 最常踩的坑**
- 看到 review 提"要不要试试 X"就无条件去补 → 先判断"不补会不会被当拒稿理由"，是建议性的就别让它拖住投稿。
- 借补实验之名又开始大改方法 → 投稿前方法已封版，补实验是打补丁不是重做；真有大改想法，记进第三课题/未来工作。

**⑤ 卡住怎么自救（决策树）**：不确定某个对比要不要补？→ 看目标期刊近一年同方向论文"标配比哪些方法"，那些就是审稿人的预期；补实验会不会来不及？→ 只补【必补】、用现成框架最快路径跑（小数据集先验证、能说明问题即可）。
**⑥ 今天（这一步）你同时学会了什么**：你学会**判断投稿前该不该补实验（按"会不会被当拒稿理由"决策）**。**做了**（补实验判断表 + 必补项方案）、**学了**（补的是可预见审稿质疑、不为补而补、用现成框架小补）、**会了**（在"补充严谨"和"按时投稿"之间做出合理取舍）。

> **技能卡｜投稿前补实验的判断**：补的是"可预见审稿质疑"对应的证据缺口（最典型：和最新方法对比、被 review 点到的设置、让结论更稳的额外验证），**不是重做方法**。三分法：【必补】（不补会被当拒稿理由）/【可补】（更好但非必须）/【不补】（放 supplementary 或未来工作）。口诀：**这实验缺了，审稿人会不会拒稿？** 复用现成框架，小补半天搞定。

## 中午段 · 补跑实验（复用现成框架，最快路径）

**① 先垫概念（为什么补实验能这么快）**
- 补一个"和最新方法 X 对比"的实验，本质就是：拿 X 的开源代码（或你的框架里实现 X）、用你统一的数据集和评测脚本跑一遍、拿到它的指标填进表。**因为你的数据加载、评测、日志全是现成的**（M3-W11 搭的框架 + M5 起规模化跑的经验），新增一个对比往往只是"加一个 config / 跑一个 baseline"。
- **和第一次跑实验对比**：第一次（M2 复现 baseline）你要从环境配起、踩遍坑；现在你框架熟、坑趟过，**补一个对比是"熟练工的活儿"**——这就是把基本功打扎实后的复利：越往后，每个新实验的边际成本越低。

**② 手把手带做**：对【必补】项，用最快路径跑——优先用现成开源实现（核对它的设置和你的公平对比口径一致：同数据集、同评测、同 train/test 划分）；先在小数据集/小设置上跑通确认无误，再跑完整设置；跑的同时记录（超参 + git commit hash + 结果），保持和你 M5 起的实验日志规范一致。如果【必补】是"加一个 seed/数据集"，直接复用你的训练脚本换参数即可。
**③ 这一步合格的样子**：补的实验跑出了可用的结果（指标合理、和你方法可公平对比）；结果已记录在实验日志里（可追溯）。
**④ 最常踩的坑**
- 补的对比方法用了和你不一样的设置（不同数据划分/不同输入尺寸）→ **不公平对比**，结论站不住；务必对齐口径（同 config 只换 method）。
- 跑出异常结果就直接填表 → 先 sanity-check（这个数字合理吗？和原论文报的差不多吗？），异常先 debug 再用。

**⑤ 卡住怎么自救（决策树）**：开源方法跑不起来/复现不出原论文指标？→ 先按它 README 的标准设置复现、对齐版本依赖；实在复现不到位 → 在论文里诚实标注"按官方代码默认设置复现"，或换一个能稳定复现的对比方法。算力/时间紧？→ 只在你的主数据集上补这一个对比，足够回应"没和最新方法比"的质疑。
**⑥ 今天（这一步）你同时学会了什么**：你学会**用现成框架快速补一个公平对比实验**。**做了**（最快路径补跑 + 公平对比口径核对 + 记录）、**学了**（补实验快的根源是框架现成、公平对比要对齐口径、异常先 sanity-check）、**会了**（低成本地为论文补上一块证据）。

## 晚上段 · 把新结果更新进表格 + 同步分析文字 + 全文数字一致

**① 先垫概念**：补完实验，**不是把数字填进表就完事**——还要：① 把新行/新列加进对应的表（主表/对比表）；② **同步更新分析文字**（4.2 的分析要把新对比也讲到，别让表里有数字、文字没提）；③ **做一次全文数字一致性检查**（新结果是否影响了 Abstract/Intro 里报的某个数字？如"我们比最强 baseline 高 X"，最强 baseline 变了 X 也要变）。**表、文字、摘要三处的数字必须一致**，这是论文严谨性的硬指标。

**③ 合格样例**：补的实验已进表 + 分析文字已同步提到 + 全文关键数字一致（Abstract = Intro = 表格）。一个自检：在论文里搜你的主指标数字，每处出现的值都一样。
**④ 坑**：① 表里加了新对比，分析文字只字未提 → 读者会困惑"这行是干嘛的"，文字必须提到；② 补实验改变了"最强 baseline"，但 Abstract 里的"提升 X"没改 → 全文数字不一致（审稿人一眼看出），必须全文同步。

## 上午段 · 全文 self-check → 论文 v1.0 定稿封版

**① 先垫概念（什么是论文定稿前的 self-check，为什么要有清单）**
- **self-check = 投稿前用一张固定清单把全文系统过一遍**，确认没有低级硬伤。它不是"再读一遍找感觉"，而是**逐项核对**（每项打勾）：章节是否齐全、编号是否连续、图表是否都被正文引用、数字是否全文一致、术语是否统一、引用是否完整、Limitation 是否诚实……。有清单才能保证"不漏检"——人凭感觉读容易跳过熟悉的部分。
- **和"通读"对比**：通读看的是"读起来顺不顺"（连贯性，主观）；self-check 看的是"该有的都有、不该错的没错"（完备性 + 正确性，客观可核对）。两者互补——你 D260 通读过（连贯），今天 self-check（完备）。
- **为什么"封版"重要**：投稿是有明确版本的——你上传的 PDF 就是审稿人读的版本。如果投稿前你还在 A 版改一点、B 版改一点，很容易投错版本或漏了某处修改。**封版 = 钉死一个"就投它"的 v1.0**（git commit + 标记），之后只在这个版本上做投稿格式调整。

**② 手把手带做**：拿出 self-check 清单（见补充包，复用第一篇的），逐项过全文打勾：①章节齐全 ②编号连续（图/表/公式/章节）③图表都被正文引用且有解读 ④全文数字一致 ⑤术语符号统一 ⑥引用完整（无"??"）⑦Limitation 诚实 ⑧贡献列表与正文一致；全打勾后 **git commit 打 v1.0 标记**，明确这是投稿版本。
**③ 这一步合格的样子**：self-check 清单全部打勾（无遗留项）；论文 v1.0 已 git commit 封版。判断标准：你能指着这版说"这就是我要投的版本，没有已知硬伤"。
**④ 最常踩的坑**
- 凭感觉读一遍就算 self-check → 容易跳过熟悉段落；**必须逐项对清单打勾**，每项都要落实地核一遍。
- 发现小问题边查边改、改完不重新确认波及 → self-check 时发现的问题改完，要确认没引入新的不一致（尤其改数字/术语）。

**⑤ 卡住怎么自救（决策树）**：self-check 发现某项不达标（如某图没被正文引用）？→ 当场补（加一句"如图 X 所示……"）或删掉没用的图；发现某处需要较大改动来不及？→ 评估是不是硬伤：硬伤必改（晚投一天也要改对），非硬伤记下、定稿照常封版。
**⑥ 今天（这一步）你同时学会了什么**：你学会**用 self-check 清单系统定稿 + 封版钉死投稿版本**。**做了**（逐项 self-check 打勾 + git commit 封版 v1.0）、**学了**（self-check 看完备/正确、与通读互补、封版避免投错版本）、**会了**（把草稿收敛成一个无已知硬伤的定稿版本）。

> **技能卡｜论文定稿 self-check 清单**：投稿前用固定清单逐项打勾（不凭感觉读）：①章节齐全 ②编号连续（图/表/公式/章节）③图表都被正文引用且有解读 ④全文数字一致 ⑤术语符号统一 ⑥引用完整（无 ??）⑦Limitation 诚实 ⑧贡献列表与正文一致。过完清单 **git commit 打 v1.0 标记封版**（钉死"就投它"的版本，避免投错）。与通读（连贯）互补。

## 中午段 · 参考文献格式检查（统一格式 + 信息完整）

**① 先垫概念（为什么参考文献格式要专门查）**
- 参考文献是**最容易出格式错、又最显"不专业"的地方**：作者名缩写不统一、期刊名时全称时缩写、年/卷/期/页缺失、arXiv 与正式发表不分、DOI 时有时无……编辑和审稿人对这些很敏感（反映你做事是否细致）。
- **和正文不同**：正文你最熟；参考文献是从各处攒来的（Scholar 导一条、网页抄一条），**格式天然不统一**，必须专门统一一遍。用 BibTeX 减少手工错误，但导入条目也要核对（Scholar 的 BibTeX 常有错）。定稿阶段是统一的最佳时机（引用已稳定）——格式不统一轻则不专业、重则被编辑返修。

**② 手把手带做**：把参考文献统一为目标刊格式（IEEE 系有固定模板）；逐条核对：①作者名缩写规则一致 ②期刊/会议名（全缩写或全全称）③信息完整（年/卷/期/页 或 arXiv 号）④区分已发表 vs 预印本 ⑤DOI；用 BibTeX 则核对每个 `.bib` 条目（Scholar 导出常错：标题大小写、作者）；确认正文 `[x]` 与文末一一对应（无孤儿引用）。
**③ 这一步合格的样子**：参考文献格式统一、信息完整、无孤儿引用；正文引用编号和文末列表一一对应。
**④ 坑**：① Scholar 导出的 BibTeX 直接用不核对 → 标题大小写错、作者漏 → 逐条核对；② arXiv 预印本标成正式发表（或反之）→ 如实区分（"arXiv preprint" vs 期刊名）；③ 正文引了文末没有（或反之）→ 编译时查 undefined reference，补齐。
**⑤ 自救**：不确定该期刊的参考文献格式？→ 用期刊官方的 LaTeX 模板（自带 .bst 文件，自动套格式）；BibTeX 条目太多核对慢？→ 先批量核对高频出错字段（标题大小写、期刊名），再逐条扫一遍。
**⑥ 今天（这一步）你同时学会了什么**：你学会**系统检查并统一参考文献格式**。**做了**（统一格式 + 逐条核对信息 + 查孤儿引用）、**学了**（参考文献是显专业度的细节、BibTeX 导入也要核对、区分已发表与预印本）、**会了**（让论文的参考文献规范完整、经得起编辑挑剔）。

> **技能卡｜参考文献格式规范**：最易出格式错、最显（不）专业处。统一项：作者名缩写规则、期刊/会议名（全缩写或全全称）、必要信息（年/卷/期/页 或 arXiv 号）、区分已发表 vs 预印本、DOI。用 BibTeX 但**核对每个条目**（Scholar 导出常错）。查孤儿引用（正文引的文末要有、反之亦然）。最省事：用期刊官方 LaTeX 模板（自带 .bst 自动套格式）。

## 晚上段 · 制作 supplementary material（补充材料）

**① 先垫概念（supplementary material 是什么，放什么）**
- **supplementary material（补充材料）= 正文放不下、但对完整性/复现性有价值的内容**，作为附件随论文提交（审稿人可选读）。作用：**正文精炼聚焦（有篇幅限制），把"详尽但非核心"的内容挪到补充**——不挤占正文，又让认真的读者查到细节。
- **典型放什么**：完整超参表（正文只给关键的）、更多可视化（正面/负面/困难案例）、次要消融/对比、完整伪代码/推导、数据集统计。**原则：正文=讲清故事的最小必要集，补充=留给深究者的全集。**
- 补充材料是加分项，能显著提升论文的**复现性和可信度**（审稿人看到详尽超参和更多可视化更信你结果）。对你"把每篇论文做扎实"的定位，认真做 supplementary 性价比很高。

**② 手把手带做**：建一个 supplementary 文档（按目标期刊要求的格式，通常是单独 PDF）；把这些从正文挪过来/补进去——完整超参表、更多可视化（你 M9 做的 8–10 张里没进正文的、再加困难案例）、次要消融、完整伪代码/推导（如有）；每部分加简短说明（"本节给出完整的实现细节，正文 Sec 4.1 的精简版见……"）；**在正文里加指引**（"更多可视化见补充材料 Sec S2"），让正文和补充材料互相呼应。
**③ 合格样例**：一份 supplementary material（完整超参 + 更多可视化 + 次要消融），格式规范、和正文有交叉引用、能让读者据此更好地理解/复现你的工作。
**④ 坑**：① 把核心内容（主表/核心消融）放进补充材料 → 核心必须在正文（审稿人主要读正文）；补充放的是"详尽但非核心"的；② supplementary 和正文完全割裂（正文不提）→ 加交叉引用让二者呼应；③ 未发表的第二篇核心代码这时不要塞进补充材料公开（守住"未发表核心代码延后开源"的线，补充材料给细节描述即可）。
**⑤ 自救**：不确定哪些放正文哪些放补充？→ 判断"这部分缺了，读者还能理解核心故事吗"——能理解就可挪补充，不能就留正文；不知道补充材料怎么排版？→ 用期刊模板，或简单做成一个结构清晰的 PDF（带 S1/S2 编号区分于正文）。
**⑥ 今天（这一步）你同时学会了什么**：你学会**制作 supplementary material（正文精炼、细节归补充）**。**做了**（建补充材料 + 挪/补详尽内容 + 加交叉引用）、**学了**（正文=最小必要集/补充=深究者的全集、补充提升复现性、核心必须在正文）、**会了**（用补充材料提升论文完整性与可信度而不挤占正文）。

> **技能卡｜supplementary material 该放什么**：补充材料=正文放不下、但对完整性/复现性有价值的内容（可选读）。典型：完整超参表、更多可视化（正面/负面/困难案例）、次要消融、完整伪代码/推导、数据集统计。**原则：正文=讲清故事的最小必要集，补充=深究者的全集。** 核心（主表/核心消融）必须在正文，与正文加交叉引用。★ 未发表核心代码此时不公开进补充。

## 上午段 · 选定第二篇的投稿目标期刊（不同刊扩大覆盖面）

**① 先垫概念（第二篇为什么建议投不同期刊，怎么选）**

- **投不同刊的三个理由**：① **多样化展示**——两篇出现在两个刊/会上，覆盖更广；② **两篇同时在审 = 更大概率至少一篇接收**——分散风险，且避免同刊同期收到你两篇的"灌水"印象；③ **不同载体不同价值**——如 IGARSS workshop 有 **poster = 学术社交**（能当面认识同行甚至目标组的人），对后续对接空天院有隐性帮助。
- **怎么选**（按你的定位）：候选 GRSL（快、门槛适中）/ JSTARS（应用导向、对"高效实用"友好）/ TGRS（顶刊、难、周期长）/ IGARSS workshop（有 poster、社交）。第一篇 GRSL → 第二篇可选 JSTARS（升一档、契合"单卡高效"卖点）或 IGARSS workshop。**核心：和第一篇错开 + 契合这篇特点 + 匹配你的时间预算**。

**② 手把手带做**：回顾第一篇投了哪个刊；列第二篇的 2–3 个候选（如 JSTARS / IGARSS workshop / TGRS）；从三个维度评分——**契合度**（期刊范围和你这篇工作的匹配，看它近期发的同方向论文）、**录用周期 vs 你的时间预算**（会议有 deadline、期刊滚动审）、**对你定位的价值**（应用导向刊对"高效实用"友好、会议 poster 有社交价值）；选定一个主投目标 + 一个备选（万一主投不合适或被拒）。
**③ 这一步合格的样子**：选定第二篇的主投目标 + 理由（为什么这个刊适合这篇、为什么和第一篇错开）+ 一个备选。判断标准：你能说清"为什么投它而不是另一个"。
**④ 最常踩的坑**
- 只看影响因子选最高的（如非要冲 TGRS）→ 还要看契合度和周期：投了范围不符的刊会被直接 desk reject；周期太长的刊不利于你"两篇尽快落地"的节奏。
- 两篇投同一个刊同一时期 → 容易给编辑"批量投稿"印象，且风险集中；**错开刊更稳**。

**⑤ 卡住怎么自救（决策树）**：在 JSTARS 和 IGARSS workshop 之间纠结？→ 看你更想要"期刊论文"（JSTARS，更正式、可写进简历的期刊条目）还是"会议+社交"（IGARSS，有 poster、能认识人，但 workshop 论文分量略轻）；不确定契合度？→ 去目标刊官网翻近一年目录，看有没有和你同方向（SAR 检测/跨域）的论文，有 = 契合。
**⑥ 今天（这一步）你同时学会了什么**：你学会**为论文做有策略的投稿目标选择（组合布局而非随机）**。**做了**（列候选 + 三维度评分 + 选主投+备选）、**学了**（两篇错开刊的三个理由、按契合/周期/定位价值选刊、不只看影响因子）、**会了**（从整体布局而非单篇视角规划投稿）。

> **技能卡｜投不同期刊的策略**：两篇建议投不同刊/会（第一篇 GRSL → 第二篇 JSTARS 或 IGARSS workshop）。三个理由：①多样化展示、覆盖更广；②同时在审=更大概率至少一篇接收（分散风险、避免"批量投稿"印象）；③不同载体不同价值（IGARSS workshop 有 poster=学术社交）。选刊三维度：契合度、录用周期 vs 时间预算、对定位的价值。不只看影响因子——范围不符会 desk reject。

## 中午段 · 读目标期刊 Author Guidelines（拿到硬约束）

**① 先垫概念（Author Guidelines 是什么，为什么投稿前必读）**
- **Author Guidelines（作者须知）= 目标期刊对投稿的硬性规定**：论文页数/字数上限、排版模板（双栏/单栏、LaTeX/Word）、图表要求（分辨率、彩图政策）、参考文献格式、补充材料政策、投稿系统、是否要 highlights/graphical abstract 等。**这些是"不符合就退回"的硬约束**，不是建议。
- **为什么必须先读再调格式**：不同刊要求差异大（GRSL 有严格页数上限、TGRS 较宽松、会议有 deadline 和模板）。**先读须知拿到约束、再据此调格式**，避免"格式调到一半发现页数超了要大删"或"投到一半发现模板不对要重排"。
- **和第一篇的关系**：你第一篇读过一次 Author Guidelines（M7 投稿时），流程你熟；但**第二篇是不同刊，须知不同**，不能照搬第一篇的格式，要重新读这个刊的。

**② 手把手带做**：去目标期刊官网找 "Author Guidelines / Information for Authors"；逐条记下硬约束——①页数/字数上限（最关键，决定要不要删减）②排版模板（下载官方 LaTeX/Word）③图表要求（分辨率/彩图）④参考文献格式 ⑤补充材料政策 ⑥是否需要 graphical abstract/highlights ⑦投稿系统（IEEE=ScholarOne）；列成"目标刊约束清单"。
**③ 这一步合格的样子**：一张"目标刊约束清单"（页数/模板/图表/参考文献/补充材料/额外要求/投稿系统），逐项明确。判断标准：照着这张清单就知道格式要怎么调、有没有需要删减的。
**④ 坑**：① 不读须知直接按第一篇格式投 → 模板/页数/参考文献格式很可能不符；② 漏看页数上限 → 调到最后发现超页要紧急删（伤筋动骨）；③ 漏看"需要 graphical abstract"等额外要求 → 投稿时缺文件。
**⑤ 自救**：找不到须知？→ 期刊主页一般有 "For Authors" 入口，或搜"<期刊名> author guidelines"；须知太长？→ 重点抓页数、模板、参考文献格式、投稿系统这四项（最影响格式调整）。
**⑥ 今天（这一步）你同时学会了什么**：你学会**读懂目标期刊的硬性投稿约束**。**做了**（找并通读 Author Guidelines + 列约束清单）、**学了**（须知是硬约束不是建议、不同刊差异大不能照搬、先读须知再调格式）、**会了**（在动手调格式前先掌握目标刊的全部规则）。

## 晚上段 · 按目标刊模板调整格式

**① 先垫概念**：拿到约束清单后，**把论文套进目标刊的官方模板**——这一步是机械但必须细致的"适配"：换模板（双栏/单栏、字体字号）、压到页数上限内（如超页，优先精简冗余表述/把次要内容挪 supplementary，而非删核心）、图表按要求处理（分辨率/彩图）、参考文献套模板的 .bst。**用官方模板能自动满足大部分排版要求**（这是模板的意义）。
**② 手把手带做**：下载目标刊官方 LaTeX/Word 模板，把你的内容迁进去；检查页数——如超上限，按"精简表述 > 挪 supplementary > 删次要图表 > （最后才）删内容"的顺序压缩；图表导出为要求的分辨率/格式；参考文献用模板自带的 .bst（自动套格式，对应昨天的统一）；编译/排版，确认无溢出、图表不跨栏错位、引用无 undefined；准备好需要的额外文件（如 graphical abstract）。
**③ 合格样例**：论文已套进目标刊模板、页数合规、图表达标、参考文献格式正确、编译无错——一份"格式符合目标刊要求"的稿子。
**④ 坑**：① 超页就硬删核心内容 → 先精简表述和挪 supplementary，核心别删；② 图分辨率不够（截图糊）→ 用矢量图（PDF/SVG）或高 DPI 重出；③ 双栏模板下宽表/宽图溢出 → 用跨栏环境（如 LaTeX 的 `table*`/`figure*`）或缩排。
**⑤ 自救**：模板套不进/编译报错？→ 从模板的示例文件起步，逐段把内容粘进去（而非把模板规则往自己文件硬塞）；页数死活超？→ 重点砍"分析文字里的重复表述"和"可挪 supplementary 的次要消融/可视化"，通常能省出 0.5–1 页。
**⑥ 今天（这一步）你同时学会了什么**：你学会**把论文适配到目标期刊的格式模板**。**做了**（套官方模板 + 压页数 + 图表达标 + 参考文献套 .bst）、**学了**（用官方模板自动满足排版、超页的压缩优先级、宽图表的跨栏处理）、**会了**（产出一份格式完全符合目标刊要求的投稿稿）。

> **技能卡｜投稿格式适配**：把论文套进**官方 LaTeX/Word 模板**（自动满足大部分排版）。超页压缩优先级：精简表述 > 挪 supplementary > 删次要图表 >（最后才）核心内容——**核心永远别删**。图表用矢量/高 DPI（截图会糊）。双栏下宽表/宽图用跨栏环境（`table*`/`figure*`）。参考文献用模板自带 .bst。编译确认无溢出/无 undefined。

> **今日交付**：✅ 投稿目标确定（主投 + 备选 + 理由）✅ 目标刊约束清单 ✅ 论文按目标刊模板调好格式（页数合规、编译无错）。

## 上午段 · 写 Cover Letter（复用第一篇经验 + 突出差异化卖点）

**① 先垫概念（Cover Letter 是什么，第二篇怎么快速写好）**
- **Cover Letter（投稿信）= 随论文提交给编辑的简短信件**：简述贡献（2–3 句）+ 为何适合本刊 + 原创声明（未一稿多投/未在别处发表）+ 礼貌结尾。**它是编辑的第一印象**——编辑先看它决定"是否符合本刊范围、是否值得送审"。
- **第二篇怎么快**：你第一篇写过 Cover Letter，**结构直接复用**（贡献+契合+声明+结尾），只换成这篇的内容和目标刊。半小时能成稿。
- **★ Cover Letter 是突出"差异化卖点"的好机会**：论文正文要中立客观，但 Cover Letter 里你可以**主动向编辑强调你工作的独特价值**——尤其你的定位（不拼规模、拼高效实用）。比如写："与依赖大规模预训练的方法不同，我们的方法**仅用单张 GPU（RTX 4090）即可训练**，在 SAR 这类标注稀缺的数据上仍然有效，这对计算/标注资源受限的遥感应用尤为重要。" **这一句就把你的卖点（单卡高效、数据友好、面向实际应用）清晰传达给编辑**，让面向应用的期刊（如 JSTARS）get 到你工作的价值点。

**② 手把手带做**：复用第一篇 Cover Letter 结构写第二篇（完整模板见补充包范例 2）——①致编辑+论文标题+拟投本刊 ②贡献 2–3 句（核心问题+你的方法+SOTA）③契合本刊，**嵌入差异化卖点**："单卡可训、数据友好，契合面向应用的本刊" ④原创声明（未在别处发表、未同时投他刊）⑤礼貌结尾；半页到一页、简洁专业。
**③ 这一步合格的样子**：一封 Cover Letter——贡献准确（和论文 v1.0 一致）、契合目标刊（点出和刊范围的匹配 + 差异化卖点）、声明完整、简短专业（≤1 页）。
**④ 最常踩的坑**
- Cover Letter 贡献和论文最终版不一致（如还写着旧的提升数字）→ 据 v1.0 同步，数字/贡献对齐正文。
- 漏了原创性声明 → 必须有（编辑要求）："本工作为原创，未在别处发表，未同时投他刊"。
- Cover Letter 写成论文摘要的复制（干巴巴）→ 它该**面向编辑、突出契合和卖点**，不是再贴一遍 Abstract。

**⑤ 卡住怎么自救（决策树）**：不会写 Cover Letter？→ 用期刊提供的模板，或复用你第一篇的（换内容）；不确定怎么写契合？→ 一句话点出"本工作属于本刊关注的<方向>，且<差异化卖点>对本刊读者（应用方）有价值"。
**⑥ 今天（这一步）你同时学会了什么**：你学会**写一封突出贡献与差异化卖点、契合目标刊的 Cover Letter**。**做了**（复用结构写第二篇 Cover Letter + 嵌入单卡高效卖点 + 原创声明）、**学了**（Cover Letter 是编辑第一印象、可主动强调卖点、第二篇复用结构最快）、**会了**（为投稿准备一封专业得体、让编辑 get 到价值的投稿信）。

> **技能卡｜Cover Letter（第二篇复用版）**：随论文给编辑的投稿信，决定是否送审。结构（复用第一篇）：①致编辑+标题+拟投本刊 ②贡献 2–3 句 ③为何契合本刊（**嵌差异化卖点**："单卡 4090 可训、数据友好"）④原创性声明 ⑤礼貌结尾。≤1 页。★ 正文中立，但 Cover Letter 可主动强调"不拼规模拼高效实用"的定位。贡献数字须和 v1.0 一致。

## 中午段 · 最终 proofreading（英文 + typo + 一致性）

**① 先垫概念（proofreading 是什么，和前面的修改有什么不同）**
- **proofreading（校对）= 投稿前最后一道"文字层面"的细查**：拼写错误、语法、标点、英文表达是否地道、术语前后一致、图表标题/编号有无笔误。它**不改内容、不改结构**（那些前几天做完了），只抓"文字面"的瑕疵。
- **和 self-check 的不同**：self-check 查"完备性/正确性"（章节齐不齐、数字对不对）；proofreading 查"文字面"（拼写/语法/表达）。是投稿前的最后一遍，目标是**让审稿人读起来挑不出低级文字错**（低级错会拉低第一印象、让审稿人怀疑你做事不细）。
- **为什么单独留一遍**：写作和修改时注意力在"内容"，文字面的小错容易留下；定稿后专门用"只看文字"的视角扫一遍，能抓出之前忽略的拼写/语法/typo。

**② 手把手带做**：用"只看文字"的视角通读全文——①拼写/语法（可借工具如 Grammarly 辅助初筛，但要人工确认，工具会误判专业术语）②英文表达（拗口的句子改顺，避免中式英语）③标点/格式统一（如逗号空格、引号样式）④术语/符号一致（同一概念全文一个写法）⑤图表标题、编号、caption 的 typo；重点扫**高曝光位置**（标题、Abstract、各节首句、图表 caption——这些审稿人一定细读）；改完的地方确认没引入新错。
**③ 这一步合格的样子**：全文无拼写/语法/typo、英文表达通顺、术语一致、高曝光位置（标题/摘要/caption）无错。判断标准：以审稿人的挑剔眼光读一遍，挑不出文字层面的低级错。
**④ 坑**：① 完全依赖 Grammarly 等工具 → 工具会误判专业术语、漏掉语义错，必须人工确认；② 只扫正文忘了图表 caption 和参考文献 → 这些也要校对（caption 常被忽略）；③ 校对时又开始改内容 → 现在只校文字，发现内容问题记下（除非硬伤），别又进入大改。
**⑤ 自救**：英文拿不准是否地道？→ 借助工具初筛 + 对照你读过的同领域论文的表达；时间紧只能扫一遍？→ 优先扫高曝光位置（标题/摘要/各节首句/图表 caption），这些错的代价最大。
**⑥ 今天（这一步）你同时学会了什么**：你学会**做投稿前的最终 proofreading（只抓文字面瑕疵）**。**做了**（只看文字通读 + 工具辅助+人工确认 + 重点扫高曝光位置）、**学了**（proofreading 抓文字面、与 self-check 互补、工具要人工复核）、**会了**（让论文文字面经得起审稿人挑剔、保住第一印象）。

> **技能卡｜投稿前 proofreading**：最后一道"文字层面"细查（不改内容/结构）：拼写/语法/标点、英文是否地道（避中式英语）、术语符号一致、图表 caption 与编号 typo。与 self-check 互补（那查完备正确，这查文字面）。可用 Grammarly **初筛但人工确认**。**重点扫高曝光位置**：标题、Abstract、各节首句、图表 caption——出错代价最大。

## 晚上段 · 备齐投稿文件（列清单 + 逐项就位）

## 二、完整可运行代码 · 论文定稿 self-check 脚本（+ 预期输出）

> 脚本对 LaTeX 源做四项自动检查：①高频数字（辅助核对全文一致）②孤儿引用（正文引了文末没有/反之）③章节齐全 ④图表都被正文引用。**自动 self-check 不替代人工通读，但能抓人眼易漏的低级硬伤。**

```python
#!/usr/bin/env python3
# paper_selfcheck.py —— 论文定稿前自动 self-check（针对 LaTeX 源）
# 用法: python paper_selfcheck.py main.tex
import re, sys, collections

def load(path):
    with open(path, encoding='utf-8') as f:
        return f.read()

def strip_comments(tex):  # 去掉 LaTeX 注释
    return re.sub(r'(?<!\\)%.*', '', tex)

def check_sections(tex):
    needed = ['abstract', 'introduction', 'related work', 'method', 'experiment', 'conclusion']
    found = [s.lower() for s in re.findall(r'\\section\*?\{([^}]*)\}', tex)]
    found_joined = ' | '.join(found)
    missing = [n for n in needed if n not in found_joined]
    return found, missing

def check_citations(tex):
    cited = set()  # 正文 \cite 的 key
    for m in re.findall(r'\\cite[a-z]*\{([^}]*)\}', tex):
        cited.update(k.strip() for k in m.split(','))
    defined = set(re.findall(r'\\bibitem\{([^}]*)\}', tex))  # 文末 \bibitem 或 .bib 的 key
    defined |= set(re.findall(r'@\w+\{([^,]+),', tex))
    return cited, defined, cited-defined, defined-cited  # 引了没定义 / 定义了没引

def check_floats(tex):  # figure/table 的 label vs 正文 \ref
    labels = set(re.findall(r'\\label\{((?:fig|tab)[^}]*)\}', tex))
    refs = set(re.findall(r'\\ref\{((?:fig|tab)[^}]*)\}', tex))
    return labels, refs, labels-refs  # labels-refs = 孤儿图表

def check_numbers(tex):  # 统计形如 90.3 的数字出现次数，辅助人工核对一致性
    return collections.Counter(re.findall(r'(?<![\w.])([0-9]{1,3}\.[0-9]{1,2})(?![\w.])', tex))

def main():
    if len(sys.argv) < 2:
        print("用法: python paper_selfcheck.py main.tex"); return
    tex = strip_comments(load(sys.argv[1]))
    print("="*56); print("论文定稿 self-check 报告"); print("="*56)

    found, missing = check_sections(tex)
    print(f"\n[1] 章节检查  共 {len(found)} 节")
    print("    缺失关键章节:", missing if missing else "无 ✅")

    cited, defined, oc, od = check_citations(tex)
    print(f"\n[2] 引用检查  正文引用 {len(cited)} 条 / 文末定义 {len(defined)} 条")
    print("    正文引了但文末没有(必修):", sorted(oc) if oc else "无 ✅")
    print("    文末有但正文没引(建议删或引):", sorted(od) if od else "无 ✅")

    labels, refs, unref = check_floats(tex)
    print(f"\n[3] 图表检查  定义 {len(labels)} 个 label / 正文引用 {len(refs)} 个")
    print("    定义了但正文没引用的图表(孤儿):", sorted(unref) if unref else "无 ✅")

    cnt = check_numbers(tex)
    top = cnt.most_common(8)
    print(f"\n[4] 高频数字(请人工核对全文一致性，尤其主指标/提升幅度):")
    for v, c in top:
        print(f"    {v}  出现 {c} 次")
    print("\n（提示：主指标/提升幅度应在 Abstract/Intro/表格 三处一致——逐处核对这些数字）")
    print("="*56)

if __name__ == '__main__':
    main()
```

**预期输出（示例）**：
```
[1] 章节检查  共 6 节 → 缺失关键章节: 无 ✅
[2] 引用检查  正文 32 条 / 文末 33 条
    正文引了但文末没有(必修): 无 ✅
    文末有但正文没引(建议删或引): ['zhang2024extra']
[3] 图表检查  定义 8 / 引用 8 → 孤儿图表: 无 ✅
[4] 高频数字(人工核对一致性): 90.3×4  2.1×3  ...
```
> 解读：脚本报告"文末有 `zhang2024extra` 但正文没引"——你去确认是删掉这条参考文献、还是正文该引它。"高频数字"列出来供你人工核对（如主指标 90.3 出现 4 次，逐处确认都是这个值、没写错）。**脚本抓机械硬伤，一致性的最终判断仍需人工。**

## 四、本周报错 / 坑 速查表（现象 → 根因 → 解法）

| # | 现象 | 根因 | 解法 |
|---|---|---|---|
| 1 | 朋友说什么都改，改完论文反而乱了 | 没标三类、无判断地全改 | 标【必改/可改/可不改】，必改优先、可不改记理由保留 |
