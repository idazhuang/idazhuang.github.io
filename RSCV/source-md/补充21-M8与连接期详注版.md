# 第一部分 · M8（W29–W32）

## W29 · 竞赛技术报告怎么写

原文让你把竞赛"沉淀成技术报告 + 开源仓库 + 影响力"。**技术报告和论文是两种文体**，别用写论文的方式写它。

| | 论文 | **竞赛技术报告** |
|---|---|---|
| 目的 | 说服审稿人这个贡献值得发表 | **让别人能复现你的名次** |
| 重点 | 创新点 + 严谨对比 | **每个 trick 涨了多少分** |
| 允许 | 必须有理论/动机支撑 | **"试出来的、说不清为什么"也可以写** |
| 长度 | 5–12 页 | 3–6 页够了 |

**核心是一张表**（原文 D188 让你写"Trick 贡献分解表"，这里给格式）：

```markdown
| # | 改动 | 线上分数 | 相对上一行 | 训练耗时 | 保留？ |
|---|------|---------|-----------|---------|--------|
| 0 | 官方 baseline | 0.612 | — | 6h | ✅ |
| 1 | + 更强 backbone | 0.641 | +0.029 | 11h | ✅ |
| 2 | + 多尺度训练 | 0.658 | +0.017 | 16h | ✅ |
| 3 | + SAHI 切片推理 | 0.679 | +0.021 | +0（仅推理） | ✅ |
| 4 | + 自监督预训练 | 0.681 | +0.002 | +14h | ❌ 性价比太低 |
| 5 | + 5 模型 Ensemble | 0.694 | +0.013 | ×5 | ⚠️ 比赛用，实用不推荐 |
```

**★ 这张表的三个要点**：
1. **每行只加一个东西**，和上一行只差一处——**和你 M4 学的方法迭代是同一套纪律**
2. **必须有"耗时"和"保留？"两列** —— 竞赛可以不计成本，但技术报告的价值在于告诉别人"哪些值得用"
3. **诚实记录没用的 trick**（第 4 行那种）—— **这比只报有用的更有参考价值**

## W30–W31 · ★ 第二课题的"复用红利"到底有多大

原文说第二篇要"复用第一篇的一切，跑出更快的节奏"。**具体能快多少，把账算出来**：

| 环节 | 第一篇花了 | **第二篇** | 为什么 |
|---|---|---|---|
| 环境搭建 | 1–2 天 | **0** | 环境还在 |
| 数据管道 | 3–5 天 | **0.5 天** | `to_dota.py`、切图、可视化全部现成 |
| 实验框架 | 1 周（W11） | **0** | 直接复用 |
| baseline 复现 | 1 周（W2） | **0.5 天** | 同一个 baseline，权重和 config 都在 |
| 绘图与表格 | 2 天 | **0.5 天** | `paper_figs.py` 现成 |
| 论文骨架 | 1 周（W15） | **2–3 天** | 结构熟了，Related Work 部分可复用 |
| 投稿流程 | 1 周 | **1 天** | 系统熟了，Cover Letter 改改就行 |
| **合计** | **约 5 周纯工程** | **约 1 周** | |

> **★ 所以第二篇真正的时间应该花在"想清楚问题"上，而不是重新造轮子。**
>
> **如果你发现第二篇又在重复第一篇的工程工作，说明你第一篇的框架没搭好**——回去补，那笔投资会在第三篇再赚一次。

## W30 · 第二课题从哪来（"从第一篇的没做完里长出来"）

**三个来源，按质量排序**：

| 来源 | 具体在哪 | 质量 |
|---|---|---|
| **① 你第一篇的 Limitation 段** | 你自己写的"本方法的不足" | ★★★ **最好**：你最清楚它为什么不足 |
| **② 审稿意见里的建议** | "如果作者能进一步探讨 X 会更好" | ★★★ **审稿人替你指的方向，而且他会认可** |
| **③ 消融里的反常现象** | W12/W19 里那些你没解释清楚的结果 | ★★ 需要额外挖 |

**★ 一个具体动作**：打开你第一篇的 Limitation 段，**逐句问"这句话能不能变成一篇论文"**。通常第一篇的 Limitation 有 3 条，其中至少 1 条是可做的。

## W32 · GitHub 仓库运营（W35 还有"爆款打造周"）

**★ 先说实话**：**大多数学术仓库不会火，这很正常。** 一个能一键复现、README 清楚的仓库，即使只有几十个 star，**在求职和联系导师时的价值已经完全兑现了**。不要把 star 数当目标。

**README 的必要结构**（按读者从上到下的注意力排）：

```markdown
# 项目名 · 一句话说清做什么
[徽章：论文链接 / 许可证 / Python 版本]

![一张效果图]              ← ★ 第一屏必须有图，这决定别人往不往下看

## Highlights
- 三条 bullet，说清和别人的区别

## Installation
（★ 完整命令，含版本号，别写"参考官方文档"）

## Quick Start
（★ 三行以内出结果的最小例子）

## Model Zoo
| 模型 | 数据集 | mAP | config | 权重 |
（★ 权重给 HuggingFace 链接）

## Reproduce
bash reproduce.sh    （你 M4 写的）

## Citation
（BibTeX，方便别人引用）

## Acknowledgement
（★ 致谢你 fork/借鉴的项目，学术礼貌）
```

**★ 三条实际有用的运营动作**（比"打造爆款"实在）：
1. **在论文的 Abstract 末尾放仓库链接** —— 这是最有效的引流
2. **给你 fork 过的上游项目提一个有用的 PR 或 issue** —— 建立真实的技术联系
3. **在 Papers with Code 上关联你的论文和代码** —— 免费曝光

# 第二部分 · ★ 连接期的三份材料（W42–W45）

## 2.1 简历（一页，针对"转行读博 + 找机会"）

**★ 你的简历和普通学生简历的区别**：你要证明的不是"我上过什么课"，而是**"我在 12 个月里从零做出了什么"**。

```markdown
# 姓名
邮箱 · GitHub · Google Scholar · 个人主页（如有）

## 研究方向
遥感图像 <你的具体方向>；<一句话说清你的技术特长>

## 教育背景
<学校 · 专业 · 学位 · 起止>    ← ★ 一行就够，不要列课程

## 研究成果                     ← ★ 放在教育背景之后、最显眼的位置
- [论文1] <标题>. IEEE GRSL, 2026 (Under Review / Accepted). [arXiv] [Code]
- [论文2] <标题>. 投稿中.
- [竞赛] <竞赛名>, 排名 X/Y (前 Z%). [技术报告] [代码]
- [开源] <仓库名>, N stars. <一句话说明它解决什么>

## 技术能力                     ← ★ 具体到工具和数字，不要写"熟悉深度学习"
- 框架：PyTorch, MMDetection/MMRotate, MMSegmentation
- 方向：旋转目标检测、SAR 图像处理、自监督预训练
- 工程：单卡训练优化（混合精度/梯度检查点）、多 seed 实验管理、可复现流程

## 代表性工作（2–3 项，各 3 行）   ← ★ 这一节让人记住你
### <项目名>（时间）
- 问题：<一句话>
- 做法：<一句话>
- 结果：<★ 带数字，如"mAP 提升 2.7，参数仅增加 3%，单卡可训">
```

**★ 四条写简历的纪律**：
1. **一页。** 超过一页说明你在写不重要的东西。
2. **每条成果带数字。** "提升了性能" → "mAP +2.7（3 seeds）"
3. **在校生的成果就放最前面**，不要按时间倒序把教育背景压在上面
4. **英文版和中文版都要有**，联系海外时用英文

## 2.2 作品集 PDF（W45，原文要"有冲击力的战绩展示板"）

**作品集是简历的展开版**，8–12 页，PDF。**结构**：

```text
第 1 页  封面：姓名 + 一句话定位 + 联系方式
第 2 页  一页总览：12 个月做了什么（时间线 + 关键节点）
第 3-5 页 项目一（第一篇论文）
         · 问题是什么（配图）
         · 我的方法（架构图）
         · 结果（主表 + 定性对比图）
         · ★ 我在这个项目里独立完成了什么
第 6-7 页 项目二（第二篇 / 竞赛）
第 8 页  技术栈与工程能力（★ 附 GitHub 截图和 reproduce.sh 的说明）
第 9 页  ★ 我最擅长的三件事 + 我想解决的下一个问题
第 10 页 附录：完整论文/竞赛/开源清单
```

**★ 第 9 页是最关键的一页**，因为它回答的是对方最关心的问题：**"这个人加入我的组，能干什么？"** 前面 8 页都是过去，这一页是未来。

## 2.3 汇报 PPT（20 分钟，W42 备好、W53 用）

```text
1 页   自我介绍（30 秒，★ 不要超过 1 页）
2 页   我做的方向 + 为什么做它（1 分钟）
3-8 页 第一篇工作（8 分钟）
       · 问题 → 现有方法的不足 → 我的方法 → 结果 → 消融
       · ★ 每页一个信息点，不要堆字
9-11页 第二篇 / 竞赛（4 分钟）
12 页  ★ 我目前的困惑 / 想请教的问题（2 分钟）
13 页  我能为您的组做什么（2 分钟）
14 页  致谢 + 联系方式
       （留 3 分钟提问）
```

> **★ 第 12 页最重要，也最容易被砍掉。** 一个只讲自己做了什么的汇报是"汇报"；**一个带着真问题来请教的汇报是"交流"**。老师会记住后者。
>
> 你 W43 为每位老师准备的"3 个尖锐问题"，就放在这一页。

# 第三部分 · ★★ 补上缺失的《附录 D · 冷邮件模板》

## 3.0 先说一件原文回避了的事：回复率

原文用 W41–W48 整整八周准备这封邮件，称它为"12 个月的最终一击"。**准备是对的，但"最终一击"这个框架有风险**——它暗示这一击成了就赢了、不成就完了。

**诚实的预期**：

```text
· 给知名教授发冷邮件，作为校外人士，★ 不回复是最常见的结果
· 收到礼貌但简短的回复（"谢谢关注，目前没有名额"）也很常见
· 收到实质性回复（愿意聊一次）就已经是很好的结果
· 三封发出去，有一封回复就算成功
```

**★ 但这不代表这八周白准备了**，理由有三条：

1. **准备的过程本身产出了三份可复用的材料**（简历 / 作品集 / 汇报 PPT），**你后面找工作、申博、申访问都要用**
2. **为了写这封邮件，你精读了三位老师的最新论文** —— 这本身就是高质量的领域跟踪
3. **一封没回复的邮件可以再发给第二批人** —— 模板和材料是复用的，边际成本很低

> **★ 所以正确的框架不是"最终一击"，而是"第一轮投递"。** 原文 W50 安排了"Plan B 启动 + 多层备选不放弃"，方向是对的——**但心理预期应该在 W48 发出之前就建立好，而不是等没回复了再调整。**

## 3.3 ★ 这封邮件的七条设计原则

| # | 原则 | 为什么 |
|---|---|---|
| 1 | **主题行要具体** | "请教" / "求指导" 会被当成群发。**主题里带上他论文的具体话题**，一眼看出你读过 |
| 2 | **第 2 段必须证明你真读了** | ★ **这是全信最重要的一段。** 老师每周收到大量泛泛的信，只有"真读过我东西"的会被读完 |
| 3 | **问题要具体、技术性、且百度不到** | 能搜到的问题说明你没认真想。**问题的质量直接代表你的水平** |
| 4 | **自我介绍不超过 3 句** | 他现在不关心你，他关心你问的问题。**成果放附件** |
| 5 | **请求要低门槛且有梯度** | "回答一个问题"比"收我做学生"容易答应得多。**先建立联系，再谈别的** |
| 6 | **给对方不回复的台阶** | "无论是否方便回复都感谢您的时间" —— 减少他的心理负担，**反而提高回复率** |
| 7 | **全信控制在 300 字以内**（正文） | 手机上能一屏看完。长信=不会读 |

## 3.4 五个会让邮件直接进垃圾桶的错误

| ❌ | 为什么致命 |
|---|---|
| 群发痕迹（"尊敬的老师"没写名字，或忘了改上一封的名字） | **立刻出局**，而且很常见 |
| 只夸不问（"拜读大作，深受启发，希望能加入您的团队"） | 没有信息量，看不出你的水平 |
| 一上来就要名额 / 要推荐信 | 门槛太高，对方只能拒绝 |
| 附件过大或格式奇怪（.rar / 20MB） | 打不开就等于没发。**PDF，总共 5MB 以内** |
| 深夜或周末发 | 会被后来的邮件淹掉。★ **工作日上午 9–10 点发**（原文说了这一条，是对的） |

## 3.5 发出后怎么办

```text
Day 0    发出。★ 然后关掉邮箱去做别的事
Day 1-6  不做任何事。不刷、不追问
Day 7    ★ 若无回复，发一封简短追问（不是重发原信）：
         "X 老师您好，上周冒昧向您请教了 <一句话概括问题>。
          知道您很忙，若不方便回复完全理解。
          如果有机会，我很期待您的看法。"
         —— 三行以内
Day 14   仍无回复 → 停止。★ 不要发第三封
         → 转 Plan B：换一批人，或换渠道（会议现场、组会旁听、共同认识的人引荐）
```

> **★ 关于追问的一条纪律**：**最多追一次。** 追第二次会从"认真"变成"打扰"，而学术圈很小，负面印象的成本远高于一次未回复。

## 3.6 收到回复了怎么办（原文 D327 说"立即认真专业地回复"，这里给具体做法）

| 回复类型 | 你该怎么回 |
|---|---|
| **实质性回答了你的问题** | ★ **当天内回**。感谢 + **针对他的回答再往前走一步**（"按您说的思路，我试了 X，观察到 Y"）—— **这一步是把一次问答变成持续对话的关键** |
| **礼貌但简短（"谢谢关注"）** | 简短感谢，不要追加要求。**留个好印象，半年后有新成果时可以再联系** |
| **表示有兴趣，问你更多** | 24 小时内详细回复 + **主动提议 20 分钟线上汇报**，给两三个时间选项 |
| **说没有名额** | 感谢 + **问一句"是否方便推荐其他老师"** —— 这是最常见的转介机会 |
