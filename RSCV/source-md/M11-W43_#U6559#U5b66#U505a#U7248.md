## 晚上段 · 写"价值卡片"（每位 200 字：我能给 X 带来什么）

**① 先垫概念（价值卡片是什么、为什么是心态锚）**
- ★ **价值卡片 = 每位老师一张"我能给你带来什么"的 200 字卡片**。它的核心是**视角转换**：联系老师时，新手容易想"我想从你那得到什么"（读博/访问/指导——索取视角），但打动老师的是"**你能给他的课题带来什么价值**"（互惠视角）。
- **为什么这是"心态锚"**：你后面写的邮件，姿态取决于心态——索取心态写出的邮件像"求收留"（卑微、容易被忽略），互惠心态写出的像"我能为你的课题做贡献"（平等、有吸引力）。**先写价值卡片，就是先把心态摆正**：你不是去"求"，而是带着实打实的能力和成果去"对接"。这一点对你尤其重要：你没有名校光环、没有导师推荐、没有现成人脉——在这种情况下，唯一能让你和老师"平等对话"的，就是你能为他的课题带来真实价值。价值卡片就是把这个"我有用"想清楚、说明白；当你自己都相信"我能为这个课题做贡献"时，写出的邮件自然有底气，对方也才感受得到。
- **你的价值是什么**（具体）：① **通用 CV 强代码能力**（工程扎实、能快速实现）；② **已有遥感方向 2 篇论文**（证明能在这个领域做出成果）；③ **开源项目 60+ stars**（影响力 + 工程能力）；④ **单卡 4090 高效路线**（和他们的大模型工作互补——他们造大模型，你做高效下游/难题）。例：给王超组的价值卡片可写"我有通用 CV 强代码能力 + 遥感 2 篇论文 + 开源 60+ stars，且专注高效路线，可以快速上手贵团队的 SAR-光学跨模态课题，在下游特化/效率上做贡献"。

**② 手把手带做**：为每位老师写一张 200 字价值卡片——① 你的核心能力/成果（代码/论文/开源/高效路线）；② **针对这位老师的课题，你能贡献什么**（结合他的热点：如能快速上手他的某课题、在某方向补充、用你的高效路线帮他做下游）；③ 体现"互补"（你做高效特化/难题，和他的基础模型工作互补，不是来抢他的活）；语气自信但不自大、具体不空泛。
**③ 这一步合格的样子**：5 张价值卡片（每位 200 字），都从"我能带来什么"出发、结合该老师的课题、体现你的具体价值和互补性。判断标准：读这张卡片，能感到"这个人能为我的课题做实事"。
**④ 最常踩的坑**
- 写成"我想得到什么"（求读博/求指导）→ ★ 转成"我能带来什么"（互惠视角）。
- 价值空泛（"我很努力很有热情")→ 用具体能力/成果（代码/论文/stars/高效路线）。
- 显得"我能取代你的活/比你强" → 体现互补（你做下游高效，和他的基础模型互补），姿态平等不冒犯。

**⑤ 卡住怎么自救（决策树）**：不知能给某老师带来什么？→ 想"我的能力/成果 × 他的课题需求 = 我能补上的点"（如他做大模型缺高效下游，你正好能补）；担心价值不够？→ 你有 2 篇论文+爆款 repo+强代码，对一个年轻人是实打实的，自信表述。
**⑥ 今天（这一步）你同时学会了什么**：你**用价值卡片摆正了"互惠"心态**。**做了**（5 张 200 字价值卡片 + 从"我能带来什么"出发 + 结合各老师课题 + 体现互补）、**学了**（价值卡片是心态锚、互惠 vs 索取决定邮件姿态、用具体价值不空泛、体现互补不冒犯）、**会了**（以"我能贡献什么"的平等心态准备对接）。

> **技能卡｜价值卡片（互惠心态）**：每位老师一张 200 字"我能给你带来什么"卡片。★ 核心=视角转换：不是"我想得到什么"（索取，像求收留）而是"我能为你的课题贡献什么"（互惠，平等有吸引力）。它是写邮件的心态锚——先摆正"我带着能力和成果来对接，不是来求"。你的价值：通用 CV 强代码+2 篇遥感论文+开源 60+stars+单卡高效路线（和大模型组互补，能快速上手其下游/难题课题）。要具体（不空泛"有热情"）、体现互补（不冒犯）。

## 中午段 · 把问题打磨成"邮件友好"的措辞

**① 先垫概念（为什么尖锐问题要改成"邮件友好"措辞）**
- 你攒的"尖锐问题"在批注里可能是直接的（"这里有问题/这个不严谨"），但**放进给老师的邮件，措辞要友好、谦逊、出于真诚的好奇**——从"我觉得这里有问题"（像挑刺/冒犯）变成"**我很好奇这个设计在 X 场景下是否……**"（像虚心请教 + 展示思考）。
- **为什么这个调整重要**：邮件是给一位你想对接的老师的，**姿态要谦逊而不卑微、有思考而不冒犯**。同样的问题，攻击性措辞会得罪人，请教式措辞会让对方觉得"这个年轻人读得深、有想法、还谦虚"——后者才可能换来回复和好感。
- **打磨原则**：① 用请教语气（"我好奇/想请教/不确定我的理解是否正确"）；② 先肯定/复述他的工作（"您用 X 取得了很好的效果"）；③ 再提延伸问题（"我好奇在 Y 场景下……"）；④ 可结合你的经验（"我在做 Z 时遇到类似情况，所以……"）——既请教又自然带出你的工作。

## 中午段 · 自审邮件（4 项检查）

**① 先垫概念（邮件自审清单）**
- 草稿写完要**自审**——用固定清单逐封检查：① **长度 ≤300 字？**（太长没人读）；② **有具体技术问题？**（体现你读了他的工作、有思考——这是定制的核心）；③ **有你的成果？**（让他知道你能带来价值——论文/stars/高效路线）；④ **有附件说明？**（主页/简历/论文，方便他了解你）。四项都满足，才是一封合格的对接邮件。
- **为什么这四项**：它们对应"短、定制、有价值、可深入了解"——一封对接邮件成功的关键要素。缺任何一项都会减分（太长没人读、没技术问题像群发、没成果不知你价值、没附件无法深入）。

**② 手把手带做**：用四项清单逐封自审 3 封草稿（可用补充包的邮件自审脚本）——① 数字数（≤300？超了精简）；② 找具体技术问题（有？针对他论文？没有就补）；③ 找你的成果（有？具体数字？没有就加）；④ 找附件说明（有？没有就补主页/简历）；逐封过、逐项改到全满足。
**③ 这一步合格的样子**：3 封草稿都通过四项自审（≤300 字 + 有技术问题 + 有成果 + 有附件说明）。

**⑤ 自审**：超 300 字砍不动？→ 砍寒暄/重复，留对接点+1 问题+1 句价值+附件；没具体技术问题？→ 从定制素材里取（你攒的邮件友好问题）。

## 晚上段 · 让朋友读草稿（"会回复吗？"）

**① 先垫概念（为什么要朋友过目）**
- 自审解决"自己能查的"，但**"这封邮件读起来什么感觉、会不会想回"是主观的，需要外部视角**。找 1 位朋友读你的草稿，问一个关键问题：**"如果你是收到这封邮件的老师，你会回复吗？为什么？"** 他的直觉反应（想回 / 不想回 + 原因）能暴露你自审发现不了的问题（姿态怪、没吸引力、像群发、太啰嗦）。
- **和模拟汇报（W42）类似**：都是用外部视角检验"对方的真实感受"。邮件最终是给老师看的，先让一个"局外人"读，能提前发现"我以为不错但别人觉得怪"的地方。一个很实用的判断标准：让朋友读完后，凭第一感觉说"想回 / 不想回"——如果他犹豫或说"不想回"，先别急着解释你的意图，而是问"是哪里让你不想回？"。往往答案很朴素（"太长了""感觉在求我""读不出你想干嘛"），而这些朴素的反应，恰恰是真实老师收到邮件时的第一反应。

**② 手把手带做**：把 3 封草稿给 1 位朋友读 → 问"如果你是这位老师，会回复吗？为什么？"→ 记录他的反应（哪封想回/不想回、哪里怪/啰嗦/像群发/没吸引力）→ 据反馈记下要改的点（明天 D301 还会最终修改）。
**③ 合格样例**：朋友读了 3 封并给了"会不会回 + 原因"的反馈，你记下了要改进的点。
**④ 坑**：① 不找人读、自我感觉良好 → 外部视角能发现你看不到的问题；② 朋友说"挺好"就过 → 追问"如果要挑，哪封最不想回、为什么"；③ 反馈不记/不改 → 记下来，D301 最终修改时落实。
**⑤ 自救**：朋友不懂科研？→ 不懂科研也能判断"这封读起来舒服吗、像不像群发、想不想回"（普通人的直觉反而真实）；反馈太笼统？→ 追问具体哪封、哪句。
**⑥ 今天（这一步）你同时学会了什么**：你**用朋友的外部视角检验了邮件**。**做了**（朋友读 3 封 + 问"会回复吗"+ 记反馈）、**学了**（外部视角检验主观感受、"会不会回"是关键问题、记下来待改）、**会了**（在发出前用局外人视角发现邮件的真实问题）。

## 二、完整可运行代码 · 邮件自审检查器（+ 预期输出）

> 这个脚本对你的邮件草稿做自动自审：查字数（≤300）、有无技术问题、有无成果数字、有无附件说明，并检测"群发模板/纯客套"的红旗词。写完草稿跑一下，低级问题先自己发现。

```python
#!/usr/bin/env python3
# email_checker.py —— 对接邮件草稿自审检查器
import re

def check_email(draft):
    n = len(re.sub(r'\s', '', draft))      # 去空白算字数
    has_question = '?' in draft or '？' in draft
    # 成果数字：stars / mAP / 论文数 / 百分比 / 60+ 等
    has_achievement = bool(re.search(r'\d+\+?\s*(stars?|篇|%|mAP)|SOTA|开源', draft))
    has_attachment = bool(re.search(r'附|主页|链接|简历|附件', draft))
    # 红旗：纯客套/群发感（久仰/拜读但无具体、模板感）
    red_flags = [w for w in ['久仰大名', '崇拜', '膜拜', '万分荣幸'] if w in draft]

    print("=== 邮件草稿自审 ===")
    print(f"[{'✅' if n<=300 else '❌'}] 字数 {n}（要求 ≤300）")
    print(f"[{'✅' if has_question else '❌'}] 含具体技术问题")
    print(f"[{'✅' if has_achievement else '❌'}] 含你的成果（数字/开源）")
    print(f"[{'✅' if has_attachment else '❌'}] 含附件/主页说明")
    if red_flags:
        print(f"[⚠️] 检测到纯客套/谄媚词：{red_flags} → 删掉，用具体+平等姿态")
    else:
        print(f"[✅] 无谄媚红旗词")
    passed = n<=300 and has_question and has_achievement and has_attachment and not red_flags
    print(f"\n{'🎉 通过自审，可进入打磨' if passed else '⚠️ 未全通过，按上面修改'}")
    return passed

sample = """王老师您好：我是一名专注遥感CV的研究者，做SAR旋转检测与speckle抑制，
已有2篇论文和开源项目60+ stars。拜读了您文本-SAR跨模态的工作，我在处理speckle时
遇到一个问题：在低信噪比下跨模态对齐是否会受影响？很想请教。我擅长单卡高效路线，
或许能在SAR下游特化上与贵团队互补。附上个人主页链接，方便您了解。期待请教。"""

if __name__ == "__main__":
    check_email(sample)
```

**预期输出**：
```
=== 邮件草稿自审 ===
[✅] 字数 146（要求 ≤300）
[✅] 含具体技术问题
[✅] 含你的成果（数字/开源）
[✅] 含附件/主页说明
[✅] 无谄媚红旗词

🎉 通过自审，可进入打磨
```
> 解读：脚本逐项检查四要素 + 谄媚红旗词。把你的草稿填进 sample，目标是五项全 ✅。注意：字数检查是去空白后的中文字符数（仅供参考，真实邮件以"短而精"为准）；技术问题/成果/附件三项缺哪补哪；检测到"久仰/崇拜"等谄媚词就删掉换成具体+平等的表达。
