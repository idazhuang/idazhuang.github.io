2. **第 2 遍（25 min）**：Introduction（**它说前人差在哪**）+ Method 的核心小节。
3. **第 3 遍（30 min）**：Experiment，**重点是消融表**。

## ② 手把手带做 + ★ 对答案

### 第 1 遍：先搞清"它要解决什么"

**★ 对答案 · 摘要的逻辑链**（读完你应该能复述出这条链）：

```text
现有的两阶段旋转检测器（比如 RoI Transformer）
    要生成旋转候选框（oriented proposal）
    → 但它们生成的方式很费时
    → 成为整个系统的速度瓶颈
        ↓
本文：设计一个 oriented RPN，几乎零额外代价地直接产生高质量旋转候选框
        ↓
结果：ResNet-50 在 DOTA 上 75.87% mAP，HRSC2016 上 96.50%，
      速度 15.1 FPS（1024×1024）—— 又快又准
```

**★ 记住 75.87 这个数字**，它是你 W2 复现的对照。**但你在 val 上单卡跑出 68–75 就正常**，原因见 [W2 实操 §6.3](w2-baseline.html)。

### 第 2 遍：它比前人多做了什么

**★ 对答案 · 这篇的核心创新（一句话）**：

> **把"生成旋转候选框"这件事，从一个昂贵的独立步骤，变成 RPN 里几乎免费的一步。**

**具体怎么做的**（这是你笔记第 2 段该写的，用自己的话）：

传统 RPN 输出的是**水平框**（4 个数：x, y, w, h）。Oriented RPN 的做法是：**在水平框的基础上，再多回归两个偏移量**，用这两个数把水平框"掰"成一个平行四边形，再规整成旋转框。

**这个设计的巧妙之处**：

| 别人的做法 | 代价 | Oriented R-CNN 的做法 |
|---|---|---|
| 用**旋转 anchor**（每个位置放多个不同角度的锚框） | anchor 数量翻好几倍，计算量爆炸 | **仍用水平 anchor**，只多回归 2 个数 |
| 先出水平 RoI，再用一个模块**学着转成旋转 RoI**（RoI Transformer 的做法） | 多一个模块，多一段计算 | **一步到位** |

**所以它的卖点是"几乎零成本"** —— 这就是摘要里 "nearly cost-free" 的含义。

### ★ 自检三问（答不出就回去重读）

1. **它说前人的瓶颈是什么？**（答：生成旋转候选框太慢）
2. **它的 oriented RPN 和普通 RPN 差在哪？**（答：多回归两个偏移量，把水平框掰成旋转框）
3. **为什么不用旋转 anchor？**（答：anchor 数量爆炸，计算量吃不消）

### 第 3 遍：消融表怎么读

**★ 读消融表的通用方法**（这一招你后面每篇方法论文都用）：

```text
① 先找 baseline 那一行（通常是第一行，所有组件都关掉）
② 再找 full model 那一行（通常是最后一行，全开）
③ 中间每一行 = 只开一个组件
④ ★ 关键动作：算每个组件的增量（这一行 − baseline 行）
   → 增量大的组件 = 论文真正的贡献
   → 增量小于 0.5 的组件 = 可能只是凑数（这是你未来找 Gap 的线索）
```

**带着这个方法去读它的消融表**，你会发现：**它的性能提升主要来自 oriented RPN 本身，而不是一堆小 trick 堆出来的**。这是一篇"干净"的论文——**干净的论文才值得当 baseline**，因为你改动之后能清楚归因。

## 2.3 五大块，在展开版里各自长什么样

**① backbone（主干：提特征）**

```python
backbone=dict(
    type='ResNet',
    depth=50,                    # ResNet-50
    num_stages=4,                # 4 个阶段，输出 4 个尺度的特征
    out_indices=(0, 1, 2, 3),    # 这 4 个阶段都往外输出（给 FPN 用）
    frozen_stages=1,             # ★ 冻结第 1 阶段不训练（低层特征很通用，省显存也更稳）
    norm_cfg=dict(type='BN', requires_grad=True),
    norm_eval=True,              # ★ BN 层用推理模式（batch 小的时候必须这样，否则统计量不稳）
    style='pytorch',
    init_cfg=dict(type='Pretrained', checkpoint='torchvision://resnet50'))
                                 # ★ 用 ImageNet 预训练权重初始化，不是从零训
```

> **`frozen_stages=1` 和 `norm_eval=True` 这两行原文完全没提，但它们解释了一个你会问的问题**：为什么 batch size 只有 2 也能训得动？**因为 BN 层根本没在更新统计量**（`norm_eval=True`），所以不受小 batch 影响。这是检测框架的标准做法。

**② neck（脖子：多尺度融合）**

```python
neck=dict(
    type='FPN',
    in_channels=[256, 512, 1024, 2048],   # 对应 ResNet 四个阶段的输出通道
    out_channels=256,                      # 统一压到 256 通道
    num_outs=5)                            # 输出 5 个尺度（多一个是下采样出来的）
```

FPN 是什么、为什么需要它，见 [《检测与训练概念详解》§2.3](../start/cv-concepts.html)——**全书正文出现 49 次，没有一句解释。**

**③ head（头：出预测）**

```python
rpn_head=dict(
    type='OrientedRPNHead',        # ★ 就是论文的核心创新
    anchor_generator=dict(
        type='AnchorGenerator',
        scales=[8], ratios=[0.5, 1.0, 2.0],   # 水平 anchor，3 种长宽比
        strides=[4, 8, 16, 32, 64]),           # 对应 FPN 五个尺度
    bbox_coder=dict(type='MidpointOffsetCoder', angle_range='le90'),
                                   # ★ "多回归两个偏移量" 就编码在这里
    ...)
roi_head=dict(
    type='OrientedStandardRoIHead',
    bbox_head=dict(num_classes=15, ...))   # ★ DOTA 的 15 类
```

> **★ 把论文和 config 对上**：你上午读到的"多回归两个偏移量把水平框掰成旋转框"，落到代码里就是 `MidpointOffsetCoder` 这一行。**能把论文的一句话指到 config 的一行，说明你真读懂了。**

**④ 数据块**

```python
dataset_type = 'DOTADataset'
data_root = 'data/split_1024_dota1_0/'    # ★ 要改成你切好图的路径
data = dict(
    samples_per_gpu=2,        # ★ 这就是 batch_size
    workers_per_gpu=2,
    train=dict(ann_file=data_root + 'trainval/annfiles/',
               img_prefix=data_root + 'trainval/images/'), ...)
```

**⑤ schedule 块**

```python
optimizer = dict(type='SGD', lr=0.005, momentum=0.9, weight_decay=0.0001)
lr_config = dict(policy='step', warmup='linear', warmup_iters=500,
                 warmup_ratio=1.0/3, step=[8, 11])   # 第 8、11 个 epoch 各降 10 倍
runner = dict(type='EpochBasedRunner', max_epochs=12)   # 1× = 12 epochs
```

## 2.4 ★ 纠正原文的自相矛盾：lr 到底是 0.0025 还是 0.005

原文中午段的示意代码写 `lr=0.0025`，但同一段的合格样例里说"lr=0.005"。**两个数不一样，新手会懵。**

**正确答案：MMRotate 的 DOTA config 里是 `lr=0.005`。**

**它对应的是"单卡 × 每卡 2 张 = 总 batch 2"。** 这一点和 MMDetection 的 COCO config 不同（那边默认 8 卡 × 2 张 = 16）。

| 你的设置 | 总 batch | lr 应该是 |
|---|---|---|
| 单卡，`samples_per_gpu=2` | 2 | **0.005（默认值，不用改）** |
| 单卡，`samples_per_gpu=1` | 1 | **0.0025** |
| 单卡，`samples_per_gpu=4` | 4 | 0.01 |

**所以原文那个 0.0025，其实是 batch=1 时的值。** 完整说明见 [W2 实操 §4.3](w2-baseline.html)。

# 3. 晚上段 · 写自己的 config + dry-run

## ② 手把手带做

### 第 1 步：新建继承式 config（不要 cp 官方文件）

原文说 `cp configs/oriented_rcnn/... configs/my_orcnn_r50.py`。**能用，但不是最佳实践**——复制出来的是完整副本，以后官方更新了你看不出差异。

**更好的做法**：新建 `configs/my/my_orcnn_r50.py`，只写你要改的：

```python
# configs/my/my_orcnn_r50.py
_base_ = ['../oriented_rcnn/oriented_rcnn_r50_fpn_1x_dota_le90.py']

data_root = 'data/split_ss_dota/'

data = dict(
    samples_per_gpu=2,      # 4090 够用；显存不足改 1，★ 同时把 lr 改成 0.0025
    workers_per_gpu=2,
    train=dict(ann_file=data_root + 'trainval/annfiles/',
               img_prefix=data_root + 'trainval/images/'),
    val=dict(ann_file=data_root + 'trainval/annfiles/',
             img_prefix=data_root + 'trainval/images/'),
    test=dict(ann_file=data_root + 'trainval/annfiles/',
              img_prefix=data_root + 'trainval/images/'))

checkpoint_config = dict(interval=4, max_keep_ckpts=2)   # 省磁盘
evaluation = dict(interval=4, metric='mAP')
```

**只有 12 行。** 半年后你回来看，一眼就知道自己改了什么。

> **注意**：这个 config 依赖 D9 切好的图。**今天 D8 晚上还没切图**，所以 dry-run 要用别的办法，见下一步。

### 第 2 步：★ 今晚怎么 dry-run（原文没解决这个时序问题）

**原文让你 D8 晚上 dry-run，但切图是 D9 中午的事**——**今晚你手上根本没有训练数据。** 这是原计划的一个时序漏洞。

**两个选择**：

**选择 A（推荐）：今晚只做"配置层面的 dry-run"**

```bash
# 验证 config 语法正确、能被解析、关键值对
python tools/misc/print_config.py configs/my/my_orcnn_r50.py | \
    grep -E "ann_file|img_prefix|samples_per_gpu|lr=|num_classes|max_epochs"
```

**期望输出**里应该看到你改的路径、`samples_per_gpu=2`、`lr=0.005`、`num_classes=15`、`max_epochs=12`。

**这一步能抓出 80% 的 config 错误，而且不需要数据。**

**选择 B：把切图提前到今晚**

如果你 D5 下的 val 已经解压好，**今晚就可以切**（[W2 实操 §3](w2-baseline.html)），切完立刻能真 dry-run。**这样 D9 中午就腾出来了**，可以提前启动正式训练——**整周节奏会宽松很多**，推荐这么干。

### 第 3 步：真 dry-run（有数据之后）

```bash
python tools/train.py configs/my/my_orcnn_r50.py \
    --work-dir work_dirs/dryrun \
    --cfg-options runner.max_epochs=1 log_config.interval=50
```

**★ 盯前 200 个 iter，对照这张表**：

| 现象 | 判断 | 动作 |
|---|---|---|
| total loss 从 ~2 稳步下降 | ✅ 健康 | Ctrl+C，去跑正式的 |
| loss 是 `nan` | ❌ lr 太高 | 减半 |
| loss 卡住不动 | ❌ 数据/标注有问题 | 用 `vis_dota.py` 抽查切图结果 |
| `acc` 一直 100 但 loss 不降 | ❌ 标注是空的 | `ann_file` 路径错 |
| 显存占用接近 0 | ❌ 在用 CPU | 检查 `torch.cuda.is_available()` |
