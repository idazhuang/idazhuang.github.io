## 上午段 · 精读 BIT(Bitemporal Image Transformer, Chen 2022, TGRS)

**① 先垫概念(假设你第一次接触变化检测)**
- **变化检测(change detection, CD)**= 对比同一地点**不同时间**拍的两张图,找出"什么变了"(建筑新增、城市扩张、灾害损毁、植被消失)。
- 它和你 M1 做的目标检测**完全不同**:目标检测输入**一张图**、输出**框+类别**;变化检测输入**两张图(双时相)**、输出**变化掩膜(mask,逐像素标"变/没变")**。
- **双时相(bitemporal)** = 两个时间点的图(常记作 T1 前时相、T2 后时相)。BIT 名字里的 "Bitemporal" 就是这个意思。
- **和通用 CV 对比**:通用 CV 几乎没有"对比两张图找差异"这种任务设定;变化检测是遥感(对地观测要看"变化")特有的高价值任务。
- **为什么变化检测是高价值任务**:对地观测的核心诉求之一就是"看变化"——城市扩张监测、违建查处、灾害(地震/洪水)损毁评估、森林砍伐/耕地保护、冰川消融。这些都是国家级刚需,且必须靠"前后对比"才能做。**这也是空天院等机构重点投入的方向之一**。
- **变化检测特有的难点(也是你未来的选题口子)**:① **伪变化**——光照、季节、传感器差异会造成"看起来变了其实没变"(如同一片地夏天绿冬天黄),模型要学会忽略这些"无关变化"只报"真实变化";② **配准误差**——两个时相的图如果没精确对齐,会产生大量假变化;③ **类别极不平衡**——一张图里真正变化的像素通常很少(这直接决定了为什么用 F1 而非准确率,明天 D30 细讲)。**"区分真变化和伪变化"本身就是一个很好的小而硬选题方向。**

**② 手把手带做**
1. 下载 BIT 论文,按精读 3 遍法(综述/方法各几遍你 M1 学过;这是方法论文,读 3 遍)。
2. 在 `10-论文笔记/2022_Chen_BIT.md` 套 5 段式模板,重点回答两问:① BIT 怎么用 **Transformer** 建模"两个时相之间的差异"?② 它把变化检测当成**什么问题**(逐像素二分类:每个像素属于"变"或"没变")?
3. 第 4 段记下:BIT 还有什么没解决的(如对小变化、配准误差敏感)——这是你未来选题的素材。

**③ 合格样例**:`2022_Chen_BIT.md` 能用一句话说清"**输入两张图、输出变化 mask,用 Transformer 把两图特征 token 化、用注意力比对差异**";第 4 段有 ≥1 条"它没解决的"。

**④ 常踩的坑**
- 用"检测=画框"的思维理解它 → 变化检测输出的是 **mask(逐像素),不是框**。
- 以为"两张图随便拍的" → 必须是**同一地点、配准好**的两个时相(否则"变化"无意义)。

**⑤ 卡住自救(决策树)**
- Transformer 那块看不懂 → 抓"它把两图特征变成 token、用注意力机制比对差异"的**直觉**即可,细节后面用到再深究。
- 不理解"逐像素二分类" → 类比:把输出图的每个像素当成一个二分类样本(变=1/没变=0)。

**⑥ 今天(这一步)你同时学会了什么**:你建立了**第三类任务(变化检测)的任务观**,理解了"同样叫'检测',输入输出可以完全不同"。**做了**(BIT 笔记)、**学了**(变化检测的定义、双时相、逐像素二分类)、**会了**(快速读懂一个新任务的代表论文并抓住其任务设定)。

## 晚上段 · BIT 训练完成 → 评估 → 记录 F1(★第一次接触 F1 指标)

**① 先垫概念(本周最重要的新概念,务必懂)**
- 变化检测**不用 mAP**,用 **F1-score(主)和 IoU**。**为什么换指标**:变化检测是"逐像素二分类(变/没变)",而且**变化像素通常远少于不变像素**(类别极不平衡)。这时光看"**准确率(accuracy)**"会**严重骗人**——全部猜"没变"也能有 95%+ 的准确率(因为大部分像素本来就没变),但这种模型毫无用处。
- **F1 = 精确率(precision)与召回率(recall)的调和平均**:
  - **precision**(精确率)= "我说'变'的像素里,有多少真的变了"(惩罚**误报**)。
  - **recall**(召回率)= "真正变了的像素里,我找到了多少"(惩罚**漏报**)。
  - F1 同时考虑两者,**只有误报和漏报都低,F1 才高** → 非常适合不平衡的变化检测。
- **一句话记牢任务↔指标**:检测用 **mAP**,分割用 **mIoU**,变化检测用 **F1**(辅以 IoU)。
- **一个具体例子看清"准确率为什么骗人"**:假设一张图 10000 个像素,真正变化的只有 200 个(2%)。一个"全猜没变"的废物模型:它把 9800 个没变的都猜对了,准确率 = 9800/10000 = **98%**,看着很高!但它一个变化都没找到——recall = 0/200 = 0,F1 = 0。**准确率 98% vs F1 = 0**,F1 一下就揭穿了这个废物模型。这就是为什么不平衡任务必须用 F1。

**② 手把手带做**:BIT 训完 → 跑它的评估脚本 → 记录 **F1**(LEVIR-CD 上 BIT 参考 ~89–91%)→ 填进昨天的 SOTA 草表 BIT 那行。如果它还输出 precision/recall/IoU,一并记下。

# D31 周三 · 两种变化检测范式(FCN vs 孪生网络)+ 体验式跑通

> 今天搞清变化检测的两大经典范式,并认识一个**会反复出现的结构:孪生网络(Siamese)**。再跑一个 baseline 体验。
>
> **预期管理**:今天的关键概念是孪生网络(共享权重双分支比对)——它在变化检测、跨模态匹配、图像检索、对比学习里反复出现,记牢它一次,处处受用。提醒:孪生的灵魂是"两分支权重完全相同(共享)",看漏这点就理解错了;晚上跑 ChangeFormer 时间不够就只跑 demo 推理,体验到即可,别在单个方法上耗太久。

## 上午段 · 精读 FCN-PP / SNUNet 两篇(两种范式)

**① 先垫概念**
- 变化检测有两类经典做法:
  - **基于 FCN(全卷积网络)**:把两张图(或它们的差/拼接)直接喂一个分割式网络,输出变化 mask。
  - **基于孪生网络(Siamese network)**:用**两个共享权重的相同分支**分别处理 T1、T2 两张图,再**比较两路特征**找差异。
- **孪生网络是重点**:它就是"**用同一双眼睛先后看两张图,再比对**"——两个分支权重完全相同(共享),保证两张图被"同样地"理解,差异才有意义。这个结构在**变化检测、跨模态匹配、图像检索、对比学习**里反复出现,务必记牢。
- **两类范式的取舍**:FCN 系(早期融合)简单直接——把两张图拼起来当一个多通道输入喂进去,让网络自己学差异;但它没有显式地"对比"两图,差异建模较隐式。孪生系(晚期融合)先各自提特征再显式比对,**更符合"变化=两图之差"的直觉,也更容易解释**,是当前主流。**理解"早期融合 vs 晚期融合"这个区分**很有用——它不只在变化检测,在所有"多输入"任务(多模态、多时相)里都是核心设计选择。
- **为什么"共享权重"是孪生的灵魂**:如果两个分支权重不同,它们就会用"两套不同的标准"看两张图,提出的特征不可比,"差异"就混入了"两套标准本身的差异",失去意义。共享权重保证"两张图用完全相同的方式被理解",这样特征之差才纯粹反映"图的内容之差"=真实变化。**这个"用同一套参数处理多个输入以保证可比性"的思想,在对比学习、度量学习里都是基石。**

**② 手把手带做**:精读 FCN-PP / SNUNet(经典论文抓范式,~25min/篇),笔记答:FCN 系和孪生系各**怎么处理"两张图"**?各自优劣(孪生更能显式比对、FCN 更简单)?

**③ 合格样例**:笔记里能画出"孪生网络 = 共享权重双分支 → 特征比对 → 变化 mask"的示意,并说清它和 FCN 系的区别。

**④ 常踩的坑**:把"共享权重"看漏 → 孪生的关键就是**两分支权重相同**;若两分支独立,就不是孪生了。

**⑤ 卡住自救**:范式细节看不懂 → 抓"孪生=共享权重双分支比对"这一句核心直觉即可,够用。

## 上午段 · 精读 UNetFormer(Wang 2022, ISPRS)

**① 先垫概念**
- **语义分割(semantic segmentation)**= 给图像**每个像素**分一个类别(建筑/道路/农田/水/植被/裸地/背景)。输出是一张"逐像素类别图(mask)"。
- **遥感分割的特殊性**(相对 Cityscapes 等通用分割):① **鸟瞰视角**(不是街景平视);② **边界模糊**(田与田、林与草之间常没有清晰边缘);③ **尺度悬殊**(一栋楼和一片森林同框)。这些是通用分割方法搬到遥感后掉点的原因(又是你 Introduction 的弹药)。
- **UNet 思路**:编码器逐步下采样抓"全局语义",解码器逐步上采样还原"精细边界";UNetFormer 在此基础上用 Transformer 增强全局上下文。
- **为什么"编码器-解码器"是分割的标准骨架**:分割既要"知道这片区域是什么(语义,需要大感受野/下采样)",又要"精确到每个像素的边界(细节,需要高分辨率/上采样)"。编码器下采样抓语义、解码器上采样还原细节,中间常有跳连(skip connection)把浅层细节传给解码器——这套结构同时满足了"语义"和"细节"两个看似矛盾的需求,所以成了分割的通用骨架。
- **遥感分割的特殊难点为什么是选题口子**:边界模糊→可做"边界增强的分割";尺度悬殊→可做"多尺度特征更好融合";类别不平衡(背景多、某些地物少)→可做"长尾分割"。这些通用分割也有,但遥感的极端程度(超大图、超悬殊尺度)让它们更突出,也更值得针对性改进。**把一个通用分割的新技巧针对遥感这些特点改造,就是"通用 CV 巧技嫁接"的典型选题。**

**③ 合格样例**:`2022_Wang_UNetFormer.md` 能说清"编码器抓全局、解码器还原细节,Transformer 增强上下文";并记下遥感分割的 ≥2 个特殊难点。

## 晚上段 · 分割 baseline 完成 → 记录 mIoU + 写"分割 vs 检测流程对比"(★mIoU)

**① 先垫概念(分割的关键指标)**
- **mIoU(mean Intersection over Union,平均交并比)**= 所有类别 **IoU 的平均**。
- **IoU**(你 M1 在检测里学过的概念)= 预测区域与真值区域的"**交集 / 并集**"(0–1,越大越准)。分割里是**逐类、逐像素**地算 IoU,再对所有类别取平均得 mIoU。
- **为什么分割用 mIoU**:它**逐类衡量"区域重叠得准不准"**,且对各类一视同仁(避免大类主导)。
- **"逐类平均"为什么关键**:遥感分割里类别极不均衡(背景/大片农田占绝大多数像素,而道路/小建筑占很少)。如果只算"总体像素准确率",模型把大类分对就能拿高分,小类全错也看不出来。**mIoU 对每个类单独算 IoU 再平均,小类和大类权重一样**——这逼着模型每个类都要分好,才能拿高 mIoU。这和变化检测用 F1 是同一个逻辑:**不均衡任务不能看总体准确率,要用对各类/各情况公平的指标。**
- **三大指标到这就集齐了,串起来记**:检测用 **mAP**(综合各类的检测精度)、变化检测用 **F1**(平衡误报漏报)、分割用 **mIoU**(逐类区域重叠)。**它们的共同思想是"不被多数类/简单情况蒙混过关"**——这正是评价不平衡问题的核心。理解了这层,你看任何新任务都能问对"它该用什么指标、为什么"。

**② 手把手带做**:① 分割 baseline 训完 → 跑评估 → 记录 **LoveDA mIoU**,填进排行榜;② 写一段 **300 字"分割实验流程 vs 检测实验流程"对比**(数据格式:框 vs 逐像素 mask;标签形式;指标:mAP vs mIoU;评估方式)。
```bash

python tools/test.py configs/loveda/my_unetformer_loveda.py \
    work_dirs/my_unetformer_loveda/latest.pth --eval mIoU
# 输出打印总 mIoU + 每个类别的 IoU；对照 分割SOTA.md 填进 UNetFormer 行
# 注意：和 M1 检测评估的区别只是 --eval mIoU（检测是 --eval mAP），其余完全一样
```
**③ 合格样例**:LoveDA mIoU 记录在案;300 字流程对比清晰指出检测与分割在"数据/标签/指标/评估"上的不同。

**④ 常踩的坑**:① mIoU 异常低 → 多半类别索引映射错或忽略类没排除;② 把检测流程直接套到分割 → 标签形式、指标、评估都不同。

## 二、完整可运行代码 — 变化检测 F1 + 语义分割 mIoU（本周新指标的实现）

> 配合 D30(F1)、D33(mIoU)。存 `20-代码实验/utils/metrics_seg_cd.py`:

```python
import numpy as np

# ① 变化检测 F1（二分类：1=变, 0=没变；pred/gt 是同形状 0/1 数组）
def change_f1(pred, gt, eps=1e-7):
    pred, gt = (pred > 0).astype(np.int64), (gt > 0).astype(np.int64)
    tp = int(((pred == 1) & (gt == 1)).sum())
    fp = int(((pred == 1) & (gt == 0)).sum())
    fn = int(((pred == 0) & (gt == 1)).sum())
    precision = tp / (tp + fp + eps)
    recall    = tp / (tp + fn + eps)
    f1        = 2 * precision * recall / (precision + recall + eps)
    return dict(precision=round(precision,4), recall=round(recall,4), f1=round(f1,4))

# ② 语义分割 mIoU（pred/gt 是 HxW 的类别索引图，num_classes 类）
def miou(pred, gt, num_classes, ignore=255):
    ious = []
    for c in range(num_classes):
        mask = (gt != ignore)
        p, g = (pred == c) & mask, (gt == c) & mask
        inter = int((p & g).sum())
        union = int((p | g).sum())
        if union == 0:        # 该类不存在则跳过(不计入平均)
            continue
        ious.append(inter / union)
    return round(float(np.mean(ious)), 4), [round(i,4) for i in ious]

if __name__ == "__main__":
    pred = np.array([[1,0],[1,1]]); gt = np.array([[1,0],[0,1]])
    print("CD:", change_f1(pred, gt))                 # 看 precision/recall/f1
    p = np.array([[0,1],[2,1]]); g = np.array([[0,1],[1,1]])
    print("mIoU:", miou(p, g, num_classes=3))         # 看 mIoU + 各类 IoU
```
**预期**:打印出 F1(变化检测主指标)和 mIoU(分割主指标)。**为什么手写一遍**:亲手实现一次,你才真懂"为什么类别不平衡要用 F1(全猜没变的准确率虚高)、mIoU 为什么逐类算再平均"。
