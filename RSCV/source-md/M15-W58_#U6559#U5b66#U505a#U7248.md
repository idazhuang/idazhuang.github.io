# D400 周一 · 论文 v1.0 定稿——英文润色 + 访问申请跟进

## 上午段 · 英文润色（语法/表达/学术性，工具辅助 + 人工通读）

**① 先垫概念（英文润色怎么做、为什么重要）**
- ★ **英文润色**是论文定稿的关键一环，对非英语母语的你尤其重要：① **语法**（消除语法错误——主谓一致、时态、冠词等）；② **表达**（地道的学术表达——避免中式英语、用学术圈惯用的措辞）；③ **学术性**（正式、客观、严谨的学术语气）。**做法**：① **工具辅助**（语法检查工具做初步检查，找出明显错误）；② ★ **人工通读**（一定要人工逐段读——工具改不出地道的学术表达和篇章逻辑），或请英语好的同行/朋友帮看。★ **为什么润色值得花时间**："writing needs improvement"是非母语作者常见的审稿意见——地道的语言不会让一篇好论文加分，但糟糕的语言会让好论文减分。
- **从哪些地方入手**：先用工具扫一遍语法错误，再人工通读重点段落（Abstract/Intro/方法描述/结论），打磨表达和逻辑。

**② 手把手带做**：① 用语法工具做初步检查（找明显错误）；② ★ 人工通读（逐段打磨表达和逻辑，尤其 Abstract/Intro/方法/结论）；③ 消除中式英语、用学术惯用表达；④ 确保语气正式客观严谨；⑤ 如可能请英语好的同行/朋友帮看。
**③ 这一步合格的样子**：英文润色推进——工具查了语法、人工通读打磨了表达和逻辑，语言地道、学术、无明显错误。
**④ 最常踩的坑**
- 只用工具不人工通读（改不出地道表达）→ ★ 人工通读打磨。
- 中式英语（不地道）→ 用学术圈惯用表达。
- 不重视润色（语言失分）→ 润色值得花时间（语言会影响评价）。

**⑤ 卡住怎么自救（决策树）**：英文不够好怎么办？→ 工具辅助 + 人工通读 + 请英语好的同行帮看；哪些先润色？→ Abstract/Intro/方法/结论（审稿人最先看的）。
**⑥ 今天（这一步）你同时学会了什么**：你**推进了论文的英文润色**。**做了**（工具查语法 + 人工通读打磨 + 消除中式英语 + 确保学术语气 + 请人帮看）、**学了**（英文润色工具辅助 + 人工通读、语言会影响评价、重点章节先润色）、**会了**（把论文语言打磨到地道学术的水平）。

> **技能卡｜英文润色（投稿级语言·人工通读）**：论文定稿的语言打磨,对非母语作者尤其重要——①语法（主谓/时态/冠词等错误）②表达（地道学术表达,避免中式英语）③学术性（正式客观严谨）。做法:★ 工具辅助（初步查语法）+ ★ 人工通读（工具改不出地道表达和篇章逻辑,一定逐段读,尤其 Abstract/Intro/方法/结论）+ 请英语好的同行帮看。★ 为什么值得花时间:"writing needs improvement"是非母语常见审稿意见——地道语言不加分,但糟糕语言会让好论文减分。

## 上午段 · 图表定稿（清晰、专业、风格统一、caption 完整）

**① 先垫概念（图表定稿要做到什么）**
- **图表定稿**——把论文里所有图表打磨到投稿级：① **清晰**（分辨率高、文字可读、不模糊）；② **专业**（美观、规范——坐标轴/图例/标注齐全）；③ ★ **风格统一**（所有图配色/字体/线宽一致，看起来是一套）；④ **caption 完整**（每个图表的标题说清画的什么、说明什么）；⑤ **位置和引用正确**（图表放在合适位置、正文都引用了）。★ **结果图突出单卡高效卖点**（Params/FPS 对比、性能-效率权衡——你的差异化优势）。**精良的图表是论文专业度的直接体现**——审稿人翻论文，图表的质量直接影响第一印象。
- **为什么图表重要**：很多审稿人会先看图表（快速了解你的方法和结果）——清晰专业的图表让人一眼看懂、印象好；粗糙的图表则减分。

**② 手把手带做**：① 检查所有图表清晰（分辨率/可读）；② 规范专业（坐标轴/图例/标注）；③ ★ 统一风格（配色/字体/线宽）；④ 完善 caption（说清画的什么/说明什么）；⑤ ★ 结果图突出单卡高效卖点 + 确认位置和引用。
**③ 这一步合格的样子**：图表定稿——清晰专业、风格统一、caption 完整、位置引用正确，结果图突出单卡高效卖点。
**④ 坑**：① 图模糊/文字不可读 → 高分辨率、文字可读；② 风格不统一（东拼西凑）→ ★ 统一配色/字体/线宽；③ caption 缺失/不清 → 完善 caption；④ 不突出卖点 → 结果图突出 Params/FPS。
**⑤ 自救**：图怎么统一？→ 定一套配色/字体/线宽，所有图套用；caption 写啥？→ 画的什么 + 说明什么。
**⑥ 今天（这一步）你同时学会了什么**：你**定稿了论文图表**。**做了**（检查清晰 + 规范专业 + 统一风格 + 完善 caption + 突出卖点）、**学了**（图表是门面、风格统一、caption 完整、结果图突出卖点）、**会了**（把论文图表打磨到投稿级）。

## 晚上段 · supplementary 补充材料

**① 先垫概念（supplementary 放什么）**
- **supplementary（补充材料）**——放正文容不下但有价值的额外内容：① **额外实验**（正文放不下的补充实验/更多对比/更多数据集结果）；② **实现细节**（详细的超参数、训练细节——方便复现）；③ **额外可视化**（更多可视化样例、失败案例分析）；④ **数学推导**（如有：详细的推导过程）。★ **supplementary 让正文聚焦核心、补充材料详尽**——既保持正文精炼，又给审稿人/读者完整的信息。**如果论文内容已经完整、没有需要额外放的，supplementary 可以简略或省略。**
- **为什么用 supplementary**：正文篇幅有限，但有些细节（复现细节、额外实验、可视化）对完整性有价值——放 supplementary 既不挤占正文，又让有需要的读者能查到。

**② 手把手带做**：① 看有哪些有价值但正文放不下的内容（额外实验/细节/可视化/推导）；② 整理成 supplementary；③ 让正文聚焦核心、补充材料详尽；④ 如内容已完整则简略/省略；⑤ 确认 supplementary 和正文呼应（正文提及"详见补充材料"）。
**③ 这一步合格的样子**：supplementary 整理好（如有）——额外实验/细节/可视化整理成补充材料，正文聚焦、补充详尽（或确认无需 supplementary）。
**④ 坑**：① 该放 supplementary 的塞正文（正文臃肿）→ 移到 supplementary；② supplementary 和正文不呼应 → 正文提及"详见补充材料"；③ 为凑 supplementary 硬塞 → 有价值才放，无则省略。
**⑤ 自救**：哪些放 supplementary？→ 复现细节/额外实验/更多可视化；没有额外内容？→ supplementary 可简略/省略。
**⑥ 今天（这一步）你同时学会了什么**：你**整理了 supplementary 补充材料**。**做了**（看有价值的额外内容 + 整理成 supplementary + 正文聚焦 + 呼应）、**学了**（supplementary 放正文容不下的有价值内容、正文聚焦补充详尽）、**会了**（用补充材料增强论文完整性而不臃肿正文）。

## 二、完整可运行代码 · 访问确认决策器（+ 预期输出）

> 这个脚本根据访问申请发出的天数和各渠道的回复状态，帮你判断当前该做什么——继续等、该追问、准备出行、还是启动 Plan B。把"访问确认判断"这个关键决策系统化。

```python
#!/usr/bin/env python3
# visit_decision.py —— 访问确认决策器
# 各渠道（老师/师兄）的访问申请状态
channels = {
    "孙显老师": {"days_since": 16, "status": "无回复"},
    "王超老师": {"days_since": 16, "status": "已确认"},   # 同意访问
    "李师兄":   {"days_since": 14, "status": "无回复"},
}

def decide(channels):
    print("=== 访问确认决策（W58 周四最终判断）===\n")
    confirmed = [n for n, c in channels.items() if c["status"] == "已确认"]
    pending   = [n for n, c in channels.items() if c["status"] == "无回复"]

    for n, c in channels.items():
        print(f"{n}: {c['status']}（发出 {c['days_since']} 天）")
    print()

    if confirmed:
        print(f"🎉 情形 A — 已确认：{', '.join(confirmed)}")
        print("   → 行动：①准备出行(租房空天院附近/交通票/笔记本+硬盘拷代码数据)")
        print("           ②通知博士导师具体日期 ③进入访问准备(W59-60)")
    else:
        to_followup = [n for n in pending if channels[n]["days_since"] >= 7]
        if to_followup:
            print(f"   📨 该追问（满7天无回复）：{', '.join(to_followup)}")
        # 到最终判断点（W58周四）：长期无回复/被拒 → 启动 Plan B
        if all(channels[n]["days_since"] >= 14 or channels[n]["status"] == "被拒"
               for n in channels):
            print("🔀 情形 B — 启动 Plan B（绝不停摆）：")
            print("   1) 其他遥感团队（自动化所/武大/西电等）")
            print("   2) ★ 线上远程合作（不去现场也能合作写论文,同样建立实质连接）")
        else:
            print("   → 继续等 + 追问；最迟本周四做最终判断")
    print("\n★ 访问只是手段、合作才是目的；路不止一条，绝不停摆。")
    print("★ 即便没促成,这一路积累的(三篇论文/交流/好印象)是下一轮的硬资产。")

if __name__ == "__main__":
    decide(channels)
```

**预期输出**：
```
=== 访问确认决策（W58 周四最终判断）===

孙显老师: 无回复（发出 16 天）
王超老师: 已确认（发出 16 天）
李师兄: 无回复（发出 14 天）

🎉 情形 A — 已确认：王超老师
   → 行动：①准备出行(租房空天院附近/交通票/笔记本+硬盘拷代码数据)
           ②通知博士导师具体日期 ③进入访问准备(W59-60)

★ 访问只是手段、合作才是目的；路不止一条，绝不停摆。
★ 即便没促成,这一路积累的(三篇论文/交流/好印象)是下一轮的硬资产。
```
> 解读：把各渠道的访问申请状态填进 channels，脚本在 W58 周四这个最终判断点给出决策——有确认（情形 A）就准备出行，全部长期无回复/被拒（情形 B）就启动 Plan B。示例里王超老师已确认，进入出行准备。这把"访问确认判断"从凭感觉变成有依据的决策——尤其帮你在"该不该启动 Plan B"上不犹豫、不停摆。
