# D50 周一 · 系统列单 + 论文 A/B/C 分级(读研究地基第一步)

> **预期管理**:今天不是"读很多",而是"先把这个方向的论文**找全、排好队**"。你可能会想"我哪知道该搜哪些词、收多少篇才算全"——没关系,下面带你用关键词检索 + 顺藤摸瓜两招把全集收出来,再教你怎么分级,把后面五天的精力投到对的 10 篇上。

## 上午段 · 系统检索你方向的核心论文,列成清单

**① 先垫概念(为什么第一步是"列全集"而不是"开始读")**
- 进一个方向做研究,和你 W1 读 Zhu 综述时**最大的不同**:那时你是"被喂"一篇地图;现在你要**自己把这个方向的论文全集捞出来**。捞全集 = 先有"这个领域到底有哪些工作"的鸟瞰,才知道哪篇重要、哪篇可跳。
- **和通用 CV 对比**:通用 CV 你随便搜 "object detection survey" 就有海量梳理;遥感子方向(如旋转检测)**英文关键词更分散**(oriented / rotated / arbitrary-oriented object detection 都指同一件事),只搜一个词会漏掉半个领域。所以遥感检索要**多关键词 + 多平台**。
- **为什么现在需要**:这张清单是本周后面所有事(分级、SOTA 榜、Gap)的"原料库"。原料不全,后面全偏。

**② 手把手带做**(按这个顺序捞,别漏)
1. 在 `10-论文笔记/{方向}_论文清单.md` 建表头:`标题 | 第一作者/年份 | 出处(会议/期刊) | 一句话主题 | 初判级别`。
2. **多关键词检索**(Google Scholar + arXiv,近 3–5 年)。以旋转检测为例,把这些词都搜一遍:`oriented object detection`、`rotated object detection`、`arbitrary-oriented detection`、`remote sensing object detection`、`DOTA benchmark`。每个词翻前 2 页,把相关的填进清单。
3. **顺藤摸瓜补全**:挑 2–3 篇你已知最重要的(如 Oriented R-CNN、ReDet、Cheng 2020 综述),看它们的 Related Work 引了谁、被谁引(Scholar 的"被引用"),把反复出现的名字补进来。
4. 初步收 **15–25 篇**,先求覆盖,不求读。

**③ 这一步合格的样子**:一张 15–25 篇的清单,**覆盖该方向的明显经典 + 近 2 年最新**(老师一眼扫过去不会说"你怎么连 XXX 都没有")。每篇有出处和一句话主题。**漏掉公认经典 = 还没捞全,回去看综述的引用。**

**④ 最常踩的坑**
- **只搜一个关键词**:遥感子方向同义词多,只搜 "rotated detection" 会漏掉所有写 "oriented" 的工作。**务必多词检索。**
- **只收最新、漏掉必引经典**:经典论文(常是公认 baseline 的来源)被引最多、最该读。新 ≠ 重要。
- **中文检索为主**:顶会顶刊主战场是英文,只搜中文会系统性漏掉核心工作。

**⑤ 卡住怎么自救(决策树)**
- 不确定收全没? → 看 1 篇最新综述的参考文献 + 1 篇最新 SOTA 的 Related Work,两边的高频名字你清单里都有 = 大概率全了。
- 一个词搜出几千篇、无从下手? → 加限定:`近3年` + `引用排序`,先收高引的;或用 **Connected Papers / Semantic Scholar** 看引用簇,簇中心就是核心。
- 实在拿不准某篇要不要收? → **先收进来标 C**,分级阶段再筛,捞全比漏掉安全。

**⑥ 今天(这一步)你同时学会了什么**:你掌握了**"为一个方向系统检索、建立论文全集"**这项研究地基能力——多关键词 + 顺藤摸瓜,而不是零散读几篇。这套你以后每开一个新方向、每写一篇论文的 Related Work 都要用。**做了**(方向论文清单)、**学了**(系统文献检索 vs 零散阅读)、**会了**(把一个方向的论文捞成"全集")。

## 中午段 · 给清单做 A/B/C 分级

**① 先垫概念(为什么要分级)**
- 清单 20 多篇,**一周不可能都精读**。分级 = 按"**与我方向相关度 × 影响力**"把论文分成三档:**A(必精读,~10 篇)/ B(应泛读,~15 篇)/ C(扫摘要即可)**。先分级,才能把"精读"这种昂贵动作只花在最值钱的 A 级上。
- **和你 W1 的对比**:W1 你每篇都老老实实 5 遍法精读(因为篇数少、要练读法);现在篇数多了,你要学会**给阅读"配额"**——这是从"学生式通读"到"研究者式有选择地读"的升级。

**② 手把手带做**
1. 给清单每篇标 **A/B/C**。判据:**A** = 顶会/顶刊(CVPR/ICCV/ECCV/TGRS/ISPRS)+ 高引,或被反复当对比基准的;**B** = 次级期刊 / 高质量 arXiv 预印本,相关但非核心;**C** = 沾边但不是你要做的那块。
2. **A 级控制在 ~10 篇**(本周精读的就是这 10 篇,排好优先序 A1…A10,A1 = 最核心/最该先读的那篇,通常是公认 baseline 或开创性工作)。
3. B 级列出来本周泛读(D54),C 级只在清单里记一句摘要。

**③ 这一步合格的样子**:清单每篇都有 A/B/C 标记;A 级**恰好约 10 篇**(不是 3 篇也不是 20 篇),且 A 级里同时含"公认经典"和"最新 SOTA"两类。

**④ 最常踩的坑**
- **全标 A**(舍不得降级):结果一周读不完 10+ 篇,分级形同虚设。**A 必须克制在 ~10。**
- **A 级全是最新、没有经典**:那你会不知道"公认 baseline 是谁"。A 级要老少搭配。
- **分级一次定死**:读着读着发现某 B 其实很关键,随时可升 A——分级是动态的。

**⑤ 卡住怎么自救(决策树)**
- 某篇 A 还是 B 拿不准? → 问自己:"它是不是公认 baseline 或当前最强?" 是 → A;"只是相关" → B;"边缘沾边" → C。
- A 级超过 12 篇下不去? → 把"方法雷同、只是小改"的合并成"读 1 篇代表 + 其余记差异",压回 10 篇。

**⑥ 今天(这一步)你同时学会了什么**:你学会了**论文分级阅读策略(A/B/C)**——把有限精力按"相关度×影响力"投到核心 10 篇上。这是研究者和学生读文献的分水岭。**做了**(A/B/C 分级 + A1–A10 优先序)、**学了**(分级阅读的判据)、**会了**(给阅读分配"配额")。

> **技能卡｜文献分级 A/B/C**:① 全集捞出(多关键词+顺藤摸瓜)→ ② 按"相关度×影响力"标级:A=顶会顶刊/高引/公认基准(精读,~10篇)、B=相关预印本(泛读)、C=沾边(记摘要)→ ③ A 级排优先序,老(经典baseline)少(最新SOTA)搭配 → ④ 分级动态可调。

## 晚上段 · 精读 A1(方向最核心的一篇)

**① 先垫概念(A1 为什么先读、它是什么角色)**
- A1 = 你 A 级里**最核心的一篇**,通常是这个方向的**公认 baseline 或开创性工作**(旋转检测里常是 Oriented R-CNN 或更早的 RoI Transformer 这类奠基方法)。它是你理解整个方向的"锚":后面每篇都在和它对话(改进它、对比它)。
- **为什么现在需要**:读懂 A1,后面 A2–A10 你就能用"差量阅读"(只补它们比 A1 多的部分)快速读完——A1 是省后面九篇时间的杠杆。

**② 手把手带做**
1. 用你 W1 学的 **5 遍法**精读 A1,写满你的 **5 段式笔记**(`10-论文笔记/A1_xxx.md`)。
2. **第 4 段("启发/可借鉴/没解决的")是今晚重点**:把它"没解决的、Future Work 提到的、实验里表现差的场景"尽量挖具体——这些是你 M3 找 Gap 的金矿,至少写 ≥2 条。
3. 第 5 段记下你没看懂的点(明天带着问题读 A2/A3 常会顺带解开)。

**③ 这一步合格的样子**:`A1_xxx.md` 完整 5 段;第 4 段有 **≥2 条具体的"未解决/局限"**(不是"还能更好"这种空话,而是"在小目标/密集排列/跨传感器时 mAP 明显掉"这种具体的)。

**④ 最常踩的坑**
- **第 4 段偷懒写空话**:"方法还可以改进"——这对找 Gap 毫无用处。要具体到"在什么样本/什么指标上,差在哪"。
- **被公式劝退**:奠基论文常有旋转框表示、角度回归的数学(如角度周期性、边界不连续问题),第一遍别纠缠,先抓"它解决了什么、怎么解决的直觉",公式留到需要时。

**⑤ 卡住怎么自救(决策树)**
- A1 数学太重读不动? → 先看它的**解读博客 / 作者讲解视频 / 官方 slides** 建立直觉,**但笔记必须用你自己的话写**(抄解读=没学会)。
- 不确定 A1 选得对不对? → 看它是不是后面多篇 A 级论文对比表里的"基准行";是 = 选对了。

**⑥ 今天(这一步)你同时学会了什么**:你精读了方向的**锚点论文**,并刻意从中挖"未解决点"。这套"先读穿锚点 → 用它当后续差量阅读的基准 → 顺手攒 Gap"的打法,是高效进入任何新方向的标准姿势。**做了**(A1 笔记 + ≥2 条 Gap 线索)、**学了**(方向的核心工作)、**会了**(从锚点论文切入一个方向并攒 Gap)。

> **今日交付**:✅ 方向论文清单(15–25 篇) ✅ A/B/C 分级(A 级 ~10 篇排序) ✅ A1 精读笔记(第 4 段 ≥2 条 Gap 线索)。

# D51 周二 · A2/A3 精读 + 找"公认 baseline"

> **预期管理**:今天读两篇 + 锁定一个"公认 baseline"。读第二、三篇会比 A1 快很多——因为你不再从零理解,而是"只看它比 A1 多了什么"。这种省力的读法叫**差量阅读**,今天就把它练成习惯。

## 上午段 · 精读 A2(练"差量阅读")

**① 先垫概念(什么是差量阅读)**
- **差量阅读** = 读同一方向第 N 篇时,**不再从背景概念啃起,而是直接问"它相对前面那些,新增/改进了什么"**。因为同方向论文有大量重复的背景、相同的 baseline、相似的数据集,真正值钱的是"这一篇独有的那点增量"。
- **和 W1 通读的对比**:W1 你每篇逐段读(在练读法);现在你已有 A1 的底子,A2 只需聚焦"它和 A1 的 delta"。这是把单篇阅读速度提上来的关键。

**② 手把手带做**
1. 精读 A2,但**带着三个问题读**:(a) 它针对 A1/前人的什么不足?(b) 它的核心新机制是什么(一句话)?(c) 它在哪个数据集上证明自己更好、好多少?
2. 写 5 段笔记,但**第 1 段动机**直接写成"它说前人(含 A1)的问题是 X,所以它做了 Y";**末尾加一句"A2 vs A1:多了 ___"**。

**③ 这一步合格的样子**:`A2_xxx.md` 5 段笔记 + 一句"A2 相对 A1 的增量"(如"A2 用 XX 表示法解决了角度边界不连续,在 DOTA 上 +1.8 mAP")。

**④ 最常踩的坑**:① 又从头逐字读(浪费时间)——盯 delta;② 记不清它和 A1 的关系(读成孤立一篇)——一定要写那句对比。

**⑤ 卡住自救**:看不出 A2 比 A1 强在哪? → 直接翻它的**实验对比表**和 Introduction 最后一段("our contributions"),那里白纸黑字写着它的卖点。

**⑥ 今天(这一步)你同时学会了什么**:你练成了**差量阅读**——读同方向第 N 篇时只抓增量,速度翻倍。这是你后面一周读完 10 篇、以后跟踪一个方向几十篇的核心生产力技能。**做了**(A2 笔记 + 对比句)、**学了**(差量阅读法)、**会了**(读同方向论文只抓 delta)。

> **技能卡｜差量精读法**:读同方向第 N 篇,只问三件事——① 它针对前人(含已读的)什么不足?② 核心新机制一句话?③ 在哪个数据集 +多少证明更好?笔记末尾必写"本篇 vs 上一篇:多了 ___"。

## 中午段 · 精读 A3(继续差量积累)

**① 先垫概念**:A3 继续用差量阅读,但此时你要开始**横向连线**——A1/A2/A3 是不是在解决"同一类问题的不同侧面"?横向连线能帮你之后画技术演进图谱、看出方向的"主线矛盾"。
**② 手把手带做**:精读 A3,5 段笔记;末尾除了"A3 vs 前面多了什么",再加一句"A1/A2/A3 共同在跟什么问题较劲"(如都在跟"角度表示的边界不连续 / 密集小目标"较劲)。
**③ 合格样例**:`A3_xxx.md` 笔记 + 增量句 + 一句"三篇共同矛盾"。
**④ 坑**:只纵向读(每篇孤立)、不横向连——那你看不出方向主线。
**⑤ 自救**:连不出共同矛盾? → 把三篇的"动机第一句"摆一起,它们抱怨的往往是同一类痛点。
**⑥ 今天(这一步)你同时学会了什么**:你在差量阅读上叠加了**横向连线**,开始看见方向的"主线矛盾"。**做了**(A3 笔记 + 横向连线)、**学了**(横向连线找主线)、**会了**(从几篇核心论文里读出方向的共同矛盾)。

## 晚上段 · 确定方向的"公认 baseline"

**① 先垫概念(公认 baseline 为什么是头等大事)**
- **公认 baseline** = 这个方向大家做实验**必然要对比**的那个(些)方法,通常是经典、开源、被反复当"基准行"的。**为什么至关重要**:你未来的方法**必须和它比**,否则审稿人第一句就是"为什么不和 XXX 比?"——不比公认 baseline,论文直接被质疑。
- **和通用 CV 对比**:通用检测的公认 baseline 很清晰(Faster R-CNN / RetinaNet / DETR);遥感旋转检测的公认 baseline 要你**从多篇论文的对比表里自己识别**(常见的有 Rotated RetinaNet、Oriented R-CNN、ReDet 等)。

**② 手把手带做**
1. 把你已读的 A 级论文的**实验对比表**摊开,找"**几乎每篇都出现、且常作为基准行**的那个方法"= 公认 baseline。
2. 记进 `10-论文笔记/{方向}_公认baseline.md`:`方法名 | 出处 | 是否开源 | 代码链接 | 主数据集上的报告指标`。通常锁 1 个"经典基准"+ 1 个"当前最强"。
3. 顺手确认它**开源且单卡可跑**(D55 你要复现它当资格证)。

**③ 这一步合格的样子**:确定 1–2 个公认 baseline(至少 1 个开源可复现),记下代码链接和它在主数据集上的报告分。

**④ 最常踩的坑**
- **把"最新 SOTA"当唯一 baseline**:还要有"公认经典 baseline"(大家都比的那个),否则审稿人觉得你回避了经典对比。

> **预期管理**:今天是集中日,做一件"硬"但极有价值的事——**复现一个 SOTA(或公认 baseline)**。这件事**很可能不会一天跑完**(下载数据、配环境、训练都要时间),也很可能第一次对不齐。**这都正常**。今天的赢法是:**把它跑起来 + 拿到第一批指标 + 学会判断"对齐没对齐"**;训练没跑完可以挂着,明天看结果。**别让"一天没复现完美"否定掉"代码底座已经到手"这个胜利。**

## 上午段 · 选一个开源 SOTA / 公认 baseline 准备复现

**① 先垫概念(为什么必须亲手复现一个)**
- **复现一个 SOTA(或公认 baseline)** = 用它的开源代码,在标准数据集上重跑出**接近它报告的指标**。**这是你的"入场资格证"**:能复现,才证明你真有能力在这个方向跑实验、做公平对比;而且这份跑通的代码,正好是你 M3 拿来改的**底座**(你不会从空白开始,而是在一个能跑出 SOTA 的代码上动刀)。
- **为什么说"能复现别人的工作"是一道真实的能力门槛(很多人卡在这)**:读懂一篇论文是一回事,**能把它的代码在自己机器上真正跑通、跑出接近报告的结果,是另一回事——而且难得多**。复现要求你打通一整条链路:看懂代码结构、配对环境和版本、准备好数据、对齐评测协议、排查各种报错……这中间任何一环卡住,就跑不出正确结果。**很多人(包括不少正经读研的人)其实迈不过这道坎**——他们能讲论文,却没真正复现过一个 SOTA,因此也没法做可信的对比实验。所以你今天亲手把一个 SOTA 复现出来,不只是"完成一个任务",而是**跨过了一道把"纸上谈兵"和"真能做研究"区分开的门槛**——这对你这个没有科班训练、要证明自己实战能力的转型者尤其重要:它是你"真的能上手做"的硬证据。
- **复现还有一个常被低估的好处:它给你一个"已知正确"的参照系**。当你 M3 在这份代码上做改进时,如果结果异常,你能立刻判断"是我的改动引入的问题,还是本来就有问题"——因为这份底座你已经验证过能跑出正确结果。**从一个"已知能 work 的代码"出发改进,比从空白或来路不明的代码出发,排查效率高得多、也更不容易怀疑人生**。所以今天的复现,既是资格证,又是你后续所有实验的可信地基。而且这份"能复现 SOTA"的本事,以后还会反复用到:第二课题、第三课题、乃至将来任何新方向,你都需要先复现该领域的基准方法作为对比和底座——今天练熟的这套复现流程(配环境/对数据/对齐评测/排错),会成为你贯穿整个研究生涯、始终都用得上的一项硬技能,越早练扎实越好。
- **和通用 CV 对比**:通用 CV 复现门槛低(COCO + torchvision 现成);遥感复现常卡在**数据准备(DOTA 要切图/转格式)、框架版本(MMRotate 版本敏感)、评测协议(DOTA 的 mAP 有 07/12 之分)**——这些坑你 W1–W2 已经踩过一轮,今天正好用上。

**② 手把手带做**
1. 从你的 SOTA 榜里选一个**开源 + 单卡 4090 可跑**的方法(优先选你的**公认 baseline**——它后面是你每张表的对比基准,复现它一举两得)。
2. clone 代码、按它 README 配环境(用你 W1 学的 mim + 版本对照排查套路)、准备数据(DOTA 切图脚本通常仓库自带)。
3. 把它的训练命令、配置文件路径记进 `20-代码实验/复现SOP_{方法}.md`。

**③ 这一步合格的样子**:选定一个开源方法,环境装通、数据就绪,训练命令已写进 SOP,准备开跑。

**④ 最常踩的坑**:① 选了不开源 / 要多卡的 SOTA——选单卡可复现的;② 没先选公认 baseline 而选了个炫但没人比的——优先复现"以后要当对比基准"的那个。
**⑤ 自救**:首选的跑不动(版本/算力)? → 换 SOTA 榜里另一个开源单卡的;实在不行,先复现公认 baseline 本身(更老更稳更容易跑通)。
**⑥ 今天(这一步)你同时学会了什么**:你学会**为复现选对目标**(开源 + 单卡 + 有对比价值)。**做了**(选定复现目标 + 环境/数据就绪)、**学了**(复现目标的选择标准)、**会了**(挑一个"可复现且后续有用"的方法)。

## 中午段 · 启动复现训练

**① 先垫概念**:复现训练通常要几小时到一天,要**后台挂起 + 记录命令 + 监控 loss**,不能开着终端干等。这也是你第一次"为了对齐别人的结果"而跑训练(之前是为了体验/学习)。
**② 手把手带做**:按 README 配好 config → 改数据路径 → `nohup ... &` 或 tmux 后台启动 → 把命令和启动时间记进 SOP → 用 TensorBoard / 日志监控 loss 是否正常下降。
**③ 合格样例**:训练正常启动、loss 开始下降、命令已记录;预计完成时间心里有数。
**④ 坑**:① 开着前台终端干等(关了就断)——用 nohup/tmux;② OOM 直接放弃——降 batch size / 输入分辨率 / 用混合精度。
**⑤ 自救**:启动就报错? → 90% 是版本或数据路径问题:`import torch;print(版本)` 对照框架要求;数据路径打印出来确认存在;报错原文去仓库 Issues 搜。
**⑥ 今天(这一步)你同时学会了什么**:你启动了一次**以"对齐"为目标的正式复现**,练了后台训练 + 监控。**做了**(复现训练启动 + SOP)、**学了**(后台训练与监控)、**会了**(把一个 SOTA 正确地跑起来)。

## 晚上段 · sanity check:复现值 vs 报告值(差距判定)

**① 先垫概念(sanity check 是什么、为什么没它后面全废)**
- **sanity check(合理性检查)** = 把你复现出的指标和论文报告值对比,**差距在合理范围(经验上 <2%)才算"复现对齐"**。
- **为什么至关重要**:如果你连复现别人的方法都对不齐,后面做自己的改进时就**无法判断"到底是我的方法有效,还是只是我的 baseline 没调好"**。**没对齐的复现不能当 baseline**——拿一个偏低的 baseline 去比,你的"提升"是假的,审稿人一眼识破。先确保 baseline 对齐,改进才有意义。

**② 手把手带做**
1. 训练完成(或到合理 epoch)→ 用它的评估脚本测指标 → 和报告值对比(用补充包的 `sanity_check` 函数,差 >2% 自动报警)。
2. 若差 >2%,**按顺序排查**:① 评测协议(DOTA 是 07 还是 12 metric?)② 数据切分 / 切图 overlap 是否和官方一致 ③ 超参是否用官方 config ④ 先用官方权重跑一遍评估脚本,验证"评估代码本身对不对"。
3. 对齐后,把"报告值 / 复现值 / 差距 / 排查记录"写进 `复现SOP` 和 sanity check 报告。

**③ 这一步合格的样子**:复现值与报告值差 **<2%**(通过 ✅);或如实记录"目前差 X%,已排查到是 ___,明天对齐后重测"。

**④ 最常踩的坑**
- **复现差不多就当对齐**(没核对评测协议):DOTA 的 07/12 metric 能差 1–2 个点,不核对就误判。用**同协议、同划分**再确认。
- **把 test 集拿来反复调到对齐**:那是作弊。调参/排查只能用 val,test 只在最终报一次。

**⑤ 卡住怎么自救(决策树)**
- 差 >2% 怎么查? → ① 先用**官方提供的权重**跑评估脚本:如果连官方权重都测不出报告值 = 你的**评估代码/协议**错了(查 07/12、查数据划分);如果官方权重能测出报告值、但你自己训的不行 = 你的**训练**没对齐(查超参/数据增强/epoch)。这一步能把问题对半切。
- 实在对不齐、时间不够? → **如实记录差距和已知原因**,标"M3-W9 第一天补齐",不要硬撑到深夜。

**⑥ 今天(这一步)你同时学会了什么**:你**复现了一个 SOTA 并通过 sanity check,拿到了"入场资格证"**,同时获得了 M3 可直接改的代码底座,还学会了"用官方权重对半切问题"的排查法。**做了**(复现 + sanity check 报告)、**学了**(复现对齐的判定标准 <2% + 排查顺序)、**会了**(判断一次复现是否真的"对齐"并定位偏差来源)。

> **技能卡｜sanity check 对齐判定**:复现值 vs 报告值,差 <2% 算对齐。差太多按序查:评测协议(07/12)→ 数据切分/overlap → 超参(官方config)。**杀手锏**:先用官方权重跑评估——官方权重都测不出报告值 = 评估代码/协议错;官方权重 OK 但自训不行 = 训练没对齐。**没对齐的 baseline 不能用。**

> **今日交付**:✅ 复现目标就绪(环境/数据/SOP) ✅ 复现训练启动 ✅ sanity check 结果(通过或已定位差距)。

## 三、完整可运行代码 — ① SOTA 榜自动排序 ② sanity check 差距判定 ③ 模型参数量统计

```python
# ===== ① 把"方法→指标"排成榜单（按主指标降序、标最强；纯 Python，可直接跑）=====
def build_leaderboard(rows, key="dota"):
    ranked = sorted(rows, key=lambda r: r["metrics"].get(key, -1), reverse=True)
    print(f"{'方法':<22}{'年份':<6}{'DOTA':<7}{'HRSC':<7}{'参数M':<7}{'FPS':<6}")
    print("-" * 58)
    for i, r in enumerate(ranked):
        m = r["metrics"]
        star = "  ★最强" if i == 0 else ""
        print(f"{r['name']:<22}{r['year']:<6}{m.get('dota','-'):<7}{m.get('hrsc','-'):<7}"
              f"{r.get('params','-'):<7}{r.get('fps','-'):<6}{star}")
    return ranked

# ===== ② sanity check：复现 vs 报告，差 >2% 报警 =====
def sanity_check(reported, reproduced, tol=2.0):
    rel = abs(reported - reproduced) / (reported + 1e-9) * 100
    ok = rel <= tol
    print(f"报告={reported}  复现={reproduced}  差={reproduced-reported:+.2f} ({rel:.1f}%) → "
          + ("✅ 通过（可作 baseline）" if ok else "⚠️ 超容差：查评测协议(07/12)/切图overlap/超参"))
    return ok

# ===== ③ 统计一个 PyTorch 模型的参数量（给 SOTA 榜补"参数M"列）=====
def count_params(model):
    total = sum(p.numel() for p in model.parameters())
    train = sum(p.numel() for p in model.parameters() if p.requires_grad)
    print(f"总参数 {total/1e6:.1f}M | 可训练 {train/1e6:.1f}M")
    return total / 1e6

if __name__ == "__main__":
    print("【SOTA 榜】")
    build_leaderboard([
        {"name": "MethodC", "year": 2024, "metrics": {"dota": 79.1, "hrsc": 90.6}, "params": 38, "fps": 22},
        {"name": "Oriented R-CNN", "year": 2021, "metrics": {"dota": 75.9, "hrsc": 90.4}, "params": 41, "fps": 16},
        {"name": "Rotated RetinaNet", "year": 2019, "metrics": {"dota": 68.4, "hrsc": 84.5}, "params": 36, "fps": 25},
    ], key="dota")
    print("\n【sanity check】")
    sanity_check(75.9, 75.5)   # 差 0.4 → 通过
    sanity_check(75.9, 73.1)   # 差 2.8 → 报警
```

## 五、本周报错速查表（现象 → 根因 → 解法）
| 现象 | 根因 | 解法 |
|---|---|---|
| 论文清单总觉得不全 | 只搜单关键词 / 只搜中文 | 多同义关键词(oriented/rotated/arbitrary-oriented)+ 顺藤摸瓜(看综述/SOTA 的引用簇) |
| A/B/C 全标成 A | 舍不得降级 | 按"相关度×影响力"克制,A 控制在 ~10 篇;雷同方法合并 |
| 复现值远低于报告(>2%) | 评测协议/切图/超参没对齐 | 先用官方权重跑评估对半切问题;核对 07/12 metric、切图 overlap、官方 config |
| 训练一开就 OOM | batch/分辨率过大 | 降 batch size、降输入分辨率、开混合精度(AMP) |
| 后台训练关终端就断 | 前台启动 | 用 `nohup ... &` 或 tmux,挂后台 |
| SOTA 榜数字裸比、不可信 | 各论文设置/划分不同 | 注明每行设置;以"自己统一复现值"作最终公平锚点 |
| 白皮书写成 idea 罗列 | 没按结构系统论证 | 套七节(定义/现状/Gap/切入/资产/风险/路线),Gap 写具体 |
| 切入点需要大算力 | 想拼"更大的基础模型" | 砍成单卡可做的下游特化/高效适配,把"单卡高效"当卖点 |
| 把 test 集用于选方法/调参 | 数据使用不规范 | 选择/调参只用 val,test 仅最终评估报一次 |
