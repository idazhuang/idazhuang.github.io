## 上午段 · 论文最终打磨——按目标期刊格式终检

**① 先垫概念（为什么要做格式终检）**
- 论文 v1.0 内容已投稿级，但**不同期刊的格式要求不同**——模板（双栏/单栏）、字数/页数限制、参考文献格式（IEEE/Elsevier 各不同）、图表要求（分辨率/位置/caption 格式）、章节结构。**投稿前必须按目标期刊的 Author Guidelines 把格式对齐**，否则编辑会因格式不符直接退回（desk reject 的常见原因之一就是格式不规范），白白浪费一轮时间。
- **格式终检不是改内容，是改"外观"**——把已写好的内容套进目标期刊的官方模板里，逐项核对 Guidelines。★ 你已经投过两篇，这套流程很熟了——下载官方 LaTeX/Word 模板、对照 Author Guidelines 一项一项核。

**② 手把手带做**：① 打开目标期刊的 Author Guidelines（投稿页面有）；② 下载官方模板（LaTeX 通常有 .cls/.bst，Word 有 .dotx）；③ 把论文套进模板（章节/格式/参考文献样式）；④ 逐项核对 Guidelines（字数/页数/图表/参考文献格式）；⑤ 超页则按优先级压缩（次要分析进 supplementary）。
**③ 这一步合格的样子**：论文按目标期刊格式定型——套了官方模板、对照 Guidelines 逐项核对通过，格式无明显不符。
**④ 最常踩的坑**
- 不看 Guidelines 直接投（格式不符被退）→ 投前逐项核对 Guidelines。
- 参考文献格式不对（用了别的刊的格式）→ 用目标期刊的 .bst/格式样式。
- 超页不处理（被要求删减）→ 按优先级压缩，次要内容进 supplementary。

**⑤ 卡住怎么自救（决策树）**：不知格式要求？→ 看 Author Guidelines（最权威）；超页了？→ 压缩次要分析/图表进 supplementary；模板不会套？→ 复用前两篇套模板的经验。
**⑥ 今天（这一步）你同时学会了什么**：你**把论文按目标期刊格式定型了**。**做了**（看 Guidelines + 套官方模板 + 逐项核对格式 + 处理超页）、**学了**（格式终检的必要性、不同刊格式不同、desk reject 常因格式）、**会了**（按目标期刊 Guidelines 把论文格式对齐）。

> **技能卡｜论文投稿前格式终检（按目标期刊定型）**：投稿前把论文格式按目标期刊对齐——①看 Author Guidelines（最权威,投稿页有）②下载官方模板（LaTeX .cls/.bst,Word .dotx）③套模板（章节/格式/参考文献样式）④逐项核对（模板双栏/单栏+字数页数限制+参考文献格式+图表分辨率/位置/caption）⑤超页按优先级压缩（次要分析/图进 supplementary）。★ 格式不符是 desk reject 常见原因,投前必核。复用前两篇套模板经验,第三次熟练。

## 上午段 · Cover Letter 定稿（复用前两篇 + 嵌差异化卖点）

**① 先垫概念（Cover Letter 写什么）**
- **Cover Letter（投稿信）= 给编辑的一封信**，简述论文 + 为什么适合该期刊。结构：① 致编辑（Dear Editor）；② 论文标题 + 核心贡献（1–2 句话说清你做了什么、解决了什么）；③ 为什么适合该期刊（方向契合 + 创新性）；④ 标准声明（原创、未一稿多投、所有作者同意投稿）；⑤ 简洁专业（控制在半页内）。★ **复用前两篇的 Cover Letter**——结构都有了，改标题、贡献、目标刊即可。
- ★ **嵌进你的差异化卖点**：在贡献描述里点出"单张 RTX 4090 实现的高效方法"（Params/FPS 效率）——这是你区别于大组大算力工作的独特价值，编辑和审稿人会注意到"资源受限下做出有竞争力的结果"是有意义的。

**② 手把手带做**：① 复用前两篇 Cover Letter 模板；② 改论文标题 + 核心贡献（1–2 句）；③ 写为什么适合该刊（方向 + 创新）；④ ★ 在贡献里嵌差异化卖点（单卡高效）；⑤ 加标准声明 + proofreading（控制半页内）。
**③ 这一步合格的样子**：Cover Letter 定稿——致编辑 + 标题/贡献 + 适合该刊的理由 + 嵌差异化卖点 + 标准声明，简洁专业半页内。
**④ 最常踩的坑**
- Cover Letter 冗长（编辑没耐心）→ 简洁半页内、要点清楚。
- 只复述摘要（无针对性）→ 说清"为什么适合这个刊"。
- 不嵌差异化卖点（埋没独特价值）→ ★ 点出单卡高效。

**⑤ 卡住怎么自救（决策树）**：Cover Letter 写什么？→ 致编辑 + 标题贡献 + 适合该刊 + 声明；不知怎么说适合？→ 论文方向和期刊范围（Aims & Scope）对上；卖点怎么嵌？→ 在贡献句里点单卡高效。
**⑥ 今天（这一步）你同时学会了什么**：你**定稿了 Cover Letter**。**做了**（复用模板 + 改标题贡献 + 写适合该刊 + 嵌卖点 + 声明）、**学了**（Cover Letter 是给编辑的第一印象、要简洁针对性、嵌差异化卖点）、**会了**（写出简洁专业、突出独特价值的投稿信）。

> **技能卡｜Cover Letter 定稿（差异化卖点）**：给编辑的投稿信,简述论文 + 为何适合该刊——①致编辑②论文标题 + 核心贡献（1-2句说清做了什么/解决什么）③为何适合该期刊（方向契合 Aims&Scope + 创新性）④标准声明（原创/未一稿多投/所有作者同意）⑤简洁专业（半页内）。★ 在贡献里嵌差异化卖点（单张 4090 高效方法,Params/FPS）——资源受限下的竞争力是独特价值。复用前两篇模板,改标题/贡献/目标刊即可。

## 二、完整可运行代码 · 行前准备清单检查器（+ 预期输出）

> 这个脚本把"行前准备全清单"做成可勾选的检查器——输入各项准备状态，输出就绪度百分比和"还差什么"，帮你在出发前一项不漏。把出发准备从凭记忆变成系统化盘点。

```python
#!/usr/bin/env python3
# pre_departure_checklist.py —— 访问行前准备清单检查器
# 各项准备状态：True=已就绪, False=待办
checklist = {
    "住宿": {
        "查房源": True, "问师兄推荐": True, "筛候选": True, "★最终确认(W60)": False,
    },
    "交通": {"定出发日期": True, "购票": True, "记录行程": True},
    "设备数据": {
        "拷代码数据到硬盘": True, "确认电脑环境": True, "★双备份": True, "带走清单": False,
    },
    "物资": {
        "备证件": True, "生活必需品": True, "★打印论文/简历/作品集": True,
        "电子配件": True, "给团队礼物(W60)": False,
    },
    "谈资": {"读最新论文3篇": True, "整理研究图景+问题": True},
    "收官(W60)": {
        "★与师兄确认报到时间地点": False, "自我介绍三版": False,
        "★博士课题交接": False, "★《访问期间工作计划》": False,
    },
}

def check(checklist):
    print("=== 访问行前准备就绪度 ===\n")
    total = done = 0
    todo = []
    for cat, items in checklist.items():
        c_done = sum(1 for v in items.values() if v)
        c_total = len(items)
        total += c_total; done += c_done
        bar = "✅" if c_done == c_total else "⏳"
        print(f"{bar} {cat}: {c_done}/{c_total}")
        for k, v in items.items():
            if not v:
                todo.append(f"{cat} · {k}")
                print(f"     □ 待办: {k}")
    pct = round(done / total * 100)
    print(f"\n总就绪度: {done}/{total} = {pct}%")
    print(f"\n还差 {len(todo)} 项（多在 W60 收官）：")
    for t in todo:
        print(f"  - {t}")
    if pct == 100:
        print("\n🎉 行前准备全部就绪，可以出发！")
    else:
        print("\n→ 把待办（尤其 ★）排进 W60 逐项收尾。")

if __name__ == "__main__":
    check(checklist)
```
