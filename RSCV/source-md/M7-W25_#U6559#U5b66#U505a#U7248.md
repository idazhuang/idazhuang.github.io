# D169 周一 · 数字审计(论文数字 vs 实验日志逐一交叉验证)

> 投稿前最关键的一道关:把论文里每一个数字,和实验日志/代码跑出来的逐一核对——数字对不上会被直接 reject。
>
> **预期管理**:M7 投稿月开始,本周做投稿前最后打磨。今天做"数字审计"(论文↔实验日志↔代码三处数字逐一交叉验证)。提醒:**数字不一致是会被直接 reject 的致命硬伤**——你 W19 删过组件、改过方法,数字变过好几轮,极易出现"正文写旧数字、表格是新数字";不只核对表格,正文里散落的"我们提升了X%"这种数字也要核;数字太多手核易漏,写个小脚本从日志/LaTeX源码自动比对。

## 上午段 · 建立"数字清单":列出论文里所有数字及其来源

**① 先垫概念(为什么数字审计是投稿前的头等大事)**:
- **数字错误是论文的致命伤**:如果审稿人(或读者复现时)发现你论文里写的数字,和你代码/checkpoint 实际跑出来的不一致,**论文很可能被直接 reject**——因为这动摇了审稿人对你**全部结果**的信任(一个数字假,其他的是不是也假?)。这不是"小错误",是关乎可信度的硬伤。
- **为什么你的论文特别容易有数字不一致**:回想你这一路——M5 你删过无效组件、改过方法(数字变了)、补跑过最终方法(数字又变了);M6 你据 mock review 补过对比、改过实验(数字再变)。**经过这么多轮迭代,论文里极易残留"旧数字"**:比如 Abstract 里写的提升幅度是早期版本的、某个表格更新了但正文引用它的地方没改、Intro 贡献列表的数字和 Experiment 表对不上。这些"历史遗留的旧数字"就是定时炸弹。
- **数字审计 = 给论文的所有数字做一次"全面体检"**:逐个表格、逐个正文引用,核对每个数字是否等于最终实验/代码跑出来的真实值。**目标:论文里 100% 的数字都能在实验日志里找到对应来源,且正文数字 = 表格数字 = 日志数字,三处完全一致**。
- **和"实验可复现"的关系**:你 W19 归档了实验日志(config/seed/命令/结果)——那是数字的"唯一可信来源"。数字审计就是拿论文里的每个数字,回到实验日志去核对。**实验日志是"事实",论文里的数字必须忠实于这个事实**。
- **数字审计也是对你诚信的保护**:有时数字不一致不是造假,只是迭代中的疏忽(忘了同步旧数字)。但**审稿人无法区分"疏忽"和"造假"——他看到的就是"数字对不上"**,后果一样严重(质疑你全部结果)。所以数字审计不只是"改错",更是**保护你的学术诚信不被误解**:确保你呈现的每个数字都经得起核对,审稿人复现时能对上,你的工作才可信、可立得住。这对一个要走学术路的人是底线。

**② 手把手带做**:
1. 通读论文,把**所有出现的数字**列成一张清单(Abstract、Intro 贡献、Experiment 各表、正文里的"提升 X%"、Conclusion 的数字……一个不漏)。
2. 给每个数字标注**它应该来自哪个实验**(哪个 config/哪张日志表)。
3. 先建清单、不急着改——穷举所有数字及其来源,下一步再逐一核对。
```python
# 从 LaTeX 源码里 grep 出所有数字（辅助建清单，别漏正文散落的数字）
import re
tex = open("paper/main.tex", encoding="utf-8").read()
# 匹配形如 78.5 / 1.3% / 21.4 FPS 等数字（粗匹配，人工再筛）
nums = re.findall(r'\d+\.\d+%?', tex)
print(f"论文里出现的数字共 {len(nums)} 处（含重复）：")
for n in sorted(set(nums)): print(" ", n, "× 出现", nums.count(n), "次")
# 输出后人工核对：每个数字来自哪个实验？正文/表格/摘要里是否一致？
```

**③ 合格样例**:一张"数字清单"——论文里每个数字 + 它的来源实验 + 出现位置(Abstract/表X/正文某段),为下一步逐一核对做准备。

**④ 常踩的坑**:
- **只想着核对表格,漏了正文散落的数字** → 正文里"我们在 DOTA 上达到 78.5""相比 baseline 提升 1.3 个点"这类散落数字,最容易残留旧值,必须一并列入清单。
- **数字清单建得不全** → 用脚本 grep 辅助(上面的代码),确保不漏。
- **把"图里的数字"忘了** → 柱状图/曲线图上标注的数值也要核对。

**⑤ 卡住自救(决策树)**:数字太多、不知从哪开始?→ 先从最重要的(Abstract 的关键结果、主表 Table 1)开始,再到消融表、正文散落数字。不确定某数字该来自哪个实验?→ 回到实验日志(W19 归档的),按"这个数字对应哪个 config/哪次运行"追溯。

**⑥ 今天(这一步)你同时学会了什么**:你学会**系统地列出论文所有数字及其来源**,为数字审计打基础。**做了**(建立数字清单 + 脚本辅助 grep)、**学了**(数字不一致=致命伤、要穷举所有数字含正文散落的)、**会了**(全面盘点论文里的每一个数字)。

## 中午段 · 逐一交叉验证:论文数字 ↔ 实验日志

**① 先垫概念**:有了数字清单,现在**逐一核对**——把清单里的每个数字,和实验日志/wandb 里的真实值比对。一致就打勾,不一致就标红待改。**核心是"以最终实验为准"**:论文里的数字必须等于最终代码/最终实验跑出来的值,不是凭印象写的、不是早期版本的。
- **为什么要"自动提取 + 交叉比对"**:手动核对几十个数字容易看花眼、漏掉。**最可靠的做法是写个小脚本,从实验日志/wandb 自动提取最终数字,和论文表格(从 LaTeX 源码提取)做交叉比对**,机器帮你找出不一致。这比纯人眼核对准得多。
- **"三处一致"的含义**:同一个指标,可能在论文里出现在三个地方——Abstract、正文引用、Experiment 表格。**这三处的数字必须完全相同**(且都等于日志里的真值)。任何一处和其他不同,都是不一致,要改。

**② 手把手带做**:
1. 从实验日志/wandb 提取所有最终指标的真值(主实验、消融、迁移等)。
2. 和数字清单逐一比对:论文里的每个数字 = 日志真值?
3. 标出所有不一致处(待 D169 晚上修正)。

**③ 合格样例**:数字清单逐项核对完毕,每个数字标注"✓一致"或"✗不一致(论文写X、日志是Y)"。

**④ 常踩的坑**:核对时只看小数点前、忽略精度(78.5 vs 78.46 取舍不一致)→ 统一精度规则(如都保留一位小数),全文一致;日志里有多次运行的值,不知用哪个 → 用最终方法的 3-seed 平均值(W19 锁定的)。

**⑤ 卡住自救**:日志找不到某数字的来源?→ 说明这个数字可能是早期的/凭印象写的,要么重新跑确认、要么删掉这个声称;wandb 记录太多找不到?→ 按 run 名/tag 过滤到最终实验。

**⑥ 今天(这一步)你同时学会了什么**:你学会**把论文数字和实验日志逐一交叉验证**。**做了**(逐项核对 + 标出不一致)、**学了**(以最终实验为准、三处一致、自动提取更可靠)、**会了**(系统核验数字的真实性)。

## 晚上段 · 修正所有不一致 + 锁定数字

**① 先垫概念**:把上午、中午标出的所有不一致**逐一修正**——统一改成最终实验的真值。改完再快速复核一遍,确保论文里的数字现在 100% 准确、三处一致。**这一步完成后,"数字对不上"这个会被直接 reject 的风险就彻底堵死了**。
- **修正原则**:永远**以最终代码/最终实验为准**,把论文里的旧数字/错数字统一改成真值。一处都不能放过(尤其正文散落的)。
- **改完要复核**:修正过程中可能改漏、或改一处引入新的不一致(如改了表格但正文又忘了同步)。改完后再过一遍数字清单,确认全部一致。

**② 手把手带做**:
1. 逐一修正所有标红的不一致(改成日志真值)。
2. 特别注意"牵一发动全身"——改了主表某个数,要检查 Abstract/Intro/Conclusion 里引用它的地方都同步改。
3. 复核:再跑一遍 grep,确认全文数字一致。

**③ 合格样例**:论文里每个数字都能在实验日志里找到对应来源;正文数字 = 表格数字 = 日志数字,三处完全一致。数字审计通过。

**④ 常踩的坑**:改了主表忘了改 Abstract/正文引用 → 牵一发动全身,改完全局复核;不同表格用了不同精度 → 统一精度规则。

**⑤ 卡住自救**:改完还是有地方对不上?→ 再跑一遍数字清单核对脚本,锁定残留;实在拿不准某数字 → 以最终实验日志为唯一标准。

**⑥ 今天(这一步)你同时学会了什么**:你完成了**投稿前的数字审计**,堵住了"数字对不上=直接 reject"的致命伤。**做了**(修正所有不一致 + 锁定数字)、**学了**(以最终实验为准统一、改完全局复核)、**会了**(让论文数字 100% 准确可信)。

> **技能卡｜数字审计**:投稿前必做——把论文里**每个数字**(含正文散落的"提升X%")列清单 → 逐一和实验日志/代码真值交叉比对 → 不一致一律以**最终实验**为准统一。目标:正文=表格=日志,三处一致。数字对不上是会被直接 reject 的致命伤。

## 上午段 · 集中清理所有历史 review 的残余问题

**① 先垫概念(投稿前要"还清所有欠账")**:
- 你这一路收过很多反馈:M6 的自审报告、两轮 mock review、第二轮快审——这些反馈里,有些问题当时改了,但可能**有些标记为"以后改"的残余问题还没处理**。投稿前,要把这些**历史欠账一次性清零**。
- **为什么投稿前清零残余问题**:投稿版是要交给真审稿人的"最终版本"。如果带着已知的、本可以改的问题去投稿,等于主动给审稿人送拒稿理由。**你自己(和朋友)已经发现的问题,一定要在投稿前改掉**——别指望审稿人不会注意到(他们专业,大概率会注意到)。
- **怎么不遗漏**:把散落在各处的残余问题(自审清单里没改的、mock review 里标"待定"的、通读时记的)**集中到一个 `paper/todo.md`**,逐条勾销。集中管理才不会漏。
- **投稿前是"还欠账"的最后窗口**:论文投出去后就进入审稿,你已知的小问题会被审稿人发现并写进意见(然后你还要在 rebuttal 里解释、在修订版里改)——**与其让审稿人替你找出你早就知道的问题,不如投稿前自己改掉**。投稿前是清理这些已知欠账的最后、也是成本最低的窗口(现在改只是改文档,投稿后改要走 rebuttal 流程)。所以别留"以后再说"的欠账,能在投稿前还清的都还清。

**② 手把手带做**:

2. 逐条处理、勾销。
3. 确认 todo 清单清零。

**③ 合格样例**:`paper/todo.md` 里所有历史残余问题逐条勾销、清零。

**④ 常踩的坑**:残余问题散落各处、漏改 → 集中到一个 todo 清单统一管理;"这个问题以后再说"拖到投稿后 → 投稿前能改的都改掉,别留欠账。

## 晚上段 · 竞赛改进:换更强 backbone(ConvNeXt-XL / InternImage)

**① 先垫概念**:竞赛冲刺阶段,**换更强的 backbone**(如 ConvNeXt-XL、InternImage)是常见的提分招——更强的特征提取器往往直接带来精度提升。但**更大的 backbone 在你单张 4090(24GB)上容易 OOM**,要用省显存技巧应对。
- **为什么换强 backbone 能提分**:backbone 是模型的"特征提取主干",更强的 backbone(更大、预训练更好)能提取更有判别力的特征,下游任务精度往往更高。竞赛冲刺时,换上当前最强的 backbone 是性价比不错的一招(虽然慢,但竞赛只看分数)。
- **4090 的显存约束(你的现实)**:ConvNeXt-XL、InternImage 这类大 backbone 显存占用大,你单卡 24GB 可能 OOM。**应对:降 batch size + 梯度累积(保持等效 batch)、混合精度训练(amp)、必要时降输入分辨率**。这些是你一路练熟的单卡省显存技巧,继续用。**注意:这里换大 backbone 是为竞赛冲分;你论文的主结果仍用高效的小模型(单卡高效是你论文的卖点),大 backbone 的结果归竞赛/附加,别混淆两条线的定位。**

**② 手把手带做**:
1. 竞赛模型换更强 backbone(ConvNeXt-XL 或 InternImage)。

## 上午段 · 准备 5 个差异化模型 + 理解 WBF

**① 先垫概念(差异化 Ensemble + WBF)**:
- **5 模型 Ensemble 是竞赛冲刺的"核心大招"**:用 5 个**不同 backbone** 的模型(如 ResNet-50、ResNet-101、Swin-T、Swin-B、ConvNeXt-B)各自预测,再融合——通常比单模型大幅提升,是竞赛榜上 top 方案的标配。
- **为什么"差异化"是关键**:Ensemble 的收益来自模型的**互补性**——不同模型犯不同的错,融合时相互纠正。**模型差异越大(backbone 结构越不同),互补性越强,Ensemble 收益越大**。如果 5 个模型都是 ResNet 系(结构相似),它们犯的错也相似,融合收益就小。所以要**用结构差异大的 backbone**(ResNet 系 + Swin 系 + ConvNeXt 系混搭)。
- **WBF(Weighted Box Fusion)是什么**:对**检测**任务,多个模型的预测是一堆框(位置、数量都不同),不能简单平均。**WBF 是专门融合多个模型检测框的算法**——它把多个模型预测的、重叠的框,按置信度加权融合成一个更准的框(而非简单取一个或平均坐标)。**检测任务的 Ensemble 必须用 WBF(或类似的框融合)**,简单合并框效果差。
- **WBF 的关键参数**:IoU threshold(判断两个框是否算"同一个目标"的重叠阈值)、skip threshold(置信度低于此的框丢弃)——**这两个阈值要调**,调好了融合效果才最佳。
- **WBF 为什么比 NMS 式合并更好(原理直觉)**:传统融合多个框可能用 NMS(非极大值抑制)——保留置信度最高的框、抑制重叠的其他框,本质是"二选一"。**WBF 不是丢弃,而是"加权融合"**:把多个模型预测的、指向同一目标的重叠框,按各自置信度**加权平均出一个更准的框**(位置综合了多个模型的判断)。这样既利用了所有模型的信息(而非只取一个),融合出的框往往比任何单个模型的框更准。这就是为什么检测 Ensemble 用 WBF 效果好——它真正"融合"了多模型的定位,而非简单取舍。

- **清单包含什么(常见项)**:① **格式**——符合目标期刊/会议的模板(字体、页边距、章节格式);② **页数**——不超过限制(超了要精简);③ **图表编号**——连续、无重复、无跳号,正文引用对得上;④ **引用格式**——统一(BibTeX)、无漏引;⑤ **拼写语法**——过一遍拼写检查;⑥ **其他**——作者信息、致谢、补充材料等齐全。
- **为什么这些"低级问题"值得专门设清单**:这些问题(格式、编号、拼写)单看都很小、很"低级",但**它们恰恰是最容易在投稿前匆忙中漏掉、又最影响第一印象的**——审稿人翻开一篇格式不规范、图表编号乱、有拼写错的论文,会下意识觉得"作者不认真",对工作本身也打折扣。**越是低级的问题,越不该出现在正式投稿里**(因为本可以避免)。清单的意义就是把这些"明知道要做、但容易在投稿前的紧张中遗漏"的核验项固化下来,逐项打勾确保万无一失。这是工程师的严谨——重要的事不靠记忆,靠流程。

**② 手把手带做**:
1. 列一份投稿前检查清单(格式/页数/图表编号/引用格式/拼写/作者信息等)。
2. 逐项核验、打勾。
3. 发现问题立即修。

**③ 合格样例**:一份逐项打勾的投稿前检查清单,所有项核验通过(或标记待修)。

**④ 常踩的坑**:不用清单凭记忆 → 漏检某项;清单过了但没真核(走过场打勾) → 每项真核验。

**⑤ 卡住自救**:不知目标期刊的格式要求?→ 看目标期刊的 Author Guidelines / LaTeX 模板;页数超了 → 把次要内容移到 supplementary、精简冗余。

## 二、实用工具 — 数字审计脚本 + WBF 融合骨架
```python
import re
# ① 数字审计：从 LaTeX 抓数字 + 和日志真值比对
def audit_numbers(tex_path, log_values):  # log_values={"main_mAP":78.5,...}
    tex = open(tex_path, encoding="utf-8").read()
    nums = re.findall(r'\d+\.\d+', tex)
    print(f"论文数字 {len(set(nums))} 种；请人工核对每个是否=日志真值：")
    for v in sorted(set(nums), key=float):
        flag = "⚠️核对来源" if float(v) not in log_values.values() else "✓在日志中"
        print(f"  {v}  {flag}")
    print("提醒:正文散落的'提升X%'也要核;改完全局复核三处一致")

# ② WBF 融合（检测多模型集成，用现成库）
def wbf_ensemble(boxes_list, scores_list, labels_list, iou_thr=0.55, skip_thr=0.0):
    from ensemble_boxes import weighted_boxes_fusion   # pip install ensemble-boxes
    # boxes_list: 各模型的框（归一化坐标）; 返回融合后的框
    boxes, scores, labels = weighted_boxes_fusion(
        boxes_list, scores_list, labels_list, iou_thr=iou_thr, skip_box_thr=skip_thr)
    return boxes, scores, labels   # 调 iou_thr/skip_thr 找最佳；模型差异越大收益越大

if __name__ == "__main__":
    audit_numbers("paper/main.tex", {"main_mAP":78.5, "delta":1.3, "fps":21.4})
```
