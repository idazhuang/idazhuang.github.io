## 上午段 · 论文打磨——Conclusion（结论：总结贡献 + 局限 + 未来工作）

**① 先垫概念（Conclusion 怎么写）**
- **Conclusion（结论）= 论文的收尾**——① **总结贡献**（简洁重述你做了什么、解决了什么、效果如何，呼应引言的承诺）；② **局限**（诚实说明方法的局限——审稿人欣赏诚实，也显你思考全面）；③ **未来工作**（指出可继续的方向）。★ **复用前两篇的 Conclusion 写法**——结构、表述都有经验。Conclusion 要简洁有力（不是重复全文，是升华）。一个好的 Conclusion 会让审稿人读完后对你工作的价值有清晰的印象——它不是简单地说"我们做了 A、B、C",而是提炼出"这项工作的意义在于…、它为这个领域带来了…",把具体的贡献上升到更有高度的认识。
- **为什么从 Conclusion 开始打磨**：v0.5 已有 Method/Experiment/Intro/Related Work，Conclusion 和 Abstract 是补全论文的"头尾"。先写 Conclusion（基于已有内容总结），再写 Abstract（D394）。

**② 手把手带做**：① 写 Conclusion（总结贡献：呼应引言、重述做了什么/效果）；② 写局限（诚实、思考全面）；③ 写未来工作（可继续的方向，可关联和目标组的合作）；④ 复用前两篇 Conclusion 结构；⑤ 简洁有力（升华非重复）。
**③ 这一步合格的样子**：Conclusion 写好——总结贡献（呼应引言）+ 局限（诚实）+ 未来工作，简洁有力，复用前两篇结构。
**④ 最常踩的坑**
- Conclusion 重复全文（冗长）→ 简洁升华（总结贡献，非复述）。
- 不写局限（显不全面）→ 诚实写局限（审稿人欣赏）。
- 不复用前两篇 → 复用结构表述。

**⑤ 卡住怎么自救（决策树）**：Conclusion 写什么？→ 总结贡献（呼应引言）+ 局限 + 未来工作；局限怎么写？→ 诚实说方法的不足（如某场景待改进）。
**⑥ 今天（这一步）你同时学会了什么**：你**写好了论文 Conclusion**。**做了**（写 Conclusion[贡献/局限/未来工作]+ 呼应引言 + 复用前两篇 + 简洁有力）、**学了**（Conclusion 升华非重复、诚实写局限、复用结构）、**会了**（写出简洁有力的论文结论）。

> **技能卡｜论文 v0.5→v1.0 打磨（投稿级）**：把初稿打磨到投稿级,补全+精修——①Conclusion（总结贡献呼应引言+诚实局限+未来工作,简洁升华非重复）②Abstract（浓缩问题+方法+结果+贡献,独立可读）③参考文献整理（规范引用+补全）④英文润色（语法/表达/学术性）⑤图表定稿（清晰专业）⑥supplementary（补充材料）。★ 复用前两篇打磨经验。配合通读自审+mock review（审稿人视角挑刺）。v1.0=投稿级（各章完整精修、可投）。

## 上午段 · 论文打磨——Abstract（摘要：浓缩问题 + 方法 + 结果 + 贡献）

**① 先垫概念（Abstract 怎么写）**
- **Abstract（摘要）= 论文的浓缩门面**——审稿人/读者第一眼看的，决定他们是否继续读。结构：① **问题/背景**（一句话）；② **方法**（你做了什么）；③ **结果**（关键提升/发现）；④ **贡献/意义**。★ **要点**：浓缩（150–250 字）、独立可读（不依赖正文也能看懂）、突出亮点（最强的结果/贡献）。复用前两篇 Abstract 写法。
- **为什么 Abstract 重要**：很多人只看 Abstract 决定要不要读全文；审稿人的第一印象也常来自 Abstract。写好 Abstract = 论文的好门面。有个实用技巧:Abstract 最好在论文主体写完后再写（或写完后再回头精修）——因为这时你对全文的贡献和结果最清楚,能提炼出最准确、最有力的浓缩版。先有内容、再提炼门面,比一开始就憋 Abstract 要高效得多。

**② 手把手带做**：① 写 Abstract（问题→方法→结果→贡献）；② 浓缩（150–250 字）；③ 独立可读（不依赖正文）；④ 突出亮点（最强结果/贡献，如"mAP 提升 X、单卡高效"）；⑤ 复用前两篇结构；⑥ 反复精炼（每句都有信息量）。
**③ 这一步合格的样子**：Abstract 写好——问题/方法/结果/贡献齐全、浓缩独立可读、突出亮点，复用前两篇。
**④ 最常踩的坑**
- Abstract 冗长/不浓缩 → 150–250 字、精炼。
- 不突出亮点 → 突出最强结果/贡献。
- 依赖正文（看不懂）→ 独立可读。

**⑤ 卡住怎么自救（决策树）**：Abstract 写什么？→ 问题→方法→结果→贡献；太长？→ 删次要、每句有信息量。
**⑥ 今天（这一步）你同时学会了什么**：你**写好了论文 Abstract**。**做了**（写 Abstract[问题/方法/结果/贡献]+ 浓缩独立可读 + 突出亮点 + 复用前两篇 + 精炼）、**学了**（Abstract 是浓缩门面、独立可读、突出亮点）、**会了**（写出精炼有力的论文摘要）。

## 中午段 · ★ 访问申请追问（如果 1 周未回复）

**① 先垫概念（访问申请追问的分寸）**
- 访问申请发出满 1 周，如**未回复 → 发追问邮件**。★ 追问的分寸同冷邮件追问：① **礼貌、简短**（"不知您是否看到我上周的访问申请，理解您繁忙"）；② **给台阶**（"邮件可能被淹没"）；③ **重申意愿 + 附材料**（"很希望有机会到贵团队访问，研究计划书见附件"）；④ **不施压、追问适度**（访问申请可追问 1-2 次，比冷邮件可稍多，因为这是正式申请、对方可能在内部讨论需要时间）。**追问给访问申请一次再被看到/推进的机会。**
- **为什么访问申请的追问可稍多于冷邮件**：访问申请是正式的、对方可能需要内部讨论/安排，所以回复周期可能更长，礼貌追问 1-2 次是合理的（但仍要礼貌、不催逼）。

**② 手把手带做**：① 检查访问申请是否满 1 周无回复；② 如是，发追问邮件（礼貌+简短+给台阶+重申意愿+附研究计划书，见补充包）；③ 对未回复的老师/师兄都可追问（各自定制）；④ 更新追踪表（已追问）；⑤ 追问后平常心（等回复，继续论文）。
**③ 这一步合格的样子**：如访问申请 1 周未回复，发了礼貌追问（重申意愿+附材料），追踪表更新，心态平稳。
**④ 坑**：① 不追问（干等）→ 满 1 周礼貌追问；② 追问催逼/施压 → 礼貌、给台阶、不施压；③ 追问太频繁 → 适度（1-2 次）。

# D398 周六 · 论文通读自审 + mock review（审稿人视角）+ 据自审修改

> **预期管理**：今天集中做投稿前的关键自检——① 上午论文通读自审（从头到尾读，找问题）；② 中午 mock review（站审稿人视角批判性审视）；③ 晚上据自审 + mock review 列修改清单 + 开始改。提醒：mock review 是投稿前的"模拟审稿"——像审稿人一样挑自己论文的刺，提前发现并修复问题，大大提高论文被接受的概率。

## 上午段 · 论文通读自审（从头到尾读，找问题）

**① 先垫概念（通读自审找什么）**
- **通读自审 = 从头到尾完整读一遍论文，找问题**：① 逻辑（论证是否清楚、有无漏洞）；② 表述（是否准确流畅、有无歧义）；③ 完整性（实验是否充分、贡献是否说清）；④ 细节（数据/符号/引用/笔误）。★ **以"第一次读这篇论文的读者"的视角读**——能不能看懂、有没有疑问、被不被说服。通读自审找出论文自己能发现的问题。
**② 手把手带做**：① 从头到尾完整通读论文（v1.0 雏形）；② 以"第一次读的读者"视角，记下：看不懂的、有疑问的、不被说服的、有问题的（逻辑/表述/完整性/细节）；③ 列出通读发现的问题清单；④ 标出严重程度（必改/可改）；⑤ 为 mock review 和修改做准备。
**③ 这一步合格的样子**：论文通读自审完成——以读者视角找出问题清单（逻辑/表述/完整性/细节），标了严重程度。
**④ 最常踩的坑**
- 不通读就投（带病投稿）→ 通读自审找问题。
- 以"作者视角"读（看不出问题）→ 以"第一次读的读者"视角。
- 发现问题不记录 → 列问题清单（待改）。

**⑤ 卡住怎么自救（决策树）**：看不出问题？→ 假装第一次读、问"能看懂吗/被说服吗/有疑问吗"；问题多？→ 标严重程度（必改先改）。
**⑥ 今天（这一步）你同时学会了什么**：你**通读自审找出了论文的问题**。**做了**（完整通读 + 读者视角 + 列问题清单[逻辑/表述/完整性/细节]+ 标严重程度）、**学了**（通读自审以读者视角找问题、列清单标严重程度）、**会了**（以读者视角通读自审论文）。

## 中午段 · mock review（站审稿人视角批判性审视）

**① 先垫概念（mock review 是什么、为什么做）**
- **mock review（模拟审稿）= 站在审稿人的视角，批判性地审视自己的论文**——像审稿人写评审意见一样，问：① **创新性**（贡献够不够、新不新）；② **有效性**（实验是否支撑结论、对比是否充分、消融是否到位）；③ **清晰性**（方法/实验是否讲清楚、能否复现）；④ **可能的质疑**（审稿人会挑什么刺、问什么问题）。★ **提前用审稿人视角挑刺，把问题在投稿前修复**——这大大提高论文被接受的概率（你先发现并修复了审稿人会指出的问题）。复用前两篇的审稿经验（你被审过、也理解审稿视角）。
- **为什么 mock review 有用**：审稿人会批判性地审视论文、挑刺。你提前做 mock review，相当于"自己先当一次审稿人"——发现论文的弱点、可能被质疑的地方，提前修复或准备应对。这里的关键是要"狠得下心"——对自己的论文,人天然会有"护短"心理,容易自我说服"这样应该没问题"。但 mock review 要求你暂时抛开作者身份、像一个挑剔的审稿人那样找茬:哪里证据不足、哪里逻辑有跳跃、哪里说得含糊。越能狠心挑出问题,投稿后被真审稿人挑出的就越少。

**② 手把手带做**：① 站审稿人视角，批判性审视论文（创新性/有效性/清晰性/可能的质疑）；② 像写评审意见一样列出"审稿人会指出的问题/质疑"；③ 对每个质疑，想：能修复吗（改论文）/能回应吗（补实验/解释）；④ 形成 mock review 清单（问题 + 应对）；⑤ 合并到修改清单。
**③ 这一步合格的样子**：mock review 完成——以审稿人视角列出可能的质疑（创新性/有效性/清晰性）+ 应对，合并到修改清单。
**④ 坑**：① 不做 mock review（投稿被审稿人挑出问题）→ 提前 mock review 挑刺修复；② mock review 不够批判（手软）→ 像真审稿人一样严格挑刺。
**⑤ 自救**：不知审稿人会挑什么？→ 创新性够吗/实验支撑吗/对比充分吗/能复现吗/有什么弱点；挑出的问题怎么办？→ 能改的改、能回应的准备回应。
**⑥ 今天（这一步）你同时学会了什么**：你**用审稿人视角挑出了论文的刺**。**做了**（审稿人视角批判审视 + 列可能质疑[创新/有效/清晰]+ 想应对 + 合并修改清单）、**学了**（mock review 提前挑刺修复、像真审稿人严格、复用审稿经验）、**会了**（用审稿人视角自审论文并准备应对）。

> **技能卡｜mock review（审稿人视角自审）**：投稿前的关键自检——站审稿人视角批判性审视论文,像写评审意见一样挑刺:①创新性（贡献够不够新）②有效性（实验支撑结论吗/对比充分吗/消融到位吗）③清晰性（方法实验讲清了吗/能复现吗）④可能的质疑（审稿人会挑什么刺）。★ 提前用审稿人视角挑刺、在投稿前修复,大大提高被接受概率（你先发现修复了审稿人会指出的问题）。复用前两篇审稿经验（你被审过、理解审稿视角）。配合通读自审（读者视角找问题）。

## 晚上段 · 据自审 + mock review 列修改清单 + 开始修改

**① 先垫概念**：晚上**据通读自审 + mock review 列修改清单 + 开始修改**——把上午通读自审和中午 mock review 发现的问题汇总成修改清单（按严重程度排序），开始修改论文。★ **自审 + mock review 的价值在于修改**——发现的问题要修复，论文才能从 v1.0 雏形到真正的 v1.0（投稿级）。修改时分两类处理:能直接改的（表述/逻辑/笔误/补个小实验）立即改;一时改不了或涉及根本性质疑的（如"创新性不够"这种），想清楚怎么在论文里更好地论证、或在 rebuttal 时怎么回应。把"自审发现的问题"变成"已修复或已准备好应对"，论文的抗审稿能力就强了。
**② 手把手带做**：① 汇总修改清单（通读自审 + mock review 的问题）；② 按严重程度排序（必改先改）；③ 开始修改（改逻辑/表述/补实验/回应质疑）；④ 重要的改完、次要的记录（W58 继续）；⑤ 论文向真正的 v1.0 推进。
**③ 这一步合格的样子**：修改清单汇总（排序）、开始修改（重要的改完），论文向 v1.0 推进。
**④ 坑**：① 自审了不改（白审）→ 据清单修改；② 不排序（眉毛胡子一把抓）→ 按严重程度（必改先改）。
**⑤ 自救**：改不完？→ 必改的先改、次要的 W58 继续；某质疑难回应？→ 补实验/解释、或在论文中说明。
**⑥ 今天（这一步）你同时学会了什么**：你**据自审修改了论文**。**做了**（汇总修改清单 + 排序 + 开始改[逻辑/表述/补/回应]+ 重要的改完）、**学了**（自审价值在修改、按严重程度排序、向 v1.0 推进）、**会了**（据自审和 mock review 修改论文）。

> **今日交付**：✅ 论文通读自审（读者视角找问题）✅ mock review（审稿人视角挑刺）✅ 据自审 + mock review 列修改清单 + 开始修改。

## 二、完整可运行代码 · 论文 v1.0 打磨就绪检查器（+ 预期输出）

> 这个脚本把"论文 v1.0（投稿级）就绪度"做成可勾选的检查器——输入各打磨环节的完成状态，输出就绪度和"还差什么"，帮你清楚看到论文距投稿级还差哪些。

```python
#!/usr/bin/env python3
# paper_v1_polish_checklist.py —— 论文 v1.0 打磨就绪检查器
checklist = {
    "首尾章节": {"Conclusion(贡献/局限/未来)": True, "Abstract(独立可读/突出亮点)": True},
    "证据与引用": {
        "参考文献整理(规范/补全/含目标组)": True, "补充实验(补审稿人会问的缺口)": True,
    },
    "整体性": {"v0.5→v1.0整体串联(逻辑/术语/呼应)": True, "各章细节完善": False},
    "图表": {"可视化图(方法图/结果图)": True, "图表定稿(清晰/统一/caption)": True},
    "投稿级要求": {
        "英文润色(语法/表达/学术性)": False, "通读自审(读者视角)": True,
        "mock review(审稿人视角挑刺)": True, "据自审修改": False,
    },
}

def check(checklist):
    print("=== 论文 v1.0（投稿级）就绪度 ===\n")
    total = done = 0
    todo = []
    for cat, items in checklist.items():
        c_done = sum(1 for v in items.values() if v)
        total += len(items); done += c_done
        bar = "✅" if c_done == len(items) else "⏳"
        print(f"{bar} {cat}: {c_done}/{len(items)}")
        for k, v in items.items():
            if not v:
                todo.append(f"{cat} · {k}")
                print(f"     □ 待办: {k}")
    pct = round(done / total * 100)
    print(f"\n论文 v1.0 就绪度: {done}/{total} = {pct}%")
    if todo:
        print("还差：")
        for t in todo:
            print(f"  - {t}")
        print("\n→ W58 定稿前补齐(尤其英文润色 + 据自审修改)。")
    else:
        print("\n🎉 论文 v1.0 投稿级就绪！W58 定稿投出。")

if __name__ == "__main__":
    check(checklist)
```
