# 前置 · 三件全书都默认你会、却从没讲过的事

原手册第一天就让你"打开终端"、写 `.md` 文件、`pip install`。**对科班出身的人这是常识，对转行的人这是三道墙。** 全书 312 万字没有一处解释它们。先用 40 分钟拆掉这三道墙，后面 729 天都受益。

## 前置 1 · 终端（命令行）

### 它是什么

**终端 = 用打字代替点鼠标来操作电脑。** 你敲一行字，电脑执行一个动作。

**为什么科研必须用它**：① 深度学习的工具绝大多数没有图形界面；② 你做的操作要能**被记录、被重复**——鼠标点击没法写进日志，命令可以；③ 远程服务器上根本没有桌面。

### 怎么打开

| 系统 | 怎么开 |
|---|---|
| **Windows** | 装完 Miniconda 后，开始菜单里搜 **Anaconda Prompt**，用它（不要用 CMD 或 PowerShell，conda 命令可能不认） |
| **macOS** | `Command + 空格`，输入 `Terminal`，回车 |
| **Linux** | `Ctrl + Alt + T` |

> **给 Windows 用户的一句真心话**：深度学习的绝大多数教程、报错、issue 都是按 Linux 写的。**如果你打算认真做两年，现在就装 WSL2**（Windows 里的真 Linux 子系统），微软官方支持，一条命令：管理员权限打开 PowerShell，运行 `wsl --install`，重启即可。**今天可以先不装，但 W2 之前一定要装。** 这能帮你避开后面几十次"教程里的命令在我这跑不了"。

### 打开后你看到什么

```text
(base) C:\Users\你的用户名>
  ↑        ↑                ↑
  当前环境  当前所在目录      光标在这敲命令
```

Linux/Mac 上长这样：

```text
(base) yourname@computer:~$
                        ↑ ~ 表示你的用户主目录（家目录）
```

**`(base)` 是关键**——它告诉你当前处在哪个 Python 环境里。中午段建完环境后，它会变成 `(rs)`。**每次敲命令前先瞄一眼这个括号**，这个习惯能帮你避开"装错环境"这个最常见的错误。

### 五个必会命令（今天只需要这五个）

```bash
pwd              # print working directory：我现在在哪个文件夹
ls               # list：列出当前文件夹里有什么（Windows CMD 用 dir，Anaconda Prompt 里 ls 通常可用）
cd 文件夹名       # change directory：进入某个文件夹
cd ..            # 回到上一层
mkdir 新文件夹名  # 新建文件夹
```

**现在就练一遍**（30 秒，别跳过）：

```bash
pwd
mkdir test_folder
cd test_folder
pwd
cd ..
```

你会看到第二次 `pwd` 的输出比第一次多了一层 `/test_folder`。**这就是"当前目录"的含义**——后面所有命令都是相对于你此刻所在的位置执行的。**新手最常见的报错"找不到文件"，八成是因为不在正确的目录里。**

### 路径：绝对与相对

| 写法 | 例子 | 含义 |
|---|---|---|
| **绝对路径** | `/home/zhang/RS-CV/data` | 从根目录写全，在哪敲都指同一个地方 |
| **相对路径** | `data/DOTA` | 相对于你**当前所在目录** |
| `~` | `~/RS-CV` | 你的家目录，Linux/Mac 常用 |
| `.` | `./train.py` | 当前目录 |
| `..` | `../configs` | 上一层目录 |

### 终端里的三个小坑

1. **复制粘贴**：终端里 `Ctrl+V` 常常没用。Linux 终端用 **`Ctrl+Shift+V`**；Windows 的 Anaconda Prompt 里直接**点鼠标右键**就是粘贴。
2. **路径里有空格**：`cd My Folder` 会失败，要写 `cd "My Folder"`。**所以你的项目路径里永远不要有空格和中文**——这条会帮你省掉很多莫名其妙的报错。
3. **命令卡住了**：按 `Ctrl+C` 中断。这是终端的"取消键"。

## 前置 3 · 包、pip、conda 的分工（★ 原文最大的概念缺口）

原文把 conda 比作"无菌实验室"，比喻很好，**但没说它到底是什么**。结果你后面一定会遇到这个问题：**"这个包我该用 conda install 还是 pip install？"** —— 全书没有答案。现在补上。

### 什么是"包"

**包（package）= 别人写好的、可以直接拿来用的代码库。** `numpy` 是包，`torch` 是包，`mmrotate` 也是包。你的研究 90% 建立在别人的包上。

### pip 和 conda 都是"装包的工具"，但来源和能力不同

| | **pip** | **conda** |
|---|---|---|
| 包从哪来 | **PyPI**（Python 官方包仓库，`pypi.org`） | Anaconda / conda-forge 等**渠道（channel）** |
| 能装什么 | **只能装 Python 包** | Python 包 **+ 非 Python 的东西**（CUDA 运行时、编译器、ffmpeg…） |
| 包的数量 | **多得多**（几十万） | 少一些，但更"整装" |
| 依赖冲突处理 | 较弱 | 较强（会解算整体依赖） |
| 谁自带 | Python 自带 | 装 Miniconda 才有 |

### 虚拟环境物理上到底是什么

**就是一个文件夹。** 当你运行 `conda create -n rs python=3.10`，conda 在磁盘上建了一个目录，大致长这样：

```text
~/miniconda3/envs/rs/
├── bin/python          ← 这个环境专属的 Python 解释器
└── lib/python3.10/site-packages/    ← 你 pip install 的所有包都装到这里
```

`conda activate rs` 做的事情，**就是修改 `PATH` 环境变量，让你敲 `python` 时找到的是 `envs/rs/bin/python` 而不是系统的那个**。

**理解这一点，你就理解了三件事**：
1. 为什么忘了 `activate` 就装包会"白装"——装到别的目录去了。
2. 为什么删环境只要 `conda env remove -n rs`——就是删个文件夹，不会污染系统。
3. 怎么确认自己在哪个环境：`which python`（Windows：`where python`），看输出路径里有没有 `envs/rs`。

### 实操规则（背下来，后面天天用）

```text
① 建环境、装 Python 本身        → conda
② 装 PyTorch                    → 用 PyTorch 官网给的那条命令（通常是 pip）
③ 其他所有 Python 包             → pip
④ 千万不要在同一个环境里，
   对同一个包一会儿 conda 一会儿 pip → 这是依赖地狱的头号成因
```

> **一条纪律**：**每个项目一个环境，环境用完即弃。** 环境搞坏了不要修，`conda env remove -n rs` 删掉重建，五分钟的事。**新手最大的时间浪费是修一个坏掉的环境。**

你两年要读大约 **200–300 篇论文**。假设你读一篇花 2 小时，那就是 500 小时。**如果没有笔记系统，这 500 小时里能留在脑子里的不到 10%。** 更要命的是，到 M3（第 9–12 周）你要"找 Gap"时，需要的正是"我在第 3 周读的那篇里，作者说了一句某方法在小目标上不行"——**这种细节人脑绝对记不住，但笔记能。**

### 为什么选 Obsidian（不是随便二选一）

原文说"Obsidian 或 Notion，别纠结"。**方向对，但理由该说清**：

| | Obsidian | Notion |
|---|---|---|
| 数据在哪 | **你自己电脑上的一堆 .md 文件** | 云端服务器 |
| 断网能用吗 | 能 | 基本不能 |
| 能用 git 备份吗 | **能**（就是普通文本文件） | 不能 |

**推荐 Obsidian，理由就一条：你的科研笔记是两年的资产，必须存成你能永远打开的格式。**

## ② 手把手带做

### 第 1 步：下载安装 Obsidian

**官网**：`https://obsidian.md`

打开后点页面上的 **Download** 按钮，它会自动识别你的系统。个人使用**完全免费**，不需要注册账号。

装完第一次打开，你会看到一个欢迎界面，上面有几个选项：

```text
Create new vault        ← 点这个
Open folder as vault
Open vault from Obsidian Sync
```

### 第 2 步：搞懂 Vault 是什么

**Vault（仓库）= 一个普通的文件夹。** Obsidian 没有任何数据库，它只是一个"能好看地显示某个文件夹里所有 .md 文件"的编辑器。

点 **Create new vault** 后：

- **Vault name** 填 `RS-CV`
- **Location** 选一个你能记住的位置，比如 `D:\` 或 `~/Documents`
- **★ 路径里不要有中文和空格**（前置 1 讲过为什么）

点 Create。你现在有了一个空仓库。

> **这意味着什么**：你磁盘上出现了一个叫 `RS-CV` 的普通文件夹。你可以用文件资源管理器直接打开它、用 git 管理它、拷到 U 盘带走。**Obsidian 只是个窗口，你的数据从来不在它手里。**

### 第 3 步：建 4 个顶层文件夹

在 Obsidian 左侧文件栏，**右键空白处 → New folder**，依次建：

```text
00-基础理论      放遥感物理概念、CV 基础、术语卡片
10-论文笔记      每篇论文一个 .md
20-代码实验      脚本、实验日志、复现报告、环境 SOP
30-数据集        每个数据集一个子文件夹 + README
```

**为什么用 `00- / 10- / 20-` 这种数字前缀？**（原文没说，但这个设计有讲究）

1. **强制排序**：文件管理器按字典序排，数字前缀让它们永远按你要的逻辑顺序排列，而不是拼音顺序。
2. **留空隙**：用 00/10/20/30 而不是 1/2/3/4，是为了**以后能往中间插**。比如后面你要加"15-会议投稿"，插进去不用重命名其他所有文件夹。
3. 这是工程界通用的编号习惯，你以后看开源项目的 `configs/` 目录也常见。

### 第 4 步：★ Obsidian 的三个核心功能（原文完全没提，但这是它的全部意义）

**功能一：新建笔记** —— `Ctrl/Cmd + N`，或右键文件夹 → New note。

**功能二：双向链接 `[[ ]]`** ← **这是 Obsidian 存在的理由**

在任何笔记里输入 `[[`，会弹出补全菜单。比如你在实验日志里写：

```markdown
今天跑的 baseline 用的方法来自 [[2021_Xie_Oriented-RCNN]]，
它的角度编码方式见 [[术语卡片#le90]]。
```

这样做的好处：**半年后你打开那篇论文笔记，Obsidian 会在页面底部的 "Backlinks" 里告诉你"有 3 个实验引用了这篇论文"**。你的笔记从一堆孤立文件变成一张网。

**这正是科研笔记和普通笔记的区别**：科研的价值在于"A 和 B 的联系"，而不是 A 或 B 本身。**从今天起，写笔记时想到相关的东西就用 `[[]]` 链上，哪怕那个文件还不存在**（Obsidian 允许链接到不存在的笔记，等你真去建时它自动接上）。

**功能三：全局搜索** —— `Ctrl/Cmd + Shift + F`，搜全库。这是你半年后找回"我在哪见过 speckle 这个词"的方式。

### 第 5 步：建 5 段式模板

在 `10-论文笔记` 下新建 `_模板_5段式.md`，内容：

```markdown
# {年份}_{第一作者}_{关键词}
- **出处**：{期刊/会议} {年份} ｜ **标签**：#综述/#方法/#数据集 #检测/#SAR/...
- **我的评级**：A（必读经典）/ B（有用）/ C（泛读即可）
- **链接**：{DOI / arXiv / 免费 PDF 地址}

## 1. 它解决什么问题（动机）

## 2. 怎么做的（方法/核心 idea）
（用你自己的话说清它的关键招数，配一句话画出 pipeline）
```

### 第 6 步：★★ 一份填满的范例（原文最缺的东西）

**光看空模板，你不知道每段该写多长、写到什么颗粒度。** 下面是 D2 你要读的那篇（Zhu 2017）填完之后应该长的样子——**现在就把它抄进 `10-论文笔记/2017_Zhu_DL-survey.md`，明天读的时候对照着改。**

```markdown
# 2017_Zhu_遥感深度学习综述
- **出处**：IEEE GRSM 2017, 5(4):8-36 ｜ **标签**：#综述 #遥感 #深度学习
- **我的评级**：A（这是我入门的地图，必读）
- **链接**：DOI 10.1109/MGRS.2017.2762307
  免费全文：北卡大学仓库 cdr.lib.unc.edu 上有公开 PDF（搜标题即可）

## 1. 它解决什么问题（动机）
深度学习 2012 年后在通用 CV 上爆发，但遥感界当时还在观望：遥感数据和自然图像
差别很大（多光谱/SAR/大尺寸/标注贵），直接搬 CNN 到底行不行、行在哪、不行在哪，
没人系统梳理过。这篇就是把"遥感 + 深度学习"这件事第一次完整盘了一遍。

## 2. 怎么做的（方法/核心 idea）
它不是提方法，是**分类学 + 资源清单**：
- 先按**数据类型**切：光学（全色/多光谱/高光谱）、SAR、以及它们的组合
- 再按**任务**切：图像预处理、像素级分类、目标检测、场景分类、时序分析、数据融合
- 每个格子里列代表工作 + 说清"这里深度学习赢在哪、还差什么"
- 最后给了一份公开数据集和代码资源清单（这部分现在已过时，看看就好）

## 3. 实验与结果
综述没有自己的实验。有价值的是它汇总的对比表——记住一个结论就够：
**在标注充足的场景（如高光谱分类、场景分类）深度学习明显赢；
在标注稀缺、物理机理强的场景（如 SAR 定量反演）当时优势不明显。**

## 4. 启发 / 可借鉴 / 没解决的  ★
- 它反复强调的三个"遥感特有难点"，正好是我未来找 Gap 的方向：
  ① 标注昂贵 → 指向自监督/半监督（对应我 W7 要看的方向）
  ② 数据是多模态多分辨率的 → 指向融合
  ③ 物理机理该不该进模型 → 这个问题到今天也没解决，是个大口子
- 它写于 2017，Transformer/基础模型/VLM 全都还没有。
  **我可以做的事：拿它的分类框架，看这 8 年每个格子里发生了什么变化。**
  这个动作本身就能让我快速建立"领域现在长什么样"的地图。

## 5. 我没看懂的 / 待查
- [ ] 高光谱的"光谱维"和 RGB 的通道到底差在哪？（→ 记进术语卡片）
- [ ] 它提到 SAR 的 speckle 是核心难点，具体难在哪？（→ 见 [[名词逐个讲透]] §1）
- [ ] "domain adaptation" 这个词反复出现，是什么？（→ 待查清单）
```

**对照这份范例，你现在知道了**：

| 段 | 该写多长 | 判断标准 |
|---|---|---|
| 1. 动机 | 2–4 句 | 能对别人说清"这篇为什么该被写出来" |
| 2. 方法 | 一小段 + 分点 | **必须是你自己的话**，抄摘要不算 |
| 3. 实验 | 3–5 句，抓一个核心结论 | 记住一个数字或一个结论就够 |
| 4. 启发 ★ | **越长越好，可以超过前面所有段之和** | 有没有至少一条"我能接的口子" |

# 中午段 · 装 conda + 建环境 + 装 PyTorch（60 分钟）

## ① 先垫概念

前置 3 已经讲了 pip/conda/虚拟环境。这里补 GPU 那一侧的三个词，**原文讲了但没讲透**。

### GPU / 驱动 / CUDA 运行时 / PyTorch —— 四层关系

新手最大的困惑是"我到底要不要单独装 CUDA"。把这四层画清楚就不困惑了：

```text
第 4 层  PyTorch              ← 你写代码用的框架（pip 装）
         ↓ 调用
第 3 层  CUDA 运行时           ← ★ 装 PyTorch 时自带，不用你管
         ↓ 调用
第 2 层  NVIDIA 显卡驱动        ← 要你自己装/更新（去 NVIDIA 官网）
         ↓ 驱动
第 1 层  GPU 硬件（你的 4090）
```

**结论（记住这三条，能省你半天）**：

1. **你不需要单独装 CUDA Toolkit。** 带 `cu121` 的 PyTorch 轮子里已经打包了运行时。
2. **你需要保证显卡驱动够新。** 驱动版本 ≥ 你要用的 CUDA 版本要求即可。
3. **`nvidia-smi` 右上角显示的 `CUDA Version` 不是"你装了 CUDA"**，它是"**你的驱动最高能支持到哪个 CUDA**"。显示 12.4 的机器完全可以跑 cu118 的 PyTorch。

> **这第 3 条是新手劝退率最高的误解**。原文一句"以为装了驱动=有 CUDA"点到了，但没说清方向，很多人反而更糊涂了。

### 为什么 Python 用 3.10（原文说"稳"，这里说为什么）

**深度学习生态永远滞后于 Python 官方版本半年到两年。** 判断规则：

```text
挑一个「不是最新、也不是最老」的版本 —— 通常是当前最新版往回数 2–3 个小版本。
```

具体到今天：Python 3.10 / 3.11 都很安全，3.9 也行（老框架兼容性最好）。**3.12+ 现在还会遇到某些包没有预编译轮子。** 这也是为什么晚上段装 MMRotate 时我建议用 3.9——那套框架更老。

**这个判断方法你要学会**，因为具体数字每年都在变，方法不变。

## ② 手把手带做

### 第 1 步：装 Miniconda

**下载地址**：`https://repo.anaconda.com/miniconda/`

这是官方的文件列表页，按系统挑：

| 系统 | 挑这个文件名 |
|---|---|
| Windows 64 位 | `Miniconda3-latest-Windows-x86_64.exe` |
| macOS（M 系列芯片） | `Miniconda3-latest-MacOSX-arm64.sh` |
| macOS（Intel 芯片） | `Miniconda3-latest-MacOSX-x86_64.sh` |
| Linux 64 位 | `Miniconda3-latest-Linux-x86_64.sh` |

**为什么是 Miniconda 而不是完整版 Anaconda**：完整版预装了几百个你用不到的包，占 3 GB 还拖慢环境解算。Miniconda 只有 conda 本身，**几十 MB，够用**。

**Windows 安装时的关键一步**（原文完全没提，但选错了会踩坑）：

安装向导走到 "Advanced Options" 时，会有几个勾选框：

```text
[ ] Add Miniconda3 to my PATH environment variable   ← 保持不勾（官方推荐）
[✓] Register Miniconda3 as my default Python         ← 勾上
```

**不勾 PATH 的原因**：勾了容易和系统里其他 Python 打架。**代价是你必须用"Anaconda Prompt"而不是普通 CMD**——这没问题，从开始菜单搜就行。

**Linux/Mac 安装**：

```bash
bash Miniconda3-latest-Linux-x86_64.sh
# 一路回车看协议，问 yes/no 时输 yes
# 最后问 "initialize Miniconda3?" → 输 yes
# 装完关掉终端重开，或运行：
source ~/.bashrc
```

**验证装好了**：

```bash
conda --version
```

**期望输出**：`conda 2x.x.x`（版本号是多少无所谓，能打印出来就行）。

如果提示 `conda: command not found`：Windows 用户请用 Anaconda Prompt；Linux/Mac 用户执行 `source ~/.bashrc` 或重开终端。

### 第 2 步：建环境

```bash
conda create -n rs python=3.10 -y
```

**逐个拆开看**（原文只给命令没解释参数）：

| 部分 | 含义 |
|---|---|
| `conda create` | 建一个新环境 |
| `-n rs` | `-n` = name，环境叫 `rs` |
| `python=3.10` | 这个环境里装 Python 3.10 |
| `-y` | 所有确认自动回答 yes，省得手动敲 |

**期望输出**：一段包列表，最后是 `done` 和一段提示 `To activate this environment, use: conda activate rs`。

```bash
conda activate rs
```

**成功标志**：命令行提示符最前面从 `(base)` 变成 **`(rs)`**。

> **★ 如果没有变**：这是最常见的第一个坑。执行 `conda init` 后**关掉终端重新打开**，再 activate 一次。

**再确认一次你真的进对了环境**：

```bash
which python      # Windows: where python
```

**期望输出**里应该包含 `envs/rs`，比如 `/home/你/miniconda3/envs/rs/bin/python`。**看到这个路径，你就真正理解了前置 3 说的"环境就是个文件夹"。**

### 第 3 步：装 PyTorch —— 教你自己去官网选命令

原文直接给了 `cu121` 那条命令。**能用，但半年后会过期。** 更重要的是教你怎么自己选：

**打开 `https://pytorch.org/get-started/locally/`**

页面上有一个选择器，你依次点：

```text
PyTorch Build : Stable          ← 选稳定版，别选 Preview
Your OS       : Linux / Windows / Mac
Package       : Pip             ← 选 Pip
Language      : Python
Compute Platform : CUDA 12.1    ← ★ 关键，见下
```

**Compute Platform 怎么选**：先运行 `nvidia-smi`，看右上角的 `CUDA Version`。**选一个不超过它的版本**。比如驱动显示 12.4，你选 CUDA 12.1 或 11.8 都行；显示 11.7，那就只能选 11.8 以下。

选完，页面下方会生成一条命令，**复制它**。对 4090 + CUDA 12.1，生成的是：

```bash
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu121
```

**`--index-url` 是什么、为什么不能丢**（原文提醒了"不带会装成 CPU 版"，但没说为什么）：

pip 默认从 PyPI 下载。**PyPI 上的 `torch` 是 CPU 版**（因为 GPU 版太大）。`--index-url` 告诉 pip："别去 PyPI，去 PyTorch 官方这个专门放 GPU 版轮子的地址下"。**丢了它，你会装到一个能跑但用不了显卡的 PyTorch，而且不报错**——这是最坑的地方，你要跑起来才发现慢得离谱。

### 第 4 步：验证（今天最重要的一步）

```bash
python -c "import torch; print(torch.__version__); print(torch.cuda.is_available()); print(torch.cuda.get_device_name(0))"
```

**期望输出**：

```text
2.x.x+cu121
True
NVIDIA GeForce RTX 4090
```

**逐行怎么读**：

| 行 | 看什么 |
|---|---|
| 第 1 行 | 版本号后面**必须有 `+cu121` 之类的后缀**。如果是纯 `2.x.x` 或 `+cpu`，你装的是 CPU 版 |
| 第 2 行 | **`True` 就是今天的及格线** |
| 第 3 行 | 认出了你的显卡 = 全链路通了 |

**再跑一个 30 秒的真实测试**（原文没有，但这一步能确认 GPU 真的在算，而不只是"能看见"）：

```bash
python -c "
import torch, time
x = torch.randn(4000, 4000, device='cuda')
torch.cuda.synchronize(); t = time.time()
for _ in range(50): y = x @ x
torch.cuda.synchronize()
print(f'GPU 矩阵乘 50 次耗时 {time.time()-t:.2f} 秒')
print(f'显存占用 {torch.cuda.memory_allocated()/1024**2:.0f} MB')
"
```

**期望**：4090 上大约 0.3–1 秒，显存占用一两百 MB。**如果超过 10 秒，说明它在用 CPU 装样子。**

### 第 5 步：国内网络加速（原文提了一句，这里给完整配置）

**pip 换源**（一次配置，永久生效）：

```bash
pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
pip config set global.trusted-host pypi.tuna.tsinghua.edu.cn
```

**★ 注意**：换源之后，装 PyTorch 那条命令里的 `--index-url` **依然要保留**——它会临时覆盖全局配置，指向 PyTorch 官方源。**两者不冲突。**

**conda 换源**：

```bash
conda config --add channels https://mirrors.tuna.tsinghua.edu.cn/anaconda/pkgs/main
conda config --add channels https://mirrors.tuna.tsinghua.edu.cn/anaconda/pkgs/free
conda config --set show_channel_urls yes
```

**验证换源生效**：`pip config list`，应该看到你设的清华地址。

## ④⑤ 常踩的坑与自救

| 症状 | 原因 | 解 |
|---|---|---|
| `conda: command not found` | 没加 PATH / 没重开终端 | Windows 用 Anaconda Prompt；Linux `source ~/.bashrc` |
| activate 后提示符没变成 `(rs)` | 没 `conda init` | 运行 `conda init`，**关掉终端重开** |
| `cuda.is_available()` 是 `False`，`nvidia-smi` 也看不到显卡 | 驱动问题 | 去 NVIDIA 官网装最新驱动，重启 |
| `cuda.is_available()` 是 `False`，但 `nvidia-smi` 能看到 4090 | 装成了 CPU 版 | `pip uninstall torch torchvision -y`，带 `--index-url` 重装 |
| 版本号是 `2.x.x+cpu` | 同上 | 同上 |
| pip 下载龟速/超时 | 网络 | 见上面换源；PyTorch 那条保留官方 `--index-url`，实在不行多试几次 |
| 装到一半磁盘满 | PyTorch 轮子约 2 GB+ | `df -h` 检查，留 20 GB |
| 一个环境搞乱了想重来 | — | `conda deactivate` → `conda env remove -n rs` → 从第 2 步重建。**五分钟的事，不要修** |
