## 中午段 · 装 Anaconda + 建虚拟环境 + 装 PyTorch(让电脑"能算")

**① 先垫概念(这几个词你后面天天见,现在一次讲清)**
- **Anaconda / conda**:一个"环境管理器"。把它想成"给每个项目单独开一间无菌实验室"——A 项目要 PyTorch 2.1,B 项目要 1.10,**装在同一个系统里会打架**,虚拟环境让它们互不污染。
- **虚拟环境(virtual environment)**:就是上面说的"一间无菌实验室"。`conda create -n rs` 就是开一间叫 `rs` 的房间;`conda activate rs` 是走进这间房;之后你装的所有包都只在这间房里。
- **GPU / CUDA**:你的 **4090 显卡**是专门做大规模并行计算的硬件,训练神经网络比 CPU 快几十倍。**CUDA** 是 NVIDIA 让代码能调用 GPU 的"驱动+工具包"。**PyTorch** 是你写模型用的框架,它要装"对应 CUDA 版本"的那一版,才能真正用上你的 4090。
- **为什么现在需要**:科研第一步是"能跑代码";而"能跑代码"的硬门槛,就是"PyTorch 能看见你的 GPU"。

**② 手把手带做**(按顺序,一步一步来)
1. 装 **Miniconda**(比完整版 Anaconda 更轻,够用;官网下 Windows/Linux 版)。装完打开终端(Windows 用 "Anaconda Prompt")。
2. 建环境(**Python 用 3.10,稳**):
   ```bash
   conda create -n rs python=3.10 -y
   conda activate rs
   ```
   看到命令行最前面变成 `(rs)` 就说明你"进房间"了。
3. 装 PyTorch(**你是 4090,用 CUDA 12.1 的轮子**):
   ```bash
   pip install torch torchvision --index-url https://download.pytorch.org/whl/cu121
   ```
4. **立刻验证**(这是今天最重要的一行命令):
   ```bash
   python -c "import torch; print(torch.__version__); print(torch.cuda.is_available()); print(torch.cuda.get_device_name(0))"
   ```

**③ 合格样例**:第 4 步输出形如
```
2.x.x+cu121
True
NVIDIA GeForce RTX 4090
```
**只要 `True` 出现 + 显示出你的 4090,中午段就满分了。** 截图存进 `20-代码实验/环境SOP.md`。

**④ 常踩的坑**
- **忘了 `conda activate rs`** 就装包:结果装进了 base 环境,白装。每次开新终端都要先 activate。
- **装成 CPU 版 PyTorch**:如果你 `pip install torch` 不带 `--index-url`,很可能装到 CPU 版,`cuda.is_available()` 会是 `False`。务必带上 cu121 的源。
- **以为"装了驱动"=有 CUDA**:你只要装对 PyTorch 的 cu121 轮子即可,**不需要**单独手动装 CUDA Toolkit(轮子自带运行时)。但你的 NVIDIA 显卡驱动要够新(支持 CUDA 12.1,4090 出厂驱动一般都够)。

**⑤ 卡住自救(决策树)**
- `cuda.is_available()` 返回 `False`?
  - → 先 `nvidia-smi`(终端运行),能看到 4090 和驱动版本吗?**看不到** = 驱动问题,去 NVIDIA 官网装最新 Game Ready/Studio 驱动。
  - → 能看到 4090 但仍 `False` = 多半装了 CPU 版,卸了重装:`pip uninstall torch torchvision -y` 再用 cu121 源重装。
- `pip install` 巨慢 / 超时?→ 换国内镜像加速,例:`pip install ... -i https://pypi.tuna.tsinghua.edu.cn/simple`(但 torch 那条要保留官方 `--index-url`,可改用清华的 pytorch 镜像源)。
- 实在搞不定?→ **今天到此为止也算赢**:只要 PyTorch + `True` 拿到了,MMRotate(晚上段)可以挪到明天。**不要让晚上段的难活,毁掉中午段已经到手的胜利。**

**⑥ 今天(这一步)你同时学会了什么**:你掌握了**"建隔离环境 + 装框架 + 验证 GPU 可用"这套深度学习的开机仪式**。以后每复现一份别人的代码,第一件事都是这套。**做了**(可用的 `rs` 环境)、**学了**(conda/虚拟环境/CUDA/PyTorch 各自是什么、怎么咬合)、**会了**("先验证 GPU 再干活"的习惯)。

> **技能卡｜深度学习环境四步**:① `conda create -n xxx python=3.10` → ② `conda activate xxx` → ③ 装对 CUDA 版本的 PyTorch → ④ `torch.cuda.is_available()` 必须为 `True` 才算开机成功。

## 晚上段 · 装 MMRotate 工具链 + 跑通第一张 DOTA demo + 写《环境 SOP》

> **重要预期管理**:你计划里"晚上装 MMCV + MMDetection + MMRotate 并跑 demo"是**整个第一周最容易吃掉一整天甚至两天的一格**。原因:MMRotate 是一套较老的框架,**它和最新的 PyTorch/CUDA 经常版本打架**。这不是你的问题,是这套生态的历史包袱。下面我给你"**最省事路径 + 打不通时的退路**",你照着走,卡住别慌。

**① 先垫概念**
- **MMxx 全家桶**:`MMCV`(底层算子库,旋转框这类特殊操作就在这)、`MMDetection`(通用目标检测框架)、`MMRotate`(在前两者之上、专做**旋转框检测**的库——遥感目标常常是斜着的飞机、船,需要旋转框)。三者是**地基→楼房→精装修**的依赖关系。
- **demo 推理**:用别人**训练好的模型权重**,对一张图跑一次预测、把框画出来。它不训练、几秒钟出结果,是验证"工具链装通了"的最快方式。
- **为什么现在需要**:W2 你要在这套工具链上跑你人生第一个 baseline(Oriented R-CNN on DOTA)。今晚先把房子盖好、用 demo 验房。

**② 手把手带做**(用 `mim` 装,能自动帮你匹配版本,**比手动 pip 省一半的坑**)
1. 确认你在 `rs` 环境里(`conda activate rs`)。
2. 装 openmim(MM 系列官方安装器):
   ```bash
   pip install -U openmim
   ```
3. **先去 MMRotate 的 GitHub README / 官方文档,看它当前版本"钦定"的 mmcv/mmdet 版本号**(这一步**必须做**,因为版本搭配会随时间变,我不能给你一个写死、半年后就过期的数字)。然后用 mim 按文档装,形如:
   ```bash
   mim install mmcv-full        # 或文档指定的 mmcv 版本
   mim install mmdet            # 文档指定版本
   # 再按 MMRotate 文档：git clone 它的仓库后 pip install -v -e .
   ```
4. 跑自带 demo(命令以 MMRotate 文档里的 `demo/image_demo.py` 为准),对一张 DOTA 样例图做推理,得到一张画了旋转框的输出图。

**③ 合格样例**:你得到一张 demo 输出图——原图上套着一圈**斜着的彩色框**,框住了飞机/车/船之类目标。看到这张图 = 工具链通了。把它连同上午、中午的截图一起,写进《环境搭建 SOP》(≥800 字,见下)。

**④ 常踩的坑**
- **直接 `pip install mmcv` 最新版**:极可能和你的 torch/cuda 不匹配,编译报错或运行时崩。**务必用 mim + 文档指定版本**。
- **MMRotate 版本与 mmcv/mmdet 错配**:MMRotate 0.x 系 ↔ mmcv 1.x + mmdet 2.x;MMRotate 1.x 系 ↔ mmcv 2.x + mmengine。**三者必须同代**,跨代必崩。这是今晚 80% 报错的根源。
- **把 SOP 写成流水账**:SOP 不是"我装了 A 又装了 B",而是"**遇到 X 报错 → 用 Y 解决**"的可复用手册——下次重装/换机直接照着来。

**⑤ 卡住自救(决策树)**
- mmcv 编译/导入报错 → ① 先确认 torch 版本 + cuda 版本(`python -c "import torch;print(torch.__version__, torch.version.cuda)"`);② 拿这两个数字去 mmcv 官方"版本对应表"找匹配的预编译包,用 mim 指定版本装,**避免现场编译**。
- demo 报 `KeyError`/找不到 config 或权重 → 多半是路径/版本不对,去对应 GitHub 的 **Issues 页搜你的报错原文**(90% 的坑别人踩过且有答案)。

**⑥ 今天(这一步)你同时学会了什么**:你第一次走完了**"装一套有版本依赖的复杂框架 + 用 demo 验证 + 写成 SOP"**的完整流程,而且学会了排查版本冲突的核心套路(查 torch/cuda 版本 → 对照官方表 → mim 指定版本 → 翻 Issues)。这套"装框架 + 排冲突"的能力,你后面复现每一份代码都要用。**做了**(MMRotate 通 + demo 图 + SOP)、**学了**(MM 全家桶依赖关系、版本同代原则)、**会了**(版本冲突的排查决策树)。

## 上午段 · 精读第 1–3 遍(只走前三遍,别贪)

**① 先垫概念(30 秒,必须先懂)**
- **综述(survey)**= 把一个领域已有工作梳理打包的文章。**第一篇就读它**,是因为你现在两眼一抹黑,需要先拿到这个领域的"地图",而不是一头扎进某个具体方法。
- **精读"5 遍法"**(你计划的核心读法,今天先用前 3 遍):
  - 第 1 遍(5min):**只看**标题 + 摘要 + 所有图表。目的:30 秒知道"这篇在干嘛"。
  - 第 2 遍(20min):读 Introduction + Conclusion。目的:知道"为什么做、最后结论是什么"。
  - 第 3 遍(30min):读 Method/核心章节。目的:知道"具体怎么做的"。
  - (第 4、5 遍读 Experiment / Related Work,明天 D3 再走。)
  - **不是每篇都读 5 遍**:综述 5 遍、方法论文 3 遍、应用/数据集论文 2 遍。
- 你会反复撞见两个词,现在记个大概即可:**backbone**(主干网络,负责从图像里"提特征"的那部分)、**task**(任务,如分类/检测/分割)。

**② 手把手带做**
- **第 1 遍(5min)**:打开 PDF,**只看**标题、摘要、和**所有图**。盯住它的 **Figure 1**(画的是"遥感数据有哪些类型")——你能从图里看出遥感数据被分成哪几大类吗?把看到的写进笔记第 1 段。读完摘要,用**一句话**回答:"这篇综述在讲什么?覆盖了哪些任务?"写不出就再看一遍摘要。
- **第 2 遍(20min)**:读 Section 1 Introduction + Section 6 Conclusion。边读边在笔记第 1 段补全:作者认为遥感深度学习**为什么重要、难在哪**。

## 上午段 · 精读 DOTA 论文(重点:标注格式 + 任务定义 + 评测协议)
**① 概念**:
- **数据集/基准论文**:它的价值是定义"**任务规则**"——数据怎么来、怎么标、用什么指标评分。所有在这个数据集上做的方法论文都得遵守它的规则,所以**吃透规则 = 拿到这个赛道的"通用语言"**。
- **旋转框(oriented/rotated bbox)**:通用 CV 用"水平框"(4 个数:左上+右下);遥感目标斜着放,水平框框不准,于是用**旋转框**。DOTA 用 **8 点表示**(4 个角点的 x,y,共 8 个数)。
- **mAP**:目标检测的总分,所有类别 AP(平均精度)的平均。现在记住"**mAP 越高检测越好**"即可,D11 评估时细讲。

## 晚上段 · 从零写 `vis_dota.py`(读标注 → 解析旋转框 → 画框 → 存图)
**① 先垫概念**:
- **为什么自己写而不用现成工具**:手写脚本会**逼你理解数据格式的每个细节**(坐标系、标注编码、图像通道)——这是你后续所有实验的基础。
- 你会用到的 3 个轮子:**OpenCV(`cv2`)** 读图/画图、**NumPy** 处理坐标数组、Python 文件读写。一个旋转框在代码里就是 **4 个角点 = 一个 (4,2) 的数组**;画它用 `cv2.polylines`(把 4 个点连成闭合多边形)。
**② 手把手带做**(照着这个结构写,变量名可改):
1. 先装轮子(在 `rs` 环境):`pip install opencv-python numpy`。
2. 在 `20-代码实验/utils/vis_dota.py` 里,按这个骨架写(**我给结构和关键行,你来补全、跑通**):
   ```python
   import cv2
   import numpy as np
   import os

   def load_dota_ann(txt_path):
       """读一张图的 DOTA 标注，返回 [(poly(4x2), cls), ...]"""
       objs = []
       with open(txt_path, "r", encoding="utf-8") as f:
           for line in f:
               parts = line.strip().split()
               if len(parts) < 9:          # 跳过表头/空行
                   continue
               coords = list(map(float, parts[:8]))   # 8 个坐标
               cls = parts[8]                          # 类别名
               poly = np.array(coords, dtype=np.int32).reshape(4, 2)
               objs.append((poly, cls))
       return objs

   def draw(img_path, txt_path, out_path):
       img = cv2.imread(img_path)
       for poly, cls in load_dota_ann(txt_path):
           cv2.polylines(img, [poly], isClosed=True, color=(0, 255, 0), thickness=2)
           cv2.putText(img, cls, tuple(poly[0]),
                       cv2.FONT_HERSHEY_SIMPLEX, 0.6, (0, 0, 255), 1)
       cv2.imwrite(out_path, img)
       print("saved:", out_path)

   if __name__ == "__main__":
       draw("样例图.png", "样例标注.txt", "vis_out.png")
   ```
3. 拿 DOTA 里**一张真实图 + 它的标注**跑一次,打开 `vis_out.png` 看框对不对。

**③ 合格样例**:`vis_out.png` 上,**绿色旋转框准确套住了图里的飞机/车/船**,左上角有红色类别名。框的角度、位置和图里目标吻合 = 你解析对了。
**④ 常踩的坑**:
- **坐标顺序/类型错**:8 个数要 `reshape(4,2)`,且画图前转 `int32`,否则 `polylines` 报错或框乱。
- **`cv2.imread` 返回 `None`**:99% 是**路径错**(中文路径/相对路径问题),先 `print(img.shape)` 验证读到了图。
- **框画歪了**:多半是把"中心+宽高+角度"格式和"8 点角点"格式搞混——DOTA 是 8 点角点,直接连点即可,**不要**自己再算角度。
**⑤ 卡住自救(决策树)**:
- 报 `None has no attribute shape` → 路径错,换绝对路径、确认文件名;
- 框对不上目标 → 打印前几行 `parts` 看解析出的数对不对;只画第 1 个框 debug;
- `cv2` 装不上 → 用 `pip install opencv-python-headless`(无 GUI 依赖那版)。
**⑥ 今天(这一步)你同时学会了什么**:你写出了**人生第一个能跑的遥感 CV 脚本**,并真正搞懂了"旋转框在数据里到底是什么、在代码里怎么表示和绘制"。这份"亲手解析+可视化数据"的能力,是你后面看模型预测、做定性分析的基础。**做了**(`vis_dota.py` + 一张验证图)、**学了**(8 点旋转框的数据↔代码表示、OpenCV 画图)、**会了**(从数据格式文档→落地成可运行脚本,以及 `imread None`/路径这类基础 debug)。

> **技能卡｜CV 脚本起手三件套**:`cv2.imread` 读图(先 print shape 验证)→ NumPy reshape 处理坐标 → `cv2.polylines/putText` 画框标注 → `cv2.imwrite` 存图肉眼检查。

## 二、D6 完整可运行代码 — `vis_dota.py`（增强版：中文路径安全 + 预期输出）

> 上面 D6 给了骨架,这里给**可直接跑、且处理了两个新手必踩的坑**(中文路径读图返回 None、坐标越界)的完整版。把它存进 `20-代码实验/utils/vis_dota.py`:

```python
import cv2
import numpy as np
import os

def imread_safe(path):
    """中文/特殊路径安全读图：cv2.imread 遇中文路径会返回 None，用 imdecode 绕过。"""
    data = np.fromfile(path, dtype=np.uint8)      # 先按字节读（支持中文路径）
    img = cv2.imdecode(data, cv2.IMREAD_COLOR)    # 再解码成图像
    if img is None:
        raise FileNotFoundError(f"读不到图，请检查路径：{path}")
    return img

def imwrite_safe(path, img):
    """中文路径安全写图。"""
    ext = os.path.splitext(path)[1]               # 如 ".png"
    ok, buf = cv2.imencode(ext, img)
    if ok:
        buf.tofile(path)

def load_dota_ann(txt_path):
    """读一张图的 DOTA 标注，返回 [(poly(4x2), cls), ...]"""
    objs = []
    with open(txt_path, "r", encoding="utf-8") as f:
        for line in f:
            parts = line.strip().split()
            if len(parts) < 9:                    # 跳过表头(如 'imagesource:...')/空行
                continue
            try:
                coords = list(map(float, parts[:8]))
            except ValueError:                    # 第一行可能是元信息，转 float 失败就跳过
                continue
            cls = parts[8]
            poly = np.array(coords, dtype=np.int32).reshape(4, 2)
            objs.append((poly, cls))
    return objs

def draw(img_path, txt_path, out_path):
    img = imread_safe(img_path)
    objs = load_dota_ann(txt_path)
    for poly, cls in objs:
        cv2.polylines(img, [poly], isClosed=True, color=(0, 255, 0), thickness=2)
        cv2.putText(img, cls, tuple(poly[0]),
                    cv2.FONT_HERSHEY_SIMPLEX, 0.6, (0, 0, 255), 1)
    imwrite_safe(out_path, img)
    print(f"共解析 {len(objs)} 个目标，已保存：{out_path}")

if __name__ == "__main__":
    # 改成你 DOTA 里真实的一对 图/标注 路径
    draw("DOTA/train/images/P0000.png",
         "DOTA/train/labelTxt/P0000.txt",
         "vis_out.png")
```

**预期终端输出**(类似):
```
共解析 137 个目标，已保存：vis_out.png
```
**预期图像**:`vis_out.png` 上,飞机/车/船被**绿色斜框**准确套住,每个框左上角有**红色类别名**(plane/small-vehicle/ship…)。框的角度和目标朝向一致 = 你解析对了。
**自测**:把 `thickness=2` 改成 `4`、`color` 改成 `(255,0,0)`(蓝),重跑看框变粗变蓝——能改动并预测结果,说明你真看懂了这段代码。

## 四、本周报错速查表（环境/代码踩坑 → 一句话解法）

| 现象 | 根因 | 解法 |
|---|---|---|
| `torch.cuda.is_available()` = False | 装了 CPU 版 torch | 卸载重装,带 `--index-url .../cu121` |
| `nvidia-smi` 都看不到显卡 | 显卡驱动太旧/没装 | 装最新 NVIDIA 驱动(支持 CUDA 12.1) |
| `pip install torch` 极慢/超时 | 默认源在国外 | torch 用官方 cu121 源;其它包用清华镜像 `-i` |
| mmcv 导入/编译报错 | mmcv 与 torch/cuda 版本不匹配 | 查 torch+cuda 版本→对照 mmcv 官方表→mim 装预编译包,别现场编译 |
| MMRotate demo `KeyError`/找不到 config | MMRotate 与 mmcv/mmdet 跨代错配 | 三者必须同代(0.x↔mmcv1.x+mmdet2.x;1.x↔mmcv2.x+mmengine) |
| `cv2.imread` 返回 None | 路径错/含中文 | 用上面的 `imread_safe`(np.fromfile + imdecode) |
| `polylines` 报错/框乱 | 坐标没 reshape(4,2)/没转 int32 | `np.array(coords).reshape(4,2).astype(np.int32)` |
| 解析出的目标数=0 | 第一行元信息被当数据/编码问题 | 跳过非 9 字段行;文件用 UTF-8 打开 |
