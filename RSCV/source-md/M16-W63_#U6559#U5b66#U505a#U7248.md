### 范例 1 · 合作点选择三种方式 + 合作=未来署名要点

```
【合作点选择(三种方式,选一个具体可行双赢的)】
①你帮师兄跑一个对比实验   → 力所能及、易上手,师兄的工作需要某对比/baseline,你帮跑
②你的方法在他的数据上验证 → 你的方法 × 他的场景,验证你的方法的泛化/适用性
③共同设计一个新的改进方案 → 深度合作,你和师兄一起设计新方法/改进(最可能形成核心合作论文)
选择标准: 具体(做什么/谁做什么/产出什么) + 可行(2-3月能出结果) + 双赢(你贡献+团队需要)

【合作=未来论文署名要点】
★ 访问核心目的=和团队建立实质合作(不只自己出成果)
★ 合作=共同产出=未来论文署名: 一篇有空天院署名的合作论文=访问最实质的成果
· 合作中及时记录共同产出(谁做了什么),为后续署名讨论(谁一作/通讯)做准备
· 署名讨论时机: W64 论文加入空天院数据结果后,和老师/师兄讨论是否可挂空天院署名
```

### 范例 2 · 完整 benchmark 清单 + 核心实验深化要点

```
【完整 benchmark 清单(团队数据上,把第一份结果做扎实)】
□ baseline 对比(你的方法 vs 多个baseline,在团队数据上)
□ 消融(你的方法各部分逐个去掉/替换看贡献,★复用前几篇消融框架零成本)
□ 可视化(对比图/可视化样例/曲线,★诚实:正面+困难/失败案例)
□ 结果分析(为什么效果好/差+和baseline差异+团队数据上的特点)
□ ★单卡高效卖点(Params/FPS,如适用)
→ 完整benchmark=扎实、可写进论文(合作论文/第三篇)的一套结果。

【核心实验深化要点】
据第一份结果: 效果好→深化(更多setting/对比/消融/可视化向benchmark)
              效果差→据分析调整(调方法/参数再看,基础不牢不硬深化)+和师兄讨论
★按团队GPU分配规则用 + 实验管理记录所有配置
```

### 范例 3 · 30min 组会汇报 PPT 结构 + 收集反馈要点

```
【30min 组会汇报 PPT 结构(如老师安排,通常访问第2-3周)】
P1-2 背景+问题(你做的方向、要解决的问题)
P3-5 你的方法(核心思路+架构图,★嵌单卡高效定位)
P6-10 ★在空天院数据上的实验进展(数据/setting/baseline对比/消融/可视化)
P11-12 初步结果+分析(你的方法在团队数据上的表现和优势)
P13 合作+下一步(合作点+接下来计划)
P14 致谢+讨论(请全组提建议)
→ ★重点是"访问期间的工作"(你做了什么、结果如何),30min控时,复用W51/W62汇报经验。

【收集反馈要点】
★ 汇报目的之一=收集全组反馈: 准备好听取建议、★记录所有反馈(谁提了什么)
· 反馈分类: 必采纳(切中要害)/可参考/存疑→汇报后据反馈改进实验/论文
· 虚心: "感谢建议,我回去试试"而非辩解
```

## 二、完整可运行代码 · 合作 + benchmark 进展追踪器（+ 预期输出）

> 这个脚本追踪 W63 的两条核心线——合作点状态 + 完整 benchmark 各项 + 30min 汇报准备 + 博士维护，输出就绪度和"还差什么"，帮你看清访问深化期的合作和实验进展。

```python
#!/usr/bin/env python3
# collaboration_benchmark_tracker.py —— 合作+benchmark进展追踪器
collaboration = {  # 合作点(M16硬交付要≥1个具体合作点)
    "确定具体合作点": True, "合作启动": True, "合作出初步结果": True,
    "共同产出记录(为署名准备)": True,
}
benchmark = {  # 完整benchmark(团队数据上)
    "baseline对比": True, "消融": True, "可视化(含困难案例)": True,
    "结果分析": False, "单卡高效卖点(Params/FPS)": True,
}
report_30min = {"PPT框架": True, "突出访问工作+结果": True, "练习计时": False}  # 如老师安排
phd_daily_1h = [True]*7  # 每天博士维护1h

def rate(d):
    done = sum(1 for v in d.values() if v); return done, len(d), round(done/len(d)*100)

def track():
    print("=== W63 合作+benchmark进展 ===\n")
    for name, d in [("★合作点", collaboration), ("完整benchmark", benchmark),
                    ("30min汇报准备(如安排)", report_30min)]:
        done, tot, pct = rate(d)
        print(f"{name}: {done}/{tot} = {pct}%")
        for k, v in d.items():
            if not v:
                print(f"   □ 待办: {k}")
    phd = sum(1 for v in phd_daily_1h if v)
    print(f"\n★博士课题维护: {phd}/7 天 (每天1h)")
    print("\n" + "="*40)
    c_pct = rate(collaboration)[2]; b_pct = rate(benchmark)[2]
    if c_pct == 100 and b_pct >= 80 and phd == 7:
        print("🎉 合作点落实+benchmark接近完整+博士维护到位!")
        print("   W64: 完整benchmark + 论文加空天院结果 + ★讨论署名。")
    else:
        print(f"合作{c_pct}% / benchmark{b_pct}% / 博士{phd}/7")
        print("→ 补齐未完成项(尤其benchmark结果分析)。")

if __name__ == "__main__":
    track()
```

**预期输出**：
```

完整benchmark: 4/5 = 80%
   □ 待办: 结果分析
30min汇报准备(如安排): 2/3 = 67%
   □ 待办: 练习计时

★博士课题维护: 7/7 天 (每天1h)

========================================
🎉 合作点落实+benchmark接近完整+博士维护到位!
   W64: 完整benchmark + 论文加空天院结果 + ★讨论署名。
```
> 解读：把合作点、完整 benchmark、30min 汇报准备、博士维护的状态填进去，脚本算出进展并列出"还差什么"。示例里合作点已落实（M16 硬交付的"≥1 个具体合作点"达成）、benchmark 接近完整（差结果分析）、博士维护到位——W64 就该做完整 benchmark + 论文加空天院结果 + 讨论署名。它把访问深化期"合作 + 实验"两条核心线的进展变得一目了然。
