全书体检 · 详注版标准

这次是读出来的，不是扫出来的 —— 六类深度缺陷与「自足」的七条标准

先看第一节那个数字　312 万字、6 条可用链接。这一页从"资源与范例"角度体检；《全书审计报告》 从"概念解释长度"角度体检，两份互补。重写样板见 《W1-D1 详注版》。

这次是读出来的，不是扫出来的

先纠正我上一版的结论。 上一版我用程序扫出“316 处缺口、3 类模式”——那个结论是机械的。程序只能发现“格式上缺东西”（没有链接、没有代码块），发现不了“讲了，但没讲透”。而后者才是你真正的痛点。

这一版我改成读内容。下面是读出来的六类问题，每一类都附了原文实例。

一、最能说明问题的一个数字

312 万字，6 条可用链接。

摊开看：

项目 被点名次数 给了地址的次数
论文（26 篇不同的） 51 0
wandb 98 0
TensorBoard 24 2
tmux 13 0
Obsidian 6 0
Notion 5 0
Miniconda 1 0
Zotero / Git 3 0

这就是“必须去别处找”的根源，而且是唯一一个可以完全机械地修好的根源。 60 个精读时段、26 篇点名论文，一个链接都没有——你每次都得自己去搜标题、判断哪个是正版、还要处理付费墙。

二、读出来的六类深度缺陷

缺陷 1 · 概念给了比喻，但没给机制

原文（D1 中午段）：

Anaconda / conda：一个“环境管理器”。把它想成“给每个项目单独开一间无菌实验室”

比喻很好，但只到比喻为止。 结果是：你知道“要隔离”，但不知道环境物理上是什么（一个目录，里面有独立的 Python 解释器和 site-packages）。于是后面必然卡在这几个问题上，而全书没有一处回答：

  • conda install 和 pip install 该用哪个？
  • 为什么忘了 activate 装的包会“白装”？
  • 怎么确认我现在到底在哪个环境里？

详注版怎么做：比喻之后必须给机制——画出目录结构，说明 activate 实际改的是 PATH，然后给出“什么时候用 conda、什么时候用 pip”的判断规则。

缺陷 2 · 给了骨架，没给填满的范例

全书统计：提到“要写出的交付物”（≥800 字 SOP、复现报告、周复盘、论文笔记…）共 880 处；给出的 Markdown 模板 98 份。

问题不在数量，在于模板几乎都是空骨架。 比如 5 段式模板给了，但每段该写多长、写到什么颗粒度、什么算写够——全靠你猜。

详注版怎么做：每个空模板后面必须跟一份填满的真实范例，并附一张“每段该写多长、判断标准是什么”的表。我在 W1-D1 详注版 里用 Zhu 2017 做了这件事——你可以直接对比空模板和填满版的差距。

缺陷 3 · 论文只导航，不导读

原文（D2 上午段）：

盯住它的 Figure 1（画的是“遥感数据有哪些类型”）——你能从图里看出遥感数据被分成哪几大类吗？

导航是对的（告诉你看哪张图），但没有导读：Figure 1 上到底是什么？你看完怎么知道自己看对了？没有答案，你只能去搜别人的解读——这正是你说的“还要另外去找资料”。

详注版怎么做：每个精读时段必须有 ① 论文获取途径（DOI + 一个免费全文来源）② 这篇的核心图讲了什么（先说结论，让你能自检）③ 哪几节可以跳过 ④ 读完该能回答的 3 个问题。

缺陷 4 · 假设了转行者没有的前置技能

原文第一天就要你“打开终端”、写 .md、pip install。全书 312 万字，没有一处解释：

终端是什么、怎么打开、提示符怎么读 · 路径（绝对/相对/~/..）· Markdown 语法 · 什么是“包” · 环境变量 · git clone 到底做了什么

对科班的人这是常识，对转行的人这是墙。 而这套手册的定位恰恰是“把一个零基础的人真正带进门”。

详注版怎么做：在 W1-D1 前面加一段「前置」，用 40 分钟一次性拆掉这三道墙。已经做了，见详注版开头。

缺陷 5 · 决策只给结论，不给依据

原文：

Python 用 3.10，稳 ／ 改 batch_size 适配 4090 ／ 用 CUDA 12.1 的轮子

结论都对，但都是“死数字”：半年后 3.10 不再是最优选、你换一张显卡、你换一个框架——你不会判断。

详注版怎么做：给结论的同时给判断方法。比如 Python 版本的规则是“当前最新版往回数 2–3 个小版本”；PyTorch 版本的规则是“先 nvidia-smi 看驱动上限，再去官网选择器选“。方法不过期，数字会。

缺陷 6 · 验证做得浅，抓不出隐蔽故障

原文（D1 中午段）的验收是 torch.cuda.is_available() 返回 True。

这个检查会漏掉一种典型故障：能看见 GPU，但实际在用 CPU 算（装了某些混合版本时会发生），你要跑起来才发现慢得离谱。

详注版怎么做：验收要能抓出隐蔽故障。我在详注版里加了一个 30 秒的矩阵乘测试——4090 上 0.3–1 秒，超过 10 秒就是在用 CPU 装样子。

三、什么叫「自足」——详注版的七条标准

一个时段满足下面全部七条，才算写到“在这套资料里就能学会”：

# 标准 检验方法
1 概念给到机制层 比喻之后能回答“它物理上是什么”
2 每个术语首次出现就地解释 通读时没有一个词需要另开搜索
3 每个外部资源给完整获取途径 软件给官网、论文给 DOI + 一个免费全文、数据集给官网 + 目录结构
4 每条命令给期望输出 你能自己判断这一步成没成
5 每个交付物给填满的范例 不只给模板，还要给“合格长什么样”和“每段写多长”
6 每个决策给判断方法，不只给数字 换个场景你能自己重新决策
7 验收能抓出隐蔽故障 不是“跑通了”，而是“跑对了”

这七条就是我接下来重写全书的标准。 你可以拿它检查我交付的任何一页。

四、说清工作量，不含糊

原文 详注版
一个时段 约 1,500 字 约 4,000–5,000 字
W1-D1 上午+中午两段 约 3,000 字 约 13,000 字（已交付）
全书 2,142 个时段 312 万字 约 900 万–1,000 万字

900 万字不可能一次交付，也不该一次交付——因为你用不到那么快，而且前面重写的经验会改进后面的写法。

所以我按批次做，每批一个能独立使用的完整单元。 优先级按“你什么时候会用到”排：

批次 内容 为什么排这里
✅ 已交付 W1-D1 全天详注版 + MMRotate 实操 你现在就在这
✅ 已交付 W2 baseline 实操 下一堵墙
✅ 已交付 M0 名词讲透 + 学习资料地图 基础理论垫底
批次 1 W1 剩下的 D2–D7 详注版 含 Zhu 2017 完整导读（缺陷 3 的样板）
批次 2 W2 剩下的 D8/D10/D12–D14 详注版 含五篇方法论文的完整导读
批次 3 W3 全周（SAR baseline） 换数据集 + 格式转换，全书没教过
批次 4 W4–W8（M1 收尾 + M2 全部） 奠基期主体
批次 5+ 按你的实际进度往后推 你走到哪我写到哪

我建议按批次 1 继续，因为 W1-D2 的论文导读是缺陷 3 的第一个样板——把“论文该怎么被导读”这件事定型下来，后面 60 个精读时段就都有模子了。

五、一个附带的好处

补上那 6 条可用链接之外的东西时，我会顺手建一份全书资源总表：26 篇点名论文的 DOI 与免费全文入口、所有工具的官网、所有数据集的下载页。

那张表本身就能解决你“还要另外去找资料”的一大半问题，而且它是一次性的工作——做完全书通用。这个会放在批次 1 一起交。
