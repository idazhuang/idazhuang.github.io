「教-学-做」带教版（满深度·对齐 M3-W11 标杆）

这一周的定位：M10 的第一周，也是阶段二后半（产出期收官）的关键加速周。你的第二课题在 M8–M9 已经做完了全部实验（最终版方法 + 多数据集大表 + 消融 + 可视化都齐了），本周要做的是把这些结果写成第二篇论文的 Method 章和 Experiment 章，并在周末整合出第二篇论文 v0.5 草稿。 这一周真正的主题词是「写作质变」：第一篇论文你从开始写到 v1 用了整整 4 周（M6 的 W21–W24）；本周你要用 1 周写出第二篇的 v0.5。这不是因为第二篇更简单，而是因为你的写作能力已经质变了——句式模板、章节结构、图表规范、论文语言，第一篇都给你攒下了可复用的资产。本周你会亲身体会到：有了第一篇的经验，第二篇的写作速度应该是第一篇的 2 倍。 本周科研能力目标（你原计划，保留）：复用第一篇论文的写作经验，加速第二篇论文的产出；一周内完成 Method + Experiment + Intro + RW + Conclusion + Abstract，整合出 v0.5。 先给你打个预防针（关于「复用」的边界）：这周你会大量复用第一篇的模板——但复用的是「结构和句式骨架」，绝不是「内容」。比如 Method 的章节顺序（Overview → 组件 → 训练策略）、Experiment 的小节划分（数据集 → 主表 → 消融 → 可视化 → 讨论）、Intro 的四段结构——这些骨架照搬；但每一句的具体内容（你的方法是什么、在什么数据集上、提升了多少）必须是第二课题真实的、重新写的。模板复用 ≠ 内容抄袭，这条线本周要一直守住（自我抄袭 self-plagiarism 在学术界同样是问题）。 本周精力怎么分配：D253 写 Method（Overview + 组件 1 + 架构图 + 组件 2 + 训练策略，目标 Method 60%）；D254 收尾 Method + 伪代码，开写 Experiment（4.1 数据集/实现 + 4.2 主表）；D255 写 Experiment 后半（4.3 消融 + 4.4 可视化 + 4.5 讨论/Limitation）+ 整合 Experiment 全章；D256 写 Intro + RW + Conclusion + Abstract（论文的「壳」）；D257 整合全文 → v0.5 + 通读自审 + 修改；D258 英文润色 + 图表最终版 + 读 2 篇新论文；D259 周复盘 + 发朋友 review + 计划 W38。教学按「复用第一篇经验、体会写作质变」组织。 贯穿示例说明（与前序一致）：第一篇是「DOTA 旋转目标检测 + 高分辨率小目标分支」；第二课题是从第一篇 Limitation 延伸出的 SAR 域难题方向（speckle 乘性噪声 / 方位角敏感 / 跨域泛化这条发力线，对接王超组）。下文用「你的第二个方法（最终版）」「SAR 数据集」做具体讲解；换具体题目只替换数据集名/方法名/指标，写作流程完全一样。

上午段

写 Method 章的 Overview + 核心组件 1

1先垫概念（Method 章是什么 + 为什么先写 Overview）

  • Method 章（通常是论文第 3 章）是论文的「技术核心」——它要把你的方法讲清楚到「别人能复现」的程度。它回答的问题是：你的方法长什么样？由哪些部分组成？每部分为什么这么设计？怎么训练？
  • Method 章的标准结构（第一篇你已经写过一遍，这套骨架直接复用）：① Overview（方法总览——一段话 + 一张架构图，让读者先看到全貌）；② 核心组件逐个展开（你方法的每个创新模块，一个一个讲：是什么、怎么算、为什么这么设计）；③ 训练策略 / 损失函数（怎么训、用什么 loss）；④（可选）Algorithm 伪代码（把整个前向流程写成伪代码，明天写）。
  • 为什么先写 Overview（自顶向下 vs 自底向上）：写 Method 最容易犯的错是「一上来扎进某个组件的公式细节」，结果读者看了半天不知道这个组件在整个方法里的位置。正确顺序是先写 Overview——先给读者一张「地图」（方法整体是什么、输入输出是什么、有哪几个关键模块、它们怎么串起来），读者有了全局观，再看每个组件的细节才不会迷路。这和你给别人讲一个系统是一个道理：先讲架构，再讲模块。
  • ★ 第二篇的复利在哪（写作质变的来源）：第一篇写 Method 时，你是「第一次摸索怎么描述一个方法」——光是「Overview 该写多少、组件该怎么组织、公式该怎么排版」就花了大量时间反复改。第二篇你已经有了第一篇这套成熟的 Method 写法：Overview 写几句、每个组件分几段（动机 → 公式 → 直觉解释）、符号怎么定义、图怎么配——这些「写作模式」全都现成。所以你今天写 Overview，本质是「往第一篇的 Overline 模板里换内容」，会快很多。这就是为什么第二篇该比第一篇快一倍：不是方法简单，是你不用再摸索「论文该怎么写」了。
  • Overview 怎么写（一段话讲清四件事）：① 你的方法叫什么、解决什么任务（如「针对 SAR 图像旋转舰船检测中的 speckle 噪声敏感问题，我们提出 XXX」）；② 整体由哪几个关键模块组成（点名两个核心组件）；③ 这些模块怎么协同（数据从输入怎么流到输出）；④ 一句话点出和现有方法的关键不同（你的核心创新）。配一张架构图（中午画），文字和图相互印证。
  • 核心组件 1 怎么写（每个组件三段式：动机 → 方法 → 直觉）：写你的第一个核心组件——复用第一篇写组件的「三段式」：① 动机段（为什么需要这个组件——现有方法在这里有什么问题，如「SAR 的 speckle 是乘性噪声，普通卷积会被噪声主导」）；② 方法段（这个组件具体怎么算——给公式 + 符号定义 + 数据维度）；③ 直觉解释段（为什么这么设计能解决动机里的问题——用通俗的话讲清 insight，不只是堆公式）。第三段（直觉）最容易被新手省略，但它恰恰是审稿人最看重的——它证明你「懂自己方法为什么work」，不是瞎凑的。

和通用 CV 论文写作对比：通用 CV（如普通图像分类/检测）的 Method 写法你可能更熟——其实遥感/SAR 论文的 Method 结构和通用 CV 完全一样（Overview + 组件 + 训练），差别只在「内容」：你的动机段要讲清遥感/SAR 特有的难点（speckle、方位角、跨域），你的方法段要体现你针对这些难点的设计。所以会写通用 CV 的 Method，就会写遥感的 Method——把领域特有的难点和你的针对性设计填进去即可。 这也是你做这个方向的优势：通用 CV 的写作范式你已掌握，迁过来只换内容。

  2. 写 Method 的 3.1 Overview：一段话讲清「方法叫什么 + 解决什么任务 + 由哪两个核心组件组成 + 怎么协同 + 核心创新」。预留架构图位置（Figure 2: Overview of ...）。
  3. 写 3.2 核心组件 1（如「Speckle-aware 特征模块」）：按三段式——动机段（现有方法的问题）→ 方法段（公式 + 符号定义 + 维度）→ 直觉段（为什么这么设计 work）。
  4. 给所有数学符号在首次出现时定义（如「令 ( F \in \mathbb{R}^{C \times H \times W} ) 为输入特征图……」）。

3合格样例

写好了 3.1 Overview（一段话 + 架构图占位）和 3.2 核心组件 1（动机/方法/直觉三段齐、公式有、符号都定义了）。判断标准：一个没看过你代码的同行，读完这两节能大致明白「你的方法整体长什么样、第一个组件是干嘛的、为什么这么设计」。

4常踩的坑

  • 一上来扎进组件细节、没写 Overview → 读者没有全局观会迷路，必须先写 Overview 给地图。
  • 只给公式、没有直觉解释段 → 审稿人会觉得「不知道为什么 work」，第三段（直觉）必须写。
  • 符号用了不定义（如直接写 (F) 不说它是什么）→ 所有符号首次出现必须定义，否则读者读不懂。
  • 直接抄第一篇的句子改几个词 → 这是自我抄袭，结构可复用、句子要重写。

5卡住自救（决策树）

  • 不知道 Overview 写多少？→ 看第一篇的 Overview 长度（通常半页一段 + 一张图），照那个体量。
  • 组件的「直觉段」不知道写什么？→ 问自己「如果用一句大白话向师弟解释这个模块为什么有用，我会怎么说」，把那句话展开。
  • 公式怎么排版？→ 复用第一篇的公式格式（编号、对齐），别重新折腾。
  • 不确定先写哪个组件？→ 先写最核心/最能体现创新的那个（通常是针对你这篇主打难点的模块）。

你学会用「Overview + 组件三段式」的标准结构写 Method 章。做了（写 3.1 Overview + 3.2 组件 1）、学了（Method 标准结构、自顶向下先写 Overview、组件三段式中「直觉段」最关键、符号必须定义、第二篇复利来自复用第一篇写作模式）、会了（把一个做好的方法准确清楚地描述成 Method 章）。

技能卡｜第二篇的写作复利（为什么该快一倍）：第一篇写到 v1 用 4 周（W21–W24），第二篇目标 1 周写到 v0.5——快的不是方法简单，是你不用再摸索「论文怎么写」。可复用资产：① 章节框架（Method/Exp 的小节顺序）；② 句式骨架（组件三段式、Intro 四段式）；③ 图表规范（架构图风格、表格样式、公式排版）；④ 论文语言（学术英语句式）。复用结构和句式，重写全部内容（自我抄袭同样违规）。一周写完 v0.5 = 你的写作能力已质变。

中午段

画架构图（复用第一篇绘图工具和风格，保持系列感）

1先垫概念（架构图的作用 + 为什么要「保持系列感」）

  • 架构图（通常是论文 Figure 2）是 Method 章的「门面」——审稿人和读者第一眼看的就是它。一张好的架构图能让人 30 秒看懂你方法的整体流程；一张乱的架构图会让人还没读文字就先困惑。
  • 架构图要画清楚的三件事：① 数据流（输入图 → 各模块 → 输出），用箭头串起来；② 你的核心组件（用醒目的颜色/框标出，让人一眼看到「创新在哪」）；③ 关键的维度/操作（如特征图尺寸、关键算子），标在图上辅助理解。
  • ★ 为什么要「复用第一篇的绘图工具和风格，保持系列感」：这是一个容易被忽略但很有价值的细节。① 效率：第一篇你已经摸索好了用什么工具画（如 draw.io / PowerPoint / TikZ）、用什么配色、模块框怎么画——第二篇直接复用这套，几小时就能画好，不用从零折腾工具；② 系列感（个人品牌）：如果你两篇论文的架构图风格统一（同样的配色逻辑、同样的模块表示法、同样的排版气质），它们看起来就像「同一个研究者的系列工作」，专业、成体系。当空天院老师或同行看到你两篇风格一致的论文时，会形成「这个人有自己成熟的研究和表达体系」的印象——这种一致性本身就是一种隐性的专业信号。反之，如果两篇图风格迥异（一篇很精致一篇很潦草），会显得不够成熟。
  • 从这件事看「表达的一致性」对长期的价值：你未来会有第三篇、第四篇，会有 GitHub 仓库、会有作品集 PDF、会有给老师汇报的 PPT——如果它们的视觉风格是统一的（同一套配色、同一种图表气质、同一种排版逻辑），你整个「作品集」就有了辨识度和专业度。这就像一个设计师的作品集有统一的视觉语言。对你这个要「用强作品说话、给空天院留下专业印象」的人，从第二篇开始有意识地维护「视觉系列感」，是在低成本地积累个人品牌资产。今天复用第一篇的绘图风格，就是这件事的起点。

晚上段

写核心组件 2 + 训练策略

1先垫概念（组件 2 + 训练策略怎么写）

  • 核心组件 2：写你方法的第二个核心模块——还是用三段式（动机 → 方法 → 直觉），和上午写组件 1 一模一样的结构。如果两个组件有协同关系（如组件 2 用了组件 1 的输出），在方法段里说清它们怎么衔接。
  • 训练策略 / 损失函数（Method 的 3.4 节）：讲你怎么训练这个方法——① 损失函数（用了什么 loss，如分类 loss + 回归 loss + 你可能加的针对性 loss，给公式）；② 训练细节里属于「方法」的部分（如有特殊的训练流程、两阶段训练、特殊的数据处理策略——注意：纯粹的超参如 lr/batch size 不放这里，放 Experiment 的「实现细节」）。

  • 你的单卡 4090 卖点在哪体现：你的「单张 4090 高效训练」是论文卖点（效率），但它主要在 Experiment 的实现细节和效率对比里体现（如「所有实验在单张 RTX 4090 完成，参数量 X M，FPS Y」），Method 里如果有「为了单卡可训而做的高效设计」（如轻量模块），可以在组件的动机/直觉里点一句。这条「单卡高效」主线第二篇要继续打（和第一篇一致，是你区别于堆算力工作的差异化卖点）。

一、合格范例 — Method/Experiment/Intro/Abstract 写作范例（照着改）

说明：以下范例以「SAR 旋转舰船检测 + speckle-aware 模块」为具体例子演示写法和句式骨架（你换具体题目时，结构照搬、内容全换成你第二课题真实的）。复用结构，重写内容——别直接抄。

【范例 1：Method Overview 段（3.1）】

Given a SAR image, our goal is to detect arbitrarily-oriented ships robustly under speckle noise. We propose XXX, which consists of two key components: (i) a speckle-aware feature module that suppresses multiplicative noise while preserving target structures, and (ii) an orientation-robust detection head that handles the azimuth sensitivity of SAR targets. Given an input image, multi-scale features are first extracted by the backbone, then refined by component (i) to obtain noise-robust representations, and finally decoded by component (ii) into oriented bounding boxes. In contrast to prior methods that directly adapt optical detectors and ignore SAR-specific physics, XXX explicitly models the speckle and orientation characteristics. An overview is shown in Figure 2.

【范例 2：核心组件「三段式」（动机→方法→直觉）】

（动机） SAR images are corrupted by multiplicative speckle noise, which conventional convolutions—designed for additive-noise natural images—handle poorly, as the noise can dominate weak target signals. （方法） To address this, we design the speckle-aware module. Let (F \in \mathbb{R}^{C \times H \times W}) denote the input feature. We first estimate a noise-attentive map (M = \sigma(\text{Conv}(F))), then modulate the feature as (F' = F \odot (1 + M)), where (\odot) is element-wise multiplication and (\sigma) is the sigmoid function. ... （直觉） Intuitively, the module learns to amplify reliable target responses and suppress noise-dominated regions, so that downstream detection focuses on genuine target structures rather than speckle artifacts. This directly tackles the motivation above.

【范例 3：4.2 主表分析文字（有 insight，不是念数字）】

平庸写法（念数字，别这样）：Our method achieves 78.5 mAP on SSDD and 71.2 on HRSID... 合格写法（有 insight）：As shown in Table 2, XXX consistently outperforms all baselines across the three SAR datasets, surpassing the strongest competitor by +1.8 mAP on average. Notably, the improvement is larger on datasets with stronger speckle noise (e.g., +2.6 on Dataset-B), which corroborates our motivation that explicitly modeling speckle is crucial for SAR detection. Moreover, XXX attains this accuracy with fewer parameters and higher FPS, using only a single RTX 4090, demonstrating its efficiency.

【范例 4：Introduction 四段结构骨架】

（段1 背景） SAR ship detection plays a vital role in maritime surveillance, working day-and-night and through clouds... （段2 Gap） However, most existing methods directly adapt detectors designed for optical images, overlooking two SAR-specific challenges: the multiplicative speckle noise and the azimuth sensitivity of targets, which leads to degraded accuracy under strong noise... （段3 方法） To bridge this gap, we propose XXX, which explicitly models speckle and orientation via two dedicated components... （段4 贡献） • We propose a speckle-aware module that suppresses multiplicative noise while preserving target structures. • We design an orientation-robust head tailored to SAR azimuth sensitivity. • XXX achieves state-of-the-art results on three SAR benchmarks using only a single RTX 4090, demonstrating both effectiveness and efficiency.

【范例 5：Abstract 骨架（四件事，150–250 词）】

（问题） SAR ship detection is crucial yet challenging due to speckle noise and azimuth sensitivity. （方法） We propose XXX, comprising a speckle-aware feature module and an orientation-robust detection head that explicitly model SAR-specific physics. （结果） Extensive experiments on three SAR benchmarks show that XXX surpasses the strongest baseline by +1.8 mAP on average, with the gains being most pronounced under heavy speckle. （亮点） Remarkably, all experiments are conducted on a single consumer-grade RTX 4090, highlighting the method's efficiency and accessibility.

【范例 6：Limitation 段（诚实 + 带未来方向）】

While XXX achieves strong results, it has limitations. First, the gains diminish on extremely low-resolution targets, where speckle and signal are hard to separate; a physically-grounded denoising prior may help in future work. Second, although efficient, processing very large SAR scenes still requires tiling; an end-to-end large-scene design is left for future exploration. （注：每条局限带一句未来方向——既显远见，又为你第三篇埋伏笔。）
