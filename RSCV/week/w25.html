周一 · 数字审计（论文数字 vs 实验日志逐一交叉验证）

0/3

投稿前最关键的一道关：把论文里每一个数字，和实验日志/代码跑出来的逐一核对——数字对不上会被直接 reject。

预期管理:M7 投稿月开始，本周做投稿前最后打磨。今天做“数字审计”（论文↔实验日志↔代码三处数字逐一交叉验证）。提醒：数字不一致是会被直接 reject 的致命硬伤——你 W19 删过组件、改过方法，数字变过好几轮，极易出现“正文写旧数字、表格是新数字”；不只核对表格，正文里散落的“我们提升了X%”这种数字也要核；数字太多手核易漏，写个小脚本从日志/LaTeX源码自动比对。

上午段

建立“数字清单”：列出论文里所有数字及其来源

1先垫概念（为什么数字审计是投稿前的头等大事）

  • 数字错误是论文的致命伤：如果审稿人（或读者复现时）发现你论文里写的数字，和你代码/checkpoint 实际跑出来的不一致，论文很可能被直接 reject——因为这动摇了审稿人对你全部结果的信任（一个数字假，其他的是不是也假?）。这不是“小错误”，是关乎可信度的硬伤。
  • 为什么你的论文特别容易有数字不一致：回想你这一路——M5 你删过无效组件、改过方法（数字变了）、补跑过最终方法（数字又变了）;M6 你据 mock review 补过对比、改过实验（数字再变）。经过这么多轮迭代，论文里极易残留“旧数字”：比如 Abstract 里写的提升幅度是早期版本的、某个表格更新了但正文引用它的地方没改、Intro 贡献列表的数字和 Experiment 表对不上。这些“历史遗留的旧数字”就是定时炸弹。
  • 数字审计 = 给论文的所有数字做一次“全面体检”：逐个表格、逐个正文引用，核对每个数字是否等于最终实验/代码跑出来的真实值。目标：论文里 100% 的数字都能在实验日志里找到对应来源，且正文数字 = 表格数字 = 日志数字，三处完全一致。
  • 和“实验可复现”的关系：你 W19 归档了实验日志（config/seed/命令/结果）——那是数字的“唯一可信来源”。数字审计就是拿论文里的每个数字，回到实验日志去核对。实验日志是“事实”，论文里的数字必须忠实于这个事实。
  • 数字审计也是对你诚信的保护：有时数字不一致不是造假，只是迭代中的疏忽（忘了同步旧数字）。但审稿人无法区分“疏忽”和“造假”——他看到的就是“数字对不上”，后果一样严重（质疑你全部结果）。所以数字审计不只是“改错”，更是保护你的学术诚信不被误解：确保你呈现的每个数字都经得起核对，审稿人复现时能对上，你的工作才可信、可立得住。这对一个要走学术路的人是底线。

2手把手带做

  1. 通读论文，把所有出现的数字列成一张清单（Abstract、Intro 贡献、Experiment 各表、正文里的“提升 X%”、Conclusion 的数字……一个不漏）。
  2. 给每个数字标注它应该来自哪个实验（哪个 config/哪张日志表）。
  3. 先建清单、不急着改——穷举所有数字及其来源，下一步再逐一核对。

一张“数字清单”——论文里每个数字 + 它的来源实验 + 出现位置（Abstract/表X/正文某段），为下一步逐一核对做准备。

中午段

逐一交叉验证：论文数字 ↔ 实验日志

1先垫概念

有了数字清单，现在逐一核对——把清单里的每个数字，和实验日志/wandb 里的真实值比对。一致就打勾，不一致就标红待改。核心是“以最终实验为准”：论文里的数字必须等于最终代码/最终实验跑出来的值，不是凭印象写的、不是早期版本的。

  • 为什么要“自动提取 + 交叉比对”：手动核对几十个数字容易看花眼、漏掉。最可靠的做法是写个小脚本，从实验日志/wandb 自动提取最终数字，和论文表格（从 LaTeX 源码提取）做交叉比对，机器帮你找出不一致。这比纯人眼核对准得多。
  • “三处一致”的含义：同一个指标，可能在论文里出现在三个地方——Abstract、正文引用、Experiment 表格。这三处的数字必须完全相同（且都等于日志里的真值）。任何一处和其他不同，都是不一致，要改。

2手把手带做

  1. 从实验日志/wandb 提取所有最终指标的真值（主实验、消融、迁移等）。
  2. 和数字清单逐一比对：论文里的每个数字 = 日志真值？
  3. 标出所有不一致处（待 D169 晚上修正）。

3合格样例

数字清单逐项核对完毕，每个数字标注“✓一致”或“✗不一致（论文写X、日志是Y）”。

4常踩的坑

核对时只看小数点前、忽略精度（78.5 vs 78.46 取舍不一致）→ 统一精度规则（如都保留一位小数），全文一致；日志里有多次运行的值，不知用哪个 → 用最终方法的 3-seed 平均值（W19 锁定的）。

5卡住自救

日志找不到某数字的来源?→ 说明这个数字可能是早期的/凭印象写的，要么重新跑确认、要么删掉这个声称；wandb 记录太多找不到?→ 按 run 名/tag 过滤到最终实验。

6今天（这一步）你同时学会了什么

你学会把论文数字和实验日志逐一交叉验证。做了（逐项核对 + 标出不一致）、学了（以最终实验为准、三处一致、自动提取更可靠）、会了（系统核验数字的真实性）。

晚上段

修正所有不一致 + 锁定数字

1先垫概念

把上午、中午标出的所有不一致逐一修正——统一改成最终实验的真值。改完再快速复核一遍，确保论文里的数字现在 100% 准确、三处一致。这一步完成后，“数字对不上”这个会被直接 reject 的风险就彻底堵死了。

  • 修正原则：永远以最终代码/最终实验为准，把论文里的旧数字/错数字统一改成真值。一处都不能放过（尤其正文散落的）。
  • 改完要复核：修正过程中可能改漏、或改一处引入新的不一致（如改了表格但正文又忘了同步）。改完后再过一遍数字清单，确认全部一致。

集中清理所有历史 review 的残余问题

1先垫概念（投稿前要“还清所有欠账”）

  • 你这一路收过很多反馈：M6 的自审报告、两轮 mock review、第二轮快审——这些反馈里，有些问题当时改了，但可能有些标记为“以后改”的残余问题还没处理。投稿前，要把这些历史欠账一次性清零。

晚上段

竞赛改进：换更强 backbone(ConvNeXt-XL / InternImage)

1先垫概念

竞赛冲刺阶段，换更强的 backbone（如 ConvNeXt-XL、InternImage）是常见的提分招——更强的特征提取器往往直接带来精度提升。但更大的 backbone 在你单张 4090(24GB)上容易 OOM，要用省显存技巧应对。

  • 为什么换强 backbone 能提分:backbone 是模型的“特征提取主干”，更强的 backbone（更大、预训练更好）能提取更有判别力的特征，下游任务精度往往更高。竞赛冲刺时，换上当前最强的 backbone 是性价比不错的一招（虽然慢，但竞赛只看分数）。
  • 4090 的显存约束（你的现实）:ConvNeXt-XL、InternImage 这类大 backbone 显存占用大，你单卡 24GB 可能 OOM。应对：降 batch size + 梯度累积（保持等效 batch）、混合精度训练(amp)、必要时降输入分辨率。这些是你一路练熟的单卡省显存技巧，继续用。注意：这里换大 backbone 是为竞赛冲分；你论文的主结果仍用高效的小模型（单卡高效是你论文的卖点），大 backbone 的结果归竞赛/附加，别混淆两条线的定位。

2手把手带做

  1. 竞赛模型换更强 backbone（ConvNeXt-XL 或 InternImage）。
  2. OOM 就降 batch + 梯度累积 + 混合精度。
  3. 训练、提交，记入 Trick 日志（Δ分/是否保留）。

3合格样例

竞赛新 backbone 版训练完成、提交，排名变化记录在 Trick 日志。

4常踩的坑

大 backbone OOM 直接放弃 → 降 batch + 梯度累积 + 混合精度先跑起来；一次换 backbone 又改别的 → 一次只改这一处，看清 backbone 的效果。

5卡住自救

上午段

准备 5 个差异化模型 + 理解 WBF

1先垫概念（差异化 Ensemble + WBF）

  • 5 模型 Ensemble 是竞赛冲刺的“核心大招”：用 5 个不同 backbone 的模型（如 ResNet-50、ResNet-101、Swin-T、Swin-B、ConvNeXt-B）各自预测，再融合——通常比单模型大幅提升，是竞赛榜上 top 方案的标配。
  • 为什么“差异化”是关键:Ensemble 的收益来自模型的互补性——不同模型犯不同的错，融合时相互纠正。模型差异越大（backbone 结构越不同），互补性越强，Ensemble 收益越大。如果 5 个模型都是 ResNet 系（结构相似），它们犯的错也相似，融合收益就小。所以要用结构差异大的 backbone（ResNet 系 + Swin 系 + ConvNeXt 系混搭）。
  • WBF(Weighted Box Fusion)是什么：对检测任务，多个模型的预测是一堆框（位置、数量都不同），不能简单平均。WBF 是专门融合多个模型检测框的算法——它把多个模型预测的、重叠的框，按置信度加权融合成一个更准的框（而非简单取一个或平均坐标）。检测任务的 Ensemble 必须用 WBF（或类似的框融合），简单合并框效果差。
  • WBF 的关键参数:IoU threshold（判断两个框是否算“同一个目标”的重叠阈值）、skip threshold（置信度低于此的框丢弃）——这两个阈值要调，调好了融合效果才最佳。
  • WBF 为什么比 NMS 式合并更好（原理直觉）：传统融合多个框可能用 NMS（非极大值抑制）——保留置信度最高的框、抑制重叠的其他框，本质是“二选一”。WBF 不是丢弃，而是“加权融合”：把多个模型预测的、指向同一目标的重叠框，按各自置信度加权平均出一个更准的框（位置综合了多个模型的判断）。这样既利用了所有模型的信息（而非只取一个），融合出的框往往比任何单个模型的框更准。这就是为什么检测 Ensemble 用 WBF 效果好——它真正“融合”了多模型的定位，而非简单取舍。
