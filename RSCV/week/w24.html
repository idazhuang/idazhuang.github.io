周一 · 读者体验通读 → v1.5

0/3

预期管理：今天换一个全新视角通读论文——不抠语法，只问“一个第一次读的人能不能顺畅看懂”。提醒：你太熟内容会不自觉脑补，读不出卡点；放慢、假装不懂，或隔一晚再读。今天产出 v1.5（读者体验更顺的版本）。

上午段

最终版通读（只关注“读者体验”）

1先垫概念（读者体验通读是什么、为什么这轮重要）

  • 这次通读换个视角——“一个第一次读这篇论文的人能否流畅理解？” 不抠语法，只看“读着顺不顺、懂不懂”。
  • 为什么到投稿前还要专门做这一轮：前几周你反复改的是“内容对不对、逻辑严不严”；但审稿人是第一次读你的论文，他的“读者体验”直接影响评审印象——一篇内容好但读着处处卡顿的论文，审稿人会读得烦躁、容易给低分。投稿前最后一轮，要从“作者视角”（内容对）切到“读者视角”（读着顺）。
  • 和你 W15 学的自审一脉相承，但更进一步:W15 是查“逻辑断点”；这轮是查“阅读流畅度”——哪怕逻辑没断，如果某段读起来费劲、某个图看不懂、某个术语突然冒出来，都是要修的“读者体验”问题。

2手把手带做

从头以“陌生读者”身份通读全文（可隔一晚让自己生疏些），边读边体会哪里卡顿/困惑，先不改、只标记。

3这一步合格的样子

一次完整的“读者视角”通读，标记出所有让你（假装第一次读）卡顿的地方。

4最常踩的坑

① 太熟会脑补（读到不清楚处自动补上脑内信息）→ 放慢、强迫自己只读纸面写的;② 边读边改（陷入细节，丢了整体流畅感）→ 这轮只通读标记，改放到晚上;③ 只读自己擅长/喜欢的章节（如跳过 Related Work）→ 审稿人会通读全文，每一章都要以读者视角过一遍。

5卡住怎么自救（决策树）

读不出问题（太熟）? → 隔一晚再读，或用 TTS 朗读（听出拗口处）；不确定算不算卡点? → 凡是“需要回头重读一遍才懂”的地方都算；时间紧? → 至少完整读一遍 Intro+Method（审稿人最先细看的）。

6今天（这一步）你同时学会了什么

你学会以读者视角审全文。做了（读者视角通读）、学了（读者体验、从作者视角切到读者视角、投稿前这轮的价值）、会了（站在读者角度看论文）。

技能卡｜读者视角通读：投稿前最后一轮通读，从“作者视角（内容对不对）”切到“读者视角（读着顺不顺）”。审稿人第一次读你的论文，阅读流畅度直接影响评审印象。只通读标记不改（改放后面）；太熟读不出就隔夜再读或 TTS 朗读。凡“需回头重读才懂”处都是卡点。

中午段

标“可能让读者困惑”处

1先垫概念

把上午通读时的感受落成一张具体的“困惑点清单”——术语没解释就用了、某步跳过了推导、某个图表难懂、某段逻辑跳跃。清单化的好处：把模糊的“读着不顺”变成一条条可执行的修改项，晚上逐条消除，不遗漏。困惑点通常集中在几类:① 术语/符号首次出现没定义;② 从 A 到 B 缺过渡（读者跟不上）;③ 图表本身不清楚或正文没讲怎么读;④ 贡献/方法的“为什么”没说清。

2手把手带做

把所有可能让读者困惑/卡顿的地方列成清单（标注在第几页第几段、什么问题、怎么改）。

3合格样例

困惑点清单（每条：位置+问题+修改方向）。

4坑

① 清单太笼统（"Method 不清楚"）→ 具体到"3.2 节公式 2 的符号 σ 没定义";② 只标问题不想改法 → 顺手记"怎么改"，晚上直接动手。

5自救

困惑点太多无从下手 → 按“影响理解程度”排序，优先改让人看不懂的（逻辑断、术语没定义）而非小瑕疵（个别措辞）；拿不准某处算不算问题 → 标上，晚上判断；清单里有些自己也不知怎么改 → 标“待想”，可问导师/同行或参考类似论文怎么处理；同一类问题反复出现（如多处术语没定义）→ 建一个术语表统一定义，一次性解决一类。

6今天（这一步）你同时学会了什么

你定位了读者卡点。做了（困惑点清单）、学了（把“读着不顺”清单化、困惑点的常见类型）、会了（识别并记录读者困惑处）。

晚上段

逐一修改 → v1.5

1先垫概念

按困惑点清单逐条消除（补解释/加过渡/改图/讲清“为什么”）→ 论文 v1.5。修改的优先级：先改“影响理解”的（术语没定义、逻辑跳跃），再改“不够顺”的（措辞、过渡）。改完要再快读一遍确认：确保改动真的解决了卡点，且没引入新的不连贯。有一类卡点要特别注意——结构性的：如果改了半天某段还是读着费劲，问题可能不在措辞而在结构（顺序不对、该合并的拆开了、该分点的挤成一段）。这种情况下，调整段落顺序/拆分合并，比抠字句更有效。判断标准：措辞问题改一两句就顺了；结构问题改了字句还是别扭——后者要动结构。

2手把手带做

逐条消除困惑点（补解释/加过渡/改图）→ 论文 v1.5；改完快速通读一遍确认更顺了。

3合格样例

论文 v1.5（读者体验明显更顺，清单上的卡点已消除）。

4坑

① 改不完就焦虑 → 先改最影响理解的，小瑕疵可留;② 改了某处引入新的不连贯 → 改完再快读确认。

5自救

某个卡点不知怎么改 → 问“读者卡在这里是因为缺了什么信息”，补上那个信息；改完仍觉得不顺 → 可能是结构问题，考虑调整段落顺序。

6今天（这一步）你同时学会了什么

你迭代到 v1.5。做了(v1.5)、学了（据读者卡点改、改完再确认）、会了（优化论文可读性到投稿线）。

今日交付:✅ 困惑点清单 ✅ 论文 v1.5（读者体验更顺）。

周二 · supplementary material + 竞赛自定义增强

0/3

预期管理：今天准备 supplementary（把正文塞不下的细节/可视化/完整消融放进附录），并给竞赛加遥感特有增强。提醒：supplementary 是“加分空间”不是“凑数”——放审稿人可能想看的细节；竞赛的几何增强一定要让标注同步跟着转。

上午段

准备 supplementary（附录）

1先垫概念（为什么写 supplementary）

正文有页数限制（通常 8–10 页），但审稿人可能想看更多细节。Supplementary 是“加分空间”——放更多实验细节、更多可视化、超参搜索结果、完整消融表、证明细节。为什么值得认真做:① 正文受页数限制只能放最核心的，很多你辛苦做的实验（完整超参搜索、更多数据集的定性图）放不下，supplementary 给它们一个去处;② 审稿人想深究时，详尽的 supplementary 能打消他的疑虑（显得你工作扎实、经得起追问）;③ 它不占正文页数，纯加分。正文 vs 附录的取舍原则：正文放“支撑核心论点必需的”，附录放“有了更好、没有也不影响主线的”。

2手把手带做

整理 supplementary 内容：更多实验细节 + 更多可视化 + 超参搜索结果 + 完整消融表（你阶段一的实验日志/消融素材正好用）；列一个 supplementary 提纲。

3合格样例

supplementary 内容齐备 + 提纲（每节对应正文哪里“详见 supplementary X”）。

4坑

① 正文塞太满超页数 → 把次要细节移到 supplementary;② supplementary 放无关内容凑数 → 只放审稿人可能想看的;③ 素材散落 → 用你阶段一已归档的实验日志。

5自救

不知哪些进正文哪些进附录 → 问“删掉它正文主线还成立吗”，成立就移到附录；supplementary 太长 → 抓审稿人最可能追问的（完整消融、更多定性、超参扫描）；担心 supplementary 没人看白做 → 它的价值在“审稿人想深究时能打消疑虑”，哪怕只有一位审稿人看，也可能是你通过的关键；不确定某实验该不该放 → 凡是“支撑你结论但正文塞不下”的证据都值得放进附录。

6今天（这一步）你同时学会了什么

你学会用 supplementary 加分。做了（supplementary 内容+提纲）、学了（正文 vs 附录的取舍、附录是加分空间）、会了（把次要细节放进附录）。

技能卡｜supplementary 取舍：正文受页数限，supplementary 是不占页数的加分空间。取舍原则：正文放“支撑核心论点必需的”，附录放“有了更好、没有也不影响主线的”（完整消融/更多定性/超参扫描/失败案例）。审稿人想深究时，详尽附录打消疑虑。判断：删掉它正文主线还成立吗？成立就移附录。

中午段

把 supplementary 整理成独立 PDF

1先垫概念

把 supplementary 排成独立 PDF（图清晰、编号规范，用 S1/S2 或 A1/A2 区别于正文编号），与正文呼应（"详见 supplementary Fig. S3"）。为什么独立成册：多数期刊要求 supplementary 作为单独文件提交；独立 PDF 也方便审稿人对照。编号要和正文区分:supplementary 的图表用 S 前缀(Fig. S1、Table S1)，避免和正文 Fig. 1 混淆。supplementary 的定位要摆正：它是"想深入的审稿人/读者才看"的补充，所以正文必须能独立成立（不依赖 supplementary 才能看懂）;supplementary 是锦上添花，不是把正文该讲的藏进去。一个常见误区：为了正文显得简洁，把方法的关键细节塞进 supplementary——这会让审稿人读正文时一头雾水（关键信息要去附录找）。正确做法：正文自包含、能完整理解方法；supplementary 放"有兴趣可深究"的额外证据和细节。

2手把手带做

把 supplementary 排成独立 PDF（图清晰、S 前缀编号）；在正文相应处加“详见 supplementary X”的指引，同时确保正文不依赖附录也能看懂。

3合格样例

supplementary PDF 成形（独立、编号规范、与正文呼应）。

4坑

① supplementary 图表编号和正文混（都叫 Fig. 1）→ 用 S 前缀;② 正文没指向 supplementary → 在相应处加“详见 supplementary”。

5自救

不确定期刊对 supplementary 的格式要求 → 看 Author Guidelines（D164 会读）；图不清晰 → 导出高分辨率矢量图。

6今天（这一步）你同时学会了什么

你产出了附录 PDF。做了(supplementary PDF)、学了（附录独立成册、S 前缀编号、与正文呼应）、会了（制作规范的独立附录）。

晚上段

竞赛改进 7：自定义数据增强（针对遥感特性）

1先垫概念

针对遥感特性的增强常对遥感竞赛有效——随机旋转 0°/90°/180°/270°（遥感目标无固定朝向，90°倍数旋转不引入插值失真）+ 多尺度裁剪（遥感目标尺度差异大）。为什么这类增强对遥感特别有效：通用 CV 的增强（如随机小角度旋转、颜色抖动）未必契合遥感；而“90°倍数旋转”利用了遥感“目标朝向均匀分布”的先验，等于免费扩充了训练数据的朝向覆盖。这是用领域知识设计增强——你的遥感理解在这里变成竞赛分数。

2手把手带做

给竞赛加遥感特有增强（90°倍数旋转 + 多尺度裁剪，几何增强时标注同步转），重训提交。

3合格样例

遥感增强版提交，排名记录（对比加增强前）。

4坑

① 几何增强但标注没同步转 → 框/mask 跟着转（否则标注全错）;② 没提升 → 记录，换下个 Trick（增强对某些任务收益有限）;③ 增强过猛把图变得不真实（如极端尺度裁剪只剩局部）→ 增强幅度要在“仍像真实遥感图”的范围内，过度增强反而伤性能。

5自救

加增强后掉点 → 检查标注是否真同步转了（可视化几张确认框还在目标上）；提升不明显 → 90°旋转对已经旋转鲁棒的模型收益小，试多尺度裁剪。

6今天（这一步）你同时学会了什么

你用遥感特有增强提分。做了（自定义增强）、学了（用领域先验设计增强、几何增强标注同步）、会了（用领域知识设计增强）。

周三 · 选目标期刊 + 调模板

0/3

预期管理：今天为论文选定投稿出口、读懂目标期刊的格式要求、把论文套进它的模板。提醒：第一篇别冲顶会（CVPR/ICCV 单卡难支撑、周期长、拒率高），优先 GRSL/JSTARS 这类对遥感/增量工作友好、周期短的期刊——先发表建立信用。

上午段

选择投稿目标期刊/会议

1先垫概念（第一篇投哪里）

优先级 GRSL（快，2–3 月出结果）> JSTARS（中，3–4 月）> TGRS（慢但含金量高，4–6 月）> IGARSS workshop。对结果有信心→GRSL（周期短反馈快）；结果特别好→可冲 TGRS；不要第一篇就冲 CVPR/ICCV（先建信用）。为什么第一篇尤其要选对出口:① 你是单卡选手，工作偏“高效特化/增量改进”，这类工作在顶会（追求新颖性/SOTA 大幅刷新）容易被拒，但在遥感期刊（看重扎实、对领域有用）很受认可;② 第一篇的目标是“成功发表、建立信心和信用”，而非“一鸣惊人”;③ 周期短的期刊(GRSL)反馈快，即使被拒也能快速改投，试错成本低。选刊是策略，不是越高越好——匹配你的工作类型和实力，成功率最高。

2手把手带做

据你的结果强度 + 时间 + 单卡体量，选定目标期刊（多数情况 GRSL/JSTARS 更稳），写一句理由，记入战略卡。

3合格样例

目标期刊确定（有明确理由，匹配工作类型+实力+时间）。

4最常踩的坑

① 第一篇冲顶会（单卡难支撑、周期长、易拒）→ 选期刊更稳;② 不看审稿周期 → 结合你的时间线选（想快反馈选 GRSL）;③ 盲目追求高 IF 忽略匹配度 → 工作类型和期刊调性要合。

5卡住怎么自救

拿不准 → 结果中等偏上选 GRSL（快、对遥感友好、增量改进可接受）；纠结期刊 vs 会议 → 第一篇选期刊（无 deadline 压力、审稿更看内容）；怕被拒 → GRSL 周期短，被拒也能快速改投，试错成本低。

WBF（Weighted Box Fusion，加权框融合）——检测里融合多个模型/多次预测的框时，比 NMS 更好。区别:NMS 是“删冗余框”（重叠的只留得分最高的，丢掉其他）;WBF 是“加权融合”（把重叠的多个框按得分加权平均成一个更准的框，信息没浪费）。为什么 WBF 在 Ensemble/TTA 时更优：当你有多个模型（或同模型多次 TTA）的预测，同一目标会有多个略有差异的框；NMS 只保留一个、丢掉其余的信息，WBF 把它们融合成更精确的框，通常涨点。适用场景：模型集成、测试时增强(TTA)的框融合；单模型单次预测的后处理仍用 NMS/Soft-NMS。
