0. 拿到论文

arXiv 搜标题即可；CVPR 论文在 openaccess.thecvf.com 有免费官方 PDF。

★ 完整导读

它要解决什么（一句话）：

前面那些方法（含 Oriented R-CNN）都是让网络自己从数据里学“旋转不变性”。ReDet 的想法是：别学了，直接把旋转不变性做进网络结构里。

核心概念：等变（equivariant）vs 不变（invariant）——这是全书没解释过、但读这篇必须先懂的：

词 意思 例子
等变（equivariant） 输入转了，输出跟着转 图转 90°，特征图也转 90°
不变（invariant） 输入转了，输出不变 图转 90°，识别结果还是“飞机”

ReDet 的两步设计：

★ 一个生活类比：等变 backbone 像一个装了指南针的相机——你转动它，它知道自己转了多少度。不变 RoI Align 像根据指南针读数把照片摆正——不管你怎么转，最后得到的照片都是正的。

★ 自检三问

  1. 等变和不变有什么区别？（答：见上表）
  2. ReDet 为什么参数反而更少？（答：旋转不变性由结构保证，不用靠大量参数去“死记”各种朝向）
  3. 它和 Oriented R-CNN 的思路差在哪？（答：Oriented R-CNN 优化的是“怎么高效生成旋转框”，ReDet 优化的是“怎么提取与朝向无关的特征”——一个在框，一个在特征）

★ 三条曲线的健康长相（原文说了，这里给具体数值感）

曲线 健康长相 典型数值（Oriented R-CNN on DOTA）

病征 → 病因对照（补充原文的决策树）

病征 最可能原因 怎么确认
loss 长期持平 lr 太小，或标注为空 看 acc 是不是一直 100%（空标注的特征）
loss 缓慢上升 lr 太大 减半重试
loss 突然 nan lr 太大 / 脏数据（宽或高为 0 的框） 先减 lr；不行就查数据

loss 锯齿状剧烈波动 batch 太小 + lr 偏大 正常范围内的抖动可接受，看趋势

晚上段 · S²A-Net 泛读 + 四大家族对比表

S²A-Net 导读（泛读，20 分钟）

一句话：它解决的是特征和框对不齐的问题。

什么叫“对不齐”（这是全书没解释的关键概念）：

检测头在特征图的某个位置做预测，但那个位置的特征是按水平的感受野提取的，而目标是斜的。特征“看”的区域和目标实际占的区域不重合——这就是 misalignment。

S²A-Net 用两个模块解决：先粗略生成旋转框（FAM），再按这个框去对齐特征（ODM），然后基于对齐后的特征做最终预测。

★ 四大家族对比表（原文让你画，这里给填好的骨架）

家族 代表 核心思路 优点 代价 一句话记忆
旋转 RoI 变换 RoI Transformer (2019) 先出水平 RoI，再学着转成旋转 RoI 精度高，思路直观 多一个模块，慢 “先水平后掰弯”
高效旋转 proposal Oriented R-CNN (2021) RPN 里多回归 2 个偏移，直接出旋转 proposal 又快又准，实现简洁 — “RPN 直接出斜框”
旋转等变 ReDet (2021) 把旋转不变性做进网络结构 特征更稳，参数更少 backbone 要专门设计和预训练 “给网络装指南针”
特征对齐 S²A-Net (2022) 按预测的框去对齐特征 解决 misalignment，单阶段也能准 多一次特征变换 “让特征跟着框转”

D12 · R³Det + 六大流派 + 第一个消融

上午段 · R³Det 导读

一句话：单阶段检测器 + 逐步精修。先快速出一个粗框，再用一个精修模块（FRM）把特征重新对齐、把框修得更准，可以精修多次。

它和 S²A-Net 的关系：两者解决同一个问题（特征对齐），思路很像。区别是 R³Det 强调“可以级联多次精修”。读完这两篇，你就理解了“单阶段旋转检测”这条线的主要矛盾是什么。

中午段 · 六大流派表

在 D10 那张四大家族表上，补两行：

家族 代表 核心思路 一句话记忆
单阶段精修 R³Det (2021) 粗框 → 特征精修 → 细框，可级联 “先画后描”
改表示 / 改 loss Gliding Vertex (2021)、GWD/KLD 绕开角度回归本身的困难 “不回归角度，回归别的”

★ 最后一行是重点，因为它指向 《名词逐个讲透》§5.2 说的角度周期性问题：−89° 和 +89° 几何上几乎相同，数值上差 178°，直接回归角度会在边界处炸掉。

  • Gliding Vertex 的解法：不直接回归角度，而是回归水平框四条边上的滑动比例。
  • GWD / KLD 的解法：把框建模成二维高斯分布，用分布之间的距离当 loss——角度周期性问题自然消失。

★ 这一行是你 M3 最可能的选题来源之一。 原因：它是纯方法层面的问题、有清晰的数学表述、不需要大算力、且至今没有公认最优解。现在就把它标记出来。

D13 · vis_results.py（含旋转框 IoU 完整实现）

原文在这里明确放弃了：“IoU 算旋转框较复杂 → 第一次可先只画框、不算 IoU”。

但没有 IoU，你就分不清“检对”和“误检”，那张图的价值就少了一半。旋转框 IoU 其实不复杂，OpenCV 有现成的求交函数。下面是完整实现，我实测跑过，并用解析解对拍验证过。

① 先垫概念

旋转框 IoU 为什么比水平框难

水平框求交很简单：交集 = max(0, min(x2) - max(x1)) × max(0, min(y2) - max(y1))。

旋转框的交集是一个多边形（可能是 3 到 8 条边），要先求出这个多边形，再算它的面积。

好消息：OpenCV 自带这个功能。

它返回交集区域的顶点，再用 cv2.contourArea 算面积即可。三行搞定，不需要装 shapely。

TP / FP / FN 是什么（全书没解释，但读 per-class AP 必须懂）

缩写 全称 含义 在图上
TP True Positive 预测框和某个 GT 的 IoU ≥ 阈值 → 检对了 绿框
FP False Positive 预测框找不到匹配的 GT → 误检 黄框
FN False Negative GT 没有任何预测框匹配上 → 漏检 粗红框

匹配规则（这就是 mAP 计算的内核）：按预测分数从高到低，每个预测去抢还没被占用的、IoU 最大的那个 GT。 抢到就是 TP，抢不到就是 FP。剩下没被抢的 GT 就是 FN。
