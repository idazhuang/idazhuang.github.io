1. 本周你要装的第三套框架

① 先垫概念：这次和前两次有什么不同

你已经装过 MMRotate（W1）和用过裸 PyTorch（W3）。这周会同时碰到三种代码组织方式，先分清：

代码 框架基础 特点 本周在哪用
BIT / ChangeFormer 裸 PyTorch（各自独立的仓库） 轻量、单文件脚本、自己写训练循环 D29、D31 变化检测
MMSegmentation MM 生态（和 MMRotate 同源） config 继承那一套，你已经熟了 D32 语义分割
GeoSeg（UNetFormer 的家） PyTorch Lightning + timm 又是另一套约定 D32（如果你要跑 UNetFormer 本体）

★ 这本身是个重要认知：开源代码没有统一标准。 你两年里会遇到至少五六种组织方式。能快速判断“这是哪一类、入口在哪”，比熟悉某一个框架更值钱。

判断方法（30 秒）： text 有 configs/ + tools/train.py → MM 系 有 pytorch_lightning 的 import → Lightning 有 main.py / train.py 且直接写 for 循环 → 裸 PyTorch

② MMSegmentation 怎么装（全书零字，这里补）

★ 关键：不要装进你的 mmrot 环境。 MMSegmentation 0.x 和 MMRotate 0.x 虽然同代，但依赖版本要求不完全一样，混装容易互相顶掉。单开一个环境。

★ 注意 -b 0.x：MMSegmentation 的默认分支是 1.x（用 mmengine + mmcv 2.x），和你熟悉的 0.x 那一套不同。为了复用你 W1 学到的知识，建议先走 0.x 分支。

验证：

如果报错，直接翻 《MMRotate 保姆级实操》第 5 节 的报错表——症状和解法完全一样，那张表是通用的。

⑥ 你同时学会了什么：第二次装 MM 系框架，你应该只花 20 分钟。 如果还是花了两小时，说明 W1 的 SOP 没写好——回去把 SOP 补成“换个框架能直接照抄”的程度。这就是当初写 SOP 的意义。

2. ★ D32 的问题：UNetFormer 不在 MMSegmentation 里

原文写的是：“跑 UNetFormer baseline（LoveDA，体验 MMSegmentation）”。

这一句把两件不兼容的事拼在了一起：

  • UNetFormer 的官方实现在 GeoSeg（github.com/WangLibo1995/GeoSeg），基于 PyTorch Lightning + timm。
  • MMSegmentation 里没有 UNetFormer。

照原文做，你会在 MMSegmentation 的 configs 里翻半天找不到 UNetFormer，然后不知道自己错在哪。

★ 两条路，先想清楚你今天要什么

路线 A：跑 UNetFormer 本体 路线 B：体验 MMSegmentation
用什么 GeoSeg（PyTorch Lightning） MMSegmentation
和你上午读的论文对得上吗 ✅ 就是那篇 ❌ 换成别的模型
复用你 W1 学的 config 技能吗 ❌ 又是一套新约定 ✅ 完全复用
参考成绩 UNetFormer 在 LoveDA 上 52.4% mIoU 看你选的模型

★ 我的建议：走路线 B，用 MMSegmentation 内置模型在 LoveDA 上跑。

理由：今天的教学目的是“体验语义分割这个任务、拿到第一个 mIoU”，不是“复现 UNetFormer 这一篇”。 用 MMSegmentation 能复用你已有的 config 技能，40 分钟就能出结果，而学 GeoSeg 那套 Lightning 约定要额外花两三小时——这两三小时这周不值当。

如果你就是想跑 UNetFormer（比如你打算做分割方向），把它挪到 W5 之后的机动时间，别占用 D32。

★ 从这三组数字读出四件事

  1. 准确率 98% 的废物模型，F1 = 0。 原文举了这个例子，现在你亲手算出来了。
  2. 真正干活的模型准确率只高了 1.3 个点（98% → 99.3%），F1 却从 0 到 0.82。 ——准确率在不平衡任务里几乎没有分辨力。
  3. ★ F1 的两种算法差 8.8 个点（0.8205 vs 0.9085）。 如果你误用了“两类平均”，会以为自己的模型比论文强很多，实际是算法用错了。BIT 在 LEVIR-CD 上报的 ~89–91% 是“只算变化类”的口径。
  4. ignore 类排不排除，mIoU 差 2.7 个点。 LoveDA 必须排除。

★ 这就是 W2-D13 那条纪律的第二次应用：任何你要用的度量，先用手算案例对拍一遍。 指标算错不会报错，只会给你一个错误的自我认知——而且会一路错到论文里。
