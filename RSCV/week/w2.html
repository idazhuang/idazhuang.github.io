上午段

精读 Oriented R-CNN(Xie et al. 2021, ICCV)

1先垫概念

  • 方法论文：核心是“它提出了什么新东西、为什么比前人好”。读它你要能回答：它解决了旋转检测里的哪个具体痛点？用什么招？
  • 两阶段检测器(two-stage)：先“生成候选框(proposal)”（可能有目标的区域），再“对候选框做精细分类+回归”。Oriented R-CNN 属于这一类，它的创新在于高效地生成“旋转候选框”。
  • 一阶段 vs 两阶段（这个范式对比要刻进脑子）：一阶段（如 YOLO 系）直接在特征图上预测框，快但通常精度略低；两阶段先选候选区再精修，准但通常慢一些。遥感旋转检测里两类都有人做。理解这个权衡，你看任何检测论文都能先归位它属于哪类、为什么这么选。
  • RoI(Region of Interest)：候选框框出的那块特征区域。旋转检测里是 Rotated RoI（旋转的候选区）。把候选框对应的特征“抠”出来送进第二阶段精修——这个“抠特征”的操作（RoI Align/旋转 RoI Align）是两阶段检测的关键零件。
  • 为什么从 Oriented R-CNN 开篇：它是空天院孙显组的代表作、社区复现成熟、在 DOTA 上是强 baseline——既是你第一个要跑通的实验，也是你后续改进（M3–M4 加自己的组件）的基座。读懂它，等于读懂了“两阶段旋转检测器”这一整类。

晚上段

准备训练 config + 改 batch_size 适配 4090 + dry-run

★ 本周四道闸门都缺关键一步，先看补充页　DOTA 没给下载地址和目录结构、切图命令没说要先改 json、"改好的 config"从没给出内容、学习率与 batch 的配比只字未提、评测没说 test 集根本没有标注。《W2 DOTA baseline 保姆级实操》 把这五处全部补齐。另有 D8 详注版（Oriented R-CNN 完整导读 + config 逐行）与 D10–D14 详注版（四篇论文导读 + 旋转框 IoU 完整实现）。
另外：本周要精读 Oriented R-CNN、逐行读 config、分析 per-class AP，这些全部建立在 backbone/FPN/anchor/IoU/mAP 之上，而全书从没讲过这层——开始前先读 《检测与训练核心概念详解》。

1先垫概念

  • dry-run（试运行）：正式开跑前，先只跑 1 个 epoch / 几十个 iteration，确认“能正常训练、不报错”，再投入几小时正式训练。这是避免“跑了 3 小时才发现路径写错”的保命操作。
  • batch_size（批大小）：一次喂给模型几张图。越大越稳但越吃显存。你是 4090(24GB),Oriented R-CNN + ResNet-50 通常能开 batch_size=2(甚至更高)，比 12GB 卡宽裕得多——这是你硬件的优势。
  • dry-run 是一种“先排雷再投入”的科研习惯：训练动辄几小时，如果路径、显存、标签有问题，等几小时崩了再发现，时间全浪费。先用 1 epoch/几十 iter 快速验证“链路通不通”，通了再正式投入——这个习惯能帮你省下大量“白等”的时间，以后每个新实验都该先 dry-run。
  • 把单卡 4090 写成你的“卖点”而非“短板”：你只有一张卡，看似不如实验室的多卡集群，但这恰恰是你论文的差异化定位——“在单张消费级 GPU 上实现 X”本身就是高效性的证明。从第一个实验起就记录“我用单张 4090、batch_size=2、训练耗时 X 小时”，这些数字以后会变成你论文里 Params/FPS/单卡可复现的卖点。资源受限不是借口，是你的特色。

2带做

复制一份 config 改成你的:① 改数据路径指向你下载/切好的 DOTA;② batch_size 先设 2（4090 够）;③ 跑一次 dry-run（把 epoch 临时设 1，或只跑几十 iter）看能否正常前进。

3合格样例

dry-run 时终端持续打印 loss（且是有限数、在变化），无报错——截图存证。这说明数据通了、模型能训。

4坑

① 直接开正式训练不 dry-run → 几小时后才暴雷;② batch_size 设太大爆显存(CUDA out of memory);③ 数据路径用了相对路径在后台跑时找不到。

5卡住自救（决策树）

  • CUDA out of memory → 把 batch_size 降到 1；仍不行→减小输入分辨率或开混合精度(fp16)。
  • loss 打印出 nan → 学习率太大，先按“batch_size 减半则 lr 减半”的线性原则调小 lr。
  • 报“找不到标注/图片” → 路径错，用绝对路径，并确认 DOTA 已按需要切过图（明天 D9 做）。

中午段

运行 DOTA 切图工具（理解“为什么切”+ overlap 的作用）

1先垫概念

  • 为什么切图(image split):DOTA 原图常 2000×4000+，整张塞进 GPU 既爆显存又让小目标更小。所以把大图切成 1024×1024 的小块(patch)再训练。这是遥感检测特有的工程步骤，通用 CV（图本就小）不需要。
  • overlap（重叠）：切块时让相邻块重叠一部分（如 200 像素），避免一个目标正好被切在边界上、两块都只看到半个。
  • 为什么这是遥感“特有”的坑：通用 CV 数据集(COCO)的图本来就几百像素、目标占比也合适，直接喂就行；遥感是“超大图 + 超小目标”的极端组合，不切图根本训不了。这个差异是你理解“遥感 CV 难在哪”的一个具体切口——很多遥感特有的设计都源于“图太大、目标太小、还任意朝向”。
  • 切图带来的新问题（也是你未来可做的点）：切块会割裂大目标（一座桥被切到两块），也会让模型看不到全局上下文；推理时还要把各块的预测拼回原图并去重。这些都是遥感检测的工程难点，记下来——它们既是你现在要正确处理的，也可能是未来论文里可以改进的地方（如何更好地处理跨块目标）。

上午段

精读 ReDet(Han et al. 2021, CVPR)——旋转等变网络

1概念

旋转等变(rotation-equivariant)——直觉：遥感目标朝向随机，如果网络“图转了多少度、特征也跟着转多少度”，就天然对朝向鲁棒。ReDet 把这种“等变性”设计进网络。理解“为什么旋转等变对遥感重要”即可。

2带做

监控训练：TensorBoard + 看懂三条曲线

1先垫概念

  • TensorBoard：可视化训练过程的工具，能画出 loss、学习率、mAP 随训练步数的曲线。
  • 三条曲线的“健康长相”：loss 应总体平稳下降（可以抖，但趋势向下）；学习率 按 schedule 变化（常见先 warmup 上升再阶梯下降）；mAP（若每隔几 epoch 验证一次）应逐步上升。
  • 为什么看曲线比看终端数字强：终端滚动的数字你只能看到“此刻这一个值”，看不出趋势；曲线把整个训练过程画出来，一眼就能判断“在降/在升/卡住/发散”。这是诊断训练的核心手段，以后每次训练都要做这个“体检”。
  • 不健康的几种长相（看到就要排查）:loss 不降反升或长期持平（lr 太大/数据标签有 bug）;loss 突然飙到 nan/inf（lr 太大或脏数据）;loss 降但 mAP 一直是 0（标签/类别映射/评测路径错）。记住这几种“病征”对应的“病因”，下面决策树会用到。
  • 学习率曲线为什么要看：它能确认 schedule 真的按预期在跑（warmup 有没有生效、阶梯下降在第几 epoch），若 loss 在某个点突然变化，对照 lr 曲线常能解释（比如 lr 阶梯下降时 loss 跟着下一个台阶）。

1先垫概念

  • 消融实验(ablation)：只改一个变量、其余完全不变，看这个变量对结果的贡献。它是科研中最基础、审稿人最看重的实验方法。换 backbone 是最安全的入门消融。

晚上段

把 `vis_dota.py` 升级为 `vis_results.py`(画预测框 vs GT 框 + 算 IoU)

1先垫概念

  • 定性分析(qualitative analysis)：不只看数字，看图判断模型好坏。标准做法：同一张图上画预测框（绿）和真值 GT 框（红），一眼看出对/错/漏。
  • GT(ground truth)：人工标注的“标准答案”框。
  • IoU(Intersection over Union)：预测框与 GT 框的“重叠程度”= 交集面积 / 并集面积，0~1，越接近 1 越准。它是判断“这个预测框算不算检测正确”的核心度量。

2手把手带做

基于 D6 的脚本扩写 20-代码实验/utils/vis_results.py:① 读模型推理结果（MMRotate 可输出预测，存成 pkl/json）;② 在图上画预测框（绿）和 GT 框（红）;③ 选做：对一对框算 IoU 并标在框上。

3合格样例

输出图上绿框=预测、红框=GT；能直观看到“哪些目标被准确框中、哪些漏检（只有红没绿）、哪些误检（只有绿没红）”。

4坑

① 预测结果的坐标格式和 GT 不一致（都要转成 8 点角点再画）;② 颜色不区分，看不出对错（务必预测/GT 不同色）。

5卡住

拿不到模型预测结果 → 用 tools/test.py 加 --out result.pkl 把预测存下来再读；IoU 算旋转框较复杂 → 第一次可先只画框、不算 IoU，把“对错漏”看清就达标。
