校订说明

做成网站时改了什么、没改什么，以及你自己需要再核实的地方。

这份手册原本是 106 个 Markdown 文件。做成网站时我通读了结构、核对了日历编号， 下面是发现的问题和站内的处理方式。原文的判断、任务和内容一律照录，没有改写观点。

一、日历编号：三处对不齐

# 现象 站内处理
1 W28、W44 没有独立周文件。102 个周文件要覆盖 104 周日历，这两周是原计划的缓冲周，被并进了相邻周。 保留 W28 / W44 的位置，做成《缓冲周怎么用》一页，把“缓冲周该干什么”补齐。
2 M8（W29–W32）的 D 编号整体前移 7 天。W29 标注 D190–D196，按“周号 × 7”应为 D197–D203。连锁结果是 D218–D224 这 7 天在正文里没有对应内容。 原文照录，在 M8 四个周页面顶部加了「编者注」。按周号顺着做即可，内容衔接不受影响。
3 W48 覆盖 14 天（D323–D336）。这是一个“两周块”：D323–D329 是完整的 7 天三时段，D330–D336 是一段收尾说明，不是三时段结构。 原文照录。W48 页面里那段收尾块单独成节，标题保留原样。

天数口径：原计划按“24 个月 = 730 天”取整表述，但 104 周 × 7 天 = 728 天； 扣掉两个缓冲周后，正文实际带教 714 天 / 2142 个时段。站内统一用 728 / 2142 这两个数。

二、模块周数：不是每个模块都是 4 周

M7 和 M11 各只有 3 个周文件（W25–W27、W41–W43），M16、M18、M21 是 5 周，M24 是 9 周（W96–W104）。 这是原计划的排布，不是缺文件。侧栏和进度地图按真实周数显示。

三、排版：统一了中文标点

原文里有约 13000 行存在中英标点混用（中文句子里用半角 , ; : ? !，以及用直引号 “…” 而不是中文引号）。站内做了规范化：

  • 中文语境下的半角逗号/分号/冒号/问号/叹号 → 全角；
  • 成对直引号 → 中文弯引号「“ ”」；
  • 含中文的半角括号 → 全角括号。

代码块、行内代码、URL、英文书名与英文标题里的标点一律不动（例如 Object Detection in Optical RS Images: A Survey 的冒号保持半角，09:00、3:1、1,000 也不动）。 数字和事实没有任何改动。

四、代码块：补了语言标注

原文 584 个围栏代码块里有 836 处没写语言（有的一个文件里多次出现）， 站内按内容自动判定为 bash / python / markdown / yaml / text 并做了语法高亮。 另外修了三类渲染问题：中文里"加粗紧贴汉字"时加粗标记失效（标准 Markdown 的规则对不加空格的中文很不友好）、 列表紧跟段落时被吞进段落、列表内代码块带多余缩进。原文里个别没有配对的孤立 ** 也一并去掉了。

五、内容层面的既有订正（原文已写明，这里汇总一次）

原手册在正文里已经做过几处事实订正，值得单独记住：

  • RingMo 归属空天院孙显组，不是自动化所；
  • SARCLIP 已替换为王超组 2025 TACMT；
  • 天智杯并非空天院主办——练手可以，但不能当作“破冰”的理由。

六、还需要你自己核实的

手册写于 2026 年年中，下面这些会随时间变化，动手前请自己查一次最新的：

  • 软件版本与安装命令：PyTorch / CUDA 轮子、MMCV / MMDetection / MMRotate 的版本匹配关系变动很快， 以官方安装文档为准；手册里的 cu121 组合是当时的稳妥解。
  • 数据集下载地址与协议：DOTA、DIOR、FAIR1M 等的官方入口、许可条款可能已调整。
  • 期刊/会议的投稿系统、截稿时间、分区：以官网为准。
  • 目标团队的人员与研究方向：老师的课题组构成、招生与合作方式会变，发邮件前先看最新主页与近两年论文。
  • 竞赛信息：主办方、赛程、赛题每年不同。
