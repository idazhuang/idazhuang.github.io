缓冲周怎么用

原计划留了两周缓冲（W28、W44）却没写内容。这一页是网站补的。

原计划里有两周是缓冲周：W28（在 M7 与 M8 之间）和 W44（在 M11 与 M12 之间）。 它们没有独立的周文件——因为缓冲周的内容本来就不该提前写死。

这一页是网站补的，用来回答一个很实际的问题：缓冲周到底该干什么？

缓冲周不是休假，也不是“多做一周”

它的作用只有一个：把偏差吸收掉，让后面 60 多周还能按原节奏走。 长周期计划失败，几乎从来不是因为某一周做慢了，而是因为慢了以后没有回正的机制， 偏差一路滚雪球，到某个点整个计划就被放弃了。缓冲周就是那个回正机制。

进缓冲周的第一件事：先诚实盘点（30 分钟）

拿出前面几周的周复盘，逐条对一遍，然后把自己归到下面三类中的一类。别骗自己，也别过度自责。

你的状态 判断依据 这一周该怎么用
A · 落后了 有明确没做完的硬交付（实验没跑完、论文某章没写、baseline 缺几个） 全周补进度，只补硬交付，不开新任务
B · 跟上了但很虚 任务都打了勾，但心里知道很多是“糊过去的”：代码没跑通只是抄了、论文读了没写笔记 全周做返工：把糊过去的地方补实
C · 真的跟上了 硬交付齐、笔记齐、实验可复现 一半时间做加固，一半时间真休息

A 类：落后了怎么补

  1. 列出所有欠账，写在一张纸上，每条标注“补完要几个时段”。
  2. 按对后续的阻塞程度排序——会卡住下一周的排最前，不会卡住的往后放。
  3. 只补前 60%。剩下的 40% 直接划掉，不是延后，是划掉。 长计划里最危险的心态是“欠的都要补上”，那样你会在补账里彻底陷进去。
  4. 一周结束时必须回到主线，无论补没补完。

划掉欠账不是失败。计划的价值在于让你两年后站在目标上，不在于每一格都打勾。

B 类：返工清单（照着查）

  • 跑过的 baseline，换台机器 / 换个终端能不能一次跑通？跑不通就说明没有真复现。
  • 读过的论文，5 段式笔记的第 4 段（启发 / 没解决的）写了没有？空着的等于没读。
  • 实验结果，随机种子固定了吗？记录在实验矩阵里了吗？没有的话数字不可信。
  • 写过的章节，能不能对着大纲说清每一段在论证什么？说不清就是堆砌。
  • 代码，有没有一份 README 让三个月后的自己能重新跑起来？

C 类：加固 + 休息

  • 加固：把《环境 SOP》《报错速查表》《实验矩阵》三份文档更新到最新；把知识库里散落的笔记打标签归位； 给已有的开源仓库补一段文档或一个 demo。这些事平时永远排不上，缓冲周正好做。
  • 休息：真的休息 2–3 天，不看论文不跑实验。24 个月是长跑，会主动休息的人才走得完。

无论哪一类，缓冲周都要做的三件事

  1. 更新阶段目标：对照阶段硬交付清单，看还差什么，把剩余周次重新分配一遍。
  2. 检查两条线的平衡：博士论文（原方向）这几周被挤掉了多少？如果连续三周为零，下一阶段必须补回来。
  3. 写一段给自己的话：这几周最消耗你的是什么？可以怎么减少？写进周复盘。

什么时候可以跳过缓冲周

只有一种情况：A 类欠账为零、B 类返工项为零，而且你最近两周睡得好、状态稳。 这时可以把缓冲周直接并进下一模块，提前一周开始。但这一周的“休息”不能省， 把它挪到周末即可。
